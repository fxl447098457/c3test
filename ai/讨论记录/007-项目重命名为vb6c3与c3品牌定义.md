# 007-项目重命名为vb6c3与c3.exe品牌定义

> 日期：2026-06-24
> 状态：已决策
> 结论：项目名从 `vb6c` 重命名为 `vb6c3`，编译器产物为 `c3.exe`

---

## 一、命名由来

VB6 原生编译工具链的核心编译器是 `c2.exe`，我们的新编译器命名为 `c3.exe`：

```
c2.exe  →  VB6 原厂编译器  →  x86, ANSI, 单线程
c3.exe  →  我们的新编译器  →  x64, Unicode, 多线程
```

**c2 → c3**，传承 + 升级。c3 自带"第三代"含义，对应三大核心特性升级。

项目名 `vb6c3` = `vb6` + `c3`，简洁明了，GitHub 无同名项目冲突。

> 注：C3 语言（c3-lang.org）是独立的编程语言项目，与我们无关，上下文中不会混淆。

---

## 二、c3.exe 核心特性定义

| 特性 | c2.exe (VB6原厂) | c3.exe (我们的) |
|------|-------------------|-----------------|
| 目标架构 | x86 (32-bit) | x64 (64-bit) |
| 字符串编码 | ANSI (VB6 String = BSTR/ANSI) | Unicode (VB6 String = BSTR/UTF-16，源码支持 UTF-8) |
| 线程模型 | 单线程 / Apartment COM | 多线程 / Free-threaded COM |
| 运行时 | MSVBVM60.dll | 自建 RTL (vb6rtl3)，静态链接为主 |
| 调试信息 | PDB | PDB（MSVC 原生） |
| COM 支持 | 原生 | 原生（MSVC ABI） |
| 后端 | 专有 c2 + link | C 代码生成 + cl.exe + link.exe |

---

## 三、重命名改动清单

### 3.1 CMakeLists.txt

- `project(vb6c ...)` → `project(vb6c3 ...)`
- `add_executable(vb6c ...)` → `add_executable(c3 ...)`（产物名为 c3.exe）
- `add_library(vb6rtl_core ...)` → `add_library(vb6rtl3_core ...)`
- `add_library(vb6rtl_win32 ...)` → `add_library(vb6rtl3_win32 ...)`
- 宏定义 `VB6C_NO_LLVM` → `VB6C3_NO_LLVM`
- 宏定义 `VB6C_LLVM_TOOL_MODE` → `VB6C3_LLVM_TOOL_MODE`
- 宏定义 `VB6C_LLVM_DIR` → `VB6C3_LLVM_DIR`
- CMake option `VB6C_ENABLE_LLVM` → `VB6C3_ENABLE_LLVM`
- CMake option `VB6C_LLVM_DIR` → `VB6C3_LLVM_DIR`

### 3.2 命名空间

- `namespace vb6c` → `namespace vb6c3`（全局搜索替换）

### 3.3 源文件中的引用

- 所有 `#include` 路径无需改动（目录结构不变）
- 注释和字符串中 `vb6c` → `vb6c3` / `c3`
- 错误信息前缀 `vb6c:` → `c3:`

### 3.4 ai/ 文档更新

- 001-006 文档中的 `vb6c` 引用改为 `vb6c3`
- 进度表 004 中的项目名更新

### 3.5 不改的

- 仓库目录名 `vb6.pro` — 仓库级名称，与内部项目名独立
- 源码目录结构 `src/` — 保持不变
- LLVM 相关占位文件 — 保留，未来可启用

## 四、验证标准

重命名完成后需满足：

- [ ] CMake 配置成功：`cmake -B build -G Ninja`
- [ ] 编译成功：`cmake --build build`
- [ ] 产物为 `c3.exe`（build 目录下）
- [ ] `c3.exe --version` 输出包含 `vb6c3` 字样
- [ ] 所有宏定义正确切换（`VB6C3_NO_LLVM` 为默认）
