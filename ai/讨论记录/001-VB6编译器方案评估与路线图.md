> 日期: 2026-06-24
> 状态: 已定方案

## 一、项目背景

目标：实现一个完整的VB6编译器，将VB6工程源码编译为原生二进制，支持x86+x64，要求100%兼容——无需修改代码即可通过编译。

参考了三个项目：
1. **FreeBASIC (fbc)** — 开源BASIC编译器（`参考/freebasic/`）
2. **AvaloniaVisualBasic6** — C#/Avalonia复刻的VB6 IDE+语言（`参考/AvaloniaVisualBasic6/`）
3. **twinBASIC** — 闭源商业VB6继任者（`D:\code\tb\_ref\release\`）

## 二、三个项目详细分析

### 2.1 FreeBASIC (fbc)

| 维度 | 详情 |
|------|------|
| 版本 | 1.20.0 |
| 许可证 | fbc: GPLv2+; rtlib/gfxlib2: LGPLv2+ (含静态链接例外) |
| 自举语言 | FreeBASIC 自身 (编译器用FB写FB) |
| rtlib/gfxlib2 语言 | C + 少量 ASM |
| 成熟度 | 生产级 (20+年历史) |
| 代码量 | ~150K行 (编译器核心~80-90K, rtlib~50-60K, gfxlib2~15-20K) |

#### 编译器架构

```
FB源码 → [词法] → [预处理] → [语法] → [AST] → [AST优化] → [IR]
    │
    ├─ -gen gas (默认32位) → [TAC] → [emit_x86] → GAS ASM → as → ld → 可执行文件
    ├─ -gen gas64          → [GAS64] → GAS x86-64 ASM → as → ld → 可执行文件
    ├─ -gen gcc            → [C代码] → gcc -c → ld → 可执行文件
    ├─ -gen clang          → [C代码] → clang -c → ld → 可执行文件
    └─ -gen llvm           → [LLVM IR] → llc → as → ld → 可执行文件
```

#### 核心模块（src/compiler/，173个文件）

| 模块 | 关键文件 | 行数估计 | 功能 |
|------|---------|---------|------|
| **驱动** | fbc.bas | ~4795 | 命令行前端、编译驱动、链接调度 |
| **词法** | lex.bas, lex-utf.bas | ~3000 | 手写LL(2)扫描器，5种编码支持 |
| **预处理** | pp.bas, pp-cond.bas, pp-define.bas | ~2000 | #if/#define/#include等 |
| **语法** | parser-*.bas (~35个) | ~15000 | 递归下降LL(2)，含表达式/声明/复合语句/quirk语句 |
| **符号表** | symb*.bas (~16个) | ~10000 | 符号类/属性/状态，过程重载解析，名称重整 |
| **AST** | ast*.bas (~28个) | ~15000 | 35种节点类，常量折叠，SSE向量化 |
| **IR+后端** | ir*.bas (~12个) | ~20000 | IR_VTBL虚表分发，TAC/C/GAS64/LLVM四种后端 |
| **发射器** | emit*.bas (~5个) | ~13000 | x86指令发射+SSE/SSE2 |
| **RTL绑定** | rtl*.bas (~18个) | ~5000 | 运行时库接口 |

#### IR设计亮点：虚表分发的多后端系统

```freebasic
' ir.bas 核心设计
select case( env.clopt.backend )
case FB_BACKEND_GCC, FB_BACKEND_CLANG
    ir.vtbl = irhlc_vtbl       '' C代码后端
case FB_BACKEND_LLVM
    ir.vtbl = irllvm_vtbl      '' LLVM IR后端
case FB_BACKEND_GAS64
    ir.vtbl = irgas64_vtbl     '' 64位GAS后端
case else
    ir.vtbl = irtac_vtbl       '' 默认：x86 32位TAC后端
end select
```

IR_VTBL 包含约40+函数指针，所有后端实现相同接口，后端切换完全透明。

#### 与VB6的核心差距

| VB6特性 | FreeBASIC状态 | 说明 |
|---------|-------------|------|
| **COM/ActiveX** | 完全不支持 | 无IDispatch/IUnknown/TypeLib/CreateObject |
| **窗体(Form)** | 不支持 | 无.frm/Form加载卸载 |
| **控件(Control)** | 不支持 | 无UI控件，无控件数组 |
| **事件(Event)** | 不支持 | 无Event/RaiseEvent/WithEvents |
| **Variant类型** | 不支持 | 无Variant/Empty/Null |
| **默认属性** | 不支持 | 无Text1 = "hello"简写 |
| **命名参数** | 不支持 | 无arg1:=value1 |
| **Optional参数** | 不支持 | 可用重载模拟 |
| **ParamArray** | 不支持 | 无参数数组 |
| **Implements** | 有限 | FB有接口继承但非VB6语义 |
| **VB6项目文件** | 不支持 | 无.vbp/.cls文件格式 |
| **VB6运行时对象** | 不支持 | 无App/Screen/Printer/Clipboard |

#### 参考价值

1. **`ir.bas` 的 IR_VTBL 虚表设计**：约40个函数指针的后端接口抽象，换后端只需换虚表
2. **`ir-gas64.bas` 的x64调用约定处理**：Windows x64 ABI的详细栈帧布局代码 (8423行)
3. **`ast.bas` 的AST节点分配/遍历**：高效的池分配+访问者模式
4. **`lex.bas` 的多token前瞻缓冲**：LL(2)实现的标准做法
5. **`symb-proc.bas` 的过程重载解析**：函数签名匹配算法 (3457行)

#### 编译器/解析器分析

**不是编译器，是树遍历解释器**：

```
VB6源码 → [ANTLR4 Lexer(VB6Lexer)] → [ANTLR4 Parser(VB6Parser)] → [Parse Tree/AST]
    → [PrePass] (注册Sub/Dim/Option)
    → [StatementExecutor] (遍历AST执行语句)
    → [ExpressionExecutor] (遍历AST计算表达式)
    → 执行结果
```

## 四、决策分析：为何不选二次开发

### VB6编译器的本质难点

VB6编译器与传统编译器的区别：**VB6语言与COM/VB6 RTL深度耦合**。传统编译器难题（词法/语法/代码生成）反而不是最大的挑战，真正的难点在于VB6特有的语义层：

| VB6特有语义 | FreeBASIC | AvaloniaVB6 | 补全难度 |
|-------------|-----------|-------------|---------|
| Variant类型系统 | 无 | 无 | 高 (VARIANT结构+12种子类型+隐式转换) |
| COM IDispatch后期绑定 | 无 | 无 | 高 (IDispatch::Invoke+TypeLib) |
| Default Property解析 | 无 | 无 | 中 (需语义分析阶段处理) |
| Named Arguments | 无 | 无 | 中 |
| ParamArray | 无 | 无 | 中 |
| WithEvents/RaiseEvent | 无 | 无 | 高 (事件连接点+Sink) |
| .frm窗体解析+控件 | 无 | 有(仅Avalonia替代) | 高 |
| On Error/Resume | 有(qb方言) | 无 | 中 |
| ByVal/ByRef默认规则 | 有 | 不完整 | 低 |

### 结论

补全这些VB6特有模块的工作量 ≈ 从零写一个VB6编译器前端，二次开发无净收益。

## 五、最终方案：C++ 从零构建

### 技术选型

| 决策 | 选择 | 理由 |
|------|------|------|
| **语言** | C++ (C++17/20) | 系统级操作、PE/COM/TypeLib直接操控 |
| **后端** | LLVM | tB验证可行，免手写x86/x64代码生成，自动优化+多目标 |
| **前端** | 手写LL(2)递归下降 | VB6语法边界情况多，手写更灵活 |
| **链接** | MSVC link.exe 或 LLD | 生成标准PE/COFF |
| **运行时** | C++实现VB6 RTL | BSTR/Variant/SAFEARRAY用Windows API |
| **参考蓝本** | FreeBASIC架构 | AST+IR虚表分后端设计成熟可借鉴 |
| **语法参考** | VB6.g4 (proleap-vb6-parser) | 最完整的VB6语法定义 |
| **兼容性验证** | twinBASIC | 作为参考实现对照 |

### 编译器架构设计

## 六、MVP路线图

### 阶段1：编译器骨架 + 纯逻辑编译（3-4个月）

**目标**：能编译无窗体的.bas/.cls模块为x86/x64原生PE

**范围**：
- 手写LL(2)词法器（参考FreeBASIC lex.bas架构）
- 手写递归下降语法器（VB6语法定义参考VB6.g4）
- 语义分析核心（类型推导、Variant、过程调用解析）
- LLVM IR后端（生成LLVM IR -> llc -> link）
- VB6 RTL子集：字符串(BSTR)、Variant、SAFEARRAY、文件I/O、错误处理
- 基本数据类型：Byte/Integer/Long/Single/Double/String/Boolean/Date/Currency/Variant
- 基本语句：Dim/Const/If/For/Do/Select/GoTo/GoSub/On Error
- 过程：Sub/Function，ByVal/ByRef，Optional，ParamArray
- Type/Enum
- Declare语句（DLL调用）

**验证**：用VB6标准模块写Fibonacci/排序/文件读写，编译运行验证

### 阶段2：COM+对象模型（3-4个月）

**目标**：支持Class模块、Implements、CreateObject、事件

**范围**：
- 对象模型：Class Initialize/Terminate、属性过程、默认属性
- COM支持：TypeLib导入、IDispatch后期绑定、vtable布局
- WithEvents/RaiseEvent编译支持
- COM互操作：CreateObject/GetObject
- Implements接口实现
- 集合/Collection
- 窗体解析（.frm格式，但不生成运行时窗口）

**验证**：编译含Class和COM的VB6工程

### 阶段3：窗体+控件+100%兼容（6-8个月）

**目标**：完整编译含.frm的VB6工程，100%兼容

**范围**：
- .frm/.frx完整解析（参考AvaloniaVB6的Deserializer）
- 窗体运行时（CreateWindowEx包装、消息循环、DoEvents）
- 内置控件集（20+个：TextBox/CommandButton/ListBox/ComboBox/Label/Frame/CheckBox/OptionButton/ScrollBar/Timer/PictureBox/Image/Shape/Line/DriveListBox/DirListBox/FileListBox/Data/OLE）
- 控件属性/事件/方法映射
- 控件数组
- MDI窗体
- 菜单系统
- .vbp工程文件完整支持
- 逐项验证tB兼容性测试用例

**验证**：真实VB6工程无需修改即可编译运行

## 八、风险与应对

| 风险 | 等级 | 应对策略 |
|------|------|---------|
| Variant类型系统复杂度 | 高 | 分阶段实现，先支持基础子类型，逐步扩展 |
| COM后期绑定性能 | 中 | 先正确后优化，可加缓存层 |
| 窗体/控件运行时工作量巨大 | 高 | 阶段3单独安排6-8个月，可考虑子代理并行开发各控件 |
| VB6语法的边界情况 | 中 | VB6.g4已覆盖大部分，可通过真实工程测试发现遗漏 |
| LLVM依赖体积 | 低 | tB已有先例，LLVM发布包完善；后期可补自有后端 |
| 与tB的兼容性差异 | 中 | 建立兼容性测试套件，逐用例对齐 |
