## 一、总体目标

实现 **vb6c3** 编译器（输出 **c3.exe**），将 VB6 工程源码编译为原生 Windows 二进制（x64 优先，x86 后补），100% 兼容 VB6 语法，无需修改源码即可通过编译。

**C 代码生成 vs LLVM IR 的优势**（ai/006 详细论证）：

| 维度 | C 代码生成 + MSVC | LLVM IR |
|------|-------------------|---------|
| 依赖 | 仅需 MSVC（Windows 自带或 Build Tools） | 需 LLVM 开发包（>1GB） |
| 调试 | 生成可读 C 代码，直接调试 | IR 难读，调试信息复杂 |
| COM 互操作 | C/C++ 天然支持 COM，零障碍 | 需手动处理 COM 类型 |
| 链接 DLL | 直接 #pragma comment(lib) | 需 LLVM 链接器配置 |
| 跨平台 | C 代码是通用的，换编译器即可 | LLVM 本身跨平台 |
| 构建速度 | MSVC 增量编译快 | LLVM 编译 IR 较慢 |

**MSVC 驱动工作流**：

```
VB6 源码 → Lexer → Parser → AST → Semantic → CCodeGen → .c/.h 文件
                                                          ↓
                                                    msvc_driver.cpp
                                                          ↓
                                              cl.exe (编译) → .obj 文件
                                                          ↓
                                              link.exe (链接) → .exe/.dll
```

## 五、风险与缓解（已修订）

| 风险 | 概率 | 影响 | 缓解策略 |
|------|------|------|---------|
| Variant 类型推导复杂度超预期 | 高 | 延期2-3周 | 先支持4-5种子类型，其余报"未实现" |
| ~130个歧义关键字导致解析混乱 | 高 | 返工 | 参考 vb6parse 的软关键字机制，逐个修复 |
| VB6 语法边界情况遗漏 | 高 | 返工 | 参考 VB6.g4 覆盖 + vb6grammarfuzz 后期引入 |
| RTL 函数数量巨大(160+) | 中 | 延期 | 分4批实现，P0 先覆盖55个核心函数 |
| C 代码生成质量问题 | 中 | 兼容性 | 生成的 C 代码必须可编译可调试，定期审查 |
| COM 互操作复杂度 | 高 | P7延期 | 前期绑定/后期绑定两步走，前期绑定优先 |
| MSVC 版本兼容性 | 低 | 低 | 生成标准 C 代码，兼容 VS2019+ |
| 窗体/控件工作量巨大 | 高 | P8延期 | 按控件使用频率排序，分批实现 |

## 六、开发纪律

1. **每个P结束验证里程碑**：不跳步，不积债
2. **每完成一个P更新004-进度表**：保持进度可追溯
3. **测试驱动**：先写测试用例，再写实现
4. **参考VB6.g4**：不确定的语法规则查语法文件
5. **参考 vb6parse**：不确定的实现方式查 Rust 原版思路（ai/011）
6. **tB对照**：P5开始用tB验证兼容性
7. **不支持报错，不静默误编译**：遇到未实现的语法，一律报"尚未支持"错误
8. **RTL 全静态链接**：编译产物不依赖 vb6rtl3.dll，运行时代码直接编入 EXE
