## 一、现状盘点（2026-09-24 摸底）

**数据已齐，裁决缺失**：

| 环节 | 现状 |
|---|---|
| 级别数据 | `Symbol::memberAccessLevels`（lower 成员名 → AccessLevel），pass-1 注册时 5 处回填（字段/过程/属性/事件，semantic_analyzer.cpp:53-157）；跨模块 extSym 拷贝（driver_crossmod）与继承合并（driver_classchain.cpp:628,670）都带上了 |
| 级别取值 | `AccessLevel{Public, Private, Friend, Protected}`（types.hpp:54；Friend 标注"VB6 无此关键字保留"——但 023 包体系已实际启用） |
| 接收者解析 | `visit(MemberAccessExpr)`（semantic_analyzer_expr.cpp:164）只认 UDT / ComModule / ComGlobalNs 三种形状；**类实例的 obj.member 一律落 Variant，无任何级别检查** |
| 变量类型 | `Symbol::variableTypeName` 在变量/参数声明处已回填（decl.cpp:142,258 / stmt.cpp:270 / register.cpp:61）——接收者→类名的原料现成 |

**为什么不能在 visit 期直接查符号表**：跨模块类符号（extSym）的成员表要到 stage 3.5 注入才有；
当前模块分析时 `lookup("OtherCls")` 查无成员 → 与 023 S03"无参裸调用不走 deferredXmodCalls_"
是同一个坑。**级别裁决数据必须由 driver 预计算、分析前下发**（同 S03 预计算屏蔽表的架构）。

## 二、语义口径（v1）

1. **Private**：仅**定义类模块内部**可见——含经 `Me.` 与经任意实例 `obj.`（VB6 语义：
   同类模块内经别的实例也能摸 Private 成员）。类外经 `obj.` 访问 → **硬错**（新诊断，3xxx 段）。
2. **Friend**（同工程内）：等同 Public（VB6 Friend = 工程内可见；本编译器无进程外部主程概念）。
   Friend 的真实约束只在**跨包边界**生效（见 M3）。
3. **Public**：可见，不裁决。
4. **Protected**（tB B08a 扩展）：家族内可见的裁决已由 classchain 通路处理；本计划不重做，
   只回归核对 M2 上线后不误伤继承家族的访问。
5. **缺成员 / 缺类数据**：维持旧行为（Variant + 既有未定义/延后诊断），**不发明新报错**——
   避免 023 踩过的"屏蔽表过宽 → 正例误杀"。

## 三、批次

### M1+M2：预计算表 + Private 硬裁决（同批交付，无发码路径改动，免逐字节护栏）

- **driver 预计算**：分析前扫全部类模块声明（复用 023 `extractProcDecls` 的扫描方式，
  扩展带出 access），建 `clsName(lower) → {memberLower → AccessLevel, definingModule}`。
  经 `setMemberAccessTable()` 下发语义层。
- **接收者解析**（visit(MemberAccessExpr) 前置分支）：
  - obj 为 `Me`（或当前类裸名）→ `currentModule_->moduleName`；
  - obj 为 `IdentifierExpr` 且变量 `variableTypeName` 命中表 → 该类；
  - 其余形状（表达式接收者/链式访问）→ v1 不裁决，落旧路径。
- **裁决**：命中类 + 成员级 = Private + `currentModule_ != definingModule` → 硬错；仅 pass 2，去重。
- **测试**：`tests/acc` 夹具（同模块 obj. Private 放行 / Me. 放行 / 跨模块 Private 拒收 /
  跨模块 Public 放行 / Friend 同工程放行 / 继承家族 Protected 不回归）。

### M3：包导出类 Friend 成员跨包拦截（闭合 023 v1 边界）

- driver 把包导出类的 Friend 成员并入预计算表（来源：包清单 `[Export]` + 包内扫描，
  而非宿主符号表），宿主 `obj.friendMember` → **VB7008**（或复用 7006，待实现时定）。
- 同包内、包→包不受限；`Friend=True` 豁免逻辑与 S03 同构。
- **测试**：pkg 分类追加 2-3 用例（cls_friend_via_obj_bad / cls_friend_via_obj_ok）。

### M4：回归核对（不新增功能）

- 继承家族 Protected 访问、WithEvents、With 字段写、COM 默认成员、委托直调各跑一遍既有套件；
  全量门禁判据照旧：`FAIL=0` 且唯一 SKIP 为 `test_vbman`。

## 四、风险

- **误杀面**：variableTypeName 指向 UDT/接口/COM 类型时不得进裁决（须确认查到的是类）；
  表按"声明过的类名"白名单收口。
- 大小写：成员键一律 lower（既有惯例）；`storageKey()` 的属性后缀形态需在预计算侧对齐。
- 判据与 022 的 stage 3.5 错峰：本计划纯语义层诊断，不动发码，预期无冲突。

## 五、M1+M2 实装记录（2026-09-24）

落地与设计的差异（两处，都是摸底后发现的硬约束）：

1. **`Me` 是独立 `MeExpr` 节点**（parser_expr.cpp:384），不是 IdentifierExpr —— 接收者解析按两种形状分派。
2. **类类型局部变量没有 `variableTypeName`**：LocalDeclStmt 原先只对委托类型回填
   （semantic_analyzer_stmt.cpp:268-272 "此处仅委托类型需要"）。守卫拿不到接收者类。
   → 放宽：`As <简单类型名>` 且名字命中预计算表（= 工程内类）时也回填。
   消费方核查过（cgen_util_classtype / comwrite / with 全部有 kind 守卫），安全。

另发现并处理一个**字段/过程不对称**（设计稿未预见）：

- B07b 继承合并时，祖先 Private **字段**仍并入派生类（inhFields 无 Private 剔除），
  祖先 Private **过程**被剔除（转发桩只收非 Private，注释原文"已去掉被遮蔽与 Private 的"）。
- 若按设计稿"家族内一律放行"：派生类 `Me.<祖先Private过程>` 语义放行 → 发码期 C2129
  （实测负例落的就是这个）。比报错糟一档。
- → `MemberAccessEntry` 加 `isField`：家族放行**只对字段**成立；Private 过程在
  定义类之外（含派生类）一律 3028 拦下。

改动清单：
- `src/semantics/symbol_table.hpp`：`MemberAccessEntry`/`MemberAccessTable`（预计算表类型）
- `src/driver/driver.hpp` + `driver_semantics.cpp`：`buildMemberAccessTable()`（扫 AST 建
  表，Property wins 判定经局部 procKindOf 映射与语义层 memberProcKinds 同构复刻）+
  `setMemberAccessTable` 下发
- `src/semantics/semantic_analyzer.hpp`：`memberAccess_` + `checkMemberAccessGuard`
- `src/semantics/semantic_analyzer_expr.cpp`：visit(MemberAccessExpr) 前置守卫 + 实现
- `src/semantics/semantic_analyzer_stmt.cpp`：LocalDeclStmt 补类类型 variableTypeName
- `src/common/diagnostics.hpp`：`SemPrivateOutsideClass = 3028`
- `tests/acc/`（3 用例）+ run_tests.ps1 `acc` 分类

实测：`acc` 分类 `PASS=3 FAIL=0`（acc_m2_ok / acc_m2_family_field / acc_m2_private_blocked）。

## 八、084c 类构造函数（带参/无参）实装记录（2026-09-24）

> 批注：此节本是独立任务"类构造函数"，为免另开文档，记在 084a 之后。

**语义设计（C3 扩展，VB6 本体不允许 `New X(...)`）**

- 无参构造：`Class_Initialize`（已有，不动）。
- 带参构造：`Class_Initialize` 直接写形参（`Sub Class_Initialize(ByVal a As Long, ByVal s As String)`），
  调用侧 `Set x = New Cls(42, "hi")`。
- 元数校验：新诊断 **VB3029**（`SemCtorArityMismatch = 3029`）。校验源 = driver 预计算
  `ctorParamCounts_`（类名→形参个数），同 memberAccess 表架构（visit 期查不到跨模块类符号）。
  - 表内类（含包导出类）：实参数 ≠ 形参数 → 3029（含"无参类给实参""带参类不给实参"两特化文案）。
  - 非本工程类（COM/外部）带实参 → 3029（运行期没有可承接的构造通路，不静默丢参）。

**发码**

- `emitClassFactory` 公共体提成 `emitFactoryBody(ctorCallSuffix)` lambda：
  - 带参类：生成 `vb6_cls_X_NewParams(<makeParamList 同类方法>)` 真工厂 +
    **`_New(void)` 保留**为默认值路径（各形参 `defaultValue()` 兜底）——默认实例
    （`_Default`）、COM 打包（`vb6_ComPack_X`）、隐式 `As New` 等内部自动创建通路仍以
    零参 `_New()` 为契约，不能因带参构造而消失。
  - 无参类：与旧输出逐字一致（lambda 体照抄）。
- 类 .h 补 `_NewParams` 原型（调用点常在别的模块）。
- `visit(NewExpr)`：本工程类带实参 → 发 `_NewParams(实参…)`。
- v1 边界：Class_Initialize 形参仅支持非 Optional 的 `ByVal`（ByRef/Optional → 发码期报错）；
  `_New(void)` 的默认值兜底即这些通路的构造语义。

**改动清单**：ast_expr.hpp（NewExpr.args）+ ast_clone.cpp、parser_expr.cpp（parseNewExpr 吃
`(...)`）、diagnostics.hpp（3029）、semantic_analyzer.{hpp,expr.cpp}、driver.{hpp,semantics.cpp}
（ctorParamCounts_）、cgen_com.cpp、cgen_base_generate_c_open.inc、cgen_expr.cpp；
tests/ctor（3 用例）+ run_tests.ps1 `ctor` 分类。

实测：ctor 3/3、pkg 22/22、acc 5/5 全绿（`amt:42` 带参构造 / `CNT:7` 无参不回归；
两负例 3029 均带行号触发）。
