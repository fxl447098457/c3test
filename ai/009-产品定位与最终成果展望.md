# 009-产品定位与最终成果展望

> 日期：2026-06-24
> 状态：已确认
> 结论：定位为**旧项目迁移工具 + 新项目编写工具**，不与 twinBASIC 竞争

---

## 一、产品定位

**vb6c3 是什么**：一个开源的、现代化的 VB6 编译器，让旧 VB6 项目能迁移到 x64/Unicode 平台，同时也支持用 VB6 语法编写新项目。

**vb6c3 不是什么**：不是 VB6 IDE 的完整替代品，不与 twinBASIC 竞争。

| 维度 | 我们的定位 | twinBASIC 的定位 |
|------|-----------|-----------------|
| 产品形态 | 编译器 + LSP + DAP 内核 | 全功能 IDE |
| 开源 | 是 | 否（闭源 + 付费） |
| 窗体设计器 | 不做（属于 IDE 项目） | 内置 |
| 竞争策略 | 做好底层，对接任意前端 | 一站式解决方案 |
| 目标用户 | 需要迁移旧项目、偏好开源的开发者 | 愿意付费换取完整体验的开发者 |

## 二、最终成果预判

### 核心判断

不会做到 100% 兼容 VB6 所有语法细节和控件行为，但能做到**常见 VB6 项目可用**的程度（70-80% 兼容度）。

### 按模块的可行性

| 模块 | 可行性 | 说明 |
|------|--------|------|
| 纯逻辑代码（.bas） | 高 | 词法/语法/语义分析核心目标 |
| 类模块（.cls） | 高 | COM 二进制契约，vtable 对齐即可 |
| 简单 COM 调用 | 高 | 按 COM 协议交互 |
| ActiveX DLL 产出 | 中高 | link.exe /DLL 开关 + .def 导出 |
| 窗体代码编译 | 中 | .frm 纯文本解析无障碍，.frx 二进制结构已推算出 |
| 旧 OCX 控件兼容 | 中 | COM 协议交互 + 自建平替（方法成员一致） |
| 运行时函数全覆盖 | 中 | 200+ 函数，循序渐进，但必须完全覆盖 |
| VB6 语义边界情况 | 低 | 无底洞，按用户反馈优先级逐步覆盖 |
| 100% 兼容旧 OCX | 极低 | 第三方控件行为不可控 |

### 关键澄清

1. **窗体设计器不是编译器项目的事** — .frm 是纯文本结构化的窗体布局描述语言（不是二进制），.frx 是二进制但结构简单且已推算出。可视化设计器属于 IDE 项目，最终可能用 Web 实现（twinBASIC 也如此）。

2. **旧 OCX 兼容靠 COM 协议** — 有暴露的成员就按协议交互，实在不行的提供自有平替（哪怕方法成员全部一致性）。

3. **运行时函数必须完全覆盖** — 数量巨大（200+），但这是正确性底线，循序渐进直至 100%。

4. **语言边界情况是无底洞** — 但不能装作不存在（详见第五章）。

## 三、成功的关键变量

| 变量 | 影响 | 我们能做的 |
|------|------|-----------|
| **窗体设计器能否做出来** | 没有 GUI 设计器，只能在纯逻辑/类库场景用，天花板低 | 不在编译器项目范围，但 IDE 项目的进展决定生态上限 |
| **twinBASIC 的走向** | 如果它转向闭源收费，开源阵营就有空间 | 做好开源社区，保持差异化 |
| **VB6 社区活力** | 社区在萎缩，但忠诚 | 优先解决旧项目迁移痛点，制造口碑 |
| **编译器质量** | 错编译比不编译更可怕 | 遇到不支持的语法报"暂不支持"，绝不通篇静默错编 |

## 四、产品形态

### 最终交付物

```
c3.exe           编译器驱动（shell-out cl.exe + link.exe）
c3-lsp.exe       语言服务器（LSP 协议，供 VS Code 等调用）
c3-dap.exe       调试适配器（DAP 协议）
vb6c3-core.lib   核心静态库（词法/语法/语义/符号/类型/诊断）
vb6c3-cgen.lib   C 代码生成后端
vb6c3-rtl3.lib   运行时库（静态链接进用户程序）
```

### 不交付

- IDE / 窗体设计器（独立项目）
- vb6rtl3.dll（不提供动态链接版，默认静态链接）
- 任意 COM 组件的完整兼容层

### VS Code 集成

通过扩展调用 c3-lsp + c3-dap，编译器项目提供协议端，扩展壳子由 IDE 项目负责。

## 五、VB6 语言边界情况（无底洞清单）

以下每一个都在真实旧项目中出现过。编译器不需要第一版全支持，但必须知道它们的存在。

### 5.1 默认属性隐式解析

```vb
' 这两行在 VB6 里等价 — Label1 的默认属性是 Caption
Label1 = "Hello"
Label1.Caption = "Hello"

' 更过分的情况
Dim x As Variant
x = Text1          ' x 得到 Text1.Text（默认属性），不是 Text1 对象本身
Set x = Text1      ' 这才是 Text1 对象
```

每个控件/类都有默认属性，不在源码里显式写出来，编译器得替你猜。

### 5.2 And / Or 的双重人格

```vb
' 同一个 And，根据操作数类型决定是逻辑运算还是位运算
Dim a As Long, b As Long
a = 6 And 3        ' 位运算：结果 2（0110 AND 0011 = 0010）

Dim c As Boolean, d As Boolean
c = True And False  ' 逻辑运算：结果 False

' 混合情况
Dim e As Variant
e = 6 And True      ' 先转 Boolean 为 Integer(-1)，6 And -1 = 6
```

### 5.3 Mid$ 语句（不是函数）

```vb
Dim s As String
s = "Hello World"
Mid$(s, 7, 5) = "VB6"   ' s 变成 "Hello VB6  d"
' Mid$ 出现在赋值号左边时是语句，不是函数
' VB6 独有的"可写函数"概念
```

### 5.4 四个空值

```vb
Dim v As Variant
' v 初始值是 Empty（不是 Nothing，不是 Null）

v = Null              ' 数据库场景常见
If v = Null Then      ' 永远是 Null（不是 True 也不是 False）
  ' 不会执行
End If
If IsNull(v) Then     ' 唯一正确判断方式
  ' 会执行
End If

' Missing：Optional 参数未传时
Sub Foo(Optional x As Variant)
  If IsMissing(x) Then  ' 只有 Variant 类型 Optional 才有 Missing
    ' ...
  End If
End Sub
```

### 5.5 IIf 两个分支都计算

```vb
' IIf 是函数，两个分支都会被计算
Dim x As Variant
x = IIf(True, 1, 1 / 0)   ' 运行时错误：除零！
' 即使条件为 True，1/0 还是会被求值
```

### 5.6 DefType 隐式类型声明

```vb
DefInt A-C    ' 以 A/B/C 开头的变量默认 Integer
DefStr D-F    ' 以 D/E/F 开头的变量默认 String

Dim answer    ' a 开头 → Integer，不是 Variant
Dim delta     ' d 开头 → String
```

老项目中很常见，现代 VB6 开发者很多都不知道。

### 5.7 隐式调用 COM 默认方法

```vb
Dim rs As Recordset
x = rs("FieldName")
' 完整展开：
x = rs.Fields.Item("FieldName").Value
' 三层默认属性隐式调用
```

### 5.8 On Error 的古怪行为

```vb
Sub Test()
  On Error Resume Next
  Err.Raise 5        ' 错误被吞掉
  Debug.Print Err.Number  ' 输出 5
  
  On Error GoTo 0    ' 关闭错误处理
  ' Err.Number 仍然是 5，没有重置
  
  On Error GoTo Handler
  ' 现在 Err.Number 是 0 — 切换处理方式时重置了
  Exit Sub
Handler:
  Resume Next
End Sub
```

### 5.9 类型强制转换的地雷

```vb
Debug.Print "3" + 4       ' 7（数值相加）
Debug.Print "3" & 4       ' "34"（字符串连接）
Debug.Print "3a" + 4      ' 运行时类型不匹配错误

Debug.Print "3" + "4"     ' "34"（字符串连接）
Debug.Print 3 + "4"       ' 7（数值相加）
' 操作数顺序影响结果类型
```

### 5.10 Integer 溢出静默截断

```vb
Dim x As Integer
x = 32767 + 1   ' 运行时溢出错误

Dim y As Long
y = 32767 + 1   ' OK

Dim a As Integer, b As Integer
a = 30000
b = 4000
y = a + b       ' 运行时溢出！两侧都是 Integer，中间结果也是 Integer
```

## 六、应对策略

### 原则

1. **第一版：能编译无窗体、无 COM 的纯逻辑代码**
2. **遇到不认识的语法报"暂不支持"，绝不静默错编** — 错编译比不编译更可怕
3. **按用户反馈频率排优先级** — 先解决最常见的边界情况
4. **运行时函数完全覆盖** — 这是正确性底线，必须 100%

### 边界情况分级

| 级别 | 含义 | 示例 |
|------|------|------|
| P0 必须支持 | 旧项目高频使用 | 默认属性、类型强制转换、On Error |
| P1 应该支持 | 常见但不一定撞上 | Mid$ 语句、IIf 双求值、DefType |
| P2 尽量支持 | 特定场景需要 | COM 默认方法链、Empty/Null 四态 |
| P3 可延后 | 极少遇到 | Integer 中间结果溢出、On Error 切换重置细节 |

### 运行时覆盖路线

```
v0.1: 核心类型（String/BSTR/Variant/SAFEARRAY）+ 错误处理 + 基本文件 I/O
v0.2: 字符串函数 + 数学函数 + 转换函数 + 日期时间
v0.3: 剩余运行时函数（逐步补充至 100%）
```
