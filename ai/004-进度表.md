## P10 - RTL 内嵌与编译流程封闭

> 目标：将 RTL 运行时库（.lib + 精简头文件）作为 Windows 资源嵌入 c3.exe，编译时释放到临时目录，编译完成后自动清除。用户分发只需 c3.exe，不再需要 rtl/ 目录和 VB6RTL_DIR 环境变量。彻底隐藏 C 语言转译实现细节，体验与 VB6 一致——开箱即用，编译过程不透明。
>
> 绝不暴露中间产物，不保留 --keep-intermediate 开关。编译问题时仅写调试日志供开发者分析。对外宣发也不提及 C 语言转译话术。

### 核心设计

- **构建时（开发侧）**：src/rtl/core/*.c -> MSVC 编译为 4 组 .lib（vb6rtl.lib / vb6com.lib / vb6comserver.lib / vb6forms.lib）；头文件精简为纯声明版（仅保留函数原型、结构体定义、必要宏，删除所有函数体、内部宏、实现注释）；.lib + 精简.h 通过 Windows RC 资源嵌入 c3.exe
- **编译时（用户侧）**：c3 在 %TMP%\C3C\{时间戳}\ 创建会话目录 -> 生成用户 C 代码 -> 从内嵌资源释放 RTL .lib + .h -> shell-out MSVC 编译链接 -> 复制最终 .exe/.dll 到用户指定输出路径 -> 清除临时目录所有内容
- **崩溃残留清理**：c3 每次启动时扫描 %TMP%\C3C\ 下所有子目录，删除时间戳超过 300 秒（5 分钟）的旧会话目录
- **编译失败处理**：失败时将临时目录中的用户 .c 代码片段、MSVC 编译器错误输出、c3 自身诊断信息写入 c3-error.log（存放在用户项目目录），不保留 RTL 文件，不保留中间 .obj/.lib
- **禁用中间产物保留**：不提供 --keep-intermediate 或类似开关。一切编译问题由开发者通过日志分析发给我这里解决

### 对当前代码的改动清单

1. **CMakeLists.txt**：新增 RTL .lib 预编译步骤 + RC 资源嵌入 c3.exe
2. **msvc_driver.cpp**：链接逻辑从编译 rtl/*.c 并链接改为链接释放的 rtl/*.lib
3. **driver.cpp**：移除 VB6RTL_DIR 环境变量查找逻辑；编译流程改为会话目录模式（创建 -> 释放 -> 编译 -> 复制 -> 清除）
4. **driver.cpp**：启动时增加 %TMP%\C3C\ 旧会话清理逻辑（>300s 删除）
5. **driver.cpp**：编译失败时写 c3-error.log（含 MSVC 错误输出 + c3 诊断信息）
6. **dist/rtl/**：整个目录删除，不再分发
7. **dist/使用说明.txt**：删除 rtl 目录说明和 VB6RTL_DIR 相关内容
8. **CLI**：移除任何与 RTL 路径/中间产物保留相关的命令行参数
9. **c3.exe 体积**：预计从 ~960KB 增至 ~1.1-1.3MB（嵌入 .lib + .h 资源）
