## 二、vb6parse — 前端全量参考

> 来源: 参考/vba-gobasic-aspgo/ai/003 + 参考/vba-gobasic-aspgo/gobasic/002-004

### 2.1 五层架构

```
Bytes/String/File → SourceFile → SourceStream → TokenStream → CST → Object Layer
                    (IO层)        (字符流)       (词法层)     (语法层) (结构化层)
```

**对 vb6c3 的映射**：

| vb6parse 层 | vb6c3 对应 | 借鉴要点 |
|-------------|-----------|---------|
| SourceStream (io/) | SourceManager | Windows-1252 解码、零拷贝字符流 |
| Lexer (lexer/) | Lexer | PHF 关键字表、120+ Token 枚举 |
| Parser (parsers/) | Parser | 迭代式 Pratt、状态机控制流 |
| CST (基于 Rowan) | AST | vb6c3 用轻量 AST，不需要无损 CST |
| library/ | rtl/ 函数清单 | 160+ 函数 + 42 语句 = 运行时完整 API 清单 |

### 2.2 词法分析器关键设计

| 特性 | vb6parse 实现 | vb6c3 采用方案 |
|------|-------------|---------------|
| 关键字查找 | `phf` crate 编译时完美哈希 O(1) | 手写 `std::unordered_map` 或 switch，Phase 0 够用 |
| 零拷贝 tokenization | Token 不拥有字符串，只记录偏移量 | 采用：Token 记录 SourceRange，不拷贝文本 |
| 大小写无关 | 输入转小写后比较 | 采用：词法扫描时 tolower 比较 |
| 类型后缀 | 完整支持 %&!#@ | 必须支持，VB6 常用 |
| 日期字面量 | 约 300 行 Rust，最复杂的词法规则 | 需完整实现 #M/d/yyyy# 等格式 |

### 2.3 语法分析器关键设计

| 特性 | vb6parse 实现 | vb6c3 采用方案 |
|------|-------------|---------------|
| 表达式解析 | 迭代式 Pratt 解析器（防栈溢出） | 采用：C++ 递归式 Pratt 深度有限，可接受 |
| 控制流解析 | 状态机（If/For/While 用 FSM） | 递归下降即可，C++ 栈空间充足 |
| 歧义标识符 | ambiguousIdentifier + ~130 个 ambiguousKeyword | 采用：软关键字机制（isSoftKeyword/expectName） |
| 错误恢复 | 同步点 + 继续解析 | 采用：跳至下一个语句边界继续 |
| CST 保留格式 | Rowan 红绿树，保留空白/注释 | 不需要：编译器只需 AST，不需要无损编辑 |

### 2.4 VB6 内置函数完整清单（14 类 160+ 函数）

这是 vb6parse 最重要的贡献——**直接作为 vb6c3 运行时 API 的实现清单**：

| 类别 | 函数 | 数量 | vb6c3 优先级 |
|------|------|------|-------------|
| 数组 | Array, Filter, Join, Split, UBound, LBound | 6 | P0 |
| 转换 | CBool, CByte, CCur, CDate, CDbl, CInt, CLng, CSng, CStr, CVar, CVErr, Str, Val, Fix, Int | 15 | P0 |
| 日期时间 | Date, Time, Now, Year, Month, Day 等 20 个 | 20 | P1 |
| 文件系统 | Dir, EOF, FileAttr, FileDateTime, FileLen 等 9 个 | 9 | P1 |
| 财务 | DDB, FV, IPmt, IRR 等 13 个 | 13 | P3 |
| 格式化 | Format, FormatCurrency 等 5 个 | 5 | P1 |
| 交互 | MsgBox, InputBox, Shell, CreateObject 等 8 个 | 8 | P1 |
| 检测 | IsArray, IsDate, IsEmpty, IsNull, IsNumeric, TypeName, VarType 等 10 个 | 10 | P0 |
| 数学 | Abs, Atn, Cos, Exp, Log, Rnd, Sgn, Sin, Sqr, Tan 等 13 个 | 13 | P1 |
| 字符串 | Left, Right, Mid, Len, InStr, Replace, Trim 等 23 个 | 23 | P0 |
| 注册表 | GetAllSettings, GetSetting, SaveSetting, DeleteSetting | 4 | P3 |
| 文件操作 | Open, Close, Get, Put, Print, Write 等 21 个 | 21 | P1 |

**实现策略**：按优先级分批实现。P0 先支持 ~55 个核心函数，可以编译大部分纯逻辑 VB6 代码。

## 三、VisualBasic6.g4 — 语法权威参考

> 来源: proleap-vb6-parser VisualBasic6.g4 (~2226 行)

### 3.1 关键数据

| 维度 | 数量 |
|------|------|
| 语句类型 | 50+ 种 |
| 歧义关键字 | ~130 个 |
| 表达式优先级 | 14 级 |
| 关键字定义行数 | ~900 行（含 26 个 fragment 字母） |

### 3.2 对 vb6c3 的直接价值

1. **语句分发清单**：50+ 语句类型 = parser_stmt.cpp 的分发 switch 完整列表
2. **歧义关键字列表**：~130 个 ambiguousKeyword = isSoftKeyword() 的查表依据
3. **表达式优先级**：14 级 = Pratt 解析器的 binding power 设定依据
4. **方括号转义**：`[Name]` 语法 = 词法/语法需要支持标识符转义

### 3.3 设计决策

- **不用 ANTLR4 的 26 个 fragment 字母方案**：手写词法器直接 tolower 比较，代码量少 900 行
- **不用 ANTLR4 生成解析器**：手写递归下降控制力更好，更容易处理 VB6 的歧义语法
- **作为权威参考**：不确定语法规则时查 VisualBasic6.g4

## 四、vb6grammarfuzz — 后期质量保障

> 来源: 参考/vba-gobasic-aspgo/参考/vb6grammarfuzz/

### 4.1 架构

```
VisualBasic6.g4 → g4_parser.rs → Grammar IR
                                     ↓
                               generator.rs → 随机 VB6 源码
                                     ↓
                               checker.rs → vb6parse 检查 Unknown 节点
                                     ↓
                               reducer.rs → ddmin 最小化
```

### 4.2 对 vb6c3 的价值

| 阶段 | 用途 |
|------|------|
| P1 完成后 | 用生成的随机 VB6 代码测试解析器的健壮性 |

**不急于实现**：P0-P1 阶段先用手工测试用例，Fuzz 测试从 P2 开始引入。

## 五、aspgo — VBScript 运行时设计参考

> 来源: 参考/vba-gobasic-aspgo/gobasic/001-004

### 5.1 关键发现

1. **aspgo 原型仅 5-8% 完成度**，代码质量不足，但设计文档（ai/001.初步设计.md）质量远高于代码实现
2. **VBScript 是 VB6 的子集**：vb6c3 完成后自动支持 VBScript 语法
3. **COM 对象工厂模式**（ProgID→Go 对象映射）是正确方向，vb6c3 的 COM 层可借鉴
4. **Variant 类型系统设计**（Go interface + type switch）思路可用，C++ 用 std::variant + 运算符重载

### 5.2 vb6go 路线 vs vb6c3 路线

gobasic 文档规划了 "VB6→Go Transpiler" 路线（vb6go），与当前 vb6c3 的 "VB6→C+MSVC" 路线对比：

| 维度 | vb6go（Go 转译器） | vb6c3（C 编译器） |
|------|-------------------|------------------|
| 目标语言 | Go | C |
| 编译管道 | VB6→Go代码→go build | VB6→C代码→cl.exe→link.exe |
| 跨平台 | Go 天然跨平台 | 依赖 MSVC（Windows），跨平台需后补 |
| 运行时 | Go 标准库 + 自建 VValue | C 运行时 + Windows API |
| COM 互操作 | Go windows-rs（不成熟） | C++ COM（成熟） |
| 前端借鉴 | vb6parse Rust→Go 翻译 | vb6parse 思路→C++ 手写 |
| IDE 集成 | 自建 LSP/DAP | IDE 是独立项目 |
| 产物 | Linux/macOS/Windows 原生 | Windows 原生（MVP） |

**结论**：vb6c3 的 C+MSVC 路线在 Windows 平台上更实际——COM 互操作天然优势、链接现成 DLL 零阻力、MSVC 的 PDB 调试体验远优于 Go。vb6go 的跨平台优势是长期方向，不在首版范围。

### 5.3 可复用的设计

| aspgo/vb6go 设计 | vb6c3 复用方式 |
|------------------|----------------|
| VVariant 类型系统（enum + type switch） | 参考 C++ 实现：std::variant + 运算符重载 |
| On Error 错误语义（defer/recover 模拟） | 参考 C++ 实现：setjmp/longjmp + ErrorContext |
| COM 对象工厂（ProgID→工厂函数映射） | 直接采用：C++ 工厂 + COM API |
| ADODB→database/sql 包装策略 | 延后：vb6c3 直接用 ADODB COM 对象 |
| 内置函数分优先级实现清单 | 直接采用：14 类 160+ 函数 |

## 七、四条技术路线的最终评判

参考文档 ai/001 分析了四条 VBA/VB6 编译路线：

| 路线 | 判断 | 理由 |
|------|------|------|
| VBA→C++ Transpiler | **当前已采用** | vb6c3 就是这条路线（VB6→C→MSVC），技术可行，社区验证 |
| P-Code→原生 AOT | ❌ 不采用 | P-Code 规范不完整，调试困难，仍需自建运行时 |
| 静态链接 msvbvm60 | ❌ 不采用 | 本质是逆向工程，长期维护成本高，不支持 x64 |
| 自造运行时+解释器 | ❌ 不采用 | 性能差，工作量大，不适合编译器定位 |

## 十、结论

1. **vb6parse 是最有价值的参考项目**：其五层架构、词法器、解析器、160+ 内置函数清单对 vb6c3 各层都有直接指导作用
2. **VisualBasic6.g4 是语法权威**：50+ 语句、130+ 歧义关键字、14 级优先级是解析器设计的完整依据
3. **aspgo/vb6go 的 Variant 和 COM 设计思路可复用**，但 Go 路线在 Windows 平台上不如 C+MSVC 实际
4. **vb6grammarfuzz 延后引入**：P2 阶段用于质量保障，前期不投入
5. **参考项目的文档已完成研究**，后续开发可直接对照本文档查询借鉴点
