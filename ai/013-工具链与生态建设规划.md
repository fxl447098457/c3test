> 日期: 2026-06-26
> 状态: 规划中

## 一、愿景

c3 不只是一个命令行编译器，而是一套完整的 VB6 开发工具链。从写代码、查错误、补全、调试到编译运行，全流程覆盖。最终形态：

```
c3 编译器 + LSP + DAP + VS Code 插件 + 窗体设计器
= VB6 的现代化开发环境
```

## 三、P0: LSP 语言服务器

### 3.1 LSP 协议映射

c3 编译器已有基础设施，LSP 本质是对现有能力的封装暴露：

| c3 已有能力 | LSP 映射 | 协议方法 |
|-------------|---------|---------|
| 词法分析 (Lexer) | 语义 token 高亮 | textDocument/semanticTokens/full |
| 语法分析 (Parser) | 文档大纲、代码折叠 | textDocument/documentSymbol |
| 语义分析 (Semantics) | 错误诊断 | textDocument/publishDiagnostics |
| 符号表 | 补全、悬停、跳转定义 | textDocument/completion, textDocument/hover, textDocument/definition |
| 符号引用 | 查找所有引用 | textDocument/references |
| 重命名支持 | 符号重命名 | textDocument/rename |

### 3.2 架构方案

```
VS Code 扩展  ←──stdin/stdout──→  c3-lsp.exe  ←──调用──→  c3.exe（增量分析）
```

- c3-lsp 独立进程，通过 stdin/stdout 与 VS Code 通信（LSP 标准传输）
- 增量分析：文件变更时仅重新分析受影响模块，复用 c3 的词法/语法/语义管线
- c3 本身不改动架构，c3-lsp 作为薄封装层

### 3.3 预计工期

| 阶段 | 内容 | 工期 |
|------|------|------|
| LSP-S1 | LSP 通信框架（JSON-RPC + 生命周期） | 1 周 |
| LSP-S2 | 诊断暴露（语义分析 → publishDiagnostics） | 1 周 |
| LSP-S3 | 补全 + 悬停（符号表 → completion/hover） | 2 周 |
| LSP-S4 | 跳转定义 + 引用查找 | 1 周 |
| LSP-S5 | 语义 token + 文档大纲 | 1 周 |

### 3.4 关键决策

1. **语言**：用 C++ 实现（复用 c3-core 静态库），不引入 Go/Node 依赖
2. **增量策略**：文件级增量（修改文件重新分析），不做更细粒度
3. **多文件支持**：VBP 工程级感知，跨模块符号解析

## 四、P1: DAP 调试适配器

### 4.1 调试信息生成

c3 生成 C 代码后由 MSVC 编译，核心问题是 **VB6 源码行号 ↔ 运行时地址** 的映射：

```
VB6 源码 hello.bas:15  →  生成 hello.c:42  →  MSVC PDB → 地址 0x00401030
```

方案：在代码生成阶段输出 **行号映射文件** `xxx.debug.map`：

```json
{
  "source": "hello.bas",
  "mappings": [
    { "vb6_line": 15, "c_line": 42, "c_file": "hello.c" },
    { "vb6_line": 16, "c_line": 45, "c_file": "hello.c" }
  ]
}
```

### 4.2 调试器架构

```
VS Code  ←──DAP──→  c3-dap.exe  ←──读取──→  .debug.map + PDB
                                  ←──控制──→  被调试进程（via Windows Debug API）
```

### 4.3 功能范围

| 功能 | 阶段 | 说明 |
|------|------|------|
| 断点设置 | DAP-S1 | VB6 行号 → C 行号 → 地址断点 |
| 启动/继续/停止 | DAP-S1 | 进程生命周期控制 |
| 单步执行 | DAP-S2 | step over / step into / step out |
| 变量查看 | DAP-S3 | 读取局部变量、全局变量、Watch 表达式 |
| 调用栈 | DAP-S3 | VB6 函数名映射（去 C 生成前缀） |

### 4.4 预计工期

| 阶段 | 内容 | 工期 |
|------|------|------|
| DAP-S1 | DAP 通信框架 + 断点 + 进程控制 | 2 周 |
| DAP-S2 | 单步执行 + 行号映射 | 2 周 |
| DAP-S3 | 变量查看 + 调用栈 | 2 周 |

## 五、P0: VS Code 插件

### 5.1 三阶段交付

| 阶段 | 内容 | 工期 | 用户体验 |
|------|------|------|---------|
| VSC-S1 | 语法高亮 + 代码片段 | 1-2 周 | .bas/.cls/.frm 文件有颜色了 |
| VSC-S2 | LSP 客户端集成 | 2-3 周 | 补全、错误红线、悬停提示 |
| VSC-S3 | DAP 客户端 + 编译命令 | 2-3 周 | F5 调试、一键编译运行 |

### 5.2 VSC-S1: 语法高亮（最早可交付）

- TextMate grammar 定义 VB6 语法高亮规则
- 代码片段（snippet）：常用语句模板（If/For/Sub/Property 等）
- 零依赖，不连接 c3，纯前端
- **可以在 c3 编译器之外独立开发，随时发布到 VS Code Marketplace**

### 5.3 VSC-S2: LSP 集成

- VS Code 扩展启动 c3-lsp.exe 子进程
- 注册为 .bas/.cls/.frm/.vbp 的语言服务
- 配置项：c3 路径、VBP 工程文件路径

### 5.4 VSC-S3: DAP 集成 + 编译

- 注册 c3-dap 为调试类型 "vb6"
- launch.json 配置：程序路径、工作目录、编译参数
- 侧边栏编译按钮：调用 c3.exe 编译当前工程
- 问题面板集成：c3 编译错误 → VS Code 诊断

### 5.5 扩展注册清单

## 六、P2: WebUI 窗体设计器

### 6.1 定位

VB6 的核心体验是拖控件画界面。没有窗体设计器，c3 只能服务纯逻辑/类库场景。WebUI 窗体设计器是 **真正的差异化功能**——市场上没有好的 VB6 窗体在线设计器。

### 6.2 技术方案

```
Monaco Editor (代码编辑)
    +
可视化画布 (拖拽布局)
    ↕  双向同步
.frm 文件 (VB6 窗体定义)
```

- 前端：React/Vue3 + 可视化拖拽框架（react-dnd / vue-draggable）
- 画布：CSS 定位模拟 VB6 的 twip 坐标系统
- 属性面板：反射控件属性，修改后实时更新 .frm
- 控件调色板：VB6 标准控件（Label/TextBox/CommandButton/ComboBox 等）
- 双向同步：画布修改 → .frm 文件更新，.frm 文件修改 → 画布重绘

### 6.3 与 c3 的协作

- c3 已有 .frm 文本格式解析能力（VBP 解析器可扩展）
- WebUI 设计器输出 .frm，c3 编译 .frm 中的代码
- .frx 二进制资源（图片等）的处理待设计

### 6.4 商业定位

| 层级 | 窗体设计器 | 定价 |
|------|-----------|------|
| 社区版 | 无 | 免费 |
| 专业版 | WebUI 窗体设计器 | 付费 |
| 企业版 | 原生窗体设计器 + 高级控件 | 更高价 |

### 6.5 预计工期

| 阶段 | 内容 | 工期 |
|------|------|------|
| WEB-S1 | 画布框架 + 控件拖拽 + 属性面板 | 3 周 |
| WEB-S2 | .frm 双向同步 + 标准控件库 | 3 周 |
| WEB-S3 | 与 VS Code 插件集成 + 预览 | 2 周 |

## 七、P3: 原生窗体设计器

### 7.1 定位

WebUI 验证可行且用户量足够后，开发原生 Win32 窗体设计器。性能更好、更接近 VB6 原生体验。

### 7.2 技术候选

| 方案 | 优势 | 劣势 |
|------|------|------|
| twinBASIC | 开发体验好、64位原生 | 闭源、依赖twinBASIC运行时 |
| C++ + Win32 | 性能最优 | 开发周期长 |
| Go + Walk | 开发较快 | 非原生控件 |
| Electron + 原生模块 | 复用WebUI代码 | 体积大 |

倾向 **twinBASIC**（保持 VB6 开发体验）或 **C++ + Win32**（性能最优），取决于 WebUI 阶段的市场反馈。

### 7.3 触发条件

- WebUI 窗体设计器日活 > 100
- 用户反馈性能不足或体验不够原生
- 企业客户有明确需求

## 十一、商业价值

### 11.1 分层定价模型

| 层级 | 内容 | 定价 | 目的 |
|------|------|------|------|
| 社区版 | c3 编译器 + LSP + DAP + VS Code 基础插件 | 免费 | 用户量、口碑、生态 |
| 专业版 | + VBA 代码保护 + WebUI 窗体设计器 + 编译优化 | 699-999 元/年 或 1999 买断 | 个人开发者收入 |
| 企业版 | + 原生窗体设计器 + 批量授权 + 技术支持 + 定制 | 4999+ 元 | B 端收入 |

### 11.2 核心判断

1. **社区版必须完整可用**——编译、补全、调试都能跑，不是残废版，否则没人用
2. **付费切入点选 VBA 保护 + 窗体设计器**——"怕"（代码被看）和"想"（画界面）是两个最强的付费驱动力
3. **公测期完全免费**——积累用户和口碑，正式版再引入分层
4. **LSP/VS Code 插件永远免费**——这是用户量入口，收费等于自断流量

### 11.3 收入预期

- 乐观：5000 用户 × 5% 付费转化 × 800 元/年 = 20 万/年
- 中性：3000 用户 × 3% 付费转化 × 800 元/年 = 7.2 万/年
- 保守：1000 用户 × 2% 付费转化 × 800 元/年 = 1.6 万/年

主要收入来自 VBA 保护功能（企业痛点）和窗体设计器（可见价值），编译器本体免费。
