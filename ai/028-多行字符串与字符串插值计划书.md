# 028-多行字符串与字符串插值计划书

> 日期：2026-09-25
> 状态：**已拍板、V1 已落地**（2026-09-25，本文件末尾「九、V1 实测读数」是落地后的回填，其中两条**推翻**了本文原来的写法）
> 来源：`todo/vi.md`「群友建议：字符串连接现代语法」（Fan XiaoLei，2026-09-15）——痛点是 VB6 的 `&` 拼接；口径是**现代语法糖，`&` 一字不动、完全兼容**。
> 一句话结论：**两批各自独立过门**。V1 = 反引号原始多行串，**在词法出口归一成普通的 `"..."` token** ⇒ AST / parser / cgen / semantics / driver 与 RTL **全部零改动**；V2 = 串内 `${expr}` 插值，**降成 `&` / `CStr()` / `Format$()` 的普通 AST**，同样不新增运行库面。四条不可让步的硬规则在第四节 —— 其中 R4 是本轮实测换来的（`rawText` 全仓 57 处消费、至少四处各自剥引号或折 `""`，见 §三.3）。

## 一、为什么必须是新字面量形态，而不是把老串改一改

VB6 只有三件套：`"..."` 不跨行（实测 `src/lexer/lexer_literal.cpp:12-19` 遇 `\n` 直接 `LexUnterminatedString`）、长行靠 `_` 续行（`lexer.cpp:300-306` + `isLineContinuation()` :77-94）、串内引号靠双写 `""`（`lexer_literal.cpp:22-33`）。写一段 SQL/JSON 的代价全在这三条上：换行要点续行符、引号要双写、`\` 与 `%` 之类的字符还得小心别跟 VB6 的行继续规则混。

把老 `"..."` 直接改宽（允许跨行 / 允许插值）是**语义变更**，不是加法：任何存量源码里的 `"a` + 未闭合，或文本里恰好出现的 `${`，含义都会漂移。本项目的最高护栏是"存量产物逐字节不变"，所以新能力必须挂在一个**今天必然编译失败**的记号上。

实测这个记号是现成的：`` ` `` 今天走 `lexer.cpp:307-309` 的 default 分支 ⇒ `LexUnexpectedChar("意外字符")`。**把一个报错变成特性**，"存量程序不受影响"这条论证天然成立，不需要额外护栏兜。

顺带三条免费的性质（都实测过）：

1. **不碰关键字表**：反引号不是标识符字符，`token.hpp:153-157` / `lexer_keywords.cpp:56-60` / `token.cpp:32-35` / `parser_helpers.cpp:57-62` 这四处软关键字登记面**一处都不用动**（区别于 `Via`/`CoClass` 那批）。
2. **不碰语句切分**：`Lexer` 是按行发 `TokenKind::NewLine`（`token.hpp:13`）的，而原始串扫描把内部换行**吃进 token 文本**、不发 `NewLine` ⇒ parser 的语句边界逻辑不知道 V1 存在。
3. **不碰预处理器**：`src/preprocessor/preprocessor.hpp:2-4` 写明它"位于 Lexer 和 Parser 之间，**过滤 token 流**" ⇒ 多行串里的 `#Const` / `#If` 落在 token 内部，不会被当指令。这条对"嵌 shell / Makefile / C 头文件"是决定性的：**串里以 `#` 开头的行是安全的**。

## 二、语法

### V1 —— 原始多行串

```vb
Dim sql As String
sql = `SELECT Id, Name
FROM Users
WHERE Name = '张三' AND Tag = "vip"`
Debug.Print Len(sql), InStr(sql, vbCrLf) > 0     ' 换行是 vbCrLf
```

| 规则 | 口径 | 依据 |
|---|---|---|
| 定界 | 起始 `` ` `` 到下一个**未成对**的 `` ` `` | 与 `""`→`"` 同一心智 |
| 反引号本身 | 双写 `` `` `` 出一个 `` ` `` | 同上 |
| 双引号 | **原样**，不需双写 | 这是它的第一价值 |
| 转义 | **完全没有**：`\n` 是两个字符、行尾 `\` 就是 `\` | 一开 `\` 口，`C:\note\{x}` 这类路径立刻变转义地狱 |
| 行内换行 | 归一成 **CRLF**（`vbNewLine`，位宽 2） | `source_manager.cpp:187-199` 在 `fromFile()` 里把 CRLF/孤立 CR **统一抹成 LF** ⇒ 词法层永远只可能见到 `\n`。所以"照抄源码原始字节"这个选项今天根本不存在，串内换行的位宽**必须**由我们规定；定成 CRLF 后它就是与文件行尾风格无关的确定值，"同一份源码存成 LF 就得到不同字符串"的坑当场消失 |
| 行尾续行 `_` | 串内是普通文本 | `isLineContinuation()` 只在 `lexer.cpp:226` 与 `:302` 被调用，`scanString` 类扫描从不调用它 |
| 空串 | **两枚就是空串**（起始 + 闭合相邻），与 VB6 的 `""` 同规 | **实测订正**：原稿写的是「表达不出空串」，实现按 VB6 同规自然得到「两枚 = 空串」，更好，故改口径 —— 见九-2 |

长度对照（**实测**，双写是贪心的：先看后一枚是否也成对）：1 枚字面反引号 ⇒ **4 枚**（起始 + 双写 + 闭合）；**3 枚 = 未闭合** ⇒ `VB1007`；想以换行结尾 ⇒ 让换行紧跟最后一个内容字符、闭合反引号另起一行（只裁起始侧那一枚）。

### V2 —— 插值

```vb
greet  = `你好 ${name}，合计 ${price * qty} 元`
line   = `坐标 (${pt.X}, ${pt.Y}) 于 ${now:yyyy-MM-dd HH:mm}`
js     = `echo $${HOME} 仍然原样输出，不是插值`
```

| 规则 | 口径 | 依据 |
|---|---|---|
| 开孔 | **`${`**（照 JS/C#/Kotlin 的直觉） | 头部痛点是 SQL/JSON，而 JSON 满是裸 `{` ⇒ 用 `{x}` 开孔等于在主要场景埋雷；`${` 在 JSON/SQL 里不出现 |
| 闭孔 | 由**内层表达式解析器**停下的位置决定，再要求紧随 `}`（或 `:` 格式段） | 于是 `` `t=${ f("a}b") }` `` 天然正确，**不需要手写花括号配平**，也不需要给原始串开反斜杠转义口 |
| 字面 `${` | 写 `$${`（`$$` → `$`） | 只在"把别的语言的源码整段嵌进来"时才用得上，一处双写 |
| 裸 `}` | 就是文本 | 与上一条配套，JSON 安全 |
| 默认语义 | `${e}` ≡ `& CStr(e) &` | 与 `Debug.Print`、`Print #` 等现有出口一致（`vb6_CStr` 内部就是 `vb6_Format(x, NULL)`，`vb6rtl_conv.c:150-151`）⇒ **区域行为与 VB6 一致**，不静默换格式 |
| 格式段 | `${e:fmt}` ≡ `Format$(e, "fmt")` | RTL 现成：`vb6rtl_format.c:157`。`:` 只在孔内**顶层**才是分隔符（`(` `[` 与字符串内的不算，由解析器停下位置自然界定）；fmt 取到第一个 `}` 为止，含 `}` 的格式串不支持（写进不做表） |
| 孔内空 | `${}` 报错 | 不静默当文本 |
| 插值作用范围 | **只在反引号串内**；`"..."` 永不插值 | 硬规则 R1 |

## 三、落地接缝（实测锚点）

### V1（纯原始串：只在词法层落地，AST / parser / cgen / semantics / driver 零改动）

1. `src/lexer/lexer.cpp:265-266`（`c == '"'` → `scanString()` 那条分支旁）加反引号分支 → `scanRawString()`。
2. `src/lexer/lexer_literal.cpp` 新增 `scanRawString()`（与 `scanString()` :7 并列）。**它的产物不是新 token，而是归一后的既有 token**：
   扫到未成对的闭合反引号 → 双写折叠（两枚反引号 → 一枚）→ 行界换行写成 CRLF → 串内 `"` 重新双写 →
   发 `TokenKind::StringLiteral`，`text` 形如 `"…"`，**与手写的 `"..."` 完全同形**。
3. 为什么必须在词法出口就归一（本轮实测的爆炸半径）：`rawText` 全仓 **57 处消费**（`src/driver` 5、
   `backend/detail/module` 3、`backend/detail/expr` 3、`semantics` 2、`ast` 2、`project` 1…），其中**至少四处各自独立地
   剥引号 / 折 `""`**：
   - `src/backend/expr/cgen_expr.cpp:95-111`（发码路径，注释明确"必须在 C 转义之前"）；
   - `src/semantics/semantic_analyzer_register.cpp:126-143`（`Const` 的串值注册，又折一遍）；
   - `src/driver/coclass_activate.cpp:28` + `:99`（`CreateObject(字面量)` 的 ProgID 走 `unquote(rawText)` 比对）；
   - `src/backend/decl/cgen_decl_api.cpp:16-23` + `:61`（`Declare … Lib "x"` 的库名与 alias 名走 `stripQuotes`）。
   ⇒ token 形状不变，这四处连同**将来新增的字面量消费者**全部天然支持反引号串（`Const` 值、`CreateObject` 的 ProgID、
   `Declare` 的库名都能直接写多行串）；
   ⇒ 反过来，若给 AST 加 `Quoted | Raw` 形态位，就得在这四处逐点加分支，且**每新增一处字面量消费者都会漏一次**——
   漏出的形状是"发码对了但 `Const` 值带着反引号"，正是本项目最怕的**静默半支持**。所以形态位这条路不走（见 R4）。
4. 诊断：已加 `LexUnterminatedRawString = 1007`（`src/common/diagnostics.hpp`，词法段 1xxx 原用到 1006），
   位置取**起始反引号**那格行列。文案 = **ASCII**（`unterminated raw string (missing closing backtick)`）——
   原稿说「与邻居同调写中文」，被 **022 D12 的硬约束否掉**：面向测试断言的错误文本一律 ASCII，
   所以断言钉的是 `VB1007` 这个号而不是文案。未闭合时**只吞掉起始那一枚**就退回（不退就会把整份余文
   吃进一个假字面量，1 条错变成一片怪错）。
5. 发码沿用现成路径：`cgen_expr.cpp:112-172` 逐字符转义，非 ASCII 解 UTF-8 码点发 `\u%04X`（星平面拆代理对 :163-169），最终 `:174` 发 `vb6_BSTR_FromStr(L"...")`。
   ⇒ **发出来的 C 字面量是纯 ASCII**，多行串里的中/日/韩/英**不受 `cl.exe` 源码编码假设影响**（不用像 `cc_cn` 那样操心 BOM），RTL 侧也没有新函数。

### V2（**落地改走路线 b：词法展开** —— 依据见本节的三条实测与「十、V2 实测读数」）

6. ~~带孔的串才发新 token kind~~ **不发新 token kind（路线 b 落地后作废）**：`scanRawString` 扫到开孔 就就地展开，第一枚交回、其余压进 `pending_` ⇒ `token.hpp` / `token.cpp` / `parser_expr.cpp` 那两处 字面量入口**一处都没动**。
   `RawInterpLiteral`（+ `token.cpp` 的 `kindToString`）；parser 的字面量入口**有两处**（`src/parser/parser_expr.cpp:78`
   与 `:284`，都是 `case TokenKind::StringLiteral:`）各加一条 case → 同一个 `parseInterpolatedString()`。
   降级点放词法还是放 parser 是本批唯一待定项，两条路线都满足 R4，先量再定：
   - **路线 b（词法展开，真·下游零改动）**：`scanRawInterp()` 把整段串展开成一串**普通 token**——文本段是普通字面量、
     连接是 `&`、孔是 `CStr(...)` 调用——注入 `lookahead_`（`lexer.hpp:93-94`，今天固定 LOOKAHEAD=2）。最理想，
     但要先证明"补料不变式"撑得住一次压进 N 个 token；
   - **路线 a（parser 展开，本批默认）**：token 只带整段文本，由 parser 逐孔子解析后拼出**普通 AST**
     （`Concat` / `CStr` / `Format` / 字面量）。多两个 case，但不碰主扫描循环的不变式，爆炸半径更小，故为默认。
7. **子解析窗口**（本批唯一动到已有接口的地方，**已落地**）：`Lexer` 构造收 `(buffer, diag, begin, end)`（默认全文 ⇒ 存量调用点一字不改），内部把 `content_` 指到 `[begin,end)` 这一 view，并用现成的 `SourceBuffer::getLocation(begin, line, column)` 播种行列。三条好处原样成立：诊断天然落在原文件上（十-2 有实测行号）、越不出孔的右界、整串一趟走完。**代价也实测到了**：`content_` 是 `string_view`， 直接写 `buffer_->content().substr(...)` 拿到的是**临时 string 的视图** ⇒ 悬垂，第一版所有源文件在 (1,1) 就"意外字符"（十-4）。
   于是每个孔 = 一个"窗口化"的 `Lexer` → `Preprocessor` → `Parser`（`Parser` 自持 `preproc_`（`parser.hpp:321`），ctor 收 `std::shared_ptr<SourceBuffer>`（`parser.hpp:31`）⇒ 共享同一份 buffer，**不用拷贝、也不必用 `fromString` 另建**），换来三样：
   - **诊断行列天然正确** —— 子树所有 `SourceLocation` 直接落在原文件上，不需要事后遍历 AST 平移位置。**这就是选"扫描窗口"而不是选"子 buffer"的全部理由**（后者要平移，且 `Const`/语义层的报错会指错行）；
   - **不会越界吃串外文本** —— 右界就是闭合反引号处；孔未闭合时子解析停在区间尾且没见到 `}` ⇒ 报 2015，而不是把后面的代码当表达式吞掉；
   - **线性扫描** —— 停在哪儿由 `Lexer::offset()`（:31，已是 public）加回 `begin` 得到，下一个孔的窗口从那里起，整串一趟走完（不必每次从孔起点重扫到串尾）。
8. 降级目标全是现成 AST：文本段 → 字面量节点（V1 那条），孔 → `CStr(e)` 调用，带格式 → `Format$(e, "fmt")`，按左结合串成 `BinaryOp::Concat`（即 `&`）链 —— 也就是说**降级产物与手写 `a & CStr(x) & b` 完全同形**，不是"看起来像"。
   ⇒ 继承 `src/backend/expr/cgen_expr_binary.cpp:33-42`（两侧 `wrapToBSTR` 已会插 `vb6_CStr(...)`，`ConcatFree` 已回收中间 BSTR）、`src/backend/detail/expr/cgen_expr_call_conv_cstr.inc:27-65`（按实参类型改发 `vb6_CStrLong/Dbl/…`）、COM 默认属性解析（`cgen_expr_binary.cpp:18/25` 的 `resolveComValue()`）。**cgen 与 RTL 零改动**。
9. 诊断（**实测后只剩两条，且都落在词法段**）：`1008 LexUnterminatedInterp`（孔没等到闭合的 `}`，含"孔跨行"这种写法）、`1009 LexEmptyInterpHole`（空孔）。原稿的 `2017 ParseInterpTrailingJunk` **不需要新号**：孔里的 token 交给真 parser 解析，坏形状自然就是既有的语法错 —— 少一条诊断、 文案与邻居一致。文案一律 ASCII（D12）。

## 四、四条不可让步的硬规则

**R1 · `"..."` 的 VB6 语义一字不动。** 不跨行、不插值、不新增转义。`LexUnterminatedString` 那条报错必须继续报（V1 的负例里钉死：`"a` + 换行仍然 1002，而不是变成多行）。插值与跨行是反引号串的私产。

**R2 · 插值必须降成真 AST，不许造"插值节点"让后端认识第二种字符串。** 理由不是洁癖：只有降成 `&` / `CStr()` / `Format$()`，`Option Explicit` 的未声明检查、按类型挑 `vb6_CStrLong`、COM 默认属性解析这三件事才是**自动继承**的。副作用是我们要的：嵌 shell 片段时 `${item}` 撞上作用域里的同名变量，**在编译器里就是响的**（未声明 ⇒ 编译错误），而不是运行期静默换掉。

**R3 · 逐字节护栏必须在"没有反引号"这条前提上闭眼成立。** 沿用 `.build/b16_emitc_guard.py` 那一代手法：BASE exe（`.build/pre_b18_C3.exe` 起新的收线 BASE）vs NEW exe，对存量工程清单跑 `--emit-c`，产物 hash 逐字节全同。V1/V2 都不改 `"..."` 的任何一步（依据是 §三.3 的归一口径 + R4：AST 里没有第二种字面量），所以护栏红 = 实现写歪了，而不是"预期变化"。


**R4 · 反引号形态不许活过降级点：AST 里、cgen 里、RTL 里不存在"第二种字符串"。** 降级产物只有三种现成节点——普通
`StringLiteral`（文本段，含已归一的 CRLF 与双写引号）、`BinaryOp::Concat`、`CStr()` / `Format$()` 调用。
这条不是洁癖，是本轮实测换来的：`rawText` 全仓 57 处消费、至少四处各自剥引号或折 `""`（§三.3）。只要字面量在 AST 里
与普通串同形，那些消费点（**含将来新增的**）就一行都不用改；反之给 AST 加形态位，等于把自己绑到"每新增一处消费者都要
记得分支"上，漏一次就是一个静默半支持的 bug。降级点在词法还是 parser（§三.6 两条路线）不影响本条。

## 五、明确不做（写死，避免下轮复议）

| 不做 | 理由 |
|---|---|
| `"..."` 里插值 / 跨行 | R1；且会让存量 `"C:\${x}"` 静默变义 |
| 一次性 `StrBuilder` 运行库 | 降成 `&` 链就够用（N 孔 N 个中间 BSTR）。真要省分配是**独立一批**：新 RTL 函数 + 新的逐字节影响面，别混进语法批 |
| 对齐 / 填充（`${x,10}` 之类） | `Format$` 已覆盖，语法先进格式段、语义后议 |
| 绝对原样档 `` r`...` ``（跨行但零魔法） | 嵌 shell/JS 大户才会需要；纯加法，v2 再说 |
| `#Const` 里用反引号 | 不存在这条路：条件编译常量的值类型只有 `Boolean/Long/Undefined`（`src/preprocessor/preprocessor.hpp:19-22` 的 `CondCompileValue`），今天根本不接受字符串 ⇒ 无需支持也不是限制 |
| `.frm` / `.vbp` 文件里的文本初值 | 那是**工程文件格式**解析（`project/vbp_parser.cpp:291-305` 的 `unquote(value)` 等），不经 Lexer ⇒ 反引号在那里没有含义。模块头的 `Attribute X = "…"` 行不同：`parser_module.cpp:351-368` 的 `parseAttribute()` 取值就是 `parseExpression()` ⇒ 按 R4 **自动可用**（V1 用例带一条） |
| `Asm` 块内的反引号串 | 块内是 MASM 文本，不是 VB 表达式 |
| 孔内放语句 / 多表达式 | 只有表达式位；`Print` 之类的副作用请写在外头 |
| 去缩进（dedent） | 见 §八待拍板第 1 条：宁要"照抄源码"也不要"哪行说了算"的规则 |
| 常量折叠（把相邻文本段并成一个字面量） | 切段时文本段天然已合并；今天全局就没有字符串常量折叠（`cgen_base_type.cpp:330` 的 Fix 010b 只折整数），不为本特性单开 |

## 六、批次与判据（门 = 推 `github/dev` 跑 Actions `ci.yml`，零新增失败）

**V1 批（原始多行串）—— 已全部落地，读数见九节**

- 判据（正例）：`tests\test_rawstr.bas` 18 条 `Add-BasTest` 读数（x64 + x86 各一条），逐条把反引号串**与手写的
  `"…"` 逐字比相等**，覆盖跨行 / 裁起始换行 / 以换行结尾 / 内嵌引号 / 双写反引号 / 零转义 / 行尾 `_` /

## 七、风险

1. **子解析窗口的边界耦合**：给 `Lexer` 加 `[begin,end)` 会同时被 `Preprocessor`/`Parser` 的构造路径看见。缓解：默认参 = 全文，存量调用点一字不改；负例含"纯 `"..."` 工程的诊断行号不变"。
2. **`--dump-preprocess` 的可读性**：它按 token 重排源码文本，多行 token 会被原样吐出（调试面，不影响正确性）。若碍事，另开小批处理，不夹进 V1/V2。
3. **归一的逆运算必须与四处消费者的折叠严格互逆**：词法把内容重新包成 `"…"` 时要把内嵌 `"` 双写、且不能碰别的东西；
   只要有一处消费者"剥引号但不折 `""`"（本轮实测：cgen / 注册 / `unquote` / `stripQuotes` 四处**都**做了折叠，互逆成立），
   那个位置就会在串含 `"` 时读出错值。⇒ 判据：V1 用例覆盖"`Const` 值含引号"、"`CreateObject` 的 ProgID 含引号（应为负例）"、
   "`Declare` 库名"三条，各打一个落点。
4. **静默替换的最后口子**：嵌 JS/模板时 `${item}` 若**恰好**撞上作用域里同名变量且类型合法，仍会被替换（R2 只能挡住"撞不上"的那部分）。残留风险到此为止，出口是 `` r`...` `` 档（v2）或改用 `"..."` + `_` 续行。
5. **行尾归一 CRLF 与外部期望**：有人会预期"我文件是 LF 就该拿到 LF"。这条要写进手册并在用例里钉死（同一内容 CRLF/LF 两份源，运行期字符串相同）——它是**特性**不是意外。
