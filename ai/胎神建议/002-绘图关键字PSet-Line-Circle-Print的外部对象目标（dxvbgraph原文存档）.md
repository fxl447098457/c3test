# 002 绘图关键字 PSet/Line/Circle/Print 的外部对象目标——群友案例 dxvbgraph 原文存档（2026-09-15）

> **来源**：群聊讨论 + 帖子 <https://www.0xaa55.com/thread-26577-1-1.html>（技术宅的结界 · 技巧探讨版块，2022-01-28 发表）
> **日期**：2026-09-15（存档时间）
> **背景**：讨论 C3 对 VB6 内置 GUI 的兼容度时，先修正了一个认知——PSet / Line / Circle / Print 是**关键字语句**而非函数调用，调用写法完全不同；随后群友（帖子作者）补充了其早年用 VC 写的 DX 绘图类库 dxvbgraph，证明这些关键字语句的**目标对象不限于内置 Form / PictureBox**——任何暴露同名成员的对象都能用关键字写法调用。本文档存档帖子原文，并提炼对 C3 的实现启示。
> **速览**：
> 1. `Scale / PSet / Line / Circle / Print` 是 VB6 关键字语句，语法形态（坐标对连接 / Step 相对坐标 / B·F 标志 / `;``,`Spc Tab 分隔）与函数调用完全不同，不能走普通方法调用路径。
> 2. 这些语句的本质 = **"特殊参数语法的成员调用"**，目标对象可以是任意对象（内置控件 / 外部 COM 类库），判定规则 = 前缀对象存在同名成员。
> 3. 帖子作者发现的"VB 隐藏多年的小秘密"：**TypeLib 中的成员名不受 VB6 词法关键字限制**——普通 VB6 代码无法定义名为 Line 的方法（关键字不能作标识符），但 VC 写的 COM 组件可以在 TypeLib 里定义，VB6 编译器照样认。
> 4. 对 C3 的实现启示：parser 新增 GraphicsStmt / PrintStmt 专用产生式 + 语义层支持任意对象前缀；外部 COM 对象把特殊语法**脱糖成普通实参**后走既有 COM 调用路径，无需专用代码。
> 5. **反向收益**：C3 的 `--dll` 用 CreateTypeLib2 生成 .tlb，成员名同样无关键字限制 → C3 编译出的 ActiveX DLL 也能定义 PSet/Line/Circle 成员供 VB6 关键字写法调用（与该库同款玩法），可作招牌 demo。

> 当年刚学VB还没到一年的时间就在想VB的Form、PictureBox、Printer、UserControl、UserDocument这些控件或类的成员里面除了我们平常用到的方法和属性外，居然还有关键字（Scale、PSet、Line、Circle、Print），就很好奇这些关键字的成员是怎么实现的，然而自己定义方法这些关键字根本没法使用（因为关键字不能作为标识符使用）。直到十二年后的最近一段时间终于发现了VB隐藏了多年的小秘密，这也成功让我实现了自己写的类库创建的对象也能支持这些成员关键字操作。
>
> 于是，我便想到VB自带的绘图是基于GDI的，绘图效率低不说，还不支持Alpha混合。既然这样，干脆我就自己来实现一个DX版的VB图形库吧，让VB原生语法操作获得GPU硬件加速功能。

### VB6 代码示例原文

```vb
Dim dxgw As GraphWindow                                                        ' 定义DX绘图窗口变量
... ...                                                                        ' 这里省略部分初始化代码
Set dxgw = CreateGraphWindow(初始化参数)                                        ' 创建DX图形窗口
dxgw.Cls [背景颜色]                                                            ' 对DX画布清屏处理（背景颜色可选）
dxgw.Scale (X1, Y1)-(X2, Y2)                                                   ' 设置画布的绘图区域
当前光标X = dxgw.CurrentX                                                      ' 获取当前输出光标的横坐标位置
当前光标Y = dxgw.CurrentY                                                      ' 获取当前输出光标的纵坐标位置
dxgw.CurrentX = 当前光标X                                                      ' 设置当前输出光标的横坐标位置
dxgw.CurrentY = 当前光标Y                                                      ' 设置当前输出光标的纵坐标位置
dxgw.Scale                                                                     ' 重置画布的绘图区域为默认
dxgw.PSet [Step](X, Y), [输出颜色]                                              ' PSet操作必须指定坐标，坐标前加上Step表示相对于 dxgw.CurrentX 和 dxgw.CurrentY 的相对坐标，不加则是绝对坐标，颜色可选
读取颜色 = dxgw.Point(X, Y)                                                    ' 和VB原生的操作一样，可以取出DX画布中的对应点的颜色值。
dxgw.Point(X, Y) = 写入颜色                                                    ' 和VB原生的操作不一样的是，DX的Point不再是方法，而是可赋值的属性（赋值表示修改DX画布中的颜色值）。
dxgw.Line [[Step](X1, Y2)]-[Step](X2, Y2), [Color], [B[F]]                     ' 直线与矩形用法：B 表示画矩形框，BF 表示画填充矩形，否则在两点之间画一条直线。
dxgw.Circle [Step](X, Y), Radius, [Color], [Start], [End], [Aspect]            ' 画圆、椭圆、弧形、扇形用法：Radius为负数表示画填充（否则画线框），Start和End为负数表示画扇形（否则为弧形）
dxgw.Print 数据1; 数据2, 数据3; Spc(相对定位); 数据4; Tab(绝对定义); 数据5       ' 文本打印（Print 有 ； , Spc Tab 四种输出定位调整控制）
dxgw.PaintPicture 图片对象, X1, Y1, [Width1], [Height1], [X2], [Y2], [Width2], [Height2], [Color]
dxgw.Refresh                                                                   ' 将画布的缓存刷新到窗口（提示：在创建dxgw时启用了垂直同步功能的话，此操作将会等待显示器实际刷新，等待期间不占用CPU和GPU）
```

> 这里只大概介绍一下，具体的详细用法请下载附件查看测试Demo中的例子。

## 三、关键技术信息提炼

### 3.1 成员清单与 VB6 原生的一致性

| 成员 | 与 VB6 原生的一致性 | 备注 |
|---|---|---|
| `Cls [背景颜色]` | 一致 | 扩展了可选背景色参数 |
| `Scale (X1,Y1)-(X2,Y2)` / 裸 `Scale` | 一致 | 设置 / 重置绘图坐标系 |
| `CurrentX` / `CurrentY` | 一致 | 读写输出光标位置 |
| `PSet [Step](X,Y), [颜色]` | 一致 | Step 相对坐标语义相同 |
| `Line [Step](X1,Y1)-[Step](X2,Y2), [颜色], [B/F]` | 一致 | B 画框、BF 填充 |
| `Circle (X,Y), 半径, [颜色], [Start], [End], [Aspect]` | 一致 | 含扇形 / 椭圆 / 弧形用法；**"Radius 为负表示画填充"是本库扩展语义**（VB6 原生对负 Radius 取绝对值） |
| `Print` | 一致 | `;`、`,`、`Spc()`、`Tab()` 四种输出定位控制 |
| `PaintPicture` | 一致 | 8 参数 + 颜色 |
| `Point(X,Y)` | **不完全一致** | 读取用法相同（方法）；写入时是**可赋值的参数化属性**：`dxgw.Point(X,Y) = 颜色`，而 VB6 原生 Point 是只读方法 |
| `Refresh` | 一致 | 扩展了垂直同步等待特性（不占 CPU/GPU） |

### 3.2 "VB 隐藏多年的小秘密"——关键字成员的实现原理

作者原话的关键段：

> VB的Form、PictureBox、Printer、UserControl、UserDocument这些控件或类的成员里面除了我们平常用到的方法和属性外，居然还有关键字（Scale、PSet、Line、Circle、Print），就很好奇这些关键字的成员是怎么实现的，然而自己定义方法这些关键字根本没法使用（因为关键字不能作为标识符使用）。直到十二年后的最近一段时间终于发现了VB隐藏了多年的小秘密……

原理拆解（对 C3 有直接参考价值）：

1. **语句语法层**：`dxgw.Line (10,10)-(100,100), vbBlue, BF` 这类写法中，编译器把 `Line` 识别为关键字语句，语句目标 = 前缀对象 `dxgw`；缺省前缀时目标 = 当前窗体（`Me`）。
2. **成员解析层**：编译器在前缀对象上查找**名为 `Line` 的成员**——普通 VB6 代码里无法定义这种名字（关键字不能作标识符），但 **COM TypeLib 里的成员名只是字符串，不受 VB6 词法关键字限制**，所以用 VC 写的组件可以在 .tlb 里定义 `PSet`/`Line`/`Circle`/`Print`/`Scale` 成员，VB6 前期绑定照样解析成功。
3. **调用层**：语句的特殊参数语法（坐标对连接、Step、B/F、`;``,`Spc Tab）在编译器内部被翻译成普通实参列表，最终就是一次普通的方法调用。

即：**关键字语句 = "特殊参数语法" + "按名字找成员" 的语法糖**，目标对象根本不限于 VB6 内置控件。

### 3.3 对 C3 语义模型的意义

- VB6 官方文档把这些语句称为 Form/PictureBox/Printer 的"图形方法"，但该案例证明**编译器并不特判目标类型**——判定规则就是"前缀对象存在同名成员"（后期绑定对象编译期不查签名，运行时 IDispatch::Invoke 按名字派发）。
- **后续修正（2026-09-15 同日，见 003 存档）**：Print 的派发机制比"同名成员"更精确——优先走隐藏 COM 接口 **VBPrint**（IID {000204F0-0000-0000-C000-000000000046}，`Output(BSTR)` / `Cursor` 属性），同名成员是兜底路径；详见 `003-VBPrint隐藏COM接口——Print语句的真正实现机制（群友补充存档）.md`。
- `Printer` 也是语句目标之一（`Printer.Print`），C3 实现 Printer 对象后同样受益。
- 作者提到的 `UserControl` / `UserDocument` 是语句目标的另外两个宿主——对应 C3 尚未走窗体解析路径的 `.ctl` / `.pag` 文件（P31 计划），届时需一并支持。

## 四、对 C3 的启示（已写入 todo.md）

已写入 `todo.md`「下一步主方向：VB6 内置控件可用度 67% → 100%」第 3 条（绘图语句与画布属性），要点复述：

1. **parser**：新增 GraphicsStmt / PrintStmt 语句产生式（词法层不动，避免 `Line` 作为控件类型名/变量名被误杀）；语法清单含 `PSet / Line / Circle / Scale / Print` 五种。
2. **语义层**：目标对象解析支持任意前缀——内置 Form/PictureBox/Printer → `vb6_*` RTL 函数；外部 COM 对象（前期 TypeLib / 后期 IDispatch）→ 把坐标对 / Step / B/F 语法**脱糖成普通实参**后走既有 COM 方法调用路径，无需专用代码。
3. **判定规则**：前缀对象存在同名成员即合法；后期绑定编译期不查签名，运行时 Invoke 派发。
4. **反向收益 / 招牌 demo**：C3 `--dll` 用 CreateTypeLib2 生成 .tlb，成员名无关键字限制 → C3 编译出的 ActiveX DLL 可定义 PSet/Line/Circle 成员供 VB6 关键字写法调用；回归测试正好用 C3 自产 DLL 验证"外部对象作语句目标"，一举两得。
5. **参数化属性**：`Point(X,Y) = 颜色` 提示 C3 需支持带参数的属性赋值语法（Property Let 带参），这是独立于绘图的语法缺口。
