## 三、RTL 拆分必备：管线同步清单

RTL 侧每个新增/重命名/删除的 `.c` `.h` 都必须同步以下位置，漏一处就是构建失败或运行期找不到文件。

第 2、3、4 处记的是**解包后的平铺文件名**，与源码树目录无关，不用动。

| # | 位置 | 要改什么 | `.c` | `.h` |
| - | ---- | -------- | ---- | ---- |
| 1 | `src/driver/c3rtl.rc` | `RCDATA` 资源项（现有 **100-146，47 项**），新增 ID；路径含家族子目录（含 `core/di/`） | 必改 | 必改 |
| 2 | `src/driver/rtl_embedded.hpp` | `RtlResourceID` 枚举 | 必改 | 必改 |
| 3 | `src/driver/rtl_embedded.cpp` | `files[]` 表（约 95-150 行），解包用 | 必改 | 必改 |

`driver.cpp` 里 sourceFiles 是**条件添加**的，拆分后要逐个照搬条件：

| 现有条目 | 添加条件 |
| -------- | -------- |
| `vb6rtl.c` / `vb6com.c` | 总是添加 |

**跨文件可见性硬约束**：RTL 各 `.c` 是**独立编译单元**（都进 `sourceFiles`，由 MSVC 分别编译成 `.obj` 再链接），因此文件级 `static` 函数/变量**跨文件不可见**。拆分时：

1. 只被同族使用的 `static` → 随族一起搬走，保持 `static`。
2. 被多个族使用的 `static` → 提升为外部链接，声明集中到新增的内部头 `<模块>_internal.h`（定义仍留在主 `.c`）。

### 生成物（原 1 个 —— 2026-09-17 已改造生成器后拆净）

`src/rtl/core/vb6_di_win32_stubs.c`（1184 行 / 213 个一行桩）是本次专题里唯一「手改会被下次生成覆盖」的文件，
2026-09-17 划出跟踪范围，随后按下述方案拆净，**不再是遗留项**。

#### 卡点：生成器不认识 Lib 家族，也无法重跑

1. **没有家族信息** —— 生成器只从生成的 `.h` 原型反推 `extern ... vb6_di_<alias>(...)`，
   原型里**不含** `Declare ... Lib "x"` 的家族名；而 `vb6_di_<alias>` 的名字本身也不编码 DLL。
2. **无法重跑** —— 它靠外部输入 `.temp/unresolved_syms.txt` 决定产出哪些桩，该文件早已不存在，
   且那份清单是某次构建临时生成的，不可复现。

#### 解法

| # | 改动 | 说明 |
| - | ---- | ---- |
| 1 | `src/backend/decl/cgen_decl_api.cpp` | C3 在每个 `vb6_di_*` 原型前多写一行标记 `/* vb6_di_lib: <libName> */`。`libName` 此时已去引号、去 `.dll` 后缀。生成头多一行注释，不影响编译 |
| 2 | `scripts/gen_di_stubs.ps1` | 读该标记 → 按 Lib 家族分组 → **每个家族一个 `.c`**；同时去掉 `-SymFile` 依赖（输入改为「生成头里的全部 `vb6_di_*` 原型」），自动跳过 `vb6_di_stubs.c` 里手写过的符号与 `ord_*`，并清理过期的旧文件 |
| 3 | 一次性迁移 | 旧单文件的桩签名就是原型的逐字拷贝，用它还原出 213 条原型 + 从仓库 VB6 源反查 `Alias -> Lib`，合成一个临时 session 头喂给新生成器（保证产出逐字一致） |

>
> **四类拆法的差别**（后续遇到同类文件照此判断）：
> - `vb6rtl.h` / `ast.hpp` 属「**多个独立声明**」型 —— 按声明边界直接切，子头用 `.hpp`，各自可独立编译。
> - `cgen.hpp` 属「**单个巨型类声明**」型 —— 无法按声明边界切（切了就不再是一个类），
>   折中办法是**类体片段**：把类体切成数段放进 `detail/*.inc`，在类体内 `#include`（C++ 允许）。
> - `semantic_analyzer_builtin.cpp` 属「**单个巨型函数**」型 —— 同理用**函数体片段**：
>   把函数体切成数段放进 `builtin/*.inc`，在**函数体内** `#include`。
>   比「提升局部 lambda 为成员函数」更稳：lambda 与局部常量原样不动，零重构。
> - `.inc` 后缀是刻意的：这些片段**不是独立头文件 / 编译单元**，单独 include 会编译不过，用 `.hpp` / `.cpp` 会误导。
> - 折中只影响可读性，不改任何语义：所有片段内容与原文件对应区间**逐行相同**。
