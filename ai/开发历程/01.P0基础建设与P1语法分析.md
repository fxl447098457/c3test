3. **P1.3-P1.7 解析器实现**: ~2900行Parser代码（4个源文件）

#### 解析器核心设计

- **LL(2)递归下降** + **Pratt表达式解析**（14级优先级，l_bp/r_bp对）
- **软关键字支持**: `isSoftKeyword()`覆盖~80个VB6软关键字（Name/String/Integer/MsgBox等）
- **Comment跳过**: `fetchNextToken()`在advance层过滤Comment token
- **语句级=号处理**: `parseExpression(9)` 用minBp阻止=被消费为比较运算符

#### 修复的Bug

| # | Bug | 根因 | 修复 |
|---|-----|------|------|
| 1 | For语句Next未被消费 | parseForStmt缺少expect(TokenKind::Next) | 添加expect(Next) |
| 2 | Name等软关键字无法做变量名 | 词法器将软关键字归为特定TokenKind而非Identifier | isSoftKeyword()+canBeName()+expectName() |
| 3 | Comment token未被跳过 | Parser advance()直接使用lexer_.nextToken() | fetchNextToken()循环跳过Comment |
| 4 | Dim arr()动态数组报错 | parseVariableDecl遇到空()时尝试parseExpression | 检查RightParen跳过空维度 |
| 5 | Set obj = Nothing崩溃 | parseSetStmt中=被Pratt当比较运算符消费 | parseExpression(9)阻止=消费 |

## 问题

- **冒号行分隔符**: 当前标签解析占用了`identifier:`模式，`a = 1 : b = 2`形式暂不支持（需区分标签冒号和行分隔冒号）
- **嵌套Soft Keyword**: If条件中的Name等软关键字在表达式位置的歧义尚未完全处理
- **With语句**: WithMemberExpr(.member)在表达式解析中的完整支持待验证
- **Select Case的多值**: `Case 2, 3`的逗号分隔是否正确解析需进一步验证

## 决策

1. **Pratt表达式优先级表**: 采用14级l_bp/r_bp对，右结合只有^（幂运算），数值不重要只保持相对顺序
2. **软关键字策略**: 词法器不变（仍识别为特定TokenKind），在Parser层通过isSoftKeyword/canBeName/expectName灵活处理
3. **Comment跳过层级**: 在fetchNextToken中过滤，而非在skipNewLines中，确保所有路径自动跳过
4. **语句级=号**: 统一使用parseExpression(9)（minBp > =的l_bp=8），包括赋值和Set/Let语句
