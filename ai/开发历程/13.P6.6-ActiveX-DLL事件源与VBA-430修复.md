## 当前阻塞问题

### c3.exe 编译 test_event_dll.vbp 时 MSVC cl.exe 返回 exit code 2 失败

- **现象**: `c3 test_event_dll.vbp --output-dir output` 在 linking 阶段失败
- **cl.exe 命令行已知**（从 verbose 模式获取），但 cl.exe 的具体编译错误看不到
- **根因**: Session 临时目录在编译失败时被 `SessionManager` 析构函数自动清空，cl.exe 的错误输出随 session 目录一起被删除
- **dll_entry.c 已生成**: verbose 日志显示 `dll_entry.c (18152 bytes)` — 比旧版 15KB 大，说明新字段确实被生成了
- **14 字段对齐确认**: `vb6_CoClassDesc` 有 14 个字段，cgen 代码输出 14 个初始化值，数量匹配

### 可能的编译错误原因（推测）

1. **`LoadTypeLib` 在 C 模式下的声明问题**: vb6comserver.c 新增了 `LoadTypeLib` + `ITypeLib_GetTypeInfoOfGuid` 调用，这些 API 在 C 文件中使用 C COM 宏需要正确的头文件包含和链接
2. **`const IID*` 类型初始化器**: cgen 输出 `&IID_vb6def_EventCalc` 作为 `const IID*` 类型的初始化值，如果 IID 常量声明有误或类型不匹配，C 编译器会报错
3. **vb6comserver.c 的 C COM 宏语法错误**: `ITypeLib_Release(pTypeLib)`, `ITypeLib_GetTypeInfoOfGuid(...)` 等宏展开需要正确的参数类型

### 解决方案（下次会话第一步）

**直接用 `--emit-c` 模式把 dll_entry.c 保留下来，然后手动运行 cl.exe 编译，一次看到错误信息。**

具体步骤：
```powershell
# 1. 用 --emit-c 生成中间文件（不链接，不清理session）
# 或者在 driver.cpp 中加入 --keep-intermediate 选项保留session
# 最简单: 直接修改 driver.cpp 让 compile 失败时调用 session.release() 而非 cleanup()

# 2. 或者更简单: 手动运行 cl.exe 编译 output/dll_entry.c 看错误
cmd /c "call vcvarsall.bat x64 >nul 2>&1 && cl.exe /c /std:c11 /DUNICODE /D_UNICODE /utf-8 /D_CRT_SECURE_NO_WARNINGS /I<D:\vb6pro\src\rtl\core> output\dll_entry.c /Fooutput\dll_entry.obj 2>&1"
```

## 重要经验教训

1. **Session 目录自动清理是调试障碍**: `SessionManager` 析构函数无条件调用 `cleanup()`， 编译失败时 cl.exe 的错误输出随 session 一起被删除。建议增加 `--keep-intermediate` 调试选项
2. **长上下文导致错误率上升**: 多轮 Node.js 脚本修改驱动代码容易出错，应一次性重写整个函数/段落
3. **C 模式 COM API 需要特殊处理**: 在 .c 文件中不能使用 C++ 风格的 `pObj->Method()`，必须用 `InterfaceName_MethodName(pObj, ...)` 宏
4. **零宽水印 hook 影响 CMakeLists.txt**: 始终用 text-writer 工具写入，或通过 .temp/ 中转 + cmd /c copy
