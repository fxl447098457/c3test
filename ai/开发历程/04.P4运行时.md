## 1. 目标

### 2.2 cgen代码生成扩展

**文件I/O语句代码生成** — 在 `emitStmtList` 的switch中添加15+种文件I/O语句：
- OpenStmt / CloseStmt / PrintStmt / WriteStmt / LineInputStmt / InputStmt
- GetStmt / PutStmt / SeekStmt / LockStmt / UnlockStmt / WidthStmt
- KillStmt / NameStmt / MkDirStmt / RmDirStmt / ChDirStmt / ChDriveStmt / FileCopyStmt

**Print/Write语句BSTR类型检测** — 使用 `isBstrExpr` 启发式判断表达式是否返回BSTR：
- BSTR表达式直接传给 `vb6_Print`
- 非BSTR表达式包装为 `vb6_Str((int32_t)(val))` 后传给 `vb6_Print`
- `knownBstrVars_` 集合跟踪已知BSTR类型变量

**错误处理代码生成**:
- `On Error Resume Next` → `vb6_err_resume_next = 1;`
- `On Error GoTo label` → 设置 `vb6_err_handler_label` + `vb6_err_jmp_active = 1;`
- `On Error GoTo 0` → 清除两个标志

**词法器修复** — `#identifier` 处理:
- `#1` (文件号后跟数字) → 返回 `Hash` token
- `#fnum` (文件号变量) → 当 `#` 后跟非条件编译关键字时，回退并返回 `Hash` token

### 2.3 修复的Bug

1. **`#identifier` 词法器bug** — `#fnum` 被误解析为未识别的条件编译指令。修复：非条件编译关键字的 `#` 后标识符 → 仅返回Hash token。

2. **`emitStmtList` 缺少文件I/O case** — 15+种文件I/O语句落入 `default: /* TODO */`。修复：逐一添加case。

3. **`LineInputStmt::varName` 类型不匹配** — 代码尝试 `cIdent(node.varName)` 但varName是 `ExprPtr` 不是字符串。修复：使用 `emitExpr(*node.varName)`。

4. **`vb6_Print` 类型不匹配** — 非BSTR参数（如Integer数组元素）直接传给 `vb6_Print(fnum, BSTR)` 导致C编译错误。修复：添加 `isBstrExpr` 检测，非BSTR参数包装 `vb6_Str()`。

5. **`vb6_Val` 声明重复** — vb6rtl.h中第164行和第183行重复声明了 `double vb6_Val(BSTR s)`。修复：移除第183行重复声明。

6. **错误处理setjmp/longjmp无限循环** — `On Error Resume Next` + setjmp/longjmp导致 `longjmp` 回到 `setjmp` 后重新执行出错语句→无限循环。修复：改为全局标志方案，`vb6_RaiseError` 检查 `vb6_err_resume_next` 标志直接返回。

7. **`vb6_VariantToLong` 截断警告** — `vb6_Val` 返回double，赋值给int32_t返回值时截断。修复：显式 `(int32_t)` 强制转换。

## 4. 问题

1. **On Error GoTo label 只有MVP** — cgen设置了标志和label指针，但实际跳转逻辑（在每条可出错语句后检查错误标志并goto）尚未实现。当前仅通过全局flag记录意图，不会真正跳转到错误处理标签。

2. **Year/Month/Day 忽略参数** — 简化实现，总是返回当前系统日期。对于 `Year(Now())` 正确，对于 `Year(someOtherDate)` 不正确。

3. **isBstrExpr 启发式** — 基于函数名前缀和变量名集合的启发式判断，不是100%准确。如果用户变量名恰好匹配内置函数前缀或BSTR函数名，可能误判。

4. **Get/Put 语句** — 仅生成 `/* TODO */` 注释，Random模式和Binary模式的记录读写尚未实现。

5. **文件I/O Random/Binary模式** — `vb6_Open` 中Random模式支持创建新文件(w+p)，但记录定位和Binary读写未实现。

## 5. 决策

| 决策点 | 选项 | 决策 | 理由 |
|--------|------|------|------|
| 错误处理机制 | setjmp/longjmp vs 全局标志 | 全局标志 | setjmp/longjmp导致无限循环(回到setjmp后重执行出错语句)，全局标志更简单可靠 |
| Print类型处理 | 修改RTL签名 vs cgen包装 | cgen包装 | 不破坏RTL API，cgen层做类型判断更灵活 |
| #identifier词法 | 维持预处理语义 vs 返回Hash | 返回Hash | 满足 `#fnum` 文件号引用需求，条件编译关键字仍走预处理路径 |
| isBstrExpr方案 | 类型系统查询 vs 启发式 | 启发式 | 语义分析后符号信息已部分丢失(popScope)，启发式足以覆盖常见场景 |
