## 目标

实现VB6窗体和控件的编译支持，使编译器能将.frm文件编译为Win32 GUI可执行文件。

## 过程

### P7.1 .frm/.frx文件解析器 ✅

**目标**: 解析VB6窗体描述文件(.frm)，提取窗体属性、控件信息和VB代码区。

**实现**:
- src/project/frm_parser.hpp (195行): 数据结构
  - FrmValue: 属性值(字符串/数字/布尔)
  - FrmPropertyBlock: BeginProperty...EndProperty块
  - FrmControl: 控件描述(类型/名称/位置/大小/属性/子控件)
  - FrmFormDesc: 窗体描述(属性+控件列表)
  - FrmFile: 完整.frm文件(描述+代码)
  - FrmParser: 解析器类

- src/project/frm_parser.cpp (441行): 解析实现
  - VERSION行解析
  - Begin...End控件块递归解析
  - BeginProperty...EndProperty块解析
  - Attribute行解析
  - 代码区提取(从第一个非描述行到文件末尾)

- FrmControlType枚举: 覆盖所有VB6标准控件(20+种)
  - Form/CommandButton/TextBox/Label/CheckBox/OptionButton
  - ListBox/ComboBox/Frame/PictureBox/Timer/HScrollBar/VScrollBar
  - Image/Shape/Line/Data/OLE/DriveListBox/DirListBox/FileListBox/Menu
  - 常见第三方: Toolbar/StatusBar/CommonDialog

- controlTypeToWin32Class(): FrmControlType→Win32窗口类名映射
  - BUTTON/EDIT/STATIC/LISTBOX/COMBOBOX/SCROLLBAR

- CLI新增 --dump-frm 选项

**验证**:
- 	ests/test_form/Form1.frm (含3个控件的窗体) 解析正确
- 	ests/vbp_project/Form1.frm (空窗体+BeginProperty Font) 解析正确
- c3.exe --dump-frm tests/test_form/Form1.frm 输出完整

### P7.2 Module集成isFormModule ✅

**目标**: 让编译器识别.frm文件为窗体模块，提取代码区进行编译。

**实现**:
- Module类新增 ool isFormModule = false 标志
- Driver的 unParser() 新增.frm检测:
  1. 调用FrmParser解析.frm文件
  2. 提取代码区(VB代码部分)
  3. 仅解析代码区(跳过Begin...End描述块)
  4. 设置module->isFormModule = true
  5. 存储frmFiles_[filePath] = frmFile
- std::map<std::string, FrmFile> frmFiles_ 存储所有窗体描述
- Driver的 unCodeGeneration() 传递FrmFormDesc*给CCodeGen

   - vb6_NextControlId/vb6_ResetControlId: 控件ID管理
   - vb6_MessageLoop: 消息循环

## 问题

1. **AIGC零宽字符hook范围扩大**: text-writer_write_text和edit_text也被污染(之前认为只有内置write/edit)
   - 根因: AIGC watermark hook拦截工作目录根目录的所有文件写入
   - 临时方案: PowerShell [System.IO.File]::WriteAllText() 绕过
   - 待确认: 重启电脑后hook行为是否改变(用户已修正全局记忆规范)

2. **CMakeLists.txt反复污染**: 每次写入后被注入~10KB零宽字符，导致CMake解析失败
   - 需要每次构建前用.NET API重写
