### P7.4 消息循环+DoEvents (已完成)

本阶段共修复 5 个问题：

#### 问题1: DoEventsStmt/BeepStmt 代码生成为 TODO 注释

- **根因**: `emitStmtList()` switch 中缺少 `BeepStmt` 和 `DoEventsStmt` case 分支，落入 default 产生 `/* TODO */`
- **修复**: 添加两个 case 到 emitStmtList：
  ```cpp
  case ASTNodeKind::BeepStmt:     visit(static_cast<BeepStmt&>(*stmt)); break;
  case ASTNodeKind::DoEventsStmt: visit(static_cast<DoEventsStmt&>(*stmt)); break;
  ```
- visit(DoEventsStmt) → `vb6_DoEvents()`，visit(BeepStmt) → `vb6_Beep()`
- 同时在 `builtinFuncs` 映射表和 `zeroArgBuiltinFuncs` 集合中添加 `doevents`/`beep`

#### 问题2: Form_Load/Form_Unload 符号查找失败

- **根因**: `symTab_.lookup(formLoadFn)` 用 C 函数名 `"vb6_Form_Load"` 查找，但符号表存的是 VB6 名 `"Form_Load"`
- **修复**: 改用 VB6 名查找：`symTab_.lookup("Form_Load")` / `symTab_.lookup("Form_Unload")`
- 影响：导致 WM_CREATE 中 Form_Load 不被调用、WM_CLOSE 中 Form_Unload 不被调用

#### 问题3: Form_Unload 回调签名不匹配

- **根因**: vb6forms.c 回调类型 `int (*)(void)` 与 VB6 的 `void Form_Unload(int16_t* Cancel)` 签名不兼容
- **修复**: 在 WndProc 之前生成 trampoline 桥接函数：
  ```c
  static int vb6_Form_Unload_trampoline(void) {
      int16_t vb6_cancel = 0;
      extern void vb6_Form_Unload(int16_t*);
      vb6_Form_Unload(&vb6_cancel);
      return (int)vb6_cancel;
  }
  ```
  WM_CLOSE 中使用 trampoline 函数指针而非直接 VB6 函数指针

#### 问题4: vb6_Beep 链接错误

- **根因**: `MessageBeep()` 在 `user32.dll` 中，但 vb6rtl.c 未包含 `windows.h`，且控制台链接缺少 `user32.lib`
- **修复**:
  - vb6rtl.c 添加 `#include <windows.h>`（在 `#ifdef _WIN32` 块内）
  - msvc_driver.cpp 所有三种链接配置（DLL/GUI/Console）均添加 `user32.lib`
- 此修复同时解决了回归测试中 15/48 个失败（所有编译测试因 VB6RTL_DIR 缺失+链接错误而失败）

#### 问题5: vb6forms.c C4133 警告 + 测试脚本 VB6RTL_DIR 缺失

- **修复**:
  - `LoadCursorA(NULL, IDC_ARROW)` → `LoadCursorA(NULL, (LPCSTR)IDC_ARROW)` 类型转换
  - `LoadIconA(NULL, IDI_APPLICATION)` → `LoadIconA(NULL, (LPCSTR)IDI_APPLICATION)` 类型转换
  - `LoadIconA((HINSTANCE)hInstance, MAKEINTRESOURCEA(iconResId))` → 添加 `(LPCSTR)` 转换
  - `run_tests.ps1` 添加 `$env:VB6RTL_DIR = "D:\vb6pro\src\rtl\core"` 在 MSVC 环境加载之后
- VB6RTL_DIR 缺失原因：c3.exe RTL 查找优先读 `VB6RTL_DIR` 环境变量，未设置时从 CWD 向上搜索 `src/rtl/core`，但测试脚本不在此工作目录运行

## P7.8 菜单系统

### 目标
实现VB6菜单栏支持，包括：顶层菜单(VB.Menu)、嵌套子菜单、分隔线、Checked/Enabled/Visible属性、菜单点击事件派发。

### 过程
1. **cgen.hpp**: 添加emitMenuItem、emitMenuClickDispatch、escapeCString三个方法声明
2. **cgen.cpp CreateControls菜单构建**: 在控件创建循环之后，检查是否有Menu类型子控件，若有则创建HMENU hMenuBar，遍历顶层Menu创建CreatePopupMenu()，递归调用emitMenuItem生成子项，最后SetMenu()
3. **cgen.cpp emitMenuItem**: 递归生成菜单项代码
   - 分隔线(Caption="-") → AppendMenuA(parent, MF_SEPARATOR, 0, NULL)
   - Checked → flags |= 0x0008 (MF_CHECKED)
   - Enabled=0 → flags |= 0x0002 (MF_GRAYED)
   - Visible=0 → 跳过但分配ID (menuId++)
   - 子菜单 → CreatePopupMenu + 递归 + MF_POPUP(0x0010)
   - 叶子项 → AppendMenuA(parent, flags, menuId, caption) + menuId++
4. **cgen.cpp emitMenuClickDispatch**: 在WM_COMMAND控件事件循环之后、break之前插入
   - 递归遍历Menu子控件，对叶子菜单项生成if (id == menuId) { extern void mnuName_Click(); mnuName_Click(); }
   - 分隔线：不分配ID，直接continue
   - Visible=0：跳过不生成Click派发，但menuId++保持ID一致
   - 子菜单：递归处理子项
5. **cgen.cpp escapeCString**: 转义C字符串中的"、\、\n、\r、\t
6. **Bug修复**: 删除emitFormFramework和emitMenuItem之间多余的}（由P7.7插入错误遗留），恢复CCodeGen命名空间完整性
