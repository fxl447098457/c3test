# 17. P16 WithEvents控件事件绑定

## 目标

实现 `Dim WithEvents cmd As CommandButton` 声明，允许窗体控件通过WithEvents变量接收事件（Click、Change等），而不是只能使用 `Command1_Click()` 标准命名约定。

## 过程

### P16.1 设计分析

VB6中有两种独立的事件分发机制：
1. **COM WithEvents/RaiseEvent** — 用于类/COM对象，通过Sink表+IConnectionPoint实现（P6.5已实现）
2. **窗体控件事件** — 通过WndProc WM_COMMAND/WM_HSCROLL/WM_VSCROLL分发，使用 `symTab_.lookup("ControlName_EventName")` 匹配

P16的设计选择了**HWND匹配方案**：WithEvents控件变量存储HWND，在WndProc中通过 `(HWND)lParam` 与变量HWND比较来分发事件。

### P16.2 数据结构与映射函数

- `cgen.hpp` 新增两个字段：
  - `knownWithEventsCtrlVars_`: lowercase var name → FrmControlType
  - `knownWithEventsCtrlOrigNames_`: lowercase var name → 原始大小写C标识符
- `cgen.cpp` 新增 `controlTypeFromName()` 静态函数：映射类型名字符串（如"CommandButton"）→ FrmControlType枚举

### P16.3 VariableDecl 处理

在 `visit(VariableDecl&)` 中，COM WithEvents注册之后添加P16块：
- 检查 `node.isWithEvents` + 类型名 → `controlTypeFromName()`
- 注册到 `knownWithEventsCtrlVars_` 和 `knownWithEventsCtrlOrigNames_`
- 覆盖 `cType = "HWND"`
- 清理 `knownObjectVars_` 和 `knownVariantVars_`（避免COM路径干扰）
- initVal: `cType == "HWND"` → `initVal = "NULL"`

### P16.4 SetStmt 处理

控件WithEvents变量不需要COM Sink/Advise，`Set cmd = Command1` 只需HWND拷贝。

关键修复：Set语句中右侧控件名会被P11.7默认属性读取截获（`Command1` → `vb6_GetControlText(vb6_hwnd_Command1)`），需要从value中提取 `vb6_hwnd_Command1`。

### P16.5 WndProc 事件分发

**WM_COMMAND**：在标准命名handler之后、菜单分发之前，添加WithEvents控件事件分发：
- 外层 `if ((HWND)lParam != NULL) { HWND hCtrlWE = (HWND)lParam; ... }`
- 对每个WithEvents控件变量，按控件类型检查通知码：
  - CommandButton/CheckBox/OptionButton: BN_CLICKED (code=0) → _Click()
  - TextBox: EN_CHANGE (code=768) → _Change()
  - ListBox: LBN_SELCHANGE (code=1) → _Click(), LBN_DBLCLK (code=2) → _DblClick()
  - ComboBox: CBN_SELCHANGE (code=1) → _Click(), CBN_EDITCHANGE (code=5) → _Change()

**WM_HSCROLL/WM_VSCROLL**：WithEvents ScrollBar通过 `scrollHwnd` 匹配事件分发。

### P16.6 属性访问（4个核心位置）

| 位置 | 函数 | 功能 | 生成代码 |
|------|------|------|----------|
| 1 | MemberAccessExpr | 非数组控件属性读取 | `readFn(weVarName)` |
| 2 | AssignmentStmt | 非数组控件属性写入 | `writeFn(weVarName, valExpr)` |
| 3 | LetStmt | 非数组控件属性写入 | `writeFn(weVarName, valExpr)` |
| 4 | SetStmt | HWND提取 | value中提取`vb6_hwnd_XXX` |

注意：WithEvents控件变量默认属性读取/写入（如 `x = cmd` 即 `x = cmd.Caption`）**未实现**，因为会与Set语句歧义冲突（`Set cmd = Command1` 中 `cmd` 和 `Command1` 都会被默认属性截获）。

### Bug修复

1. **Timer循环多余花括号** — `c_.dedent()`+`c_.emitLine("}")` 误放在Timer的for循环体内，导致每个控件都多一个`}`。移到循环外并删除。
2. **P16 lParam闭合花括号在if块外** — `c_.dedent()`+`c_.emitLine("}")` 放在 `if (!knownWithEventsCtrlVars_.empty())` 块外，导致无WithEvents时也生成多余的`}`。移入if块内。
3. **PowerShell双引号转义** — PowerShell的here-string将 `"` 翻倍为 `""`，导致 `controlTypeFromName()` map中的字符串字面量变成了 `""commandbutton""`。用 `String.Replace` 后修复。

## 验证

- **回归测试**: 74/74 通过，零失败
- **WithEvents测试**: `form_test_withevent.frm` 编译生成exe成功

## 问题与决策

| 问题 | 决策 |
|------|------|
| WithEvents控件变量用COM Sink还是HWND匹配？ | HWND匹配更简单，不需要IConnectionPoint |
| cProcName大小写问题 | 使用 `handlerSym->name` 保证正确大小写 |
| 默认属性与Set语句冲突 | 不实现WithEvents控件变量默认属性（安全优先） |
| PowerShell写文件导致双引号翻倍 | 用后处理 `String.Replace` 修复 |
