## 二、过程

### P15.1 RaiseEvent VARIANT 类型推断修复

**问题**：`RaiseEvent EventName(arg1, arg2)` 代码生成时，所有参数一律强制为 `VT_BSTR`（字符串类型），导致 Long/Double/Single/Object 类型参数被错误打包，运行时事件接收方读到错误 VARIANT 类型。

**根因**：cgen.cpp `visit(RaiseEventStmt&)` 中，参数 VARIANT 设置代码写死 `vt = VT_BSTR; bstrVal = vb6_BSTR_FromStr(...)`，未根据参数实际类型分发。

**实现**：

1. 引入 `inferExprType()` 对每个参数表达式推断 VB6 类型
2. 类型分发逻辑：
   - Long/Integer/Boolean → `VT_I4`, `lVal = (int32_t)(expr)`
   - Single → `VT_R4`, `lVal = *(int32_t*)&(float){expr}`（bit-cast 保持 IEEE 754）
   - Double → `VT_R8`, `dblVal = (double)(expr)`
   - Object → `VT_DISPATCH`, `pdispVal = (IDispatch*)(expr)`
   - 其他（String 等）→ `VT_BSTR`, `bstrVal = vb6_BSTR_FromStr(expr)`
3. 补充缺失的 `for (size_t i = 0; i < node.args.size(); i++) {` 循环语句（原代码直接使用未声明的 `i`）

**修改文件**：`src/backend/cgen.cpp`（line ~5596-5617）

**验证**：74/74 回归零失败。

### P15.2 UDT 固定大小数组成员代码生成

**问题**：VB6 `Type` 声明中固定大小数组成员（如 `Buf(0 To 255) As Byte`）在 C 代码生成时被静默忽略，只生成标量成员，导致结构体布局与 VB6 不一致，内存访问越界。

**根因**：cgen.cpp `visit(TypeDecl&)` 中有 `member->arraySize` 判断分支，但使用了不存在的 `ASTNodeKind::IntegerLiteral` 和 `IntegerLiteral` 类名（正确应为 `ASTNodeKind::LiteralExpr` 和 `LiteralExpr`），编译失败后该分支实际从未生效。

**实现**：

1. 将 `ASTNodeKind::IntegerLiteral` 修正为 `ASTNodeKind::LiteralExpr`
2. 将 `static_cast<IntegerLiteral&>` 修正为 `static_cast<LiteralExpr&>`
3. 使用 `LiteralKind` 判断上界值：
   - `LiteralKind::Long` → `lit.longValue`
   - `LiteralKind::Integer` → `lit.intValue`
4. 生成 `type member[upperBound + 1];`（VB6 下界默认 0，元素数 = 上界 + 1）
5. 非字面量上界（表达式）：`emitExpr()` 后生成 `type member[(expr) + 1];`

**修改文件**：`src/backend/cgen.cpp`（line ~4884-4895）

**验证**：74/74 回归零失败。

### P15.3 Close All 文件句柄

**问题**：VB6 的 `Close` 语句（不带文件号）应关闭所有已打开文件，但 c3 只生成一行注释 `// Close all files`，无实际操作。

**实现**：

1. **RTL 新增** `vb6_CloseAll()` 函数（vb6rtl.h + vb6rtl.c）：
   - 遍历 `vb6_file_table[1..511]`，对每个非 NULL 的 FILE* 调用 `fclose()` 并清零
   - 同时清零 `vb6_file_mode` 和 `vb6_file_reclen`
2. **cgen 修改**：`visit(CloseStmt&)` 中，当 `node.filenums` 为空时调用 `vb6_CloseAll()` 而非生成注释

**修改文件**：`src/backend/cgen.cpp`（line ~4141）、`src/rtl/core/vb6rtl.h`、`src/rtl/core/vb6rtl.c`

**验证**：74/74 回归零失败。

### P15.4 Input$() 函数实现

**问题**：VB6 的 `Input$(filenumber, count)` 函数从已打开文件读取指定数量的字符并返回字符串。c3 完全缺失此函数，P14.2.6 已标注为遗漏。

**实现（三处修改）**：

1. **解析器**（parser_expr.cpp）：
   - 在 `parseNullDenotation()` 的 switch 中新增 `case TokenKind::Input`
   - 逻辑：`Input` 后跟 `(` → 解析为函数调用；`Input` 后跟 `$` → 跳过 $ 后缀再跟 `(`
   - 生成 `IndexOrCallExpr(IdentifierExpr("Input$"), args)`
   - 参数列表内联解析（逗号分隔，`parseExpression()` 逐个消费）
2. **RTL 运行时**（vb6rtl.h + vb6rtl.c）：
   - 新增 `BSTR vb6_InputString(int32_t filenumber, int32_t count)`
   - 实现：malloc wchar_t 缓冲区 → fgetc 逐字节读取 → 转为 wchar_t → `vb6_BSTR_FromStr()` 返回
   - 边界检查：filenumber 范围 1-511、vb6_file_table 非空、count > 0
3. **cgen 内置函数表**（cgen.cpp）：
   - builtinFuncs 表新增 `{"input$", "vb6_InputString"}` 条目
   - `IdentifierExpr("Input$")` 经 `Symbol::toLower` 后匹配 `"input$"` → 生成 `vb6_InputString()` 调用

**修改文件**：`src/parser/parser_expr.cpp`（line ~158-183）、`src/backend/cgen.cpp`（line ~1093）、`src/rtl/core/vb6rtl.h`、`src/rtl/core/vb6rtl.c`

**验证**：74/74 回归零失败。

### P15.5 Enum 成员自动递增确认

**问题**：初始怀疑 Enum 显式赋值后 `nextValue` 重置为 0，导致后续成员从 0 开始而非从显式值 +1 递增。

**审查结果**：检查 `semantic_analyzer.cpp` line 696-715，逻辑正确：
- `nextValue` 初始为 0
- 有显式值时 `nextValue = lit.longValue / lit.intValue`（覆盖）
- `memberSym->constIntValue = nextValue`（赋值当前值）
- `nextValue++`（递增）
- 下一个无显式值的成员从 `显式值 + 1` 开始

**验证用例**（test_enum_auto.bas）：
```vb6
Enum TestEnum : A = 5 : B : C : D = 10 : E : End Enum
' A=5, B=6, C=7, D=10, E=11 — 符合VB6行为
```

**结论**：无需修改，逻辑正确。

### P15.6 Debug.Print 负数字面量解析修复

**问题**：`Debug.Print -1` 被错误解析为 `vb6_DebugPrint - 1`（二元减法，结果为 DebugPrint 的返回值减 1），而非 `vb6_DebugPrint(-1)`（输出负一）。

**根因**：`parseLabelOrAssignmentOrCall()` 调用 `parseExpression(9)` 解析语句左侧，minBp=9 阻止了 `=` 被当作比较运算符，但 `-` 的 l_bp=12 > 9，所以 `-` 被当作中缀减法运算符消费。

解析路径：
1. `parseExpression(9)` 解析 `Debug.Print` → `MemberAccessExpr`
2. 遇到 `-`，l_bp=12 > minBp=9 → 当作中缀运算符
3. 右侧解析 `1` → `LiteralExpr(1)`
4. 结果：`BinaryExpr(MemberAccessExpr(Debug, Print), Sub, LiteralExpr(1))` = `Debug.Print - 1`

**实现**：

1. 在 `parseLabelOrAssignmentOrCall()` 中，表达式解析后检测是否为 `Debug.Print` / `Debug.Assert`：
   - 检查 `expr->kind == ASTNodeKind::MemberAccessExpr`
   - 检查 `object` 为 `IdentifierExpr` 且 `name` toLower 后为 `"debug"`
   - 检查 `memberName` toLower 后为 `"print"` 或 `"assert"`
   - 设置 `isDebugPrint = true` 标志
2. 修改后续条件判断：`!isInfixOperator(cur_.kind) || isDebugPrint`
   - 当 `isDebugPrint` 为 true 时，即使当前 token 是中缀运算符（如 `-`），也进入参数解析分支
   - `-1` 被正确解析为 `UnaryExpr(Negate, LiteralExpr(1))`

**修改文件**：`src/parser/parser_stmt.cpp`（line ~894-910）

**验证**：74/74 回归零失败。

## 四、问题与决策

| # | 问题 | 决策 | 原因 |
|---|------|------|------|
| 1 | P15.2 使用不存在的 `IntegerLiteral` 类名 | 改用 `LiteralExpr` + `LiteralKind` 判断 | AST 中整数字面量统一为 `LiteralExpr`，通过 `literalKind` 区分 Integer/Long |
| 2 | P15.1 缺失 `for` 循环导致 `i` 未声明 | 补充 `for (size_t i = 0; i < node.args.size(); i++) {` | 初始写入时遗漏循环头 |
| 3 | P15.4 `vb6_files` 引用不存在 | 改为 `vb6_file_table` | 文件句柄表变量名是 `vb6_file_table`，不是 `vb6_files` |
| 4 | P15.4 `vb6_BSTR_FromStr("")` 类型不匹配 | 改为 `vb6_BSTR_Empty()` | 空字符串字面量是 `char*`，`vb6_BSTR_FromStr` 需要 `wchar_t*` |
| 5 | P15.4 `parseArgList()` 函数不存在 | 内联参数解析（do-while + match(Comma)） | parser 中无独立 parseArgList 函数，参数解析在 parsePostfix 内联 |
| 6 | P15.5 Enum 递增疑似 bug | 审查确认逻辑正确，不做修改 | `nextValue = explicitValue` + `nextValue++` 语义正确 |
| 7 | P15.6 `-` 在 Debug.Print 后被当作中缀 | 特判 Debug.Print/Assert，允许中缀运算符作参数开头 | VB6 语义中 Debug.Print 后是新表达式上下文，`-` 应为一元负号 |

---

## 五、决策

- **P15.2 类型名修正**：不新增 AST 节点类型，复用现有 `LiteralExpr`，最小改动原则。
- **P15.4 Input$ 解析**：在 `parseNullDenotation` switch 中特判 `TokenKind::Input`，而非将其加入软关键字列表，避免影响 `Input #` 语句解析。
- **P15.6 修复范围**：仅对 `Debug.Print/Debug.Assert` 特判，不修改全局 minBp，避免影响其他语句的运算符优先级。
