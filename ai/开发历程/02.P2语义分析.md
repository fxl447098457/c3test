## 过程

### P2.1 符号表 (symbol_table.hpp/cpp)

- 三层作用域结构：Module → Procedure → Block
- VB6 不区分大小写：所有符号以 lowercase 名称为 key
- Symbol 结构体：kind/name/type/access/params/constValue/isBuiltin
- `define()` 注册、`lookup()` 向上查找、`pushScope()/popScope()` 作用域切换
- 修复：缺少 `<algorithm>` include 导致编译失败

### P2.2 类型系统 (type_system.hpp/cpp)

- Vb6Type 枚举：Empty/Boolean/Byte/Integer/Long/LongLong/Single/Double/Currency/Date/String/Object/Variant/Unknown 等 17 种
- 隐式转换检查：`canConvert(from, to)` + `isWidening(from, to)`
- 类型提升：`promote(a, b)` 算术运算自然提升
- 类型大小：`sizeOf()` 供后端代码生成使用

### P2.3-P2.8 语义分析器 (semantic_analyzer.hpp/cpp, ~1396行)

- 两遍扫描架构：
  - Pass 1：收集模块级声明（Sub/Function/Property/Type/Enum/Dim/Const/Declare）
  - Pass 2：分析过程体（赋值类型检查、调用参数校验、标识符声明检查）
- 手动分派：AST 节点无 `accept()` 方法，使用 `dispatchDecl()/dispatchStmt()/dispatchExpr()` 按 kind 分派
- 表达式类型推导：`analyzeExpr()` 推导并缓存 `lastExprType_`
- Option Explicit 支持：未声明标识符报错
- 未使用符号检查：`checkUnreferencedSymbols()`
- 驱动集成：`--dump-symbols` CLI 选项，`runSemanticAnalysis()` 实现
- With 语句对象类型栈

### 关键 Bug 修复：Pratt 非运算符 token 丢失表达式

**症状**：`a = 42` 解析后 AssignmentStmt.value 为 nullptr

**根因**：`parseExpression(minBp=0)` 的 while 循环中：
1. `getBindingPower(NewLine)` 返回 `{0, 0}`
2. 条件 `0 < 0` 为 false，不退出循环
3. `parseLeftDenotation(std::move(left), minBp)` 接管了有效的 left（通过 std::move），但遇到非运算符 token 返回 nullptr
4. 原 left 被 move 后丢失，left 变成 nullptr

**修复**：在调用 `parseLeftDenotation` 前增加守卫条件——如果当前 token 既非中缀运算符（bp={0,0}）也非后缀起始（`.`/`(`/`!`），则直接 break，避免有效表达式被 move 走。

## 问题与决策

| # | 问题 | 决策 |
|---|------|------|
| 1 | AST 节点无 accept() 方法 | 使用 dispatch 辅助函数按 kind 分派，避免修改 AST 核心类 |
| 2 | Symbol 无 isByVal 字段 | 只有 ParameterInfo 有 isByVal，移除错误引用 |
