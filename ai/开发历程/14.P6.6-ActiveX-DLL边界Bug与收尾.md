# 14. P6.6 ActiveX DLL收尾 - VBA 459修复与边界Bug

## 目标
- 修复 VBA Error 459 (WithEvents 事件不匹配)
- 审查并修复 ActiveX DLL 边界 case
- 清理调试代码，为 P7 做准备

## 过程

### VBA Error 459 根因定位
- cgen 自行使用 `generateIid("source:...")` 生成 sourceIfaceIid（FNV-1a hash）
- TypeLib builder 使用 `generateUuid("_ClassNameEvents")` 生成事件接口 IID（不同种子）
- 两者不匹配，导致 `IProvideClassInfo2::GetGUID` 返回的 IID 与 `FindConnectionPoint` 中的 IID 不一致
- 修复：cgen 优先读取 TypeLib builder 回写的 `sym->comSourceIfaceIid`

### VBA Error 430 根因（上一轮已修复，本轮验证通过）
- TypeLib 构建在 generateDllEntry() 之后执行 → IID 未回写符号表
- 符号表隔离：TypeLib builder 写 per-module 表，cgen 读 merged 表

### 边界 Bug 审计与修复
通过子代理系统性审查 cgen.cpp 和 driver.cpp，发现并修复 6 个 bug：

| Bug | 描述 | 修复 |
|-----|------|------|
| BUG-1 | 零公共方法类生成非法零长度C数组 | 跳过方法表，coclass用NULL |
| BUG-2 | 零公共类ActiveX DLL链接错误 | 生成最小stub |
| BUG-3 | DISPID跨类不匹配(shared dispIdMap) | 改为per-class |
| BUG-4 | PublicNotCreatable类可通过CF创建 | 仅MultiUse/SingleUse入coclasses |
| BUG-5 | addDispInterface失败仍写回IID | 失败时跳过 |
| BUG-6 | 事件源addDispInterface返回值未检查 | 检查失败时跳过 |

### 调试日志清理
- 移除 vb6_com_debug_log 和 vb6_format_iid 函数
- 移除所有 QI/GetTypeInfo 调试调用
- 移除不再需要的 `#include <stdarg.h>` 和 `#include <stdio.h>`

## 验证
- VBA 早期绑定 `Dim ec As EventCalc; Set ec = New EventCalc` — 通过
- VBA WithEvents `Dim WithEvents a As EventCalc; a_Changed 事件回调` — 通过
- 回归测试 74/74 PASS

## 问题
无阻塞问题

## 决策
1. PublicNotCreatable(2) 不应通过 DllGetClassObject 创建，只允许 MultiUse(5)/SingleUse(3)
2. DISPID 必须与 TypeLib 保持一致（per-class 顺序分配）
3. addDispInterface 失败时跳过整个 coclass 而不是部分生成（不完整的 TypeLib 比缺失更危险）
