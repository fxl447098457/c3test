## P6.4 Implements接口实现 — 已完成

### 设计决策

**编译时vtable + 接口引用包装类型**：
- 接口类（如IShape）标记为 `isInterface=true`，不生成方法实现体和工厂函数
- 实现类（如CRectangle）生成vtable结构体 + 全局vtable实例 + wrap函数
- 接口引用类型 `vb6_iface_IFoo { vtbl*, void* obj }` 作为值类型
- `Set ifaceRef = obj` → `ifaceRef = vb6_iface_IFoo_wrap(obj)` 自动包装
- 方法调用 `ifaceRef.Method(args)` → `ifaceRef.vtbl->Method(ifaceRef.obj, args)` vtable分发

### 完成内容

#### 层1: 符号表扩展 (symbol_table.hpp)

- Symbol新增字段（SymbolKind::Class时有效）:
  - `isInterface` (bool) — 标记接口类
  - `implementsNames` (vector<string>) — Implements列表
  - `interfaceMethodNames` (vector<string>) — 接口方法名列表
  - `interfaceMethodParams` (vector<ParameterInfo>) — 接口方法参数列表

#### 层2: 语义分析 (semantic_analyzer.cpp)

- `analyze()` Pass 1: 收集implementsNames到类符号
- `analyze()` Pass 2后: Implements验证
  1. 检查接口类在符号表中存在
  2. 标记接口类 `isInterface = true`
  3. 收集接口方法名到 `interfaceMethodNames`
  4. 验证所有接口方法在实现类中存在（检查 `IFoo_MethodName` 格式）
  5. 使用 `SemUndeclaredIdentifier` 报告缺失

#### 层3: 驱动集成 (driver.cpp)

- **Stage 3.6**: 跨模块isInterface传播
  - 遍历所有analyzer的类符号
  - 对每个有implementsNames的类，在所有analyzer中查找并标记对应的接口类
  - 跨模块符号链接(Stage 3.5)传播isInterface/implementsNames/interfaceMethodNames

#### 层4: 代码生成 (cgen.cpp)

- **mapTypeRef**: 接口类(`isInterface=true`) → `vb6_iface_<Name>` (值类型, 非指针)
- **emitInterfaceVtable()**: 新方法，为每个Implements接口生成:
  1. vtable结构体 `typedef struct vb6_vtbl_IFoo { ... }` 含函数指针
  2. 接口引用包装类型 `typedef struct vb6_iface_IFoo { vtbl*; void* obj; }`
  3. 全局vtable实例 `static vb6_vtbl_IFoo vb6_vtbl_IFoo_for_ClassName = { .Method = vb6_ClassName_IFoo_Method, ... }`
  4. wrap函数声明(.h) + 定义(.c): `vb6_iface_IFoo_wrap(obj)`
- **MemberAccessExpr**: P6.4接口引用检测(knownIfaceVars_) → 设置isComMarker_
- **IndexOrCallExpr**: P6.4 vtable调用分支 → `ifaceRef.vtbl->Method(ifaceRef.obj, args)`
- **LocalDeclStmt/VariableDecl**: 接口变量注册到knownIfaceVars_, 初始化为 `{0}`
- **SetStmt**: `Set ifaceRef = obj` → `ifaceRef = vb6_iface_IFoo_wrap(obj)`
- **类结构体**: 空结构体添加 `_placeholder` 字段（C不允许空struct）
- **接口类跳过**: currentClassIsInterface标志 → 跳过方法前向声明(.h) + 方法实现体(.c) + 工厂/析构函数(.c)
- **类指针字段访问**: `r.Width` where `r` is `vb6_cls_CRectangle*` → `r->Width`
- **头文件**: usedVb6IfaceTypes_收集 → 生成vtable和接口引用类型前向声明

### 修复的关键bug

1. **currentClassIsInterface不生效**: cgen中过程实现循环（.c第二遍）缺少currentClassIsInterface检查。.h的方法前向声明有跳过，但.c的过程体生成没有→IShape.c仍生成方法实现体，导致C4028警告(参数类型不匹配)。修复: 在过程实现循环和工厂函数生成处添加currentClassIsInterface检查。

2. **C空结构体**: 接口类无数据成员→`typedef struct vb6_cls_IFoo {} vb6_cls_IFoo`非法C。修复: 添加`int _placeholder`字段。

3. **类指针字段访问运算符**: `r.Width` where r是`vb6_cls_CRectangle*`生成`r.Width`而非`r->Width`。修复: 检查knownClassVars_/knownTypedComVars_使用`->`运算符。

### 目标

### 为什么重要
VB6 IDE的二进制兼容模式要求CLSID在跨编译间保持稳定。没有固定CLSID：
- 每次重新编译DLL都生成不同CLSID→所有客户端ProgID→CLSID映射失效
- 跨机器部署时CLSID不一致→注册表混乱
- 无法在版本控制中追踪COM接口变更

VB6官方格式: Class=ClassName; File.cls; {CLSID}

### 实现步骤

1. **VbpSourceEntry 新增 clsidStr 字段** (vbp_parser.hpp)
   - 仅 Class 类型有效
   - 格式: {XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX}

2. **VBP 解析器支持 3 段格式** (vbp_parser.cpp)
   - 原来只处理 Class=Name; File.cls (2段)
   - 现在支持 Class=Name; File.cls; {CLSID} (3段)
   - 第三段检测 {...} 格式校验合法性

3. **Driver 收集并注入 CLSID** (driver.cpp/hpp)
   - classClsidMap_ 成员: moduleName(小写) → clsidStr
   - VBP 解析阶段填充
   - generateDllEntry() 前注入到 Symbol.comClsidStr
   - 跨模块解析也复制 comClsidStr

4. **cgen 优先使用指定 CLSID** (cgen.cpp)
   - generateDllEntry(): sym->comClsidStr.empty() ? generateClsid(...) : sym->comClsidStr
   - 指定CLSID优先；未指定时回退FNV-1a自动生成
