## P6.2 COM后期绑定 — 已完成

### 完成内容

#### 层1: IDispatch::Invoke封装 (vb6com.c)

- `vb6_getDispid()` — GetIDsOfNames封装 + 线性缓存(256条)
- `vb6_ComCall(disp, methodName, args, argc)` — DISPATCH_METHOD
- `vb6_ComGetProp(disp, propName)` — DISPATCH_PROPERTYGET
- `vb6_ComSetProp(disp, propName, value)` — DISPATCH_PROPERTYPUT
- `vb6_ComSetRef(disp, propName, objRef)` — DISPATCH_PROPERTYPUTREF + 回退PROPERTYPUT

#### 层2: VARIANT pack/unpack (vb6com.c)

- Pack: `vb6_ComPackBSTR/Int/Double/Object` — 值→堆分配VARIANT*
- Unpack: `vb6_ComUnpackBSTR/Int/Double/Object` — VARIANT*→值
- 清理: `vb6_ComVarClear(variant)` — VariantClear + free
- 清理: `vb6_ComVarFree(variant)` — 仅free（对象所有权转移场景）

#### 层3: 一体化辅助函数 (vb6com.c)

- `vb6_ComCallObject(disp, method, args, argc)` — 方法→对象(UnpackObject+VarFree)
- `vb6_ComCallBSTR(disp, method, args, argc)` — 方法→BSTR(UnpackBSTR+VarClear)
- `vb6_ComCallInt(disp, method, args, argc)` — 方法→int
- `vb6_ComCallDouble(disp, method, args, argc)` — 方法→double
- `vb6_ComGetStringProp(disp, prop)` — 属性Get→BSTR(UnpackBSTR+VarClear)
- `vb6_ComGetIntProp(disp, prop)` — 属性Get→int
- `vb6_ComGetDoubleProp(disp, prop)` — 属性Get→double
- `vb6_ComGetObjectProp(disp, prop)` — 属性Get→对象(UnpackObject+VarFree)

#### 层4: 代码生成 (cgen.cpp)

- **COM标记协议**: `isComMarker_`/`comObjExpr_`/`comMemberName_` 成员变量
- **MemberAccessExpr**: COM对象优先检测(knownObjectVars_) → 设置标记
- **IndexOrCallExpr**: 检测COM标记 → 生成vb6_ComCall
- **AssignmentStmt**: COM目标→vb6_ComSetProp, COM值→resolveComValue()
- **SetStmt**: COM目标→vb6_ComSetRef, ComCall结果→vb6_ComCallObject
- **CallStmt**: COM方法调用+结果释放(VarFree/VarClear)
- **Debug.Print**: COM属性→vb6_ComGetStringProp + BSTR输出+释放
- **链式调用**: MemberAccessExpr通用路径检测vb6_ComCall/vb6_ComGetProp表达式→自动转为CallObject/GetObjectProp→设置新COM标记

### 修复的关键bug

1. **VARIANT双重释放**: `vb6_ComCall`中dp.rgvarg是args的浅拷贝，VariantClear(dp.rgvarg)后再VariantClear(args)导致BSTR double free。修复: args仅free结构体，内容由dp.rgvarg清理。

2. **对象所有权转移**: `vb6_ComUnpackObject`提取pdispVal后，对VARIANT*做VariantClear会Release掉对象。修复: 新增`vb6_ComVarFree`仅free结构体，不Release内容。

3. **空BSTR处理**: `folder.Name`对根目录返回VT_BSTR+NULL bstrVal。`vb6_ComUnpackBSTR`跳过了bstrVal==NULL的情况。修复: 增加显式VT_BSTR+NULL分支，返回NULL(等价vb6_BSTR_Empty)。

4. **LocalDeclStmt缺knownObjectVars_**: `Dim fso As Object`在过程内只注册了knownBstrVars_/knownDoubleVars_。修复: 添加void*类型→knownObjectVars_注册。

- test_com2.bas: FSO+GetFolder+Name+Path+Attributes+链式调用 → 全部通过
- test_com3.bas: Is Nothing+GetFile+Size+对象释放 → 全部通过

## P6.3 TypeLib导入+早期绑定 — 已完成

### 设计决策

**编译时TypeLib导入 + 运行时QI + vtable直接调用**：
- 编译时通过 `LoadRegTypeLib` + `ITypeInfo` 提取类型信息（coclass、接口、方法签名、vtable索引）
- 代码生成抽象化C代码（使用 `vb6_ComVtableGetXxx(obj, vtIndex, ...)` 而非硬编码vtable偏移）
- 运行时先 `CreateObject` 再 `QueryInterface` 获取类型化接口指针，然后通过vtable间接调用
- 优势：性能好（vtable直接调用 vs IDispatch::Invoke），且抽象化设计保留跨平台潜力

### 完成内容

#### 层1: TypeLib解析器 (src/com/typelib_parser.hpp + .cpp, ~782行)

- `TypeLibParser` 类，支持三种加载方式：
  - `loadByProgId(progId)` — ProgID → CLSIDFromProgID → LoadRegTypeLib
  - `loadByClsid(clsidStr)` — CLSID字符串 → LoadRegTypeLib
  - `loadByPath(path)` — 直接LoadTypeLib
- 解析内容：ComCoClassInfo/coclass、ComInterfaceInfo/接口、ComMemberInfo/方法、ComParamInfo/参数
- TYPEDESC → Vb6Type 映射
- TypeLib结果缓存 + findCachedCoClass查找

#### 层2: 符号表扩展

- 新增 SymbolKind::ComClass / ComInterface
- Symbol新增COM字段: iidStr/clsidStr/progId/defaultIfaceName/vtblBase/isDual/comMethods
- ComMethodSig: realName, memid, vtableIndex, returnType, isPropertyGet/Put/PutRef, params
- define()修改: 允许ComClass/ComInterface与同名用户变量共存

#### 层3: 驱动集成

- runTypeLibImport() — 编译流水线 Stage 2.5
- 自动加载: Scripting.FileSystemObject/Dictionary, ADODB.Connection, Excel/Word.Application
- CLI: --typelib <ref>, --no-auto-typelib
- 语义分析注入ComClass/ComInterface符号

#### 层4: 代码生成

- knownTypedComVars_ — 早期绑定变量跟踪
- usedComIfaceTypes_ — COM接口类型收集→.h typedef前向声明
- MemberAccessExpr优先级0早期绑定→设置isEarlyBoundCom_+earlyBoundSym_
- IndexOrCallExpr早期绑定→vb6_ComVtableGet<type>/CallVoid
- mapTypeRef: ComClass→vb6_ComIface_<Iface>*
- LocalDeclStmt/VariableDecl: COM接口指针初始化NULL
- SetStmt: CreateObject→vb6_ComCreateTyped, Set Nothing→vb6_ComReleaseTyped
- 头文件: 自动插入typedef前向声明

#### 层5: 运行时支持

- vb6_UnknownQI/Release — C风格vtable辅助
- vb6_ComQI — IID字符串+QI
- vb6_ComCreateTyped — CreateObject+QI
- vb6_ComReleaseTyped — Release+置NULL
- vb6_ComVtableCallVoid/GetBSTR/GetInt/GetDouble/GetObject/GetVoid — vtable间接调用+VARIANT解封

### 修复的关键bug

1. **IUnknown C++方法调用**: → 改用C风格lpVtbl辅助函数
2. **COM接口类型未定义**: → usedComIfaceTypes_收集+.h typedef前向声明

4. **vtable调用参数多余this**: → 参数生成不再包含objExpr

## P6.4 Implements接口实现 — 已完成

### 设计决策

**编译时vtable + 接口引用包装类型**：
- 接口类（如IShape）标记为 `isInterface=true`，不生成方法实现体和工厂函数
- 实现类（如CRectangle）生成vtable结构体 + 全局vtable实例 + wrap函数
- 接口引用类型 `vb6_iface_IFoo { vtbl*, void* obj }` 作为值类型
- `Set ifaceRef = obj` → `ifaceRef = vb6_iface_IFoo_wrap(obj)` 自动包装
- 方法调用 `ifaceRef.Method(args)` → `ifaceRef.vtbl->Method(ifaceRef.obj, args)` vtable分发

### 完成内容

#### 层1: 符号表扩展 (symbol_table.hpp)

- Symbol新增字段（SymbolKind::Class时有效）:
  - `isInterface` (bool) — 标记接口类
  - `implementsNames` (vector<string>) — Implements列表
  - `interfaceMethodNames` (vector<string>) — 接口方法名列表
  - `interfaceMethodParams` (vector<ParameterInfo>) — 接口方法参数列表

#### 层2: 语义分析 (semantic_analyzer.cpp)

- `analyze()` Pass 1: 收集implementsNames到类符号
- `analyze()` Pass 2后: Implements验证
  1. 检查接口类在符号表中存在
  2. 标记接口类 `isInterface = true`
  3. 收集接口方法名到 `interfaceMethodNames`
  4. 验证所有接口方法在实现类中存在（检查 `IFoo_MethodName` 格式）
  5. 使用 `SemUndeclaredIdentifier` 报告缺失

#### 层3: 驱动集成 (driver.cpp)

- **Stage 3.6**: 跨模块isInterface传播
  - 遍历所有analyzer的类符号
  - 对每个有implementsNames的类，在所有analyzer中查找并标记对应的接口类
  - 跨模块符号链接(Stage 3.5)传播isInterface/implementsNames/interfaceMethodNames

#### 层4: 代码生成 (cgen.cpp)

- **mapTypeRef**: 接口类(`isInterface=true`) → `vb6_iface_<Name>` (值类型, 非指针)
- **emitInterfaceVtable()**: 新方法，为每个Implements接口生成:
  1. vtable结构体 `typedef struct vb6_vtbl_IFoo { ... }` 含函数指针
  2. 接口引用包装类型 `typedef struct vb6_iface_IFoo { vtbl*; void* obj; }`
  3. 全局vtable实例 `static vb6_vtbl_IFoo vb6_vtbl_IFoo_for_ClassName = { .Method = vb6_ClassName_IFoo_Method, ... }`
  4. wrap函数声明(.h) + 定义(.c): `vb6_iface_IFoo_wrap(obj)`
- **MemberAccessExpr**: P6.4接口引用检测(knownIfaceVars_) → 设置isComMarker_
- **IndexOrCallExpr**: P6.4 vtable调用分支 → `ifaceRef.vtbl->Method(ifaceRef.obj, args)`
- **LocalDeclStmt/VariableDecl**: 接口变量注册到knownIfaceVars_, 初始化为 `{0}`
- **SetStmt**: `Set ifaceRef = obj` → `ifaceRef = vb6_iface_IFoo_wrap(obj)`
- **类结构体**: 空结构体添加 `_placeholder` 字段（C不允许空struct）
- **接口类跳过**: currentClassIsInterface标志 → 跳过方法前向声明(.h) + 方法实现体(.c) + 工厂/析构函数(.c)
- **类指针字段访问**: `r.Width` where `r` is `vb6_cls_CRectangle*` → `r->Width`
- **头文件**: usedVb6IfaceTypes_收集 → 生成vtable和接口引用类型前向声明

### 修复的关键bug

1. **currentClassIsInterface不生效**: cgen中过程实现循环（.c第二遍）缺少currentClassIsInterface检查。.h的方法前向声明有跳过，但.c的过程体生成没有→IShape.c仍生成方法实现体，导致C4028警告(参数类型不匹配)。修复: 在过程实现循环和工厂函数生成处添加currentClassIsInterface检查。

2. **C空结构体**: 接口类无数据成员→`typedef struct vb6_cls_IFoo {} vb6_cls_IFoo`非法C。修复: 添加`int _placeholder`字段。

3. **类指针字段访问运算符**: `r.Width` where r是`vb6_cls_CRectangle*`生成`r.Width`而非`r->Width`。修复: 检查knownClassVars_/knownTypedComVars_使用`->`运算符。

### 生成的代码示例 (test_implements.vbp)

**IShape.h** — 接口类: 仅结构体定义, 无方法声明
```c
typedef struct vb6_cls_IShape { int _placeholder; } vb6_cls_IShape;
```

**CRectangle.h** — 实现类: vtable + wrap + 方法声明
```c
typedef struct vb6_vtbl_IShape {
    double (*Area)(vb6_cls_CRectangle* me);
    double (*Perimeter)(vb6_cls_CRectangle* me);
    void (*Describe)(vb6_cls_CRectangle* me);
} vb6_vtbl_IShape;
typedef struct vb6_iface_IShape { vb6_vtbl_IShape* vtbl; void* obj; } vb6_iface_IShape;
vb6_iface_IShape vb6_iface_IShape_wrap(vb6_cls_CRectangle* obj);
```

**test_implements.c** — 主程序: vtable分发
```c
vb6_cls_CRectangle* r = NULL; r = vb6_cls_CRectangle_New();
r->Width = 3.0; r->Height = 4.0;
vb6_iface_IShape s = {0}; s = vb6_iface_IShape_wrap(r);
vb6_DebugWriteLong((int32_t)(s.vtbl->Area(s.obj)));      // → 12
vb6_DebugWriteLong((int32_t)(s.vtbl->Perimeter(s.obj))); // → 14
s.vtbl->Describe(s.obj);                                  // → "Rectangle"
```

- 输出: Area = 12, Perimeter = 14, Rectangle, Implements test PASSED
