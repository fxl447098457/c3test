## 目标

将 RTL 运行时库作为 Windows RC 资源嵌入 c3.exe，编译时自动释放到临时会话目录，编译完成后自动清除。用户分发只需 c3.exe，不再需要 rtl/ 目录和 VB6RTL_DIR 环境变量。

## 架构决策

**RC 资源嵌入（选择） vs .lib 预编译（原计划）**

原计划：将 8 个 RTL .c 文件预编译为 .lib，再嵌入 c3.exe。
实际选择：直接嵌入完整 .h/.c 源文件作为 RCDATA 资源，编译时释放到临时目录，MSVC 编译 .c 文件。

理由：
1. 保持现有 MSVC 驱动逻辑不变（编译 .c 文件而非链接 .lib）
2. 避免引入预编译步骤（build_rtl_libs.bat）和头文件精简工具
3. 8 个文件总大小仅 151KB，嵌入后 c3.exe 从 960KB 增至 1154KB，完全可接受

## 过程

### P10.1-P10.2: 不适用

RC 方案不需要预编译和头文件精简，跳过。

### P10.3: Windows RC 资源嵌入

创建 `src/driver/c3rtl.rc`：
- 8 个 RTL 文件（4 .h + 4 .c）作为 RCDATA 资源
- 资源 ID 100-107（对应 RTL_VB6RTL_H 到 RTL_VB6FORMS_C）
- **关键修复**：RC 路径必须使用正斜杠 `/`，反斜杠 `\` 在 CRLF 文件中被当作回车符

```
100 RCDATA "../rtl/core/vb6rtl.h"
101 RCDATA "../rtl/core/vb6rtl.c"
...
```

### P10.4: 运行时资源释放

创建 `src/driver/rtl_embedded.hpp` + `src/driver/rtl_embedded.cpp`：
- `loadRtlResource()`: FindResource → LoadResource → LockResource 读取 RCDATA
- `SessionManager::create()`: 创建会话目录 + 释放 8 个文件
- `SessionManager::cleanup()`: 递归删除会话目录
- `SessionManager::cleanupOldSessions()`: 清理 >300s 的旧会话

**修复 bug**：`rtl_embedded.hpp` 注释末尾 `\` 被 MSVC 当作行续符，导致成员变量声明失败。修复方案：注释中避免反斜杠。

### P10.5-P10.6: 会话目录管理

```
%TMP%\C3C\{steady_clock_timestamp}\
  └── rtl\
      ├── vb6rtl.h
      ├── vb6rtl.c
      ├── vb6com.h / .c
      ├── vb6comserver.h / .c
      └── vb6forms.h / .c
```

- 每次编译创建独立会话目录
- SessionManager 析构自动清理
- 旧会话 >300s 自动删除

## 决策

1. **RC 资源 vs .lib 预编译**：选择 RC 资源嵌入完整源文件，保持现有 MSVC 编译逻辑不变
2. **会话目录路径**：使用 `%TMP%\C3C\{steady_clock_timestamp}\`，避免冲突
3. **旧会话清理阈值**：300 秒（5 分钟），足够长不误删，足够短不积累
4. **c3-error.log 存放位置**：输出目录（与 .exe 同目录），便于用户查找
