## 目标

1. 实现VB6多模块工程(.vbp)的跨模块符号解析，使模块A调用模块B的Public函数时，生成的C代码能正确链接。
2. 实现VB6类模块(.cls)编译，支持对象创建(New)、方法调用、属性访问、跨模块类引用。

## 过程

### 5.1 跨模块符号解析

VBP多模块编译（MainMod.bas + MathUtils.bas）在MSVC链接阶段失败：
- MathUtils.c 定义 `vb6_Add` / `vb6_Multiply`（带 `vb6_` 前缀）
- MainMod.c 调用 `Add` / `Multiply`（不带前缀）
- 链接器找不到 `Add` / `Multiply` 符号

根因：每个模块有独立的 SymbolTable，语义分析时 MainMod 找不到 MathUtils 的 Public 符号。

#### 5.3c 语义分析

- 类模块注册 Class 符号：`SymbolKind::Class`, 包含 `instancing` 和 `memberNames`
- `visit(NewExpr&)`: 查找类符号，规范化名称
- `visit(MeExpr&)`: 非类模块中使用发出警告
- 类模块变量（Private m_Count）注册为模块级变量（代码生成时转为结构体字段）

#### 5.3d C代码生成 — 类模块核心

**类结构体**: `vb6_cls_<Name>` typedef，模块级变量作为字段

**方法签名**: 每个方法增加 `me` 参数作为第一参数
```c
void vb6_Counter_Increment(vb6_cls_Counter* me);
int32_t vb6_Counter_GetCount(vb6_cls_Counter* me);
```

**工厂函数**:
- `vb6_cls_Counter_New()`: vb6_Alloc分配 + 字段初始化 + Class_Initialize调用
- `vb6_cls_Counter_Destroy()`: Class_Terminate调用 + BSTR/数组释放 + vb6_Free

**New表达式**: `New Counter` → `(vb6_cls_Counter_New())`

**Me表达式**: `Me` → `me`

**成员访问**: `c.Increment` → `vb6_Counter_Increment(c)` (通过knownClassVars_跟踪)

**变量声明**: `Dim c As Counter` → `vb6_cls_Counter* c = NULL;` (通过mapTypeRef类→指针类型)

**Property代码生成**: Property Get/Let/Set 完整签名生成

**Event存根**: 生成前向声明，后续P6实现

#### 5.3e 跨模块类引用（关键Bug修复）

**根因**：Attribute VB_Name = "Counter" 被解析为模块属性，但 `module.moduleName` 从未被设置（空字符串），导致：
1. 类符号以空名注册 → 其他模块找不到 "Counter" 类符号
2. 跨模块解析无法匹配 → 类符号未注入到 test_class.bas 的符号表
3. mapTypeRef 回退到 VARIANT → Dim c As Counter 生成错误类型
4. knownClassVars_ 为空 → 成员访问回退到 C struct dot 语法

**修复1 — Attribute VB_Name 提取** (driver.cpp):
```cpp
// 从 Attribute VB_Name 提取模块名
for (const auto& attr : module->attributes) {
    if (attr->attrName == "VB_Name" && attr->value) {
        if (attr->value->kind == ASTNodeKind::LiteralExpr) {
            auto& lit = static_cast<LiteralExpr&>(*attr->value);
            if (lit.literalKind == LiteralKind::String && !lit.rawText.empty()) {
                module->moduleName = /* 去掉引号的rawText */;
            }
        }
    }
}
// 没有VB_Name属性则使用文件名
if (module->moduleName.empty()) {
    module->moduleName = p.stem().string();
}
```

**修复2 — 跨模块Class符号完整复制** (driver.cpp runCrossModuleResolution):
- 原来只复制了 `params` 和 `isArray`
- 新增：Class符号复制 `instancing` 和 `memberNames`

**修复3 — 跨模块类方法调用** (cgen.cpp MemberAccessExpr):
- `cProcName` 需要传入外部符号的 `sourceModule`，否则跨模块类方法缺少模块前缀
- `c.Increment` → `vb6_Counter_Increment(c)` (外部: sourceModule="Counter")

**修复4 — IndexOrCallExpr完整调用检测** (cgen.cpp):
- `c.GetCount()` 被解析为 `IndexOrCallExpr(MemberAccessExpr(c, GetCount))`
- MemberAccessExpr 已生成 `vb6_Counter_GetCount(c)` (完整调用)
- IndexOrCallExpr 又追加 `()` → 双重括号
- 修复：检测 callee 是否已是完整函数调用（以匹配右括号结尾），若是且无额外参数则直接使用

**修复5 — 清理死代码**: 删除 MemberAccessExpr 中未使用的 clsSym 查找块

## 问题

1. **冗余跨模块 #include**：MathUtils.h 包含了 MainMod.h（未被引用），因为 runCrossModuleResolution 把所有其他模块的 Public 符号都注入了。#ifndef guard 保护，功能无影响。

2. **类模块私有方法跨模块可见**：`knownClassVars_` 仅跟踪类类型变量名，不区分类的具体类型。如果同一模块有两个不同类的实例变量，方法名可能混淆。

3. **IndexOrCallExpr 参数合并未实现**：当类方法调用带用户参数（如 `c.Method(arg)`）且 callee 已经是完整调用时，需要拆开并合并参数，目前只处理了无额外参数的情况。

4. **引用计数缺失**：Set 赋值不进行 AddRef/Release，类实例不会被自动销毁（需手动调用 Destroy）。

## 决策

1. **类编译策略**：选择"C结构体+工厂函数"而非vtable，MVP阶段够用，P6阶段再引入虚函数表。

2. **me参数注入**：所有类方法通过第一个参数注入 `me` 指针，而非this指针（C结构体无成员函数）。

3. **Attribute VB_Name 提取时机**：在Driver的runParser中（parseModule之后立即提取），而非在语义分析中。确保符号注册时moduleName已被设置。

4. **无VB_Name时回退到文件名**：标准模块(.bas)通常没有VB_Name属性，用文件名（去掉扩展名）作为模块名。
