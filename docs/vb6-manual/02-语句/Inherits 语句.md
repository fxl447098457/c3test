# Inherits 语句

> **本项目扩展**（twinBASIC 风格适配），非微软 VB6 原生语句。规范与实施进度见仓库内 `ai/018`、`ai/022`。

**Inherits 语句**

在类模块里指定本类的**基类**，从而继承其字段与过程实现。

**语法**

**Inherits** *BaseClass*

**说明**

- `Inherits` 是**类模块级声明**，只能写在 `.cls` 里（标准模块、窗体、泛型类模板内都拒绝），
  且只能是独立成行的一条子句；写在 `Class Foo Inherits Bar` 这种头行形式里当前不被接受。
- **单继承**：一个类只能有一个基类。基类必须是**同一工程内**的类模块（`Project.Base` 形式的
  点号限定名会被剥掉前缀后再查）。基类不能是接口宿主（即那个只含同名 `Interface` 块的 `.cls`）。
- 链上出现环（`A Inherits B`、`B Inherits A`）或深度超过 16 层会报错；一个环只报一条。
- `Inherits`（类继承）与 `Extends`（接口继承）**永不同义**：接口块的父接口用
  [Interface 语句](Interface%20语句.md) 的 `Extends`，类的基类用本页的 `Inherits`。
- 继承来的成员按 COM 惯例做**前缀兼容布局**：派生类结构体 = 祖先字段（自根到叶）+ 自有字段，
  因此调用继承来的过程时编译器发的是转调基类实现的中转函数，不复制过程体。
- **遮蔽**：派生类自己声明的同名成员胜出，基类那份对它不可见（也不会被转调）。遮蔽与覆盖是两回事：
  只有写了 `Overrides` 的那份参与虚派发（见下），普通同名声明只是把自己的成员表项换成了自己的实现，
  基类自己内部的调用仍按基类那份走。
- 基类的 `Private` 成员对派生类不可见（其字段仍占布局，以保住基类实现自己的偏移）。
- **`Protected`**（本项目扩展的访问修饰符）= 只在**类家族内**可见：基类的 `Protected` 字段/过程/属性
  会被派生类继承，并可经 `Me.` *成员名* 使用；它不进 `Public` 那份 COM 对外暴露清单。
  `Interface` 块内写任何访问修饰符（含 `Protected`）都会被拒（契约成员一律公开）。
  **家族外越权会被拒**（`VB3023`）：家族 = 声明该成员的那个类，以及它的（间接）派生类；
  标准模块、窗体、以及不在同一条链上的类写 `obj.` *成员名* 都报错，读、写、`Set`/`Let` 与调用
  一视同仁（判定发生在调用点，不是在跨模块注入里过滤成员表 —— 后者会把越权退化成运行期才炸的
  晚绑定 COM 调用）。判定认得这三种接收者形状：模块级 `Dim w As C`、过程内 `Dim w As C`、
  `ByVal w As C` 形参，外加 `Me.`。以下形状**不判**（照旧静默通过，不是漏网成错误代码，只是
  编译器不去证明越权）：数组元素 `w(1).X`、属性/函数返回的对象 `pvSocket.X`、`With w` 块内的
  `.X`、以及泛型模板类与接口宿主内部的引用（那里推不出家族链）。判定的成员口径是
  `字段`/`Sub`/`Function`/`Property` 四类（与继承合并用的是同一套），`Event` 不在其中。
  同名属性的多个方向（`Get`/`Let`/
  `Set`）按**名字**取严：任一方向是 `Protected` 就按 `Protected` 论，因为调用点上分不清方向。
- **`Overridable` / `Overrides` / `NotOverridable`**（VB6 原生虚方法修饰符，配合 `Inherits` 使用）：
  基类用 `Overridable` 声明可被覆盖的成员，派生类用 `Overrides` 换上自己的实现，
  `NotOverridable` 显式声明不可覆盖（等于 VB6 默认）。三者只作用于 `Sub`/`Function`/`Property`，
  写在访问修饰符之后（`Public Overridable Sub X`），访问修饰符省掉时也可单独起一行
  （`Overridable Sub X`），互斥且最多一个，同段里写两个会报错。属性的覆盖按**方向**配对
  （`Property Get` 只覆盖 `Property Get`）。`Overrides` 是错误级契约检查：祖先链上必须有同名同向的
  成员、那份必须是 `Overridable`（或 `Overrides`）、且不能是 `Private`，参数与返回类型逐项一致。
- **虚派发（类虚表）**：一条链上只要有人 `Overrides` 某成员，链上**每个**类都会多出一个
  `__cvtbl` 字段，指向自己那张函数指针表；表的槽序按"该成员首次被 `Overridable` 声明的位置"
  自根到叶排列，因此祖先那张表是后代那张表的**前缀**，同一槽在整条链上偏移一致。于是：
  基类体内的 `Me.` *成员名* 会按**实例真实类型**绑定，绑到"从实例所在类往上数最近的那份覆盖"
  （叶类自己不覆盖时用中间类的实现）；同样地，声明为基类型、实际持有派生实例的变量，
  调这个成员也走派生实现（不再切片回基类）。没被任何人 `Overrides` 的 `Overridable` 成员不建槽、
  不加字段，代码与不用虚修饰符时逐字节相同。
- **`MyBase`**（本项目扩展，twinBASIC 风格）= 在派生类体内**显式调用基类那一份实现**，与虚表无关
  （去虚化）：`MyBase.Speak()` 拿到的永远是"直接基类会跑的那一份"，即使本类 `Overrides` 了它、
  即使实例属于更深的派生类。取的是**就近声明**：直接基类自己声明过就用它，没有就沿基类的链往上
  找最近的一份（与中转函数同一条口径）—— 所以中间类用普通同名声明**遮蔽**了某成员时，
  深层类里 `MyBase.` *成员名* 用的就是中间类那份，不是根上的。带参数（可选实参的 `_has_` 标志
  按基类那份签名补齐）、属性读、属性 `Let` 写与继承来的 `Public` 字段读写都走这条。
  三种写法**报错**（`VB3028`）：本类没有 `Inherits` 子句、基类面上没有这个名字、目标是基类的
  `Private` 成员（它在 C 层就是 `static`，跨翻译单元连不到；VB6 语义上私有成员也对派生类不可见）。
  唯一的例外是 `MyBase.Class_Initialize`，它走下面那条构造链的入口。
- **构造链**：`New` 一个派生类时，祖先的 `Class_Initialize` 按**自根到叶**先跑、本类那份最后跑
  （`base;mid;leaf;`）。桥接函数 `vb6_<基>_chain_init` 只在"这个类自己写了 `Class_Initialize`
  **且**确实被谁继承"时才发，所以零继承工程的代码逐字节不变。`Class_Terminate` 的反序链本版**没做**。

**注意**

以下形态在 v1 直接**报错**而不是静默降级，因为它们都会让生成的代码与基类布局对不上：

- 派生类重声明祖先已有的**同名字段**（C 结构体容不下两个同名成员）。
- 基类声明了 **Event**（事件接收器指针挂在结构体尾部，前缀复制不成立）。
- 基类或派生类实现了 **Interface 语句**声明的新式接口（引用计数与虚表槽字段的继承规则另批设计）。
- 基类含**同名重载**过程（中转函数需要与重载指纹一起设计）。
- 在类内**裸名**调用继承来的成员，或在类体内裸名调用一个会被后代覆盖的成员：请写
  `Me.` *成员名*。合并发生在类符号的成员表上，模块作用域里没有它的过程符号，裸名会静默生成
  空调用；而虚表派发只接在成员调用那条解析路上，裸名那条路发的还是直接调用，故编译器拒绝。
- 覆盖 `Property Let` / `Property Set`：报错。写上下文（`Me.Props(1) = v` 这类）的发码在另一条
  路径上，本版只发 `Sub`/`Function`/`Property Get` 的槽 —— 与其让它静默绑回基类实现，不如拒绝。
- 接收者是**带函数调用的表达式**（属性返回的对象 `pvSocket.Pick()`、方法结果 `GetFoo().Pick()`、
  属性链 `k.Own.Speak()`）时本版**一律报错**（`VB3027`）：间接调用要把接收者用两次，带调用就是
  求值两次，而发码层没有"把一个表达式提升成临时变量"的机制。要派发就先把它赋给一个变量再调 ——
  `Me`、普通类变量（含模块级字段，如 `m_h.Speak()`）、`(*形参)`、`With w` 块内的 `.Speak()`、
  带 `Me.` 前缀的字段链 `Me.m_h.Speak()`、**UDT 里的对象字段** `u.h.Speak()`（`h As <类>`）、
  以及**函数体内用函数名读自己的返回值**
  （`Function Maker() As CBase` 体内的 `Maker.Speak()`）这些纯读接收者是正常派发的
  （`ai/022` B08e-1/-2/-4/-6 分批接上，属性读 `Me.m_h.Level` 也按实例的表绑定）。
  **属性写的方向不参与派发**（3.4b 不给 `Property Let`/`Set`
  建槽，见上），所以 `Me.m_h.Level = 5` 发的是基类那份 `prop_let_`；读同一句属性时才走虚表。
  预声明实例（`cFoo.Pick()` 那条 `X_Default()` 通路）与工程 UserControl 的子控件
  （`ucChartBar1.AddSerie(...)`，接收者是 `vb6_UC_InstanceOf(hwnd)`）按直调处理：
  它们的动态类型恒等于静态类型，直调本来就正确。
- 类数组元素的成员访问（`arr(1).Speak()`）本版**编译不过**（不是静默错码），与访问控制无关。
- `Interface` 块成员写 `Overridable`/`Overrides`/`NotOverridable` 会被拒：契约没有实现体，谈不上覆盖。
