# 260921 IDispatch 桥接修复（EXE 工程类过 COM 边界）

接续文档：跨会话恢复上下文的第一锚点。修复对象 = VBMAN_DEMO.exe 启动崩溃 0xC0000005。

## 崩溃机制（三路证据互洽，勿重查）

- demo 侧 `New bHello`（EXE 工程类，MultiUse）生成裸 C 结构体指针，塞进 VT_DISPATCH VARIANT 传给 VBMAN.dll
- DLL 侧 `Set Controllers(ControllerName) = Controller`（cHttpServerRouter.cls:63，Dictionary 是 VBMAN 工程类）取值/释放路径对 VT_DISPATCH AddRef → 裸结构体首字段被当 vtable → `callq *0x8(%rax)` → AV
- 接收侧 `cHttpServerRouter.cls:236-237` 用 `CallByName C, ActionName, VbMethod, ctx` 晚绑定 —— 需要真 IDispatch 应答 GetIDsOfNames + Invoke
- 本质：C3 的 IDispatch 生成原先被 8 处 `isDll_` 守卫锁在 ActiveX DLL 侧；EXE 工程类实例无 `__comObj`、无 coclass 表、vb6comserver*.c 不链入
- 方向已拍板（用户）：完整实现 IDispatch 桥接（非报错拦截）；tests 布局一起统一到 tests_github

## 阶段 3 实施（已落地，本机 A/B 验证通过）

实现方式：**不动 visit(NewExpr) 的输出**（裸 `vb6_cls_X_New()` 留给本工程内部早绑定使用），
只把「`New <本工程类>` 出现在 COM 实参打包点」这一条路径改道 —— 天然收窄，无泄漏面。

改动 5 文件（注释前缀 ExeComBridge 03）：
1. `src/backend/cgen_util_com.cpp` comPackExpr 开头加 NewExpr 分支：`lookupModuleDotted(name)->kind == Class`
   → 返回按类打包函数 `vb6_ComPack_<类>`（ComClass 仍走 vb6_NewObject，其余分支零改动）
2. `src/backend/module/cgen_com.cpp` emitClassFactory 末尾：每个类模块生成
   `void* vb6_ComPack_<类>(void* instance) { return vb6_ComPackVB6InstanceRaw("<类名>", instance); }`
3. `src/backend/detail/base/cgen_base_generate_c_open.inc` 类工厂声明后输出该函数声明
   （调用点常在其他模块，缺声明 = 隐式 int 截断指针）
4. `src/rtl/core/vb6comserver/vb6comserver.h` + `vb6comserver_obj.c` 新增
   `vb6_ComPackVB6InstanceRaw(const char* classVariable, void* instance)`：
   FindCoClassDesc → ComObject_FromInstance → 转 VARIANT*（VT_DISPATCH）。
   **引用计数**：FromInstance 给的 1 个引用直接转移给 VARIANT，不额外 AddRef（否则包装器与实例永不释放）。
   类不在 coclass 表（Private / 非 MultiUse|SingleUse）→ 返回 NULL（等效 Nothing），不冒充对象。

## 阶段 3 已知限制（未覆盖）

`Set h = New bHello`（赋给 `As Object` 变量）后再传**变量** → 仍 0xC0000005
（`tmp/verify_p3b/` 复现：`S1 assigned` 后崩）。原因：comPackExpr 只识别字面 `New` 表达式，
变量路径走通用 `vb6_ComPackObject`（对裸实例直接 AddRef）。
VBMAN_DEMO 用的是字面 `New`（已覆盖），不影响止血目标；继续收口需在
「Set 变量 = New 工程类」赋值点也接 FromInstance（另一轮改动 + 回归）。
