# C3 GUI 用例验证方案（自验证）

> 日期：2026-09-15 ｜ 背景：tests/ 的窗体用例（P7 段）目前只做 compile（编译通过即 PASS），从不运行；控制台用例已有 stdout 对比校验。本文给出 GUI exe 的验证分层与落地顺序。

## 核心认知

C3 是编译器项目，GUI 验证的目标是「编译器生成的窗体代码对不对」，不是「应用交互逻辑好不好用」。编译器的窗体 bug 绝大多数表现为：启动即崩、控件没建出来、控件属性/布局错、事件不触发——都能用比「完整 UI 自动化」轻得多的手段抓到。

验证的本质：给每个用例一个**可判定的输出谓词**。控制台程序天然有 stdout/exit code；GUI 程序需要人为制造可判定信号。

## 现状（tests/run_tests.ps1）

| 类别 | 验证内容 | 判定谓词 |
|------|----------|----------|
| compile | 编译器接受源码、codegen/link 不崩 | C3 exit code = 0 |
| run | 编译 + 运行 + 输出正确 | stdout 重定向后与 ExpectedOutputs 逐行匹配 |
| 窗体（P7 段） | **只编译，从不运行** | 无 —— 空白区 |

## 验证分层（按成本递增，抓的缺陷不同）

| 档 | 手段 | 能抓什么 | 成本 |
|----|------|----------|------|
| L1 冒烟 | 启动 exe → 等主窗口句柄 → WM_CLOSE → 查退出码 | 启动即崩（0xC0000005）、消息循环没起来、窗体代码崩溃 | run_tests.ps1 加约 30 行 PowerShell |
| L2 结构验证 | EnumChildWindows 枚举控件树，dump 类名/标题/位置为文本，与期望清单比对 | 控件缺失/多余、属性错、布局错 | PowerShell P/Invoke，不截图、比像素对比稳定得多 |
| L3 自验证窗体 | Form_Load 内自行断言（Controls.Count、控件属性），结果写文件到工作目录后自动 Unload | 语义级行为（事件触发、属性读写） | 只写 VB6 测试代码，零框架依赖 |
| L4 差分测试 | 同一 .vbp 分别用 VB6 原生 /make 与 C3 编译，双运行对比 stdout/控件树 dump | 与原版的一切行为差异（最强验证） | 需 VB6 环境；/make 注意 IDE 必须完全关闭、用绝对路径 |
| L5 完整 UI 自动化 + 截图金样 | FlaUI/pywinauto 模拟交互、截图感知哈希对比 | 交互逻辑、视觉渲染 | 对本项目大概率过度；截图受 DPI/字体渲染差异干扰，脆弱 |

## 关键技术判断

1. **L1+L2 先行**：不需要引入 UI 自动化框架，纯 PowerShell（`Add-Type` P/Invoke `FindWindow` / `EnumChildWindows` / `PostMessage`）即可把 8 个 P7 窗体用例从 compile 升级到 run 类。
2. **L3 上报表走文件不走 stdout**：窗体 exe 默认无控制台，Print/Debug.Print 拿不到；写结果文件恰好契合 run_tests.ps1 现有「工作目录 = output/」约定。注意 L3 断言走的是被测 RTL 自身（Controls 集合等），编译器错则断言可能跟着错（假阴性风险），须与 L2 的外部视角互补。
3. **差分测试是终验王牌**：对 VBMAN 等大型真实工程与 VB6 原生产物对比最有说服力。注意窗口类名归一化——VB6 原生为 ThunderRT6Form 系，C3 自研 RTL 类名不同（以 cgen_form 生成代码为准），比对控件树前先做类名映射。
4. **截图对比放最后或不做**：控件树 dump 是「视觉等价」的稳定代理；真要截图须固定 DPI 与字体并接受感知哈希阈值，否则环境变化即误报。

## 外部工具现状（2026-09 检索）

- WinAppDriver：2020-11 v1.2.1 后停滞，1100+ 未修 issue，服务器源码未开源——不用于新工作。
- FlaUI：活跃维护（2025-02 发布 5.0.0，MIT），.NET 生态首选。
- pywinauto：活跃维护，Python 生态，Win32 + UIA 双后端。
- Coded UI：VS2019 弃用、VS2026 移除。
- 结论：本项目 L1/L2 用纯 PowerShell 即可，无需引入上述框架。

## 落地顺序

1. run_tests.ps1 新增 Test-FormRun（L1 冒烟 + L2 控件树 dump 比对），把 8 个窗体用例升级为 run 类。
2. 挑 2-3 个窗体用例写 L3 自验证（Form_Load 断言 + 写结果文件 + 自动退出）。
3. VBMAN 大工程做 L4 差分抽样（复用 /make 命令行编译经验：PowerShell Start-Process -Wait、IDE 完全关闭、绝对路径）。
