# Fix 034 — 内置函数注册参数签名，让 calleeParams 类型转换包装生效 (C2198/C2440)

## 错误现象

### 问题：内置函数 calleeParams 为空导致类型转换包装失效

C3 的 Fix 024 P2（cgen_expr.cpp:2706-2709）和 Fix 029（cgen_expr.cpp:2710-2743）依赖 `calleeParams` 列表来插入自动类型转换包装：

- **Fix 024 P2**（正向包装）：当 `calleeParams[i]` 是 `ByVal Variant` 且实参是标量/BSTR 时，自动包装为 `vb6_VariantFromValue(arg)`。
- **Fix 029**（反向提取）：当 `calleeParams[i]` 是 `ByVal 具体类型`（如 Double/String）且实参确定为 Variant 时，自动调用提取函数（如 `vb6_VariantToDouble`、`vb6_VariantToString`）。

但绝大多数内置函数（Len/CInt/CLng/Format/DateAdd/…）此前通过 `addBuiltinFunc` 注册，**不写 `calleeParams`**。这导致：

1. **C2198 "parameter not enough"**：内置函数的 Optional 参数未被 `!calleeIsBuiltin` guard 之外的一般 padding 代码填充（line 3291 的 guard 跳过内置函数）。
   - 典型：`Round(x)` 缺 `decimals=0`；`StrComp(s1, s2)` 缺 `compare=0`；`InStrRev(s1, s2)` 缺 `start=-1, compare=0`；`Rnd()` 缺 `seed=0`。
2. **C2440 "类型转换"**：实参类型与 RTL C 函数期望类型不匹配时，`calleeParams` 为空导致 Fix 024 P2/Fix 029 包装未触发。
   - 典型：`DateAdd("d", 1, Now)` 中 Now 返回 Date(double) → DateAdd 第 3 参 VB6 期望 Date，无问题；但若实参是 Variant 变量且 RTL 期望 double，则缺 `vb6_VariantToDouble(arg)` 包装 → C2440。

## 根本原因

### 内置函数注册策略：`addBuiltinFunc` vs `addBuiltinFuncWithParams`

`semantic_analyzer.cpp` 的 `registerBuiltins()` 有两个 lambda：

- `addBuiltinFunc(name, retType)` — 注册 Function 符号，**不写 `params`**。Fix 030b 之前所有内置函数都走这里。
- `addBuiltinFuncWithParams(name, retType, params)` — 注册 Function 符号，**写入 `params`**。Fix 030b 引入，仅 UBound/LBound 使用。

绝大多数内置函数仍走 `addBuiltinFunc`（无 params），所以 `calleeParams` 查找总是空 → 类型转换包装和参数 padding 都失效。

## 修复方案（四部分）

### Part 1: 大规模把内置函数改为 `addBuiltinFuncWithParams`（semantic_analyzer.cpp）

把 ~60 个内置函数从 `addBuiltinFunc` 转为 `addBuiltinFuncWithParams`，参数签名严格按 `src/rtl/core/vb6rtl.h` 的 C 签名填写：

| 类别 | 代表函数 | 参数签名（按 RTL C 签名） |
| --- | --- | --- |
| 字符串 | Len/Left/Right/Mid/InStrRev/Replace/Split/Join/StrComp/StrReverse/Space/String/Asc/Chr/Val/Str/LCase/UCase/LTrim/RTrim/Trim | ByVal String + Optional 数值 |
| 类型转换 | CSng/CBool/CDate/CByte/CCur/CDec/CVErr/Hex/Oct | ByVal Double / Variant / Long |
| 数值 | Abs/Int/Fix/Sgn/Sqr/Round | ByVal Double |
| 类型检查 | IsNumeric/IsDate/IsEmpty/IsNull/IsObject/IsArray/IsError/TypeName/VarType | ByVal Variant |
| 数学 | Sin/Cos/Tan/Atn/Exp/Log | ByVal Double |
| 文件 | LOF/EOF/Loc/Seek/GetAttr/FileLen/FileDateTime/Dir/CurDir/Shell/Environ/FileAttr | ByVal Long/String |
| 日期 | DateAdd/DateDiff/DatePart/DateSerial/DateValue/TimeSerial/TimeValue/Year/Month/Day/Hour/Minute/Second/Weekday | ByVal String/Double/Long + Optional |
| 杂项 | RGB/QBColor/Tab/Spc/CreateObject/GetObject/LoadPicture/AscW/ChrW/AscB/ChrB/StrConv | 各按 RTL 签名 |

### Part 2: 五个内置函数保持 `addBuiltinFunc`（避免与 cgen callee-rewrite 冲突）

⚠️ **关键陷阱**：cgen_expr.cpp 有四个 calle-rewrite 特殊分支会改写 callee 函数名或参数：

1. **CStr**（cgen_expr.cpp:3383-3425）：根据 arg 类型把 callee 改写为 `vb6_CStrLong`(int32_t) / `vb6_CStrDbl`(double) / `vb6_CStrBool`(int16_t) / `vb6_CStrDate`(double)。
2. **CInt/CLng/CDbl**（cgen_expr.cpp:3428-3444）：已知 Variant 变量时改写 callee 为 `vb6_CIntV`/`vb6_CLngV`/`vb6_CDblV`（均接受 `vb6_VARIANT` 参数，见 vb6rtl.h:372-374）。
3. **Format**（cgen_expr.cpp:3487-3507）：按 `inferExprType` 把 args[0] 包装为 `vb6_VariantLong`(int32_t) / `vb6_VariantDouble`(double) / `vb6_VariantString`(BSTR) / `vb6_VariantInt`(int16_t)。

这三个特殊分支都在 Fix 024 P2/Fix 029 wrapping **之后**运行。如果给这 5 个函数注册 calleeParams，会发生**双重包装冲突**：

| 函数 | calleeParams | Fix 024 P2/Fix 029 行为 | cgen 特殊分支行为 | 结果 |
| --- | --- | --- | --- | --- |
| CStr | ByVal Variant | 包装 `vb6_VariantFromValue(arg)` → VARIANT | 改 callee 为 `vb6_CStrLong`(int32_t) | VARIANT 传给 int32_t → **C2440** |
| CLng | ByVal Double | Variant arg → `vb6_VariantToDouble(arg)` → double | 改 callee 为 `vb6_CLngV`(VARIANT) | double 传给 VARIANT → **C2440** |
| Format | ByVal Variant | 包装 `vb6_VariantFromValue(arg)` → VARIANT | 包装 `vb6_VariantLong(VARIANT)` | VARIANT 传给 int32_t → **C2440** |

修复方案：维持 `addBuiltinFunc`（无 calleeParams）让特殊分支独立工作。一次中转尝试后发现 C2440 +7（1247→1254，**regression**），定位为这 5 个函数双重包装冲突，回退后 C2440 净 -3。

### Part 3: InStr 双形态保留 `addBuiltinFunc`

`InStr(s1, s2)` (2 args) vs `InStr(start, s1, s2)` (3 args) 是 VB6 双形态语法。cgen_expr.cpp:3143 已硬编码把 2-arg 改写为 `1, s1, s2`。

若给 InStr 注册 calleeParams `{start:Long, s1:String, s2:String}`，2-arg 形态的 s1 会被 fix 029 按 `start:Long` 参数处理（错位），导致额外错误。保持 InStr 为 `addBuiltinFunc`，沿用 cgen 硬编码改写策略。

### Part 4: 内置函数的 Optional 参数硬编码 padding（cgen_expr.cpp）

cgen_expr.cpp:3291 的一般 padding 有 `!calleeIsBuiltin` guard，跳过内置函数。这意味着改为 `addBuiltinFuncWithParams` 的内置函数即使有 Optional 参数也不会自动 padding。

新增硬编码 padding 块（cgen_expr.cpp:3290-3316）：

```cpp
// InStrRev(s1, s2[, start[, compare]]) — RTL vb6_InStrRev(BSTR, BSTR, int32_t, int32_t)
if (callee == "vb6_InStrRev") {
    if (args.size() == 2) { argList += ", -1"; args.push_back("-1"); }
    if (args.size() == 3) { argList += ", 0";  args.push_back("0"); }
}
// Round(x[, decimals]) — RTL vb6_Round(double, int32_t)
if (callee == "vb6_Rnd" && args.empty())     { argList = "0";  args.push_back("0"); }
if (callee == "vb6_Randomize" && args.empty()){ argList = "0.0"; args.push_back("0.0"); }
// StrComp(s1, s2[, compare]) — RTL vb6_StrComp(BSTR, BSTR, int32_t)
if (callee == "vb6_StrComp" && args.size() == 2) { argList += ", 0"; args.push_back("0"); }
// Shell(path[, windowstyle]) — RTL vb6_Shell(BSTR, int32_t), 默认 vbHide=0/vbNormalFocus=1
if (callee == "vb6_Shell" && args.size() == 1)   { argList += ", 2"; args.push_back("2"); }
```

cgen_stmt.cpp:2275-2278 也新增 Randomize 裸调用（Sub bare-call）默认 seed=0.0 padding。

### C2198 主收益 (-13)

C2198 "parameter not enough" 从 187 降至 174（-13），主要来自内置函数 Optional 参数的硬编码 padding：
- InStrRev/Round/StrComp/Rnd/Randomize 等的 Optional 参数现在被正确填充默认值。

### C2440 净改进 (-3)

中转版 C2440 +7（regression）来自 CStr/CInt/CLng/CDbl/Format 双重包装冲突。回退这 5 个函数后 C2440 净 -3（基线 1247 → 最终 1244），说明：
- CSng/CBool/CDate/CByte/CCur/CDec/CVErr/Hex/Oct + 数值函数/类型检查/日期函数等正确注册 calleeParams 后，Fix 024 P2/Fix 029 包装成功消除了部分基线 C2440。
- 整体来看，注册 calleeParams 的收益（约 -10）超过 5 函数回退带来的损失（约 -7）。

### C2197 微增 (+2)

C2197 +2 可能来自参数签名修正后，部分此前被错误签名为长参数列表的调用现在反映真实参数数（更少），少量场景从 "too many" 翻转为 "too few"。规模很小，不影响整体收益。

## 设计经验：callee-rewrite 与 calleeParams wrapping 的冲突

本次修复的核心教训：**当 cgen 对某个内置函数有 callee-rewrite 特殊分支时（改写 callee 名或重写 args[i]），不能给它注册 calleeParams** —— 否则 Fix 024 P2/Fix 029 的 wrapping 会先改变 arg 的 C 类型，与下游 callee-rewrite 期望的原始类型不匹配 → C2440。

未来若要为这类函数补充类型转换能力，应直接在 cgen callee-rewrite 特殊分支内部完成类型选择（如 CStr 已做），不要走 calleeParams 通道。
