# Fix 010: C 代码生成修复（vbman 完整编译）

## 背景

Fix 009 之后，C3 已经能成功调用 MSVC 编译器并生成 126 个 .c 源文件，但 MSVC 报出 13000+
行 C 代码生成错误。Fix 010 是 C3 编译 vbman 项目（125 个源文件的 ActiveX DLL）过程中的
C 代码生成器（cgen）全面修复，目标是将错误数从 13000+ 降到 0。

> 本 c3log 为阶段性记录：截至 `010r-12c`，错误数已从 13000+ 降到 4064。后续仍在
> 持续修复（将在下一轮 c3log 中追加）。

## 错误趋势

- 初始（Fix 009 后开始 Fix 010 时）：13000+
- 010a–010r-11 完成后：约 4673（早期未被精确统计）
- 010r-12a 完成后：4512（基准线）
- 010r-12b 完成后：4312
- **010r-12c 完成后：4064** ✅ 当前
- C2039（类成员访问错误）：207 → 127 → 118 → 120（010r-12c 有微小回退，源自
  With-block 类型系统变更引发的级联）
- C2079（UDT 未定义值成员）：129 → 0（完全清除）

## 修复内容

> Fix 010 包含约 30 个子修复（010a ~ 010r-12c），按主题分组如下。

### 主题 1：类型映射与 Windows API 互操作

- **010a — Any → void\***：VB6 `As Any` 参数映射为 C `void*`，避免类型不兼容。
- **010f — LongPtr/Vb\*/OLE_\* 类型映射**：
  - `LongPtr` → `int32_t`（C3 目标平台不支持 64 位 LongPtr）
  - `VbMsgBoxStyle` 等内置枚举别名映射为 `int32_t`
  - `OLE_COLOR`、`OLE_HANDLE` 等 COM 别名映射为基础类型
- **010b — Windows API 重定义保护**：在生成的 .c 中对 Windows API 函数加 `#ifndef` 守卫，
  避免与 `<windows.h>` 中同名声明冲突。
- **010r-2 — 枚举常量默认值**：未初始化的枚举成员默认值为 `0`（VB6 语义）。
- **010r-3 — VB6 内置常量**：补充约 50 个 VB6 标准常量（vbOKOnly/vbCrLf/vbCrLf 等）。
- **010r-4 — vbEmpty 去重**：vbEmpty 在 vb6_types.h 中已定义，移除 cgen 中的重复定义。

### 主题 2：跨模块符号与枚举/UDT 解析

- **010c — 枚举/UDT 跨模块解析**：消费模块在引用其他模块的枚举常量或 UDT 类型时，
  能正确从 cross-module 符号表中找到。
- **010d — #ifndef 守卫**：每个生成的 .h 文件加 `#ifndef VB6_MODNAME_H` 包裹，
  防止循环 include 重定义。
- **010e — 枚举常量折叠**：尝试用 `tryEvalConstInt()` 在生成阶段把枚举常量折叠为字面值，
  用于数组维度等需要编译期常量的场景。
- **010r-7 — UDT 类型名前缀**：所有 UDT 在 C 中统一为 `vb6_type_<UDTName>` 前缀，
  避免与类名冲突。
- **010r-6 — 类成员数组类型**：类结构体中的数组成员使用 `vb6_SafeArray1D*` 指针形式。

### 主题 3：错误处理与内置函数

- **010g — Err.LastDllError**：直接调用 `GetLastError()`，不经过 `Err` 对象。
- **010i — UDT 数组维度常量折叠**：`Dim a(1 To N) As UDT` 中 N 用
  `tryEvalConstInt()` 在生成阶段折叠，避免 MSVC 抱怨 "constant expression expected"。
- **010j — Err.Raise → vb6_ErrRaise**：自动插入 `vb6_ErrRaise` 运行时调用。
- **010r-1 — vb6_ErrRaise 名称冲突**：`ErrRaise` 名字与 `<winerror.h>` 中的宏冲突，
  重命名为 `vb6_ErrRaiseCall`（公共 API 仍为 `vb6_ErrRaise`）。
- **010r-8 — Err.Raise 参数填充**：可选参数填充为默认值（0/空串/Nothing）。
- **010r-9 — 内置函数可选参数填充**：Left/Mid/Right 等内置函数的可选参数填充默认值。
- **010r-3a — 零参内置函数**：rnd/erl/doevents 等无参内置函数作为裸值引用。

### 主题 4：类成员访问与 `me->` 前缀

- **010k — trackOnly_ 标志**：纯扫描模式（不发射代码）下 `trackOnly_=true`，用于
  在声明收集阶段不重复发出代码。
- **010l — IdentifierExpr 中的 PropertyGet**：在表达式上下文识别 Property Get 调用，
  发出 `vb6_cX_prop_get_Y(obj, ...)`。
- **010m — CallStmt 的 me-> 前缀**：在 CallStmt 中识别类成员调用并加 `me->` 前缀
  （实际类方法生成 `vb6_cls_cX_Y(me, ...)` 形式）。
- **010n — With-block 分类**：识别 With 块的目标对象类型（类实例 / COM / UDT）以
  选择正确的成员访问语法。
- **010o — classUdtMembers_ 持久化**：UDT 类成员信息在整个模块范围内持续累积，
  不随过程清理。
- **010p — SubDecl 签名重建**：在生成过程签名时使用解析阶段保存的原始声明信息，
  避免被跨模块符号注入污染。
- **010q — knownLocalVars_ 修复 me-> 前缀**：在 `visit(IdentifierExpr)` 中检查
  `knownLocalVars_`，避免把局部变量误识别为类成员加 me-> 前缀。
- **010r — With-block 拆括号修复**：With 块内 `Call Obj.Method(a,b)` 的参数列表
  括号被错误地拆分到调用语法中，导致生成的 C 语法错误。

### 主题 5：字符串、表单与运行时辅助

- **010h — Form 句柄变量移到 .c**：Form 的 `vb6_hwnd_*` 全局变量原本在 .h 中，
  会引发跨模块循环依赖，移到 .c 中并加 `extern` 声明。
- **010r-5 — 字符串字面量拼接**：VB6 `&` 拼接生成正确的 C 表达式（BSTR 拼接 +
  正确的内存释放顺序）。

### 主题 6：数组参数与跨模块类实例

- **010r-10 — Erase/ReDim 的 me-> 前缀**：通过 `classMemberVars_` 集合判断
  Erase/ReDim 目标是否为类成员，正确生成 `me->` 前缀。
- **010r-11 — 数组参数注册 + 跨模块类实例变量**（关键大改）：
  - 新增 `knownArrays_` 集合跟踪数组名
  - `makeParamList()` 生成 `vb6_SafeArray1D*` 形参类型
  - ByRef 数组参数自动解引用 `(*arr)` 形式
  - 局部数组也加入 `knownLocalVars_`
  - `me` 加入 `knownClassVars_`（指向当前类自身）
  - 新增 `zeroArgBuiltinFuncs`（Rnd/Erl/DoEvents 等）
  - **`knownClassVars_` 从 `unordered_set<string>` 改为
    `unordered_map<string, string>`**（变量名 → 类名），支持完整类信息查询
  - **`Symbol` 结构体添加 `variableTypeName` 字段**：在 `registerVariable()` 中
    设置变量类型名；在 `runCrossModuleResolution()` 中复制到外部符号
  - 在 `cgen_base.cpp::generate()` 中扫描当前模块的 `moduleScope()` 符号，
    把类实例变量自动注册到 `knownClassVars_`，解决跨模块 `obj.Method()` 调用

### 主题 7：C2079 / Property Let / 局部变量遮蔽（最新三组关键修复）

#### 010r-12a — UDT include 策略修复（C2079: 129 → 0）

**问题**：`vbman/src/Socket/cTlsSocket.cls` 第 426 行有
`Private m_uCtx As UcsTlsContext`，作为类结构体的 UDT **值成员**（非指针）。
`UcsTlsContext` 在 `mdTlsThunks.bas` 第 467 行定义为 `Public Type UcsTlsContext`。
原 include 策略把标准模块之间的 #include 放到 .c 文件（避免 .h 循环依赖），
导致 `cTlsSocket.h` 只有 UDT 前向声明而看不到完整定义，
引发 129 个 `C2079: "m_uCtx" uses undefined struct` 错误。

**根因**：UDT 不引用类类型（只含基本类型/其他 UDT/指针），可安全地在
跨模块 #include 之前输出。

**修复**（`src/backend/cgen_base.cpp`）：
1. 把 Enum 定义和 Type(UDT) 定义移到跨模块 `#include` 指令**之前**输出
2. include 策略调整：
   - 类模块引用任何模块（类或标准）→ .h（类结构体需要完整 UDT/类类型定义）
   - 标准模块引用类模块 → .h（函数参数需要完整类类型）
   - 标准模块引用标准模块 → .c（避免 .h 循环依赖）

**结果**：4512 → 4400 (-112)；C2079：129 → 0（完全消除！）。

#### 010r-12b — Property Let/Set 跨模块解析（Pattern G 完全修复）

**问题**：VB6 `obj.Property = value` 应生成 `vb6_cX_prop_set_Property(obj, value)`
或 `vb6_cX_prop_let_Property(obj, value)`，但错误地生成
`vb6_cX_prop_get_Property(obj) = value`（Property Get 当左值），引发 C2106。

**根因**：`driver.cpp::runCrossModuleResolution()` 中
`globalPublicSyms` 以 `lowerName` 为 key，而 Property Get/Let/Set 共用 name 但
`storageKey()` 不同（`$pg`/`$pl`/`$ps`），所以只有第一个变体（通常是 Property Get）
被注册为外部符号。Consumer 模块的 `lookupModuleByKind(name, PropertyLet)` 失败，
导致 `AssignmentStmt` 中的 P6.7 Property Let 分发不触发，落到
`emitExpr(target) = value` 的通用兜底路径。

**修复**（`src/driver/driver.cpp`）：
1. `globalPublicSyms` 的 key 从 `lowerName` 改为 `sym->storageKey()`，让所有
   Property 变体分别保留
2. 注入循环：Property 符号用 `lookupModuleByKind(name, kind)` 逐变体检查；
   非 Property 符号用 `lookupModule(name)`

**结果**：4400 → 4312 (-88)。
- Pattern G（COM 属性带下标赋值）：12 → 0（完全修复）
- Pattern F（COM 字符串属性赋值）：17 → 3（大部分修复）
- Pattern D（类属性简写）：19 → 13（部分修复）
- **但** Pattern H（局部变量遮蔽跨模块符号）：12 → 41 (+29，回退)

#### 010r-12c — 局部变量遮蔽跨模块外部符号（Pattern H 完全修复）

**问题**：010r-12b 后，所有 Property 变体（Get/Let/Set）都作为外部符号注入到模块
作用域。Codegen 时 `symTab_.lookup(node.name)` 优先找到这些外部 Property 符号。
本地 `Dim` 变量同名时（例如 `cFormater.cls` 第 763 行 `Dim Pos As Long`）被
错误地解析为跨模块 Property 符号（`vb6_cToast_Pos`），而不是局部变量。

**根因（两部分）**：
1. `cgen_expr.cpp::visit(IdentifierExpr)` 在跳到外部符号解析前，没有先检查
   `knownLocalVars_`。`knownLocalVars_` 检查只存在于 `me->` 前缀路径。
2. **关键**：`cgen_stmt.cpp::visit(LocalDeclStmt)` 只在数组和动态数组 case 中
   调用 `knownLocalVars_.insert()`。非数组局部 `Dim`（如 `Dim Pos As Long`）
   从未注册到 `knownLocalVars_`，所以遮蔽检查根本无法触发。

**修复**：
1. `cgen_expr.cpp`（ByRef 参数检查之后）：新增早退检查——
   `if (knownLocalVars_.count(lower) && (!foundSym || foundSym->isExternal))`
   则直接发出局部变量名
2. `cgen_stmt.cpp::visit(LocalDeclStmt)` 在存储类确定前，对所有非数组局部
   `Dim` 变量调用 `knownLocalVars_.insert(lower)`（覆盖类类型 / UDT / Enum /
   BSTR / Long / Double / Variant / Object / 固定字符串等所有类型）
3. `visit(LocalDeclStmt)` ConstDecl case 也有类似 `knownLocalVars_.insert()`

**结果**：4312 → 4064 (-248)。C2106：203 → 166 (-37)。
- Pattern H（局部变量遮蔽）：41 → 0（完全修复！）
