# Fix 017: 跨模块枚举常量 + VB6 内置常量发出裸标识符 (C2065)

## 背景

Fix 016 (commit `958a2bb`) 后, vbman 编译总错误 3873, 其中 C2065 (未声明的标识符) 759 个,
是仅次于 C2440 (1716) 的第二大错误类别. 逐类排查 C2065 标识符发现两个独立根因:

1. **跨模块 EnumMember 外部符号丢失常量值** — 用户定义的 `Public Enum` 成员
   (如 `HASH_ALG_SHA256`、`ucsSfdRead`、`WS_STATE_CLOSED`) 在定义模块内能正确发出数值,
   但跨模块引用时发出裸标识符, C 代码中无对应 `#define` → C2065.
2. **VB6 内置常量 (`vbMethod`、`vbDirectory`) 发裸名** — 这些常量在 C3 内部注册为
   `SymbolKind::Constant` + `hasConstValue=true`, 但 cgen 的 Constant 分支对所有 Constant
   一律发出裸 `cName`, C 代码中无 `#define vbMethod 2` → C2065.

本修复 (P1 + P3) 解决上述两类. COM 类型库枚举 (`TextCompare`、`adStateClosed` 等, 来源
Scripting Runtime / ADO msado28.tlb) 的解析缺失 (P2) 难度较高且属独立子系统, 拆为 Fix 018.

## 问题

### 现象

**Fix 017 前 C2065 主要标识符分布** (来自 `_c3_msvc_out.txt`, 共 759 个 C2065):

| 标识符 | 次数 | 来源 | 根因 |
|--------|------|------|------|
| `TextCompare` | 32 | Scripting.Runtime COM 类型库 | P2 (未修) |
| `VbMethod` / `vbMethod` | 13 | C3 内置常量 (vbMethod=2) | **P3** |
| `HASH_ALG_SHA256` | 13 | vbman `Public Enum CryptoHashAlgorithm` | **P1** |
| `ucsSfdRead` | 12 | vbman `Public Enum UcsAsyncSocketEventMaskEnum` | **P1** |
| `ucsSfdWrite` | 11 | 同上 | **P1** |
| `WS_STATE_CLOSED` | 9 | vbman `Public Enum WsState` | **P1** |
| `ucsSfdConnect` | 8 | 同 ucsSfdRead | **P1** |
| `vbDirectory` | 7 | C3 内置常量 (vbDirectory=16) | **P3** |
| `WS_STATE_OPEN` | 6 | 同 WS_STATE_CLOSED | **P1** |
| `HASH_ALG_MD5` | 6 | 同 HASH_ALG_SHA256 | **P1** |
| `adStateClosed` | 7 | ADO msado28.tlb COM 类型库 | P2 (未修) |
| `adLockReadOnly` | 6 | 同上 | P2 (未修) |

P1 + P3 合计覆盖约 92 个 C2065 (13+13+12+11+9+8+7+6+6+6+1). 其余 C2065 来自 P2 (COM 枚举
~51 个) 和其它零散标识符 (未声明函数名、Variant 运行时分发等).

### 误判影响范围

- **P1 (跨模块 EnumMember)**: 任何在 A 模块定义 `Public Enum`、在 B 模块引用其成员名的场景.
  vbman 中典型: `cCryptoHash.cls` 定义 `Public Enum CryptoHashAlgorithm`, 在 `cCryptoHMAC.cls`、
  `Demo.bas` 等模块引用 `HASH_ALG_SHA256` / `HASH_ALG_MD5` → C2065.
- **P3 (VB6 内置常量)**: 任何使用 `vbMethod` (Dir/Open 选项)、`vbDirectory` (Dir 第二参数) 的
  模块. vbman 中典型: `ToolsStr.bas` `Dir(path, vbDirectory)`, 多处 `CallByName(..., vbMethod)`.
- 本修复**不**改变 C 代码中枚举值的求值正确性 — 仅确保发出数值而非裸名. 部分枚举值
  (如 `ucsSfdRead = 2 ^ 0`) 在 `EnumDecl` 处理器中未求值 (用自增值), 此为独立遗留问题,
  见"下一步".

## 根因分析

### 路径 P1: 外部符号注入丢失常量值

`driver.cpp` `injectExternalSymbols()` (约 1083-1143 行) 为每个模块构建外部符号集合
(从 `globalPublicSyms` 取所有公共符号, 注入到当前模块符号表). 构造外部符号时:

```cpp
// 旧代码 (Fix 017 前)
auto extSym = std::make_unique<Symbol>(
    srcSym->kind, srcSym->name, srcSym->type,
    srcSym->location, srcSym->access
);
extSym->isExternal = true;
extSym->sourceModule = moduleBaseNames[srcIdx];
extSym->params = srcSym->params;
extSym->isArray = srcSym->isArray;
// ... Class / Variable 特定字段复制 ...
extSym->variableTypeName = srcSym->variableTypeName;  // Fix 015
// ❌ 未复制 hasConstValue / constIntValue / constType
```

`Symbol` 构造函数只初始化 `kind/name/type/location/access`, `hasConstValue` 默认 `false`.
因此跨模块注入的 `EnumMember` 外部符号 (以及任何带常量值的 `Constant` 外部符号) 的
`hasConstValue=false`.

cgen_expr.cpp `visit(IdentifierExpr)` 的 `EnumMember` 分支 (336-344 行):

```cpp
if (foundSym && foundSym->kind == SymbolKind::EnumMember) {
    if (foundSym->hasConstValue) {
        lastExpr_ = std::to_string(foundSym->constIntValue);
    } else {
        lastExpr_ = cName;   // ← 裸标识符, 触发 C2065
    }
    return;
}
```

定义模块内: 原始 EnumMember 符号 `hasConstValue=true` → 发出数值. 跨模块: 外部副本
`hasConstValue=false` → 发出裸名 `HASH_ALG_SHA256` → C2065.

### 路径 P3: Constant 分支未使用常量值

cgen_expr.cpp `visit(IdentifierExpr)` 第 357-438 行处理 `SymbolKind::Variable` 和
`SymbolKind::Constant`. 该分支开头有一个 `Dim As New` / 内置 Object 默认属性等分支,
然后通过 `lastExpr_ = cName` 兜底 (436 行附近):

```cpp
// 旧代码 (Fix 017 前)
if (foundSym && (foundSym->kind == SymbolKind::Variable
              || foundSym->kind == SymbolKind::Constant)) {
    // ... isBuiltin Object / 类模块 me-> / Dim As New 等分支 ...
    // 兜底:
    lastExpr_ = cName;   // ← 对 Constant 也走这里, 发出裸名
}
```

VB6 内置常量在 `semantic_analyzer.cpp` `registerBuiltins()` 注册为
`SymbolKind::Constant` + `hasConstValue=true` + `constIntValue=N`:

```cpp
// semantic_analyzer.cpp (~2018, ~1762)
addConst("vbMethod", Vb6Type::Long, 2);
addConst("vbDirectory", Vb6Type::Long, 16);
```

但 cgen 不查 `hasConstValue`, 直接发 `vbMethod` / `vbDirectory` 裸名. C 运行时头文件
(如 `vb6_runtime.h`) 没有这些 `#define` → C2065.

### 为什么 EnumMember 走 P1 而 Constant 走 P3

两个分支在 cgen_expr.cpp 中是独立的:
- `EnumMember` 分支 (336-344) 已正确用 `hasConstValue` 判断数值/裸名 (Fix 016 前已存在),
  但外部副本丢值 → P1.
- `Constant` 分支 (357+) 从未查 `hasConstValue` → P3 (对所有 Constant, 不区分本地/外部).

P1 修复后跨模块 EnumMember 走 `std::to_string(constIntValue)` (对 EnumMember 分支生效).
P3 修复后内置 Constant 走 `std::to_string(constIntValue)` (对 Constant 分支生效).
两者互补, 共同确保所有带 `hasConstValue` 的符号发出数值.

## 修复

### Fix 017-P1: 外部符号注入复制常量值字段

**driver.cpp** (~1131-1137, 注入循环内, 在 `variableTypeName` 复制之后):

```cpp
// Fix 017: 复制常量值 (EnumMember / Constant 跨模块注入后需保留值).
// 外部 EnumMember 若 hasConstValue=false, cgen 会发出裸标识符 (如
// HASH_ALG_SHA256) 而非数值 → C2065. 此前外部符号构造只复制
// kind/name/type/location/access, 丢失 hasConstValue/constIntValue.
extSym->hasConstValue = srcSym->hasConstValue;
extSym->constIntValue = srcSym->constIntValue;
extSym->constType = srcSym->constType;
```

该复制对所有 kind 的外部符号生效 (无条件). 对非常量符号 (`hasConstValue=false`)
复制 `false`/`0`/`Empty`, 无副作用. 对 `Constant` / `EnumMember` 跨模块引用, 保留
定义模块中求出的常量值.

### Fix 017-P3: Constant 分支对 hasConstValue=true 直接输出数值

**cgen_expr.cpp** (~359-366, Constant/Variable 分支开头, 在所有其它子分支之前):

```cpp
if (foundSym && (foundSym->kind == SymbolKind::Variable
              || foundSym->kind == SymbolKind::Constant)) {
    // Fix 017: 数值常量 (内置 vbMethod=2/vbDirectory=16, 或用户 Public Const,
    // 或跨模块注入的 EnumMember-as-Constant) 直接输出数值, 避免发出裸标识符
    // (C 代码中无对应 #define → C2065). hasConstValue 仅对整型常量为 true,
    // 字符串常量等不受影响.
    if (foundSym->kind == SymbolKind::Constant && foundSym->hasConstValue) {
        lastExpr_ = std::to_string(foundSym->constIntValue);
        return;
    }
    // ... 原有 isBuiltin Object / me-> / Dim As New / 兜底 cName 分支不变 ...
}
```

提前 `return` 跳过 `Variable` 相关分支 (因为限定 `kind == Constant`), 不影响 `Variable`
的处理. 字符串常量 (`hasConstValue=false`, 走 `cName` 兜底) 不受影响 — 它们的值通过
`#define` 或全局变量在 cgen_decl.cpp 中发出, 不在此处理.

### 残留 C2065 (516 个)

- **P2 (COM 类型库枚举, ~51 个)**: `TextCompare`(32)、`adStateClosed`(7)、`adLockReadOnly`(6)、
  `adOpenStatic` 等. 根因: `typelib_parser.cpp` `parseTypeLib()` TYPEKIND switch 无
  `case TKIND_ENUM`, COM 枚举从未被解析; `TypeLibResult` 也无 enums 容器. → 留给 Fix 018.
- **枚举值求值限制**: 部分非字面量枚举值 (`2 ^ 0` BinaryExpr、引用 Private Const 的
  `IdentifierExpr`) 在 `EnumDecl` 处理器 (semantic_analyzer.cpp:860-877) 中未正确求值,
  使用自增值. P1 修复后这些标识符不再 C2065 (发出数值而非裸名), 但数值可能不正确.
  独立遗留问题, 不阻塞编译.
- **其余 C2065**: 零散未声明函数名 (VB6 库函数未在 C3 内置表注册)、Variant 运行时分发
  产生的临时名等.

## 注意

- 此修复改变编译错误计数: 总错误 3873 → 3716 (-157), C2065 759 → 516 (-243).
- C2440 / C2198 表面上升 (+67) 是 C1003 限制解除的副作用, 非回归.
- P1 对**所有**外部符号复制常量值字段 (非仅 EnumMember), 顺带修复了跨模块 `Public Const`
  的同类潜在问题 (虽 vbman 中 Public Const 较少跨模块引用).
- P3 限定 `kind == Constant`, 不影响 `Variable` 分支.
