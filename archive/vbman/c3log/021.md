# Fix 021 — BSTR 字符串字面量 \xHHHH 转义超出范围 (C7744)

**修复编号**: 021
**提交**: pending
**日期**: 2026-07-19
**类型**: CJK/CJK 字符串生成 bug 修复

## 现象

Fix 020 后 49 处 `C7744: 转义序列超出范围`, 集中在含 CJK 字符的 VB6 字符串字面量, 例:

```
Demo.c(576): error C7744: 转义序列"\x7B2C1"超出范围
Demo.c(582): error C7744: 转义序列"\x5BB91"超出范围
cAliyunCaptcha.c(412): error C7744: 转义序列"\xFF1ACa"超出范围
Demo_Database.c(96): error C7744: 转义序列"\x8BD50"超出范围
```

## 调查

观察 `\x7B2C1` 的特点:
- `0x7B2C` 是 CJK 字符 `第` 的 Unicode 码点
- 紧跟 `1` 是 VB6 字符串中的字面字符

C 标准定义 `\x` 为 **十六进制 escape**, 会**贪婪消费所有后续十六进制数字** (`0-9 A-F a-f`) 而无长度限制, 值需装入目标字符类型. Windows `wchar_t` 为 16 位, 最大 `0xFFFF`.

所以 C3 生成的 `L"\x7B2C1..."` 被 MSVC 解析为单个 hex escape `0x7B2C1` (5 位 hex = 501,057) → 超出 `wchar_t` 范围 → C7744.

定位 C3 发出位置: `src/backend/cgen_expr.cpp:108-122` (BSTR 字面量转义) 和 `src/backend/cgen_form.cpp:2108-2122` (`escapeWideCString`, 用于菜单/窗体 caption). 两处代码相同, 都用 `snprintf(hex, ..., "\\x%04X", cp)` 输出.

### 附带 bug: 4-byte UTF-8 lead byte 掩码错误

```cpp
else if ((ch & 0xF8) == 0xF8) { cp = ch & 0x07; bytes = 4; }
```

`0xF8` 掩码匹配 `11111xxx` (0xF8-0xFF), **但这些是非法 UTF-8 字节**. 应该匹配 `11110xxx` (0xF0-0xF7, 4-byte UTF-8 lead byte), 即 `(ch & 0xF8) == 0xF0`.

后果: 4-byte UTF-8 (emoji 等 supplementary plane 字符) 不进 4-byte 分支, 落入 else 的 `cp = ch; bytes = 1;` 回退, 生成错误的低 code point. VB6 源码罕见此类字符, bug 长期休眠.

## 修复方案

### 1. 改 `\x%04X` 为 `\u%04X`

C99/C11 `\u` universal character escape **恰好消费 4 位十六进制**, 后续字符无论是否十六进制都被视为独立字符. 这样 `L"\u7B2C1\u6761"` 正确解析为 CJK `第` + ASCII `1` + CJK `条`.

**`\u` 的有效范围**: 必须 ≥ 0xA0 (除 `$` `@` `` ` ``). 对 C3 来说本分支只对 `ch >= 0x80` 调用, 实际多数为 CJK / 拉丁扩展 (≥ 0xA0). C1 控制字符 (0x80-0x9F) 罕见于 VB6 源码.

### 2. 补充 plane 处理 (codepoint > 0xFFFF)

Windows `wchar_t` 16 位, 单个 `\u` 无法表达 > 0xFFFF 的码点 (emoji 等). 拆为 UTF-16 surrogate pair:

```cpp
if (cp <= 0xFFFF) {
    snprintf(hex, sizeof(hex), "\\u%04X", cp);
} else {
    uint32_t v = cp - 0x10000;
    uint16_t hi = 0xD800 + (v >> 10);
    uint16_t lo = 0xDC00 + (v & 0x3FF);
    snprintf(hex, sizeof(hex), "\\u%04X\\u%04X", hi, lo);
}
```

`hex` 缓冲区从 `8` 扩大为 `16` 字节 (surrogate pair 需 13 字节含 `\0`).

### 3. 修复 4-byte UTF-8 lead byte 掩码

```cpp
else if ((ch & 0xF8) == 0xF0) { cp = ch & 0x07; bytes = 4; }
//             ^^^                 ^^^ (0xF8 -> 0xF0)
```
