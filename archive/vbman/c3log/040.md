# Fix 040: C2172 Function Argument Not Pointer

**Date**: 2026-07-22
**Starting point**: After Fix 039b — 1923 tracked errors, C2172=66
**Final result**: 1718 tracked errors (-205), C2172=9 (-57)
**Also improved**: C2440 939→912 (-27), C2197 130→102 (-28), C2198 179→169 (-10)

## Root Cause

C2172 ("实参不是指针" / "function argument not pointer") occurs when a C function
expects a pointer parameter but receives a non-pointer value. Six distinct patterns
were identified:

| Pattern | Count | Function | Root Cause |
|---------|-------|----------|------------|
| A | 20 | `vb6_ToolsTlsThunks_SearchCollection` | `ByVal oCol As Collection` → resolveTypeRef returns Variant → vb6_VariantFromValue wraps void* → C2172 |
| B | 12 | `vb6_TypeOf` | Operand is `vb6_VARIANT` (TmpO) but function expects `void*` |
| C/F | 16 | `vb6_ForEach_Init` | Collection expression is `vb6_VARIANT` but function expects `void*` |
| D | 9 | `vb6_CallByName` | Variadic args passed directly; C signature expects `(void* args, int32_t argc)` |
| E | 4 | `vb6_VariantObject` | `vb6_VariantFromValue(udt)` → _Generic default → `vb6_VariantObject(void*)` but UDT is not a pointer |
| G/I | 6 | Various | `ByVal Certificates As Collection` → Variant → wrapped with vb6_VariantFromValue |
| H | 4 | `vb6_cTlsReMaster_pvSetError` | `Optional LastError As VBA.ErrObject` → Variant → wrapped |
| J | 2 | `vb6_di_CryptDecodeObjectEx` | Declare function param type mismatch |
| K | 2 | `vb6_di_SetCommState` | Declare function param type mismatch |
| L | 1 | `vb6_cDataBase_Conn_ExecuteComplete` | Event handler param: pConnection is vb6_VARIANT but function expects pointer |

## Fixes Applied

### Fix 040a: Builtin object type resolution (semantic_analyzer.cpp)

**Problem**: `resolveTypeRef()` returned `Vb6Type::Variant` for VB6 builtin object types
(Collection, ErrObject, etc.) when `resolveTypeName()` returned `Unknown`. This caused
ByVal Collection/ErrObject parameters to be treated as Variant, and the codegen wrapped
the `void*` argument with `vb6_VariantFromValue()`, producing a `vb6_VARIANT` struct
where the C function expected `void*`.

**Fix**: Added a `vb6BuiltinObjTypes` set check in `resolveTypeRef()` (mirroring the
same set in `cgen_base.cpp mapTypeRef()`). When the type name matches a builtin object
type (Collection, Forms, ErrObject, App, Screen, Printer, Clipboard), returns
`Vb6Type::Object` instead of falling through to Variant.

**VBA. prefix handling**: The VB6 source uses qualified names like `VBA.ErrObject`.
The initial implementation checked `simple.name` directly against the set, which didn't
match `VBA.ErrObject`. Fixed by stripping the `VBA.` prefix before checking (same logic
as `cgen_base.cpp mapTypeRef()` line 1010-1012).

**File**: `src/semantics/semantic_analyzer.cpp` ~line 550

**Impact**: Fixed patterns A (20), G (4), I (2), H (4) = ~30 errors. Also fixed
secondary C2440 errors from `&(vb6_VARIANT){void*}` compound literal pattern (-27 C2440).

### Fix 040b: TypeOf with Variant operand (cgen_expr.cpp)

**Problem**: `vb6_TypeOf(void* obj, const wchar_t* typeName)` expects `void*`
(IDispatch*). When the operand is a `vb6_VARIANT` struct (e.g., from a Variant
variable, `vb6_VariantArrayGet()`, or `VB6_SA_AT(vb6_VARIANT, ...)`), passing it
directly causes C2172.

**Fix**: In `visit(TypeOfExpr)`, added Variant detection for the operand:
1. `cExprIsVariant(obj)` — checks C string prefixes (vb6_VariantArrayGet, etc.)
2. `knownVariantVars_` — checks if the identifier is a known Variant variable
3. Added `VB6_SA_AT(vb6_VARIANT` pattern to `cExprIsVariant()` (cgen_util.cpp) —
   detects array element access that yields a vb6_VARIANT value

When detected, wraps with `vb6_VariantToObjectVal()` before passing to `vb6_TypeOf()`.

**Files**: `src/backend/cgen_expr.cpp` ~line 4135, `src/backend/cgen_util.cpp` ~line 903

**Impact**: Fixed pattern B (12 errors → 0).

### Fix 040c: ForEach_Init with Variant collection (cgen_stmt.cpp)

**Problem**: `vb6_ForEach_Init(void* disp)` expects `void*` (IDispatch*). When the
collection expression is a `vb6_VARIANT` (e.g., from a Variant variable or a project
function returning Variant), passing it directly causes C2172.

**Fix**: In `visit(ForEachStmt)`, added Variant detection for the collection expression:
1. `cExprIsVariant(collExpr)` — C string level
2. `knownVariantVars_` — identifier lookup
3. `isDefinitelyVariantExpr(*node.collection)` — AST-level fallback for project
   class methods returning Variant (e.g., `Dictionary.Keys`)

When detected, wraps with `vb6_VariantToObjectVal()` before passing to
`vb6_ForEach_Init()`.

**File**: `src/backend/cgen_stmt.cpp` ~line 1642

**Impact**: Fixed patterns C, F (16 errors → 2 remaining, which are project functions
where `isDefinitelyVariantExpr` didn't fire).

### Fix 040d: CallByName variadic args packing (cgen_expr.cpp + vb6rtl.c)

**Problem**: `vb6_CallByName(void* obj, const wchar_t* procName, int32_t callType,
void* args, int32_t argc)` has a fixed 5-parameter C signature. The codegen passed
variadic method arguments directly (e.g., `vb6_CallByName(obj, proc, 2, arg1, arg2, ...)`),
but the C function doesn't accept variadic args. Also, when no extra args were provided
(3 args), the C call was missing the `void* args, int32_t argc` parameters (C2198).

**Fix**:

1. **Runtime change** (`vb6rtl.c`): Modified `vb6_CallByName` to accept `VARIANT**`
   (array of pointers to VARIANTs) instead of contiguous `VARIANT[]` structs. This
   matches the convention used by `vb6_ComCall`. Each arg is a packed VARIANT pointer
   allocated by `vb6_ComPackBSTR/Int/Double/Object/Value`. Updated cleanup to free
   packed args (same pattern as `vb6_ComCall`).

2. **Codegen change** (`cgen_expr.cpp`): Added CallByName special case before the final
   `lastExpr_ = callee + "(" + argList + ")"` assembly:
   - When `args.size() == 3`: pads with `NULL, 0` (no extra method args)
   - When `args.size() > 3`: packs args[3+] into `(void*[]){vb6_ComPackValue(arg), ...}`
     with `argc = args.size() - 3`

**Files**: `src/backend/cgen_expr.cpp` ~line 4087, `src/rtl/core/vb6rtl.c` ~line 4138

**Impact**: Fixed pattern D (9 errors → 0). Also fixed C2198 for 3-arg CallByName calls
(-10 C2198). Also fixed C2197 for >3-arg CallByName calls (-28 C2197).
