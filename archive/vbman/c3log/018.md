# Fix 018: COM 类型库 TKIND_ENUM 解析 (TextCompare / adXXX 等 C2065 -66)

## 背景

Fix 017 (commit `90fb172`) 解决了"跨模块 EnumMember 丢失常量值"(P1) 和"VB6 内置常量发裸名"(P3),
将 C2065 从 759 降至 516. 当时明确推迟的 **P2** — COM 类型库枚举解析 — 是 Fix 017 后 C2065
剩余的最大单一类别: `TextCompare`(32)、`adStateClosed`(7)、`adLockReadOnly`(6) 等 ~51 个错误,
来自 VBMAN.vbp 引用的 Scripting Runtime (`scrrun.dll`) 与 ADO (`msado28.tlb`) 类型库.

VB6 语义: 引用 COM 类型库后, 其 `TKIND_ENUM` 类型的成员成为全局可见的命名常量. C3 此前
**从未解析 TKIND_ENUM** — `typelib_parser.cpp` 的 TYPEKIND switch 只处理 INTERFACE/DISPATCH/
COCLASS/MODULE, TKIND_ENUM 落入 `default` 分支被忽略. 因此 `TextCompare`、`adStateClosed`
等 COM 枚举成员在符号表中不存在, cgen 发出裸名 → C2065 (C 代码无对应 `#define`).

## 问题

### 现象

**Fix 017 后 C2065 的 COM 枚举成员分布** (516 个 C2065 中的 ~51 个):

| 标识符 | 次数 | 来源类型库 | 所属枚举 |
|--------|------|-----------|---------|
| `TextCompare` | 32 | scrrun.dll (Scripting Runtime) | CompareMethod |
| `adStateClosed` | 7 | msado28.tlb (ADO 2.8) | ObjectStateEnum |
| `adLockReadOnly` | 6 | msado28.tlb | LockTypeEnum |
| `adStateOpen` / `adOpenStatic` / `adUseClient` / `adCmdText` 等 | ~8 | msado28.tlb | 各 ADO 枚举 |

这些标识符在 VBMAN 源码中被作为裸名使用 (如 `dic.CompareMode = TextCompare`、
`rs.LockType = adLockReadOnly`), 但 C3 既未在符号表注册它们, 也没有对应的 `#define`,
故 cgen 发出的 C 代码中它们是未声明标识符 → MSVC C2065.

### 根因定位

1. **`typelib_parser.cpp` `parseTypeLib()` TYPEKIND switch (410-438 行) 无 `case TKIND_ENUM`**:
   ```cpp
   switch (typeKind) {
       case TKIND_INTERFACE:
       case TKIND_DISPATCH: { ... }
       case TKIND_COCLASS: { ... }
       case TKIND_MODULE: { ... }
       case TKIND_ALIAS:
       case TKIND_RECORD:
       default:
           break;   // ← TKIND_ENUM 落入此处, 被忽略
   }
   ```
   有趣的是 `mapTypeDesc()` (912 行) 已检查 `pRefAttr->typekind == TKIND_ENUM` 把枚举类型
   引用映射为 `Vb6Type::Long`, 但枚举**成员**从未被提取.

2. **`TypeLibResult` 结构体 (typelib_parser.hpp:130-180) 无 enums 容器**:
   只有 `interfaces`/`coclasses`/`modules` 三个 vector, 无处存放解析出的枚举.

3. **`driver.cpp` COM 符号注入 (805-994 行) 不注册枚举成员**:
   只注册 ComClass / ComInterface / ComModule / ComGlobalNs, 枚举成员即使被解析也无注入路径.

## 修复

### Fix 018a: TKIND_ENUM 解析 (typelib_parser.hpp + .cpp)

**typelib_parser.hpp** — 新增 `ComEnumMemberInfo` / `ComEnumInfo` 结构体, `TypeLibResult` 增加
`enums` vector, `TypeLibParser` 增加 `parseEnum()` 声明:

```cpp
struct ComEnumMemberInfo {
    std::string name;           // 成员名 (原始大小写, 如 "TextCompare")
    std::string lowerName;      // 小写 (查找用)
    int64_t value = 0;          // 枚举值 (来自 VARDESC.lpvarValue)
};
struct ComEnumInfo {
    std::string name;           // 枚举类型名 (如 "CompareMethod")
    std::string lowerName;
    std::vector<ComEnumMemberInfo> members;
};
// TypeLibResult 新增:
std::vector<std::unique_ptr<ComEnumInfo>> enums;   // Fix 018: TKIND_ENUM
```

**typelib_parser.cpp** — TYPEKIND switch 新增 `case TKIND_ENUM` (调用 `parseEnum`), 并实现
`parseEnum()`: 获取 `TYPEATTR.cVars`, 枚举每个 `VARDESC` (varkind==VAR_CONST), 通过
`GetDocumentation(memid)` 取成员名, 从 `lpvarValue` (VARIANT*) 提取值 (处理 VT_I4/I2/UI4/
BOOL 等). 同时更新 `parseTypeLib()` 返回值纳入 `!result.enums.empty()`.

枚举成员值提取 (核心逻辑):
```cpp
if (pVarDesc->varkind == VAR_CONST && pVarDesc->lpvarValue) {
    VARIANT* pVar = pVarDesc->lpvarValue;
    VARTYPE vt = pVar->vt & VT_TYPEMASK;
    switch (vt) {
        case VT_I4:   m.value = pVar->lVal; break;
        case VT_I2:   m.value = pVar->iVal; break;
        case VT_UI4:  m.value = (int64_t)pVar->ulVal; break;
        case VT_BOOL: m.value = (pVar->boolVal != 0) ? -1 : 0; break;  // VB6 True=-1
        // ... VT_I1/UI1/UI2 等
    }
}
```

### Fix 018b: driver.cpp 注册 COM 枚举成员 + 体积守卫

在 COM 符号注入的 `for (auto& tl : cachedResults())` 循环内 (紧随 interfaces 注册之后),
新增枚举成员注册:

```cpp
// Fix 018: 注册COM枚举成员为EnumMember符号 (TextCompare/adStateClosed 等)
size_t totalEnumMembers = 0;
for (auto& en : tl->enums) totalEnumMembers += en->members.size();
if (totalEnumMembers <= 1000) {        // ← 体积守卫
    for (auto& en : tl->enums) {
        for (auto& m : en->members) {
            auto enumSym = std::make_unique<Symbol>(
                SymbolKind::EnumMember, m.name, Vb6Type::Long, ...);
            enumSym->isBuiltin = true;
            enumSym->hasConstValue = true;
            enumSym->constIntValue = m.value;
            enumSym->constType = Vb6Type::Long;
            analyzer->symbolTable().define(std::move(enumSym));
        }
    }
}
```

`hasConstValue=true` 使 cgen 走 Fix 017-P1/P3 路径发出数值 (而非裸名), 消除 C2065.

**体积守卫 (totalEnumMembers <= 1000)**: VBMAN.vbp 引用了 `mshtml.tlb` (Microsoft HTML Object
Library) — 一个含数千个枚举成员的巨型类型库. 全量注册会导致:
- **内存膨胀**: 125 个模块 × N 成员 的 Symbol 对象 (每个 ~200 字节)
- **VB3002 重复声明**: MSHTML 内部多个枚举跨 enum 同名成员碰撞 (首次实测 2600 个 VB3002)

守卫跳过 MSHTML (数千成员 > 1000), 仅注册小型库 (Scripting ~30 成员, ADO ~200 成员, MSXML
~200, stdole 极少), 精准覆盖 TextCompare / adXXX 等已知 C2065.

### Fix 018c: symbol_table.cpp 允许 builtin EnumMember 跳过 + 用户 EnumMember 覆盖 builtin

Fix 018b 首次实测触发两类 VB3002 (共 2600+26 个), C3 在语义阶段中止, 无法到达 codegen:

**问题 1 (2600 个 VB3002)**: MSHTML 跨 enum 同名成员. 即使体积守卫跳过 MSHTML, 小型库
(如 ADO) 内部也可能有少量跨 enum 同名. `SymbolTable::define()` 的"builtin COM 类型跳过"
逻辑 (118-125 行) 只覆盖 ComClass/ComInterface/ComModule/ComGlobalNs, **不含 EnumMember**,
导致 builtin EnumMember 重复 define 时走错误路径 (158 行 VB3002).

**修复**: 118-125 行条件新增 `|| sym->kind == SymbolKind::EnumMember` — builtin EnumMember
遇同名 existing 时 first-wins 静默跳过 (不报错).

**问题 2 (26 个 VB3002)**: `cDatabase.cls` (128-153 行) 自定义 `Public Enum` 含 `adEmpty` /
`adTinyInt` / `adInteger` ... 等 26 个成员, 与 ADO `DataTypeEnum` 的同名成员冲突. COM 注入
先注册 builtin `adEmpty`, 用户随后声明 `adEmpty` 应覆盖之, 但"用户覆盖 builtin"逻辑
(138-151 行) 只允许 Sub/Function/Variable/Constant 覆盖, **不含 EnumMember** → VB3002.

**修复**: 138-151 行条件新增 `|| sym->kind == SymbolKind::EnumMember` — 用户 EnumMember 可
覆盖 builtin COM 枚举成员 (符合 VB6 "项目声明优先于引用类型库" 语义).

## 注意

- 此修复改变编译错误计数: 总 3716 → 3622 (-94), C2065 516 → 450 (-66), VB3002 始终为 0.
- **体积守卫是必要的妥协**: MSHTML (mshtml.tlb) 含数千枚举成员, 全量注册会内存膨胀 +
  VB3002 爆炸. 守卫阈值 1000 覆盖 Scripting/ADO/MSXML/small, 跳过 MSHTML. 若后续发现
  VBMAN 使用了 MSHTML 枚举成员作为裸名 (当前未见), 可改用 "全局 COM 枚举查找表 + 标识符
  解析兜底" 架构 (不按模块注册, 零内存膨胀), 但属更大改造.
- **枚举值正确性**: Fix 018 从 VARDESC.lpvarValue 提取真实值 (如 TextCompare=1,
  adStateClosed=0), 比 Fix 017 遗留的"非字面量枚举值用自增值"问题更准确. COM 枚举值
  正确; 用户自定义枚举的非字面量值求值仍遗留 (独立问题).
- Fix 017-P1 (外部符号复制 constIntValue) 与 Fix 018b 协同: COM 枚举成员注册到首个模块
  后, 经 `globalPublicSyms` 跨模块注入时保留 constIntValue, 全模块可见.
