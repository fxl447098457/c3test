# Fix 020 — VB6 字段名与 C/Windows 标准宏冲突 (EOF)

**修复编号**: 020
**提交**: pending
**日期**: 2026-07-19
**类型**: 系统性 codegen 防护

## 现象

Fix 015 引入的 method-chain compound literal (方法链复合字面量) 修复后, cHttpServerSession.c:378 出现一组 cascading C2059 语法错误:

```c
// generated C code (line 378)
if ((~Db->Rs  /* class var .Rs field */.EOF)) {
```

MSVC 在该行报 `error C2059: 语法错误: "("`, 进而吞掉后续行号信息, 触发 8 处 C2065 `me` 未声明错误 (Fix 019 残留的 8 处 `me` 全部源自此处), 以及 C2143, C2223 等级联错误.

## 调查过程

### 1. 排除括号平衡问题

对 cHttpServerSession.c:377 (本行) 和 :378 (错误行) 做 char 级括号平衡分析: 13 个 `(` 与 13 个 `)` 配对正确, `{` 多 1 个与下一行 `if` 块匹配. **括号不是问题**.

### 2. 最小复现 — compound literal 模式本身?

手工构造 5 个最小复现 `.c` 文件, 测试 compound literal 各种形态:

| 文件 | 内容 | 结果 |
|------|------|------|
| `test_compound_lit.c` | 原始不平衡版本 | 复现 C2059 |
| `test_cl_simple.c` | 单层 compound literal | 仅 C2198, 无 C2059 |
| `test_cl_two.c` | 双层嵌套 compound literal | 仅 C2198, 无 C2059 |
| `test_cl_balanced.c` | 平衡括号 + 类型匹配 | C2198 + C2231, 无 C2059 |
| `test_cl_mismatch.c` | 类型不匹配 | C2440 + C2198 + C2231, 无 C2059 |

**关键洞察**: 5 个复现都没产生真实的 C2059, 说明 cHttpServerSession.c:378 的 C2059 不只是 compound literal 模式问题.

### 3. EOF 宏冲突假设

注意错误行包含 `.EOF` — 这是 ADO Recordset 对象的字段. 而 `<stdio.h>` 定义了 `#define EOF (-1)`, `<windows.h>` 也定义大量全大写标识符为宏.

**假设**: 预处理器将 `.EOF` 展开为 `.(-1)`, 导致 `.` 后跟 `(` 的语法错误 → C2059 "(".

### 4. 验证 EOF 宏假设

创建 `.temp\test_eof_clash.c`:
```c
#include <stdio.h>
typedef struct { int EOF; } RsType;  // 第 5 行
int main(void) { return 0; }
```
编译 → 第 5 行报 `error C2059: 语法错误:"-"`. 这是 `int EOF;` 被展开为 `int (-1);`, lexer 看到 `-` 报错. 与 `.EOF` 展开为 `.(-1)` lexer 看到 `(` 是同一根因的两个表象.

### 5. 验证 `#undef EOF` 清除错误

构造含 `#undef EOF` 后的相同代码:
```c
#include <stdio.h>
#ifdef EOF
#undef EOF
#endif
typedef struct { int EOF; } RsType;  // OK
int main(void) { ... (~db.Rs .EOF) ... }
```
编译 → 仅剩 C2231 (指针/结构操作符, 与宏无关). **C2059 完全消失**.

### 6. 确认 include 链

`cHttpServerSession.h` 包含 `vb6rtl.h`; `vb6rtl.h` (位于 `src/rtl/core/`) 前 18 行包含:
```c
#include <stdint.h>
#include <stddef.h>
#include <stdbool.h>
#include <wchar.h>
#include <stdlib.h>
#include <string.h>
#include <setjmp.h>
#include <stdio.h>      // ← 定义 EOF
#include <math.h>
#include <limits.h>
#include <windows.h>    // ← 定义 ERROR/min/max 等
#include <oleauto.h>
```
include 链确认 `EOF` 来自 `vb6rtl.h → stdio.h`.

### 7. 扫描 vbman 生成代码中所有与标准宏冲突的字段名

grep 所有 `.c` 文件查找 `.MacroName` 模式 (MacroName ∈ 候选宏列表), 只找到 **EOF** 一个硬冲突, 共 11 处:
- `Demo_Database.c`: 3 处 `TestDB->Rs.EOF`
- `cCsv.c`: 6 处 `Rs.EOF`
- `cHttpServerSession.c`: 2 处 `Db->Rs.EOF`

其他常见宏 (ERROR/DELETE/min/max/IN/OUT/OPTIONAL/BEEP) 在生成代码中的出现均为字符串字面量 (`L"Error: "`, `L"DELETE FROM "`, `L"max 65535"`) 或作为变量名 (大小写敏感, `Min`/`Max` 不撞宏 `min`/`max`). **vb6rtl.h 和所有 rtl 头文件均不使用这些宏**.

## 根因

C3 生成的 C 代码用 `.FieldName` 形式访问 VB6 类实例的字段. 当 FieldName 与 C/Windows 标准宏同名时, C 预处理器会展开该字段名, 破坏语法.

最严重冲突: `EOF` (stdio.h 中 `#define EOF (-1)`), `.EOF` → `.(-1)` → C2059 语法错误.

## 修复

在 `src/backend/cgen_base.cpp` 的 `.h` emit 流中, 紧跟 `#include "vb6rtl.h"` 之后注入一段防御性 `#undef` 块:

```cpp
h_.emitLine("#include \"vb6rtl.h\"");
// Fix 020: 取消 C/Windows 标准宏定义, 防止与 VB6 字段/方法名冲突
{
    static const char* kClashMacros[] = {
        "EOF", "ERROR", "DELETE", "min", "max",
        "OPTIONAL", "IN", "OUT", "BEEP"
    };
    h_.emitLine("/* Fix 020: undef C/Windows macros clashing with VB6 identifiers */");
    for (auto m : kClashMacros) {
        h_.emitLine(std::string("#ifdef ") + m);
        h_.emitLine(std::string("#undef ") + m);
        h_.emitLine("#endif");
    }
}
```

### 设计选择

**位置**: 在每个生成 .h 文件的 `#include "vb6rtl.h"` 之后. 因为:
1. vb6rtl.h 此前 transitive include 的 stdio.h/windows.h 已完成声明 (windows.h 的 include guard 冻结其副作用)
2. vb6rtl.h 内部代码不需要宏 (扫描确认 0 处使用)
3. 后续生成的所有代码 (UDT/struct field/method decl/方法体等) 都被保护
4. .c 文件通过 `#include "baseName.h"` 间接获得保护, 无需重复

**宏列表 9 项** (保守选择, 仅含确认会冲突或极可能冲突者):
- `EOF` (stdio.h) — ADO Recordset 字段 — **确认 vbman 中冲突 11 处**
- `ERROR` (winerror.h) — VB6 常用作属性/枚举名
- `DELETE` (winuser.h MF_DELETE) — ADO `Command.Delete` 等
- `min`/`max` (windef.h 宏) — VB6 大小写不敏感, Min/Max 等会撞
- `OPTIONAL`/`IN`/`OUT` (sal.h 注解宏) — VB6 参数名常见
- `BEEP` (winuser.h) — 防 VB6 内置 Beep 语句被字段名撞

**`#ifdef` + `#undef` 配对**: 安全处理未定义的宏 (跳过), 避免在某些环境下未定义时的潜在警告.

**未对 vb6rtl.h 本身做修改** (避免影响其它项目), 仅修改 cgen 生成的代码. dll_entry.c 虽然也 include vb6rtl.h, 但其代码不涉及字段访问, 暂不需要.
