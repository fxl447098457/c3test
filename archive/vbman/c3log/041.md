# Fix 041 — C2198/C2197 Argument Count Mismatch

**Date**: 2026-07-22
**Starting point**: After Fix 040 (commit 8d176d2): 1718 tracked errors. C2198=169, C2197=102.
**Final result**: 1682 tracked errors (-36). C2198=141 (-28), C2197=79 (-23).

## Fix 041a — Rnd Zero-Arg + InStr 4-Arg Truncation

### Problem A: Rnd() Called With Zero Arguments (13 C2197 errors)

VB6's `Rnd` function is a zero-argument builtin. The codegen emitted `vb6_Rnd()` (no args), but the C runtime function `vb6_Rnd` expects one argument (`int32_t number`). This caused C2197 "too many arguments" — actually C2198 "too few arguments" since the C function has 1 param but 0 args were passed.

**Fix**: In `cgen_expr.cpp` `visit(IdentifierExpr)` (~line 682), when the identifier is `Rnd` and it's in a zero-arg builtin context, emit `vb6_Rnd(0)` instead of `vb6_Rnd()`.

### Problem B: InStr Called With 4 Arguments (22 C2197 errors)

VB6's `InStr` function can be called with 2, 3, or 4 arguments:
- `InStr(string1, string2)` — 2 args
- `InStr(start, string1, string2)` — 3 args
- `InStr(start, string1, string2, compare)` — 4 args

The C runtime function `vb6_InStr` only accepts 3 arguments (start, string1, string2). When called with 4 args (including compare method), the extra argument caused C2197.

**Fix**: In `cgen_expr.cpp` `visit(IndexOrCallExpr)` (~line 3854), when `callee == "vb6_InStr"` and `args.size() > 3`, truncate to first 3 args. The `compare` argument is ignored (binary comparison is the default in C runtime).

**Result**: 1718 → 1696 (-22). C2198 169→156 (-13), C2197 102→80 (-22).

## Fix 041b — WithMemberExpr calleeParams + Arg Truncation

### Problem A: WithMemberExpr CalleeParams Lookup Missing

When `.Add(...)` is called inside a `With` block targeting a project class instance, the callee is a `WithMemberExpr` node. However, the `calleeParams` lookup code in `visit(IndexOrCallExpr)` only handled `IdentifierExpr` and `MemberAccessExpr` callee types. Without `calleeParams`, Optional parameter padding and IsMissing `_has_` flags were not generated, causing C2198 "too few arguments".

**Fix**: Added a new `calleeParamsFound` bool flag (cgen_expr.cpp ~line 2993) to distinguish "params not looked up" from "looked up with 0 params". Set it `true` in all three existing lookup paths (IdentifierExpr, MemberAccessExpr class-aware, MemberAccessExpr fallback).

Added new `WithMemberExpr` calleeParams lookup block (~line 3074): When the callee is a `WithMemberExpr` and the With-block's `info.kind == ClassInstance && !info.className.empty()`, calls `findClassMemberCallParams(info.className, wmExpr.memberName, ...)`. If found, sets `calleeParams` + `calleeParamsFound`.

### Problem B: Excess Args Not Truncated

When a function has fewer C parameters than the VB6 call passes arguments (e.g., Declare functions with Optional params, Property Get with index args), the extra args were not truncated, causing C2197.

**Fix**: Added arg truncation logic (~line 3575) in the "No ParamArray" branch of argList construction: when `calleeParamsFound && !calleeIsBuiltin && args.size() > calleeParams.size()`, truncate args to `calleeParams.size()`.

**Result**: 1696 → 1682 (-14). C2198 156→141 (-15), C2197 80→79 (-1).
