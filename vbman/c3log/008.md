## 问题概述

cDatabase.cls 是最后一个未通过的文件（1 CRASH）。该文件有 1605 行，包含大量 ADODB 类型库的限定类型名引用。存在三个独立的解析器缺陷：

## 缺陷 1: parseTypeRef() 限定类型名中的关键字组件（段错误根因）

### 根因分析

`parseTypeRef()` 在解析限定类型名（dotted type name）时，对 `.` 后面的组件使用硬编码的 token 列表检查：

```cpp
// 旧代码: 只接受 Identifier 和内置类型关键字
if (cur_.kind == TokenKind::Identifier || cur_.kind == TokenKind::Boolean ||
    cur_.kind == TokenKind::Byte || cur_.kind == TokenKind::Integer ||
    ... || cur_.kind == TokenKind::Variant) {
    qualified += "." + advance().text;
} else {
    break;
}
```

VB6 中 `ADODB.Error` 和 `ADODB.Command` 的 `Error`（TokenKind::Error）和 `Command`（TokenKind::Command）是关键字，不在上述列表中。这导致：

1. `parseTypeRef()` 消费了 `ADODB` 和 `.`，但 NOT 消费 `Error`
2. 返回 `SimpleTypeRef("ADODB")`，当前 token 仍是 `Error`
3. `parseParameterList()` 的 `expect(RightParen)` 失败（不消费 token）
4. `parseSubDecl()` 的 `expectEndOfStatement()` 消费了 `Error`，进入 `parseBlockUntil({End})`
5. Sub body 解析器面对残留的参数 token，产生空指针 ExprPtr
6. 后续操作解引用空指针 → **0xC0000005 段错误**

### 二分搜索定位

对 cDatabase.cls 做逐行二分搜索：
- 行 1-1599: ExitCode=1（正常退出，有语法错误）
- 行 1-1600: ExitCode=-1073741819 (0xC0000005) 或 TIMEOUT

行 1600 即为 `Private Sub Conn_ExecuteComplete(...ADODB.Error...ADODB.Command...)`。

### 确认的限限定类型名中的关键字

vbman 项目中所有 dotted type 模式：
```
ADODB.Error        ← Error  = TokenKind::Error      (硬关键字)
ADODB.Command      ← Command = TokenKind::Command    (硬关键字)
ADODB.Connection, ADODB.EventStatusEnum, ADODB.Field,
ADODB.Parameter, ADODB.Recordset, ADODB.Stream    ← 均为 Identifier (无问题)
MSHTML.IHTMLScriptElement, Scripting.Dictionary, etc. ← 均为 Identifier (无问题)
```

### 修复

在 `parseTypeRef()` 的 dotted 类型名 while 循环中，复用 Fix 002 在 `parsePostfix()` Dot 分支中的模式：先用 `canBeName()` 接受标识符和软关键字，再用文本非空检查接受硬关键字：

**文件**: `src/parser/parser_decl.cpp`, `parseTypeRef()`, 约 571 行

```cpp
// 旧: 硬编码 token 列表
if (cur_.kind == TokenKind::Identifier || cur_.kind == TokenKind::Boolean || ...) {
    qualified += "." + advance().text;
} else { break; }

// 新: canBeName + 文本检查 (与 parsePostfix/parseWithMemberExpr 一致)
if (canBeName(cur_.kind)) {
    qualified += "." + advance().text;
} else if (!cur_.text.empty() && cur_.kind != TokenKind::EndOfFile &&
           cur_.kind != TokenKind::NewLine && cur_.kind != TokenKind::Colon &&
           cur_.kind != TokenKind::LeftParen && cur_.kind != TokenKind::RightParen &&
           cur_.kind != TokenKind::Comma) {
    // 硬关键字也可作为限定类型名组件 (如 Error, Command, Type 等)
    qualified += "." + advance().text;
} else {
    break;
}
```

## 缺陷 2: parseEventDecl() 缺失 expectEndOfStatement()

### 根因分析

`parseEventDecl()` 解析完参数列表后直接返回，没有调用 `expectEndOfStatement()`：

```cpp
// 旧代码
std::unique_ptr<EventDecl> Parser::parseEventDecl(AccessLevel access) {
    auto loc = currentLoc();
    advance(); // consume 'Event'
    auto nameTok = expectName("expected Event name");
    auto params = parseParameterList();
    return std::make_unique<EventDecl>(...);  // ← 缺少 expectEndOfStatement()
}
```

当参数列表解析失败（如缺陷 1 的 `ADODB.Error`），`parseParameterList()` 返回时当前 token 不在行尾。由于 `parseEventDecl()` 不做任何收尾，当前 token 直接泄漏到模块级解析器。模块级 `parseModuleBody()` 遇到非声明 token 时报 `unexpected token at module level` 并 `skipToNextLine()`，跳过整行剩余内容。

### 修复

**文件**: `src/parser/parser_decl.cpp`, `parseEventDecl()`, 约 333 行

```cpp
auto params = parseParameterList();
expectEndOfStatement();  // ← 新增
return std::make_unique<EventDecl>(...);
```

## 缺陷 3: 单行 If 冒号分隔多语句未正确处理

### 根因分析

VB6 语法允许单行 If 的 Then/Else 体包含冒号分隔的多条语句：
```vb
If x Then stmt1: stmt2: Exit Function
```

但 `parseIfStmt()` 的单行分支只解析一条 Then 语句：
```cpp
// 旧代码
auto stmt = parseStatement();
if (stmt) thenBody.push_back(std::move(stmt));
// 直接检查 Else，没有处理后续冒号分隔语句
```

解析 `stmt1` 后，控制返回到块解析器。块解析器的 `expectEndOfStatement()` 消费冒号，然后 `ResetBuilder` 出现在语句起始位置。`parseLabelOrAssignmentOrCall()` 的标签检测逻辑 `canBeName(cur_.kind) && next_.kind == Colon` 判定 `ResetBuilder:` 为标签，消费了 `ResetBuilder:`。之后 `Exit` 被当作非语句结束符消费，`Function` 出现在语句起始产生错误。

### 错误位置

- 行 1313: `If whereSql = "" Then LastErr = "...": ResetBuilder: Exit Function`
- 行 1352: `If whereSql = "" Then LastErr = "...": ResetBuilder: Exit Function`

### 修复

两部分修改：

**A. parseIfStmt() 单行分支: 追加冒号分隔语句解析**

**文件**: `src/parser/parser_stmt.cpp`, `parseIfStmt()`, 约 374-398 行

```cpp
// 新增: Then 体冒号分隔语句
while (cur_.kind == TokenKind::Colon) {
    advance(); // consume ':'
    if (cur_.kind == TokenKind::Else) break;
    auto moreStmt = parseStatement();
    if (moreStmt) thenBody.push_back(std::move(moreStmt));
}

// 新增: Else 体冒号分隔语句
if (match(TokenKind::Else)) {
    auto elseStmt = parseStatement();
    if (elseStmt) elseBody.push_back(std::move(elseStmt));
    while (cur_.kind == TokenKind::Colon) {
        advance();
        auto moreStmt = parseStatement();
        if (moreStmt) elseBody.push_back(std::move(moreStmt));
    }
}
```

**B. 新增 inSingleLineIf_ 标志: 禁止单行 If 内的标签检测**

**文件**: `src/parser/parser.hpp`, 约 262 行 — 新增成员变量
```cpp
int inSingleLineIf_ = 0;  // >0 时禁止标签检测 (colon是语句分隔符)
```

**文件**: `src/parser/parser_stmt.cpp`, `parseIfStmt()` 单行分支 — 设置/重置标志
```cpp
inSingleLineIf_++;
// ... parse then-body, else-body ...
inSingleLineIf_--;
```

**文件**: `src/parser/parser_stmt.cpp`, `parseLabelOrAssignmentOrCall()` — 检查标志
```cpp
// 旧: 总是检查标签
if (canBeName(cur_.kind) && next_.kind == TokenKind::Colon) {
    // treat as label
}
// 新: 单行 If 内跳过标签检测
if (inSingleLineIf_ == 0 && canBeName(cur_.kind) && next_.kind == TokenKind::Colon) {
    // treat as label
}
```
