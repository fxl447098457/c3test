## 根本原因

`knownVariantVars_` 集合用于 `AssignmentStmt` 代码生成时判断赋值目标是否为 Variant 类型。如果是 Variant，则调用 `wrapVariantValue()` 将右侧表达式包装为 `vb6_VARIANT` (例如 `vb6_VariantLong(x)`, `vb6_VariantString(s)`, `vb6_VariantFromValue(x)` 等)。如果不注册，则生成裸赋值 `target = value;`，当右侧是具体类型 (int32_t/BSTR/...) 而左侧是 vb6_VARIANT 时产生 C2440。

### 缺失的两处注册

1. **FunctionDecl 返回值变量** (`cgen_decl.cpp` ~line 286):
   原代码只注册 String/Double/Long/Integer/Boolean 返回值到对应的 `knownBstrVars_`/`knownDoubleVars_`/`knownLongVars_`，**遗漏了 Variant 返回值**。导致 `Function Foo() As Variant` 中 `Foo = concrete_expr` 赋值不触发 `wrapVariantValue`，生成 `vb6_ret_foo = concrete_value;` → C2440 (BSTR/int32_t → vb6_VARIANT)。
   PropertyDecl 返回值变量 (~line 1062) 已正确注册 Variant，不受影响。

2. **Sub/Function/Property 参数** (`cgen_decl.cpp` ~line 78/237/1011):
   原代码只注册 String/Double/Long 类型参数，**遗漏了 Variant 参数**。三个 visitor 函数 (`visit(SubDecl)`, `visit(FunctionDecl)`, `visit(PropertyDecl)`) 中都有相同的参数注册块，都缺失 Variant 注册。导致 ByRef Variant 参数 `(*Data) = concrete_expr` 写穿透赋值不触发 `wrapVariantValue` → C2440。

## 修复方案

### 1. FunctionDecl 返回值变量 Variant 注册 (`cgen_decl.cpp` ~line 293-295)

```cpp
// Fix 035: Variant 返回值变量也要注册, 否则 `Foo = concrete_expr` 赋值不会触发
// wrapVariantValue 包装, 导致 C2440 (BSTR/int32_t → vb6_VARIANT).
else if (funcRetVb6Type == Vb6Type::Variant) knownVariantVars_.insert(funcRetLower);
```

### 2. 参数 Variant 注册 (三处, 使用 replaceAll)

在 `visit(SubDecl)` (~line 78), `visit(FunctionDecl)` (~line 237), `visit(PropertyDecl)` (~line 1011) 的参数类型注册块末尾添加:

```cpp
// Fix 035: Variant 参数也要注册, 否则 `(*X) = concrete` 赋值不会触发
// wrapVariantValue 包装, 导致 C2440 (ByRef Variant 参数写穿透场景).
else if (paramType == Vb6Type::Variant) knownVariantVars_.insert(pLower);
```

三处注册块完全相同 (5 行), 使用 `replaceAll: true` 一次性修复全部三处。
