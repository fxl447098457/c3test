# Fix 043: ForEachStmt GoSub detection + With-block COM field detection + Parser space-aware disambiguation

**Date**: 2026-07-22
**Starting point**: Fix 042 (commit 10c6dd4) — 1652 tracked errors
**Result**: 1595 tracked errors (-57)
**Commits**: (to be filled after commit)

## Overview

Three sub-fixes addressing different error categories:
- **043a**: C2065 GoSub variable undeclared (ForEachStmt missing from recursive detection)
- **043b**: C2198 With-block COM field detection (class fields + early-bound COM locals)
- **043c**: C2064 regression prevention (parser space-aware `.Member .Member` disambiguation)

## Fix 043a — ForEachStmt missing from hasGoSub/hasResume/hasOnError

**Problem**: `hasGoSubInStmts()`, `hasResumeInStmts()`, and `hasOnErrorInStmts()` in `cgen_util.cpp` recursively scan statement lists for GoSub/Resume/OnError statements. They checked `ForStmt`, `DoLoopStmt`, `WhileWendStmt`, `SelectCaseStmt`, `IfStmt` — but NOT `ForEachStmt`. This meant GoSub/Resume/OnError inside a `For Each` loop body were not detected, causing the local variable declarations (e.g., `int vb6_gosub_stack[32]; int vb6_gosub_sp = 0;`) to not be emitted, leading to C2065 "undeclared identifier" errors.

**Fix**: Added `ForEachStmt` case to all three recursive detection functions in `src/backend/cgen_util.cpp`:
- `hasGoSubInStmts()` (~line 1030)
- `hasResumeInStmts()` (~line 1067)
- `hasOnErrorInStmts()` (~line 1100)

Each now recursively checks `ForEachStmt.body` (the loop body statement list).

**Result**: C2065 GoSub-related errors 15→0 (identifiers `vb6_gosub_sp` 10→0, `vb6_gosub_stack` 5→0).

## Fix 043b — With-block COM field detection

**Problem**: `visit(WithStmt)` in `cgen_stmt.cpp` determines `withInfo.kind` (WithObjKind enum) to dispatch `.Member` access correctly. The detection for `IdentifierExpr` objects checked:
1. `knownObjectVars_` (local `Dim x As Object` variables → COMObject)
2. `knownClassVars_` (local class instance variables → ClassInstance)
3. `knownUdtVars_` (UDT variables)

But this missed two critical cases:
- **Class fields of COM interface type** (e.g., `Public Dic As Dictionary` in a class module) — `knownObjectVars_` and `knownClassVars_` only contain local variables/parameters, NOT class fields. When a `With` block targeted a class field like `Dic`, the kind fell through as `Unknown`, causing `.Add` inside the With block to be resolved as the class's own `Add` method instead of COM dispatch (C2198).
- **Early-bound COM local variables** (e.g., `Dim Dic As Dictionary` where `Dictionary` is a ComInterface symbol) — these were in `knownTypedComVars_` but not checked by the With block detection.

**Fix**: Added three new detection blocks in `visit(WithStmt)` in `src/backend/cgen_stmt.cpp` (~line 1998-2045), inserted after `knownClassVars_` check and before `knownUdtVars_` check:

1. **`knownTypedComVars_` check** (~line 1998): When the identifier is in `knownTypedComVars_` (early-bound COM local variable), set `withInfo.kind = COMObject`. This catches locals like `Dim Dic As Dictionary` in non-class modules.

2. **`classVoidFieldMap_` check** (~line 2010, only when `isClassModule_`): If the field name is in `classVoidFieldMap_[moduleName_]` (void* fields), set `withInfo.kind = COMObject`. These are COM interface fields declared as `As Object` or `As Dictionary` etc.

3. **`classTypedFieldMap_` check** (~line 2025, only when `isClassModule_`): If the field name is in `classTypedFieldMap_[moduleName_]`, check the type marker:
   - If it starts with `"COM:"` → set `withInfo.kind = COMObject` (COM interface field like `As Dictionary`)
   - Otherwise → set `withInfo.kind = ClassInstance` with `withInfo.className = typeMarker` (project class field like `As cCollection`)

**Result**: C2198 errors 141→117 (-24). The `vb6_cHttpServerRouter_Add` errors (23→0 in cHttpServerRouter.c itself, plus 14 in other modules) were fixed by the combined effect of 043b's three checks.

## Fix 043c — Parser space-aware `.Member .Member` disambiguation (C2064 regression prevention)

**Problem**: After Fix 043b, With blocks on COM Dictionary fields were correctly detected as `COMObject`. However, 2 new C2064 errors appeared in cCsv.c.

The VB6 source in `SyncColumnWidth()`:
```vb6
With HeadTitleWidth
    Do Until .Count = d0n
        .Add .Count + 1, HeadTitleWidthDefault
    Loop
End With
```

The parser was treating `.Add .Count + 1, HeadTitleWidthDefault` as `(.Add.Count + 1)(HeadTitleWidthDefault)` — a member access chain `.Add.Count` followed by a function call — instead of a sub call `.Add` with two arguments `.Count + 1` and `HeadTitleWidthDefault`.

**Root cause**: In `parsePostfix()` (`src/parser/parser_expr.cpp`), when the expression parser saw a `.` after a `WithMemberExpr`, it always treated it as a member access (`MemberAccessExpr`), regardless of whether there was a space between the member name and the `.`. In VB6:
- `.Add.Count` (no space) → member access (Count is a member of Add's return value)
- `.Add .Count` (space) → sub call (Add is called with .Count as an argument)

The tokenizer consumes whitespace, so the parser had no way to distinguish these cases.

**Fix**: Three-part change:

1. **`src/parser/parser.hpp`**: Added `Token prevTok_` field to track the last consumed token (with position info: line, column, length).

2. **`src/parser/parser.cpp`** (`advance()`): Save the consumed token to `prevTok_` before returning it.

3. **`src/parser/parser_expr.cpp`** (`parsePostfix()`, `case TokenKind::Dot:`): Added a space-detection check before consuming the `.`:
```cpp
// Fix 043c: In With context, ".Member1 .Member2" (space before 2nd dot)
// is a sub call: .Member1(.Member2), NOT member access .Member1.Member2.
if (withDepth_ > 0 && expr->kind == ASTNodeKind::WithMemberExpr &&
    prevTok_.line == cur_.line &&
    prevTok_.column + prevTok_.length < cur_.column) {
    return expr;  // space detected — let caller parse .Member2 as argument
}
```

The check compares `prevTok_.column + prevTok_.length` (end column of the previous token, e.g., "Add") with `cur_.column` (start column of the `.`). If there's a gap (space), the expression is returned without consuming the `.`, allowing the caller (`parseLabelOrAssignmentOrCall`) to parse the remaining tokens as sub call arguments.

**Verification**: The generated C code for `.Add .Count + 1, HeadTitleWidthDefault` is now correct:
```c
vb6_ComCall(_vb6_with_6, L"Add",
    (void*[]){vb6_ComPackValue((vb6_ComGetIntProp(_vb6_with_6, L"Count") + 1)),
              vb6_ComPackInt(me->HeadTitleWidthDefault)}, 2);
```

And `.Remove .Count`:
```c
vb6_ComCall(_vb6_with_6, L"Remove",
    (void*[]){vb6_ComPackValue(_vb6_with_6)}, 1);
```

**Result**: C2064 errors 0→0 (no regression). The 2 C2064 errors that appeared after Fix 043b (before 043c was applied) are now prevented.
