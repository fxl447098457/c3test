# Fix 012 — With-block 类型系统 + 类成员精确解析 (011r-1 / 011r-1b)

## 目标

修复以下两个长期存在的 With-block / 类实例访问错误模式:

- **Pattern A2** — With 块中类实例变量的成员赋值, `symTab_.lookupModule()` 捡到错的模块
  (例如 vbman 中多个类都有 `Item` 属性, lookupModule 不分模块顺序返回, 经常误中)
- **Pattern D1** — 跨模块类 Public 数据字段访问被误判为方法调用
  (例如 cHttpServerClientInfo.hSocket 被生成成 vb6_cls_cHttpServerClientInfo_hSocket(CI) 而非 CI->hSocket)
- **C2231 / C2224 / C2275 / C2037 / C2223** — With-block 类型被推断为 void*
  或 vb6_VARIANT, 导致 `.member`/`->member` 操作符选择错误

## 核心架构变更

### 1. WithObjInfo 增加 className 字段 (cgen.hpp)

```cpp
struct WithObjInfo {
    WithObjKind kind;
    FrmControlType ctrlType;
    std::string ctrlOrigName;
    std::string className;   // ← 新增 011r-1: 当前 With 对象的 VB6 类名
};
```

`visit(WithStmt)` 在所有 ClassInstance 识别路径中设置 `withInfo.className`:

- **With New X** — 通过 NewExpr 的 className 设置
- **WithMemberExpr 嵌套** — 继承外层 `outerInfo.className`
- **IdentifierExpr** — 从 `knownClassVars_` map 中查得类名
- **MemberAccessExpr (With me.member)** — 从 `knownClassVars_` 或 `memSym->variableTypeName`
- **IndexOrCallExpr** — 从 callee 的 IndexOrCallExpr 解析

同时设置 `tempType = "vb6_cls_<className>*"`, 让 With-block 临时变量获得正确类型,
使 `(*tempVar).member` 操作符选择正确 → 直接消除 C2231 (该使用 `.` 而非 `->`) 等.

### 2. 新增 `resolveClassMemberCall()` 精确解析类成员 (cgen_util.cpp)

签名:
```cpp
std::string resolveClassMemberCall(const std::string& className,
                                    const std::string& memberName) const;
```

逻辑:
1. 遍历 `symTab_.moduleScope()->symbols()`, 按 `lowerName == memberLower` 过滤
2. 类匹配判定 (VB6 case-insensitive):
   - 外部类: `Symbol::toLower(sym->sourceModule) == classNameLower`
   - 同模块自身: `Symbol::toLower(baseName_) == classNameLower`
3. 按成员类型收集 (优先级 在调用方按上下文决定):
   - `PropertyGet` → `prop_get_`
   - `PropertyLet` → `prop_let_`
   - `PropertySet` → `prop_set_`
   - `Sub`/`Function` → 无前缀
4. **优先级** (读上下文, 由 resolveClassMemberCall 自己应用):
   Get > Sub/Function > Let > Set
   (写上下文由 visit(AssignmentStmt) 单独遍历选 Let/Set)
5. 返回函数名: `vb6_<canonicalClassName>_<prefix><memberName>`
   - 强制使用 canonical class name (来自符号表 `sourceModule` 或 `baseName_`),
     避免用户源代码大小写差异导致生成函数名与定义不匹配

调用点:
- `visit(WithMemberExpr)` ClassInstance case (读上下文): 优先 resolveClassMemberCall;
  返回空 → 视为数据字段 `tempVar->member`
- `visit(MemberAccessExpr)` Priority 2 (obj.Method): 当 obj 在 knownClassVars_ 中,
  优先 resolveClassMemberCall; 返回空 → 落入下方 cross-module fallback
- `visit(MemberAccessExpr)` cross-module fallback (Pattern D1): resolveClassMemberCall
  返回空 → 数据字段 `obj->member` (而非 vb6_cls_X_member(obj) 方法调用)
- `visit(AssignmentStmt)` WithMemberExpr ClassInstance case (写上下文): 单独遍历符号,
  找匹配类的 Property Let/Set, 生成 `vb6_<canonical>_prop_{let,set}_<member>(tempVar, value)`;
  未找到 → 数据字段写 `tempVar->member = value`

### 3. visit(WithStmt) 为所有 ClassInstance 路径设置 className + tempType (cgen_stmt.cpp)

详见 §1 的列表. 关键效果是 `withObjectVars_` 中的临时变量获得 `vb6_cls_<className>*` 类型,
让所有 `(*tempVar).member` / `tempVar->member` 表达式都能正确编译 —
直接消除 C2231("应使用 . 而非 ->") 和 C2224(".member 在 void* 上") 等大量错误.

### 4. 011r-1b: Case-insensitive 类名匹配 (核心修复)

在 `resolveClassMemberCall()` 与 `visit(AssignmentStmt)` WithMemberExpr 的两处类匹配判定中:

原代码 (case-sensitive):
```cpp
if (sym->isExternal) {
    matches = (sym->sourceModule == className);
} else if (isClassModule_ && baseName_ == className) {
    matches = true;
}
```

修复 (case-insensitive + canonical name 输出):
```cpp
if (sym->isExternal) {
    if (Symbol::toLower(sym->sourceModule) == classNameLower) {
        matches = true;
        if (canonicalClassName.empty()) canonicalClassName = sym->sourceModule;
    }
} else if (isClassModule_ && Symbol::toLower(baseName_) == classNameLower) {
    matches = true;
    if (canonicalClassName.empty()) canonicalClassName = baseName_;
}
```

并强制输出函数名用 canonical name:
```cpp
return "vb6_" + cIdent(canonicalClassName) + "_" + prefix + cIdent(memberName);
```

## 背景: 为什么 case-insensitive 关键

VB6 源代码大小写不敏感, 但 C 编译器对 struct tag 名大小写敏感. C3 在不同路径下
用不同的大小写来源:

- **类模块自身编译时** — `baseName_` 取自**文件名** (.cls)
  例如 `cWinSock.cls` → `baseName_ = "cWinSock"`, 生成的 struct 定义是 `vb6_cls_cWinSock`
- **变量声明时** — `variableTypeName` 取自**用户源代码**的 `As xxx` 类型名
  例如 `Dim x As cWinsock` → 注册 `cWinsock` (lowercase s), 生成的 param/var 类型是 `vb6_cls_cWinsock`

**这造成两类不同大小的 struct tag**:
- `vb6_cls_cWinSock` (capital S — 定义)
- `vb6_cls_cWinsock` (lowercase s — 仅 forward decl)

之前的 case-sensitive 匹配导致: 当用户代码 `Dim Client As cWinsock` 后,
`knownClassVars_["client"] = "cWinsock"` (lowercase), 但同模块自身编译时
`baseName_ = "cWinSock"` (capital), 比较不相等 → resolveClassMemberCall 返回空 → 误判为
数据字段 → 生成 `(*Client).CurrentUser = User;` 而非 Property Let 调用.

case-insensitive 匹配修复了这个根因.

### 本修复揭示的深层问题

C2037 (+73) 是预期的 — 之前 C2231 ("应使用 . 而非 ->") 是错误地选了 `.` 而类型为 `vb6_VARIANT`,
现在正确推断成 `vb6_cls_<className>*`, 但因 struct 仅有 forward declaration (incomplete type),
访问 `.X` 需要完整定义 → 转为 C2037. 这是**正确的方向上一步**, 暴露:

1. **Public 变量未被生成为 struct 字段**
   - 例: cWinSock.cls 中 `Public CurrentUser As Variant` (line 187)
   - 生成的 `vb6_cls_cWinSock` struct (cWinSock.h line 222-258) **未包含 CurrentUser field**
   - 导致 `(*Client).CurrentUser = User` 编译失败
   - **留待 Fix 013 专项处理**

2. **类型名大小写不一致** (`vb6_cls_cWinSock` vs `vb6_cls_cWinsock`)
   - 根因: `baseName_` 取自文件名, `variableTypeName` 取自用户源代码
   - 本修复通过 canonical name 输出已缓解了大部分影响, 但 struct 字段访问
     仍需 canonical 类型一致 (留待 Fix 013)
