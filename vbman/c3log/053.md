# Fix 053: COM dispatch 重复函数定义修复 (C2084)

## 日期
2026-07-23

## 错误概览
- 修复前: 1210 个总错误, C2084 3 个
- 修复后: 1207 个总错误, C2084 0 个
- 净减少: -3 个总错误

## 根因分析

### C2084: 函数已有主体 (3个)

`dll_entry.c` 中 dispatch 桥接函数被生成了两次, 涉及:
- `vb6_disp_cTlsReMaster_CloseSck_invoke`
- `vb6_disp_cTlsReMaster_Connect_invoke`
- `vb6_disp_cWinsock_Connect_invoke`

原因: VB6 允许 `Public Event CloseSck()` 和 `Public Sub CloseSck()` 同名共存。
语义分析器将两者都添加到类的 `memberNames` 列表中。
dispatch 代码遍历 `memberNames` 时, 对 `CloseSck` 查找符号, 找到 Sub 符号并添加到公共方法列表。
第二次遍历到 `CloseSck` (来自 Event 的 memberName) 时, 再次找到同一个 Sub 符号, 重复添加。

### 类去重 (预防性)

`symTab_.moduleScope()->symbols()` 中同一类可能因符号表合并出现多次。
添加 `seenCoClassNames` 集合去重。

## 修复方案

### 修改1: memberNames 去重
**文件**: `src/backend/cgen_util.cpp`

在遍历 `sym->memberNames` 时, 使用 `seenMemberNames` 集合跟踪已处理的成员名。
如果小写成员名已存在, 跳过 (`continue`)。

### 修改2: coClasses 去重 (预防性)
**文件**: `src/backend/cgen_util.cpp`

添加 `seenCoClassNames` 集合, 在添加 CoClassInfo 前检查类名是否已处理。
