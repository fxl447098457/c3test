## 修复内容

### 2a. 逗号分隔的 Dim/Private/Public 声明

**问题**: VB6 允许在模块级别使用逗号分隔的变量声明，如 `Dim x, y, z As Long`。解析器的 `parseVariableDecl()` 只返回单个 `VariableDecl`，没有逗号循环处理。`parseConstDecl()` 同样不支持逗号分隔的常量声明（如 `Const A = 1, B = 2`）。

**根因**: 
- `src/parser/parser_decl.cpp` 的 `parseVariableDecl()` 返回 `VariableDecl`（单个），无逗号循环。
- 模块级 `parseDeclaration()` 直接调用它，无法处理多变量声明。
- `parseConstDecl()` 同样返回单个 `ConstDecl`。

**修复**:
1. `src/ast/ast.hpp`: 新增 `MultiDecl` 节点到 `ASTNodeKind` 枚举和 `MultiDecl` 类（在 `VariableDecl` 之后），用于将多个声明包装为一个节点。更新 `isDecl()` 范围以包含新节点。
2. `src/parser/parser_decl.cpp`: 
   - 新增 `parseVariableDeclList()` — 调用 `parseVariableDecl()` 并循环消费逗号，将多个声明包装为 `MultiDecl`。
   - 新增 `parseConstDeclList()` — 同理处理常量声明的逗号分隔。
3. `src/parser/parser_decl.cpp` `parseDeclaration()`: 将对 `parseVariableDecl()` 和 `parseConstDecl()` 的直接调用改为调用 `parseVariableDeclList()` 和 `parseConstDeclList()`。
4. `src/parser/parser.cpp` `parseModule()`: 遍历模块声明列表时，遇到 `MultiDecl` 节点则展开为多个独立声明。

### 2b. Case 子句值后面的冒号

**问题**: VB6 的 `Select Case` 语句中，`Case` 子句值后可以使用冒号 `:` 分隔条件和语句体，如 `Case 0: x = 1`。解析器在 `Case` 和 `Case Else` 子句中没有处理冒号。

**根因**: `src/parser/parser_stmt.cpp` 的 `parseSelectCaseStmt()` 中，`skipNewLines()` 后直接调用 `parseBlockUntil()`，没有先消费可能存在的冒号。

**修复**: 在 `parseSelectCaseStmt()` 的 `Case` 子句和 `Case Else` 子句中，在 `skipNewLines()` 之后、`parseBlockUntil()` 之前，添加 `match(TokenKind::Colon);` 以可选地消费冒号。

涉及位置: `src/parser/parser_stmt.cpp` 约第 572 行和第 583 行。

### 2c. 硬关键字作为成员名

**问题**: VB6 允许使用硬关键字作为对象的成员名，如 `obj.Type = 5`、`obj.Loop = True`。解析器的 `parsePostfix()` 在 Dot 分支中调用 `expectName()`，只接受 `Identifier` 和软关键字（通过 `canBeName()`），拒绝 `Type`、`Loop`、`Next`、`Step` 等硬关键字。

**根因**: `src/parser/parser_expr.cpp` 的 `parsePostfix()` Dot 分支中，`expectName()` 函数只接受 `Identifier` 和有限的软关键字。

**修复**: 在 Dot 分支中，将 `expectName()` 替换为更宽泛的成员名接受逻辑：接受任何具有非空文本的 token 作为成员名（排除 EOF、NewLine、Colon、括号、逗号等分隔符 token）。具体实现为检查当前 token 的文本是否非空，如果是则创建成员访问节点并前进，否则报错 "expected member name after '.'"。

涉及位置: `src/parser/parser_expr.cpp` 约第 385-421 行。

### 2d. ByVal/ByRef 在函数调用参数中

**问题**: VB6 允许在调用函数时覆盖参数传递方式，如 `MyFunc(ByVal arg)` 或 `MyFunc(ByRef x)`。解析器的 `parsePostfix()` 在 LeftParen 分支的参数循环中没有处理 `ByVal`/`ByRef` 前缀。

**根因**: `src/parser/parser_expr.cpp` 的 `parsePostfix()` LeftParen 分支中，参数解析循环直接解析表达式，没有检查前导的 `ByVal`/`ByRef` 关键字。

**修复**: 在参数循环的顶部添加检查：`if (cur_.kind == TokenKind::ByVal || cur_.kind == TokenKind::ByRef) { advance(); }`，在解析参数表达式前消费可选的 `ByVal`/`ByRef` 关键字。

涉及位置: `src/parser/parser_expr.cpp` 约第 434 行。
