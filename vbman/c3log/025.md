# Fix 025: ByRef Variant/BSTR 参数写穿透 — (*name) 形式识别 (C2440 -33)

> 阶段: Fix 025 (小步快跑)
> 基线: Fix 024 v2 (commit `681d2b0`) — 总错误 3153, C2440 1612
> 结果: Fix 025 — 总错误 3129 (-24), C2440 1579 (-33)
> 状态: 已编译验证, 待提交

## 背景

Fix 024 P1+P2 主要处理 `_vcmp_N` 临时变量 + ByVal Variant 形参两类 C2440。剩余 1612
处 C2440 中, 一个突出子类是 **`(*vOutput) = X`** —— 给 ByRef Variant/BSTR 参数赋值
(写穿透), codegen emit 出 `(*name) = rhs;` 形式, 但现有 `knownVariantVars_` /
`knownBstrVars_` 检测只按字面名查找, 找不到 `(*voutput)` 这个名字, 于是走默认
`target = value;` 路径直接生成 `(*vOutput) = _arr_2;` → C2440 (scalar/SafeArray → VARIANT)。

## 根因

`src/backend/cgen_stmt.cpp visit(AssignmentStmt&)` (L740-781):

```cpp
std::string checkName = target;                          // 例: "(*vOutput)"
if (checkName.substr(0, 4) == "me->") checkName = ...;   // 仅剥 me-> 前缀
std::string lower = checkName;                           // "(*voutput)"
if (knownVariantVars_.count(lower)) targetIsVariant = true;  // ← 永远 false
```

`(*vOutput)` 中的内部名 `vOutput` 才是真正的变量名 (在 knownVariantVars_ 中),
但代码只剥 `me->` 前缀, 没剥 `(* ... )` 解引用外层。

## 修复

### 改动 1: `src/backend/cgen_stmt.cpp`

`visit(AssignmentStmt&)` 中对 `targetIsBstr` (L741) 和 `targetIsVariant` (L758)
两个检测块各加一段 `(*name)` 形式剥离:

```cpp
// Fix 025: (*name) 解引用形式 — ByRef Variant/BSTR 参数写穿透
if (checkName.size() > 4 && checkName[0] == '(' && checkName[1] == '*'
    && checkName.back() == ')') {
    checkName = checkName.substr(2, checkName.size() - 3);
}
```

剥出内部名后, 再走 tolower + knownVariantVars_/knownBstrVars_ 查找即可正确触发
已有的 `vb6_VariantClear + wrapVariantValue` 包装路径。

### 改动 2: `src/backend/cgen_util.cpp` `wrapVariantValue`

把默认 fallback 从 `vb6_VariantLong(cExpr)` 改为 `vb6_VariantFromValue(cExpr)`。

原默认 `vb6_VariantLong` 对非整数 rhs (SafeArray*/void*/class ptr) 会触发 C2440;
改用 P1+P2 引入的 `_Generic` 多态宏, 编译器按实类型自动选择 ctor,
覆盖更全面 (BSTR→String, void*→Object, SafeArray*→Array, 等)。

### 新揭示错误类别 (C1003 上限解锁)

Fix 025 减少了早期文件错误, MSVC 进度推进, 揭示了之前被隐藏的错误:

| 错误码 | 计数 | 性质 | 备选下一步 |
|---|---|---|---|
| C2231 | 48 | `obj.Prop` 左操作数是指针, 应用 `->` | codegen 类成员访问 bug, 需要修 |
| C2063 | 46 | `X(...)` 中 X 不是函数 | 变量被当函数调用, codegen 解析问题 |
| C2297 | 43 | 位运算 `&`/`\|` 右操作数非整数 | 类型推断错误 |
| C2171 | 27 | 运算符 `~` 应用于指针 | 同上 |
| C2106 | 27 | `=` 左操作数不是左值 | For Each codegen emit `func() = ...` 问题 |
| C2223 | 23 | `->`/`.` 左操作数是 void* | 类型推断错误 |
| C2102 | 14 | `+=`/`-=` 操作数非左值 | codegen bug |
| C2296 | 13 | 表达式非左值取地址 | codegen bug |

这些是 **揭示-非引入** (revealed-not-introduced)。每个新类别都需独立 fix。

## 已知 C2106 案例 (待 Fix 026 修)

```
cAsyncSocket.c:1352: vb6_VariantArrayGet(&vGateway, lIdx) = vb6_VariantArrayGet(&vGateway, lIdx, 0);
```

来自 For Each 循环 codegen, LHS 是函数返回值 (非左值), 应该改用 vb6_VariantArraySet。
VB6 源码可能是 `For Each vElem In vGateway: ... Next` 但 codegen 把
循环变量赋值 emit 成了 `vb6_VariantArrayGet(...) = ...` 而非 `vElem = ...`。

## 已知局限

- 仅识别 `(*name)` 完整解引用形式, 不处理 `(*name).field` 等更深结构 (Variant 不会有这种, BSTR 也不会)
- 没有处理跨模块 calleeParams 为空时的 P2 回退 (留待后续 Fix 处理剩余 ~560 outbound→VARIANT cases)
