# Fix 045: 跨模块 Variant 返回值函数检测 + Object 目标转换

## 日期
2026-07-22

## 问题

C2440 类型转换错误（905个）是当前最大的错误类别。核心缺口：

1. **`cExprIsVariant()` 无法检测项目类函数返回 Variant** — 该函数仅检查 `vb6_Variant*` 前缀的运行时函数，无法识别项目函数（如 `vb6_cAsyncSocket_Znl(...)` 返回 `vb6_VARIANT`）。这导致赋值语句和函数参数中 Variant 值未被正确转换。

2. **赋值处理器缺少 Object (void*) 目标检测** — 当 `void*` 变量接收 Variant 值时，未插入 `vb6_VariantToObjectVal()` 转换。

## 根因分析

### `cExprIsVariant()` 的限制

`cExprIsVariant()` 是 C 字符串级别的 Variant 检测函数，通过前缀匹配判断表达式是否为 `vb6_VARIANT` 类型。它识别 23 个 `vb6_Variant*` 前缀和 `VB6_SA_AT(vb6_VARIANT` 模式，但无法识别项目函数（如 `vb6_cAsyncSocket_Znl`、`vb6_cJson_NewItem` 等）返回的 Variant。

之前的 Fix 045 尝试使用 `isDefinitelyVariantExpr()`（AST 级检测）补充，但因符号表作用域匹配问题导致 +185 C2440 回归（905→1090），已回退。

### 解决方案：跨模块 Variant 返回值函数 C 名集合

在 `driver.cpp` 中预扫描所有模块的 `FunctionDecl` 和 `PropertyDecl(PropertyGet)`，检查 `returnType` 是否为 Variant（nullptr = 隐式 Variant，或 SimpleTypeRef name="Variant"）。构建 C 函数名集合（`vb6_<moduleName>_<procName>` 格式，与 `cProcName()` 多模块模式一致），传递给 `CCodeGen`，在 `cExprIsVariant()` 中查询。

## 修改内容

### 1. `src/driver/driver.cpp`
- 添加 `#include <unordered_set>`
- 在 `classTypedFieldMap` 构建后、主 codegen 循环前，添加 `variantReturnFuncs` 集合构建循环：
  - 遍历所有模块的 `module->declarations`
  - 对 `FunctionDecl`：检查 `returnType`（nullptr 或 SimpleTypeRef "Variant"）
  - 对 `PropertyDecl`：仅处理 `PropertyGet`，procName 加 `prop_get_` 前缀
  - 构建 C 函数名：`vb6_<cIdent(moduleName)>_<cIdent(procName)>`（内联 cIdent 等价逻辑）
- 在两处 `CCodeGen` 构造调用中传入 `&variantReturnFuncs`

### 2. `src/backend/cgen.hpp`
- 构造函数添加参数：`const std::unordered_set<std::string>* variantReturnFuncs = nullptr`
- 添加成员变量：`const std::unordered_set<std::string>* variantReturnFuncs_ = nullptr`
- `cExprIsVariant()` 从 `static` 改为非静态成员函数（需访问 `variantReturnFuncs_`）

### 3. `src/backend/cgen_base.cpp`
- 构造函数添加 `variantReturnFuncs` 参数和初始化

### 4. `src/backend/cgen_util.cpp`
- `cExprIsVariant()` 添加项目函数检查：提取 C 表达式中的函数名（从 start 到第一个 `(`），查询 `variantReturnFuncs_` 集合

### 5. `src/backend/cgen_stmt.cpp`（Fix 045 前期变更，保留）
- `AssignmentStmt` concrete-target 分支：添加 `knownObjectVars_` 检测，Variant 值 → `vb6_VariantToObjectVal()` 转换
- `LetStmt` concrete-target 分支：同上

## 局限性

1. **函数参数上下文未改善** — "vb6_VARIANT → int32_t" 作为函数参数的错误未减少。原因：部分函数的 `calleeParams` 中参数类型与实际 C 签名不匹配（VB6 声明为 Variant 但 C 生成 int32_t），或 `calleeParams` 为空（运行时函数）。
2. **"具体类型 → vb6_VARIANT" 方向未改善** — int/BSTR/void* → vb6_VARIANT（392个错误）需要 `calleeParams` 正确识别 Variant 参数，与 `variantReturnFuncs_` 无关。
3. **C2106 +1 回归** — 可能是 Variant 检测改变导致某处赋值目标变化，影响微小。
