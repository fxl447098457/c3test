# c3log 005: 四个解析器修复（Type 成员硬关键字、ReDim 点访问、Erase 点访问、If-Then 冒号）

## 日期
2026-07-16

## 问题概述

Fix 004 之后，对剩余 23 个 FAIL + 3 CRASH 文件的新错误进行分析，识别出 4 个解析器缺陷。

修复前: 106 PASS / 16 FAIL / 3 CRASH (共 125)
修复后: 110 PASS / 13 FAIL / 2 CRASH (共 125)

## 修复内容

### 5a. Type 成员名使用硬关键字

**问题**: VB6 自定义类型的成员名可以使用硬关键字，如 `Next As Long`、`Type As Long`。`parseTypeDecl()` 使用 `expectName()` 只接受 Identifier 和软关键字。

**根因**: `parser_decl.cpp:169` `expectName("expected member name")` 不接受 `Next`、`Type` 等硬关键字。

**修复**: 在 `parseTypeDecl()` 中用与 `parseWithMemberExpr()` 相同的硬关键字容忍逻辑替换 `expectName()`。

### 5b. ReDim 语句的点访问

**问题**: `ReDim uOutput.Buffer(0 To lPos - 1) As CERT_RDN_ATTR` — ReDim 与 UDT 成员的点访问。解析器只接受单个变量名，不支持 `obj.Member`。

**根因**: `parseReDimStmt()` (`parser_stmt.cpp:904`) 使用 `expectName()` 只解析单个变量名，然后 `expect(LeftParen)` 期望 `(` 紧跟其后。遇到 `.` 时报错 "expected '(' after ReDim variable (got .)"。

**修复**: 在 `expectName()` 之后添加 `while (match(Dot))` 循环，解析 `.member` 链并拼接到变量名字符串中。使用与 Type 成员名相同的硬关键字容忍逻辑。

### 5c. Erase 语句的点访问和 With 块成员

**问题**: `Erase .RemoteLegacyNextTrafficKey` — Erase 语句操作 With 块成员。解析器只接受简单变量名。

**根因**: `parseEraseStmt()` (`parser_stmt.cpp:973`) 使用 `expectName()` 只接受 Identifier，遇到 `.` 报错 "expected variable name (got .)"。

**修复**: 重写 `parseEraseStmt()`，添加辅助 lambda 解析目标名：
- 如果以 `.` 开头，先消费，表示 With 块成员
- 然后接受 `canBeName()` 或硬关键字作为成员名
- 支持 `obj.Member.Member` 链

### 5d. 单行 If 的 Then 后冒号

**问题**: `If utc_NegativeOffset Then: utc_Offset = -utc_Offset` — `Then` 后跟冒号 `:` 是合法 VB6 语法。冒号作为语句分隔符。

**根因**: `parseIfStmt()` (`parser_stmt.cpp:370`) 在 `Then` 之后检查 `cur_` 是否为 NewLine/EOF 来判断单行 If，但没有跳过可能存在的冒号。`parseStatement()` 在收到 `Colon` 时报 "unexpected token in statement: :"。

**修复**: 在 `Then` 后、判断单行 If 之前，添加 `if (cur_.kind == TokenKind::Colon) { advance(); }` 跳过可选冒号。
