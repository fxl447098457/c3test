# Fix 044: WithMemberExpr ClassInstance Optional param padding

## Date
2026-07-22

## Problem
C2198 errors (too few arguments) for With-block class method calls where Optional parameters were not being padded. Two patterns:

1. **Standalone WithMemberExpr** (e.g., `.NewItem()` in a With block): When a WithMemberExpr with ClassInstance kind was used as a standalone expression (not as a callee in IndexOrCallExpr), it emitted `funcName(tempVar)` without padding Optional parameters.

2. **IndexOrCallExpr with WithMemberExpr callee**: When a WithMemberExpr class method was used as a callee in IndexOrCallExpr, the early-return optimization (line 2948) skipped the Optional padding logic. The callee `funcName(tempVar)` was returned as-is without padding.

## Root Cause
- `visit(WithMemberExpr)` ClassInstance case only emitted `funcName(tempVar)` without Optional padding when `!asCallCallee_`.
- `visit(IndexOrCallExpr)` had an early-return when callee was already a complete call `func(args)` with no extra args, skipping the calleeParams lookup and Optional padding.

## Fix

### Fix 044a: WithMemberExpr standalone Optional padding (cgen_expr.cpp ~line 4321)
In `visit(WithMemberExpr)` ClassInstance case, when `!asCallCallee_`:
- Call `findClassMemberCallParams()` to get the method's parameter list
- Pad Optional parameters with `defaultValue()` for ByVal, `&(type){default}` for ByRef
- Append `_has_` flags (all 0) for Optional params
- Generate `funcName(tempVar, pad1, pad2, ..., 0, 0)`

When `asCallCallee_=true`, still emit `funcName(tempVar)` and let IndexOrCallExpr handle padding.

### Fix 044b: IndexOrCallExpr needsSplitForOptionalPad flag (cgen_expr.cpp ~line 2922)
Added `needsSplitForOptionalPad` bool flag:
- When callee is `WithMemberExpr` with `ClassInstance` kind and known className, set flag to true
- Modified early-return condition: `if (isCompleteCall && !needsSplitForOptionalPad)` — skips early return when flag is set
- Modified split condition: `(!node.positional.empty() || !node.named.empty()) || needsSplitForOptionalPad` — triggers split even with 0 user args
- This allows the normal calleeParams lookup (Fix 041b) and Optional padding (line 3916+) to fire

## Result
- Total errors: 1595 -> 1592 (-3)
- C2198: 117 -> 114 (-3)
- Other categories unchanged

## Limitation
Only 3 errors fixed. Most remaining C2198 errors are from different patterns:
- Cross-module bare-call with Property Get object (pvSocket pattern)
- Property Let missing value argument
- VB6_SA_AT member access dropping arguments
- COM dispatch With-block objects detected as COMObject not ClassInstance
- Various other cross-module call issues

These need separate fixes (Fix 045+).
