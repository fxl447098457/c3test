## 1. 现象 (Symptom)

MSVC 报大量类型转换 + 参数数量错误, 抽样集中在 `cAsyncSocket.c` / `cTlsSocket.c` /
`cTlsReMaster.c` 等大量使用 WinAPI Declare 的文件:

```text
cAsyncSocket.c(380): error C2440: ".": 无法从"vb6_type_SOCKADDR_IN"转换为"vb6_type_SOCKADDR_IN *"
cAsyncSocket.c(612): error C2198: "int32_t vb6_di_ws_htons(int32_t)": 用于调用的参数太少
```

样本统计 C2440 子分类 (n=1586):
- **to_UDT 112** (UDT 值 → 指针, 系统性) ← Fix 027 主目标
- to_SafeArray 101
- to_int32 242
- BSTR 139
- 其他 ~992

## 2. 根因 (Root Cause — 主问题)

`cgen_expr.cpp::visit(IndexOrCallExpr&)` 调用处 ByRef 参数 emit 路径 (line 2546-2608) 依赖
`calleeParams` 被正确填充:

```cpp
bool isByRef = (i < calleeParams.size() && !calleeParams[i].isByVal
                && !calleeParams[i].isParamArray);
```

但 `calleeParams` 仅对 `SymbolKind::Sub/Function/Property*` 这 5 种符号 kind 填充:

```cpp
if (funcSym && (funcSym->kind == SymbolKind::Sub || funcSym->kind == SymbolKind::Function
    || funcSym->kind == SymbolKind::PropertyGet || ...)) {
    calleeParams = funcSym->params;
}
```

`Private Declare Function ws_getpeername Lib "ws2_32" Alias "getpeername" (...)
    As Long` 在符号表里是 `SymbolKind::DeclareFunc`, 不在上述 5 种之内, 故:

1. `IdentifierExpr` 路径 (line 691-716) 正确识别 declare 并 emit `cIdent(name)` (后续 `#define` 展开成 `vb6_di_<name>`), 表明声明被识别;
2. 但 `IndexOrCallExpr` 调用解析时, `DeclareFunc`/`DeclareSub` 不在 kind 白名单里 → `calleeParams` 留空;
3. ByRef 路径不触发 → ByRef 实参按值传递 → WinAPI 的 `SOCKADDR_IN*` 期望与 emit 的 `SOCKADDR_IN` 值不符 → C2440.

vbman 关键 Declare (摘自 `cAsyncSocket.cls`):

```vb6
Private Declare Function ws_getpeername Lib "ws2_32" Alias "getpeername" _
        (ByVal lSocket As Long, uName As SOCKADDR_IN, lpNameLen As Long) As Long
```

`uName` / `lpNameLen` 在 VB6 默认 ByRef, 调用 `ws_getpeername(socket, uAddr, LenB(uAddr))`
C 端期望 `&uAddr` / `&lenBarg`. 原 emit 没加 `&`, C 编译报无法从 `vb6_type_SOCKADDR_IN`
转换为 `vb6_type_SOCKADDR_IN *`.

## 3. 修改 P1: 把 DeclareSub / DeclareFunc 加入 kind 白名单 (Fix 027)

`src/backend/cgen_expr.cpp::visit(IndexOrCallExpr&)` 中 2 处 kind 检查同步加入 DeclareSub/DeclareFunc:

### IdentifierExpr callee 路径 (line ~2461-2484)

```cpp
// 旧:
if (!funcSym || (funcSym->kind != SymbolKind::Sub && funcSym->kind != SymbolKind::Function
    && funcSym->kind != SymbolKind::PropertyGet && funcSym->kind != SymbolKind::PropertyLet
    && funcSym->kind != SymbolKind::PropertySet)) {  // <- DeclareSub/Func 走这条 fallback, 再查一次仍 miss
    funcSym = symTab_.lookup(idExpr.name);
}
if (funcSym && (funcSym->kind == SymbolKind::Sub || funcSym->kind == SymbolKind::Function
    || funcSym->kind == SymbolKind::PropertyGet || funcSym->kind == SymbolKind::PropertyLet
    || funcSym->kind == SymbolKind::PropertySet)) {  // <- calleeParams 始终留空
    calleeParams = funcSym->params;
}

// 新:
if (!funcSym || (funcSym->kind != SymbolKind::Sub && funcSym->kind != SymbolKind::Function
    && funcSym->kind != SymbolKind::PropertyGet && funcSym->kind != SymbolKind::PropertyLet
    && funcSym->kind != SymbolKind::PropertySet
    && funcSym->kind != SymbolKind::DeclareSub && funcSym->kind != SymbolKind::DeclareFunc)) {
    funcSym = symTab_.lookup(idExpr.name);
}
if (funcSym && (funcSym->kind == SymbolKind::Sub || funcSym->kind == SymbolKind::Function
    || funcSym->kind == SymbolKind::PropertyGet || funcSym->kind == SymbolKind::PropertyLet
    || funcSym->kind == SymbolKind::PropertySet
    || funcSym->kind == SymbolKind::DeclareSub || funcSym->kind == SymbolKind::DeclareFunc)) {
    calleeParams = funcSym->params;
}
```

### MemberAccessExpr callee 路径 (line ~2475-2483) 同步加入

调用 `Module.SomeDeclare(...)` 形式也能拿到签名.

## 4. 副作用: C4002 类函数宏参数过多 (Fix 027a 触发, 70 个新错误)

加上 Fix 027 后, MSVC 报 70 个新 `C4002` 错误, 集中在 cAsyncSocket/cTlsSocket/cTlsReMaster:

```text
cAsyncSocket.c(1214): error C4002: 类函数宏的调用"RtlCopyMemory"参数过多
```

### 根因 2 (次问题)

C3 头文件为 Declare 生成:

```c
#ifndef CopyMemory
#define CopyMemory vb6_di_RtlMoveMemory
```

这是 **对象式** 宏, 但 Windows SDK `winnt.h` 早就 #define 了:

```c
#define RtlCopyMemory(Destination,Source,Length) memcpy((Destination),(Source),(Length))
```

`CopyMemory(a,b,c)` 经 `CopyMemory RtlCopyMemory` 间接展开到 `RtlCopyMemory(a,b,c)`,
理论上 3 个实参对的; 但 Fix 027 ByRef 路径把实参 emit 成 `&(vb6_VARIANT){.vt=VT_X, .field=Y}`
形式, **C 预处理器不认 `{}`作为实参分组括号**, 把 `{...}` 里的 `,` 当成宏实参分隔符, 算成 4 个参数
→ C4002 "参数过多".

Fix 026 基线时, calleeParams 为空 → ByRef 路径不触发 → 实参保持原样 (无 `&(T){...}` 包装) → 不踩这个坑.

### 修改 P2: 复合字面量地址 emit 加外层括号 (Fix 027b)

`src/backend/cgen_expr.cpp` IndexOrCallExpr ByRef 复合字面量地址 emit (line ~2587-2616) 全部
8 个分支加外层 `(...)`:

```cpp
// 旧 (7 个 VARIANT 分支):
argVal = "&(vb6_VARIANT){.vt=VT_BSTR, .bstrVal=" + argVal + "}";
// 旧 (通用):
argVal = "&(" + cType + "){" + argVal + "}";

// 新:
argVal = "(&(vb6_VARIANT){.vt=VT_BSTR, .bstrVal=" + argVal + "})";
argVal = "(&(" + cType + "){" + argVal + "})";
```

8 个分支 (VARIANT 7 种 .vt + 通用 1 种) 全部带外层括号 — `(&(T){.a=X, .b=Y})` 形式让 C
预处理器把整个 `(...)` 视为一个宏实参 (parens 是合法的分组符, 不像 braces 不算).

C 语法正确性: `(&(T){...})` 等价于 `&(T){...}` — 只是表达式外加了一层括号, 同样取得地址.

样本 emit (Fix 027 后):

```c
// Before (Fix 026):
ws_getpeername(me->m_hSocket, uAddr, LenB(uAddr))              // C2440!
// After (Fix 027b):
ws_getpeername(me->m_hSocket, &uAddr, (&(int32_t){LenB(uAddr)}))  // C2440 & C4002 都消失
```

`CopyMemory(&lPtr, (&(vb6_VARIANT){.vt=VT_BOOL, .boolVal=...}), LenB(lPtr))` — 复合字面量
被括号包住, 预处理器看到 3 个宏实参 ✓.

### 未改动的相似位置

`cgen_expr.cpp` / `cgen_stmt.cpp` 中还有几处 `&(T){0}` / `&(T){defVal}` 默认实参 emit (lines 2678, 2877, 2879, 3195, 3197, 2255, 2257) **未加括号**. 它们
emit 的是 `{0}` 或 `{单一标量}` (没有 `,`), 预处理器不会错算实参, 不踩 C4002 坑, 故暂不改.

P3 后续 (Fix 028+) 如出现默认值 defVal 含逗号的情形 (例如 `&(vb6_VARIANT){.vt=VT_BSTR, .bstrVal=X}`)
会引发同样的 C4002, 届时统一加括号.

## 8. 影响范围 (Scope of Change)

- **修改文件**: 1 个 (`src/backend/cgen_expr.cpp`)
- **改动行数**: P1 (+10 行 kind 检查) + P2 (8 处 emit 加外层 `()`) = ~25 行变化
- **机制**:
  - P1: IndexOrCallExpr 调用解析时把 DeclareSub/DeclareFunc 当作 Sub/Func 等价处理, 让
    calleeParams 拿到 declare 签名, 触发既有 ByRef `&` emit 路径.
  - P2: 实参包装复合字面量时, 整个 `&(T){...}` 外加 `(...)` 让 C 预处理器把它视为一个
    宏实参 (避免 `{a,b}` 里的 `,` 错算成宏实参分隔符 → C4002).
- **不破坏 ByVal 路径**: ByVal 实参不经 ByRef path, emit 不变.
- **不破坏对象式宏 declare** (vb6_InStr 等): `cIdent(name)` 在函数定义式 #define 下不影响.
