## Fix 007a: 允许用户 Sub/Function/Variable/Constant 覆盖内置符号

### 问题
4 个文件的类方法/变量名与 VB6 内置函数/对象同名，导致 VB3002 "重复声明"：

| 文件 | 行 | 名称 | 冲突的内置符号 |
|------|-----|------|----------------|
| cTimer.cls | 35 | `Timer` | 内置函数 `Timer` (semantic_analyzer.cpp:2231) |
| cTimers.cls | — | `Timer` | 同上 |
| cToolsDateTime.cls | 96 | `FormatDateTime` | 内置函数 `FormatDateTime` (semantic_analyzer.cpp:2244) |
| cRedisClient.cls | 1118 | `LTrim` | 内置函数 `LTrim` (semantic_analyzer.cpp:2103) |
| cHttpServerContext.cls | 19 | `App` | 内置对象 `App` (semantic_analyzer.cpp:2084) |

### 根因分析
`registerBuiltins()` 在 Pass 1 之前将 ~165 个内置函数和 7 个内置对象（如 `Timer`, `FormatDateTime`, `LTrim`, `App`）注册到模块作用域，全部带 `isBuiltin = true` 标志。

当用户定义同名方法时（如 `Public Function Timer() As Single`），`SymbolTable::define()` 调用 `Scope::define()`，后者发现 `storageKey()` 相同（都是 `lowerName`），返回 `false`，触发 VB3002。

已有的 COM 覆盖逻辑（行 126-135）仅处理 `ComClass/ComInterface/ComModule/ComGlobalNs` 类型的符号，不覆盖内置函数/变量。

### 修复
在 `SymbolTable::define()` 中（`symbol_table.cpp` 行 136 与 141 之间），添加内置符号覆盖逻辑：

```cpp
{
    auto* existing = current_->lookupLocal(lowerName);
    if (existing && existing->isBuiltin
        && !sym->isBuiltin
        && (sym->kind == SymbolKind::Sub
            || sym->kind == SymbolKind::Function
            || sym->kind == SymbolKind::Variable
            || sym->kind == SymbolKind::Constant)) {
        current_->symbols_.erase(existing->storageKey());
    }
}
```

逻辑：当已有符号是内置的（`isBuiltin == true`），新符号是用户定义的（`isBuiltin == false`）且类型为 Sub/Function/Variable/Constant 时，先移除内置符号，再注册用户符号。

### 安全性验证
- `getPublicSymbols()` (symbol_table.cpp:216) 已过滤 `isBuiltin`，覆盖后用户符号正常导出
- `lookup()` 查找时找到用户符号（同作用域），不影响调用解析
- `!sym->isBuiltin` 保证内置-vs-内置注册仍会检测重复

### 受影响文件
- `cTimer.cls` → PASS
- `cTimers.cls` → PASS
- `cToolsDateTime.cls` → PASS
- `cRedisClient.cls` → PASS
- `cHttpServerContext.cls` → PASS

### 修改位置
- `src\semantics\symbol_table.cpp` — `SymbolTable::define()` 函数 (约第 137-148 行)

## Fix 007b: Event 符号使用独立存储键，允许与同名 Sub/Function 共存

### 问题
2 个文件中声明了 Event 和 Sub 同名，导致 VB3002：

| 文件 | 行 | 名称 | 冲突 |
|------|-----|------|------|
| cTlsReMaster.cls | 44, 286 | `CloseSck` | `Public Event CloseSck()` vs `Public Sub CloseSck()` |
| cTlsReMaster.cls | 45, 301 | `Connect` | `Public Event Connect()` vs `Public Sub Connect()` |
| cWinsock.cls | 929 | `Connect` | 同上模式 |

### 根因分析
VB6 允许 Event 和 Sub/Function 同名——它们在不同的命名空间。Event 通过 `RaiseEvent EventName` 引用，Sub 通过普通调用引用。

C3 的 `storageKey()` 对 Property 使用 `$pg`/`$pl`/`$ps` 后缀区分，但对 Event 不加后缀，直接使用 `lowerName`，与 Sub/Function 冲突。

### 修复
在 `storageKey()` (`symbol_table.hpp` 行 190) 中为 Event 添加 `$ev` 后缀：

```cpp
if (kind == SymbolKind::Event) {
    return lowerName + "$ev";
}
```

### 安全性验证
- `RaiseEvent` 在语义分析中是 no-op (semantic_analyzer.cpp:56)，在代码生成中直接使用 `node.eventName`，不通过符号表查找 Event 符号
- 事件名通过 `classSym->eventNames` 独立收集 (semantic_analyzer.cpp:145)，与 `SymbolKind::Event` 符号无关
- 后端和驱动代码均不通过 `lookupLocal()` 查找 Event 符号
- `lookupLocal("closesck")` 现在找到的是 Sub（key=`closesck`），不会误找到 Event（key=`closesck$ev`）

### 受影响文件
- `cTlsReMaster.cls` → PASS (2 个 VB3002 错误消除)
- `cWinsock.cls` → PASS (1 个 VB3002 错误消除)

### 修改位置
- `src\semantics\symbol_table.hpp` — `storageKey()` 方法 (约第 190-202 行)
