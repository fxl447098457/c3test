# Fix 014 — 类实例方法调用的跨模块解析 (C2039 大幅减少)

## 概要

错误数 4103 → 3883 (-220). C2039 (not a member) 315 → 107 (-208).
本修复解决类实例方法 (obj.Method) 被错误生成为数据字段访问 (obj.member) 的问题.

## 问题分析

### 现象

`me.m_oSocket.Create(...)` 生成 C 代码为

```c
me->m_oSocket.Create(0, (me->m_eProtocol & 1), ...);  // 错误
```

应为:

```c
vb6_cTlsSocket_Create(me->m_oSocket, 0, (me->m_eProtocol & 1), ...);
```

`cTlsSocket.Create` / `cTlsSocket.SockOpt` / `cTlsSocket.Attach` /
`cTlsSocket.Close_` / `cTlsSocket.Accept` 等方法调用全部失败,
而 `cTlsSocket.UseTls` (Property Get) 调用正确.

### 根本原因 1: 链式成员访问 fallback 未处理 C 表达式

`visit(MemberAccessExpr)` 在 `cgen_expr.cpp` 中有两个分支:

- **Priority 2** (line ~1320): 处理 `<IdentifierExpr>.<Member>` 模式,
  对 `knownClassVars_` 中的对象变量调用 `resolveClassMemberCall`.
  仅在 `node.object->kind == ASTNodeKind::IdentifierExpr` 时触发.
- 通用 fallback (line ~1470): 处理任意对象表达式, 也尝试在 `knownClassVars_` 中查找.

对 `m_oSocket.Create` (对象是简单 IdentifierExpr), Priority 2 应触发.
但实际测试发现 Priority 2 内 `resolveClassMemberCall` 返回空,
fallback 也未命中 (因为 `objLower` 是完整 C 表达式 `me->m_osocket`,
而 `knownClassVars_` 只按简单变量名 `m_osocket` 注册).

### 根本原因 2: 跨模块符号去重导致 sourceModule 不匹配

`driver.cpp` 的全局 Public 符号注入逻辑以 `storageKey` 为 key 去重:

```cpp
std::unordered_map<std::string, std::pair<size_t, const Symbol*>> globalPublicSyms;
// storageKey 对 Sub/Function = lowerName (如 "create")
```

VB6 中多个类可以有同名的 Public 方法 (常见模式):

| Method | Declaring Classes |
|--------|------------------|
| Create | cAsyncSocket, cTlsSocket, cPassword |
| Attach | cAsyncSocket, cTlsSocket |
| Accept | cAsyncSocket, cTlsSocket, cTlsRemaster |
| Close_ | cModbusTransportRTU, cTlsClient, cAsyncSocket, cTlsSocket, cWinSock |
| LastError (PropertyGet) | 14 个类 (cZipArchive, cMSMQ*, cRedisClient, ...) |

`globalPublicSyms` 只保留 storageKey 首个出现的符号, 跨模块注入时
消费模块只能拿到错误类的方法符号 (`sourceModule` 是其他类).
`resolveClassMemberCall` 检查 `sym->sourceModule == className` 失败,
`foundSubFn` 保持 null → 返回空字符串 → 视为数据字段访问 → 生成 `obj.member` (C2039).

### 根本原因 3: Property Get 同样受 storageKey 冲突影响

对 LastError (PropertyGet, storageKey = `lasterror$pg`),
14 个类同名属性只能注入一个 → 无法通过常规 scope iteration 解析.
直接 Class symbol fallback 时不知道 method kind, 会按 Sub/Function 风格发出
`vb6_cTlsSocket_LastError` (无 prop_get_ 前缀), 与定义不匹配 → LNK 失败.

## 修复方案

### Fix 014a: `cgen_expr.cpp` visit(MemberAccessExpr) 通用 fallback

在通用 fallback 的 `knownClassVars_.find(objLower)` 失败时,
提取 obj 表达式尾部标识符再做查找:

- `me->m_oSocket` → `m_osocket`
- `(*p).field` → `field`
- `vb6_x()->y` → `y`

仅当尾部标识符在 `knownClassVars_` 中找到时, 用其类名调用
`resolveClassMemberCall` 解析成员. 此分支解决链式成员访问场景.

### Fix 014b: `cgen_util.cpp` resolveClassMemberCall — Class symbol fallback

当常规 scope iteration 返回空时:

1. 查找目标 `className` 对应的 Class 符号 (同模块或外部 sourceModule == className).
   每个 Class 符号 storageKey 为 lowerName, 模块间唯一, 不会被同名方法冲突覆盖.
2. 验证 `memberName` 在 Class 符号的 `memberNames` 列表中.
3. 确定前缀启发式: 若作用域中存在 `<memberLower>$pg` 外部符号 (任意类的同名属性),
   判定为 Property Get → 使用 `prop_get_` 前缀; 否则按 Sub/Function 无前缀.
4. 返回 `vb6_<className>_<prefix><memberName>`.

### Fix 014c: `cgen_base.cpp` 类成员扫描

首次尝试在第一遍扫描注册类成员到 `knownClassVars_` — 实际上 visit(VariableDecl)
的 trackOnly_=true 路径已经做了, 此改动冗余, 故 revert 回简单 NOTE 注释.

## 文件变更

- `src/backend/cgen_expr.cpp` (~1470-1560): visit(MemberAccessExpr) 通用 fallback
  新增尾部标识符提取 + 链式访问类变量识别.
- `src/backend/cgen_util.cpp` (~1158-1212): resolveClassMemberCall
  新增 Class symbol fallback + $pg 外部符号启发式前缀判定.
- `src/backend/cgen_base.cpp` (~130): 类成员扫描注释说明 (revert 冗余编辑).

## 结果

### 错误数对比 (Fix 013 → Fix 014)

| Error | Before | After | Δ |
|-------|--------|-------|---|
| C2039 | 315 | 107 | **-208** |
| C2223 | 17 | 32 | +15 (revealed) |
| C2440  | 1624 | 1692 | +68 (revealed) |
| 其他 | 2147 | 2052 | -95 |
| 总计 | 4103 | 3883 | **-220** |

C2223/C2440 增加是因为 C2039 减少后 MSVC 能深入检查更多文件, 暴露原本隐藏的
类型转换错误. 这些是真实错误, 将在后续 Fix (C2440 类型转换系列) 中处理.

### 样例修复

cTlsReMaster.c (原):

```c
me->m_oSocket.Create(0, ...);                /* 错误 */
me->m_oSocket->Close_  /* class var .Close_ field */();  /* 错误 */
me->m_oSocket->LastError  /* class var .LastError field */  /* 错误 */
```

cTlsReMaster.c (新):

```c
vb6_cTlsSocket_Create(me->m_oSocket, 0, ...);                       /* 正确 */
vb6_cTlsSocket_Close_(me->m_oSocket);                               /* 正确 */
vb6_cTlsSocket_prop_get_LastError(me->m_oSocket);                   /* 正确 (prop_get_ 前缀) */
```

## 已知限制

1. Property Let/Set 同名变体冲突 — 当前 fallback 仅处理 Get (读上下文).
   写上下文的 Property Let/Set 解析由 tryRewriteCOMLvalue 处理, 暂未触及.
2. 若目标类的成员 kind 与 scope 中已注入外部符号所属类的 kind 不同
   (例如 A 类有 Function LastError, B 类有 Property Get LastError),
   启发式会选错前缀 → LNK 错误. 可在 Class 符号中保留 memberKinds 解决.
3. 跨类同名字段 (Public Variable) 在本修复中未单独处理, 可能仍以数据字段方式访问.
