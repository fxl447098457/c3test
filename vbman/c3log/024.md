# Fix 024: scalar → VARIANT 编译期包装 (C2440 1842 → 1612, -230)

> 阶段: Fix 024 (P1 + P2)
> 基线: Fix 023e 之后 (commit `3085d2d`) — 总错误 3349, 其中 C2440 1842 (占总数 55%)
> 结果: Fix 024 v2 — 总错误 3153 (-196), 其中 C2440 1612 (-230)
> 状态: 已编译验证, 待提交
> 上游: 基于合并 `06a64df` (含 108 虚拟机同步) 后的工作树

## 背景

C2440 («不能从 X 转换到 Y») 占 Fix 023e 后总错误的 55%, 单一类错误量远超其它错误码。
按上下文 × 目标类型拆分, 主要瓶颈是 **scalar C 值 → vb6_VARIANT**:

| 上下文 | 目标类型 | 计数 | 说明 |
|---|---|---|---|
| 初始化 (=`_vcmp_N`) | vb6_VARIANT | 277 | BinaryExpr 比较临时变量 |
| 函数调用 (ByVal) | vb6_VARIANT | 633 | 调用点实参 → Variant 形参 |
| 赋值 | vb6_VARIANT | 137 | `var = scalar;` 左值为 Variant |
| 类型转换 | vb6_VARIANT | ~70 | 显式 cast |
| 函数调用 | BSTR | 126 | (其它类, 不在本 fix 范围) |
| 函数调用 | int32_t | 123 | (VARIANT → scalar, 不在本 fix 范围) |

P1+P2 锁定前两类 (INIT 277 + FUNCCALL 633 = 910, 占 C2440 总数 49%)。

## 根因

### P1: BinaryExpr `_vcmp_N` 临时变量

`src/backend/cgen_expr.cpp` `visit(BinaryExpr&)` 处理 Variant 比较时, 会 emit:

```cpp
vb6_VARIANT _vcmp_N = <left>;   // ← C2440 当 left 是 int32_t / BSTR 等标量
```

当 `inferExprType` 判定某侧为 Variant (例如 VB6 端 `LenB()` 返回 Variant 语义),
但实际 codegen emit 出的是 C 标量 (`int32_t`), 就直接产生 C2440。

共 **4 个临时变量初始化点**:
- L1017-1020: `Variant vs NonVariant` 路径, 包装 `left`
- L1043-1045: `NonVariant vs Variant` 反向路径, 包装 `right`
- L1059: `Variant vs Variant` 路径, 包装 `left` (lambda 内)
- L1060: `Variant vs Variant` 路径, 包装 `right` (lambda 内)

### P2: ByVal Variant 形参的实参包装

`visit(IndexOrCallExpr&)` 参数循环中, 当被调用方某形参声明为
`ByVal x As Variant` 时, 实参 side 必须传 `vb6_VARIANT` 值。
但 codegen emit 出来的实参往往是 `int32_t` / `BSTR` / `void*` 等标量 → C2440。

原 ByRef 路径已有 VARIANT 包装逻辑 (L2564-2592), 但 ByVal 路径未做对称处理。

## 修复方案

核心思路: **在 RTL 层提供一个 `_Generic` 多态宏 `vb6_VariantFromValue(x)`,
编译期按实参 C 类型自动选择对应的 Variant 构造函数**, 让 codegen 无需知道
实参精确类型即可完成标量 → VARIANT 的转换。

### 改动 1: `src/rtl/core/vb6rtl.h` (新增构造函数 + _Generic 宏)

在现有 Variant 构造函数后 (L250 之后) 新增:

```cpp
// Fix 024: 补充缺失的 Variant 构造函数
static inline vb6_VARIANT vb6_VariantByte(uint8_t val) {
    vb6_VARIANT v; memset(&v, 0, sizeof(v));
    v.vt = VT_UI1; v.bVal = val; return v;
}
static inline vb6_VARIANT vb6_VariantObject(void* val) {
    vb6_VARIANT v; memset(&v, 0, sizeof(v));
    v.vt = VT_UNKNOWN; v.punkVal = (IUnknown*)val; return v;
}
// Fix 024: Variant identity passthrough — used by vb6_VariantFromValue
static inline vb6_VARIANT vb6_VariantIdentity(vb6_VARIANT v) { return v; }

// Fix 024: 编译期多态包装宏 — 按 C 实参类型自动选择构造函数
//   用法: vb6_VARIANT v = vb6_VariantFromValue(any_C_expr);
//   语义: 把任意标量/指针/已 Variant 包装成 vb6_VARIANT, 消除 C2440
#define vb6_VariantFromValue(x) _Generic((x), \
    int:                  vb6_VariantLong, \
    unsigned int:         vb6_VariantLong, \
    long:                 vb6_VariantLong, \
    unsigned long:        vb6_VariantLong, \
    short:                vb6_VariantInt, \
    unsigned short:       vb6_VariantInt,   /* ← 注: 见下方坑 */ \
    int16_t:              vb6_VariantInt, \
    uint16_t:             vb6_VariantInt, \
    int32_t:              vb6_VariantLong, \
    uint32_t:             vb6_VariantLong, \
    int64_t:              vb6_VariantLong, \
    uint64_t:             vb6_VariantLong, \
    long long:            vb6_VariantLong, \
    unsigned long long:   vb6_VariantLong, \
    char:                 vb6_VariantInt, \
    signed char:          vb6_VariantInt, \
    unsigned char:        vb6_VariantByte, \
    float:                vb6_VariantDouble, \
    double:               vb6_VariantDouble, \
    void*:                vb6_VariantObject, \
    const void*:          vb6_VariantObject, \
    wchar_t:              vb6_VariantInt, \
    BSTR:                 vb6_VariantString, \
    const BSTR:           vb6_VariantString, \
    VARIANT_BOOL:         vb6_VariantBool, \
    vb6_VARIANT:          vb6_VariantIdentity, \
    default:              vb6_VariantObject \
)(x)
```

> **坑 (已修复)**: 初版还包含 `unsigned short:` 和 `long double:` 两个选择器, 导致 490 个 C7700
> (wchar_t 与 unsigned short 兼容冲突, `_Generic` 选择器必须唯一) 。已删除这两个选择器。
> 原因: MSVC 默认 `/Zc:wchar_t` 将 `wchar_t` 视为原生类型, 与 `unsigned short` 不兼容 — `_Generic`
> 不能同时列出二者。删除后 C7700 回到 0。

### 改动 2: `src/backend/cgen_expr.cpp` — P1 (4 处 `_vcmp_` 初始化)

把 `vb6_VARIANT <tmp> = <expr>;` 全部改为 `vb6_VARIANT <tmp> = vb6_VariantFromValue(<expr>);`
(对应 L1020, L1045, L1059, L1060)。
这样无论 `inferExprType` 与 codegen 实际类型是否一致, 都能由编译器挑选正确构造函数。

### 改动 3: `src/backend/cgen_expr.cpp` — P2 (ByVal Variant 形参包装)

在 `visit(IndexOrCallExpr&)` 参数循环 ByVal 路径 (L2602 前, `args.push_back` 之前) 新增:

```cpp
// Fix 024 P2: ByVal Variant 参数 — 调用点用 vb6_VariantFromValue 包装实参.
if (!isByRef && i < calleeParams.size() && calleeParams[i].isByVal
    && calleeParams[i].type == Vb6Type::Variant) {
    argVal = "vb6_VariantFromValue(" + argVal + ")";
}
```

仅在 calleeParams 已解析 (本模块内函数, 或同模块 Public 函数) 且对应形参明确声明为
ByVal Variant 时触发, 避免对错误场景造成误包装。

## 已知局限与下一步

### P2 覆盖率不足 (560 残留)

P2 条件 `calleeParams[i].type == Vb6Type::Variant` 要求 calleeParams 已解析。
当被调用方是 **跨模块/COM 调用** (`symTab_.lookupModule` 失败) 时, `calleeParams` 为空,
P2 不触发。剩余 560 处源类型分布:

- `vb6_SafeArray1D *` 137 — 需走 `vb6_VariantArray`, `_Generic` 已覆盖但 calleeParams 解析失败
- `int` / `int32_t` 192 — 同上
- `void *` 66 — 同上
- `BSTR` 33, `const BSTR` 25 — 同上
- `LONG` 21, `BSTR *` 18 — 同上
- 其它指针 — 同上

**Fix 025 候选方向**: 给 P2 增加回退路径 — 当 `calleeParams.empty()` 且实参 inferExprType
不是 Variant 但被调用方 hint 是 Variant (或无条件回退) 时, 也走 `vb6_VariantFromValue`。
风险: 可能对不应包装的场景误包装 → C2197 增加。需配合 callee hint 推断。

### 未实施的 C2440 类别 (后续 Fix)

- **VARIANT → scalar 反向提取** (2a, ~330 处): 需 `vb6_VariantToLong/Double/...` 在右值上下文使用
- **SafeArray ↔ VARIANT** (~200 处): SafeArray* ↔ VARIANT 的双向转换
- **UDT value → UDT\*** (3 类, ~73 处): ByRef UDT 形参需要取地址, 实参是 UDT 值
- **ASSIGN → VARIANT** (137 处): 赋值上下文的标量 → Variant, 类似 P1 但在 `visit(AssignStmt&)`

### 次生错误小幅上升 (-196 净, 但个别 +N)

- C2197 +15, C2172 +10, C2198 +2: P2 包装后参数类型变化触发 — 大多是无害的类型对齐
  噪音, 后续 Fix 中可一并处理。
