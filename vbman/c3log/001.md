# c3log 001: 行续行符（`_`）在词法分析器中为死代码

## 日期
2026-07-15

## 问题概述

C3 编译器的词法分析器中，VB6 的行续行符（`_`）处理逻辑完全不可达，导致所有使用行续行的 VB6 源文件无法正确编译。这是 vbman 项目（125 个源文件）中大部分编译失败的根本原因。

## 根因分析

### 1. isAlpha() 包含下划线

`src/lexer/lexer.cpp` 第 183-184 行：

```cpp
bool Lexer::isAlpha(char c) const {
    return (c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z') || c == '_';
}
```

`isAlpha('_')` 返回 `true`。

### 2. scanToken() 分发顺序问题

`src/lexer/lexer.cpp` 的 `scanToken()` 函数中，标识符/关键字的分发检查（第 359 行）在 `case '_'`（第 428 行）之前执行：

```cpp
// 第 359 行 — 先执行
if (isAlpha(c) || c == '[') {
    // ...
    return scanIdentifierOrKeyword();  // _ 被当作标识符首字符
}

// ... switch 中的其他 case ...

// 第 428 行 — 永远不会到达
case '_':
    if (isLineContinuation()) {
        return scanLineContinuation();
    }
    return scanIdentifierOrKeyword();
```

由于 `isAlpha('_')` 返回 `true`，任何 `_` 字符都会被路由到 `scanIdentifierOrKeyword()`，而不是行续行处理逻辑。`case '_'` 及其调用的 `isLineContinuation()` 和 `scanLineContinuation()` 成为死代码。

### 3. 完整的行续行基础设施存在但不可达

- `TokenKind::LineContinuation`（token.hpp 第 291 行）—— 已定义
- `isLineContinuation()`（lexer.cpp 第 211-228 行）—— 检查 `_` 后是否只有空白和换行
- `scanLineContinuation()`（lexer.cpp 第 684-706 行）—— 消费 `_`、尾部空白、换行、下一行开头的空白
- `afterLineContinuation_` 标志（lexer.hpp 第 94 行）—— 被设置但从未被读取
- `case '_'`（lexer.cpp 第 428-434 行）—— 死代码

### 4. 解析器未过滤 LineContinuation token

`src/parser/parser.cpp` 中：
- `fetchNextToken()`（第 125 行）只过滤 `Comment` token，不过滤 `LineContinuation`
- `skipNewLines()`（第 289 行）只跳过 `NewLine` 和 `Comment`，不跳过 `LineContinuation`

## 修复方案

### 修复 1：lexer.cpp — 在 isAlpha 检查之前增加行续行检查

在 `scanToken()` 中，在 `if (isAlpha(c) || c == '[')` 之前添加行续行检查：

```cpp
// 行续接符 _ (必须在 isAlpha 检查之前, 因为 isAlpha('_') 返回 true,
// 否则 _ 会被当作标识符首字符, 导致行续接逻辑成为死代码)
if (c == '_' && isLineContinuation()) {
    return scanLineContinuation();
}

// 标识符/关键字
if (isAlpha(c) || c == '[') {
```

**设计决策**：没有从 `isAlpha()` 中移除 `_`，因为 `_` 仍然是标识符中的有效字符（如 `my_var`）。只是在分发逻辑中提前检查行续行，如果 `_` 后面不是只有空白+换行，则正常落入 `isAlpha()` 路径作为标识符处理。

### 修复 2：parser.cpp — fetchNextToken() 过滤 LineContinuation

```cpp
// 修改前
} while (tok.kind == TokenKind::Comment);

// 修改后
} while (tok.kind == TokenKind::Comment || tok.kind == TokenKind::LineContinuation);
```

### 修复 3：parser.cpp — skipNewLines() 跳过 LineContinuation

```cpp
// 修改前
while (cur_.kind == TokenKind::NewLine || cur_.kind == TokenKind::Comment) {

// 修改后
while (cur_.kind == TokenKind::NewLine || cur_.kind == TokenKind::Comment || cur_.kind == TokenKind::LineContinuation) {
```

### 预处理器

预处理器（`preprocessor.cpp`）不需要修改。`processToken()` 通过 `fetchRaw()` 传递所有非预处理指令 token，`LineContinuation` token 会被正常传递给解析器，由解析器负责过滤。
