# Fix 049: 局部/模块常量类型注册 + wrapToBSTR BSTR 检测 + isDefinitelyVariantExpr 误报修复

## 错误现象

C2440 "BSTR → vb6_VARIANT" 错误（85个），主要来自两个根因：

1. **wrapToBSTR 误报**: `VB6_SA_AT(BSTR, cookieArray, iCookie)` 返回 BSTR，但 `inferExprType` 回退到 Variant，`wrapToBSTR` 生成 `vb6_CStr(BSTR_expr)` → C2440（`vb6_CStr` 期望 VARIANT 参数）。

2. **isDefinitelyVariantExpr 误报**: BSTR 参数/变量（如 `Key As String`）被 `isDefinitelyVariantExpr` 误判为 Variant，导致参数包装代码插入 `vb6_VariantToString(BSTR_expr)` → C2440（`vb6_VariantToString` 期望 VARIANT 参数）。

3. **常量类型未注册**: 局部 `Const FUNC_NAME As String = "..."` 和模块级 `Const` 声明只在 `knownLocalVars_` 中注册，不在 `knownBstrVars_`/`knownLongVars_` 等类型特定集合中注册。`inferExprType` 找不到符号，回退到 Variant。

## 根因分析

### 根因 1: wrapToBSTR 缺少 VB6_SA_AT(BSTR, 检测

`wrapToBSTR` (cgen_expr.cpp:790) 的 BSTR 检测链中，没有检测 `VB6_SA_AT(BSTR, arr, idx)` 模式。该宏返回 BSTR 类型值，但由于不以 `vb6_` 开头，跳过了所有前缀检查，最终到达 `inferExprType` 回退到 Variant，生成 `vb6_CStr(expr)`。

### 根因 2: isDefinitelyVariantExpr 不检查 knownBstrVars_

`isDefinitelyVariantExpr` (cgen_util.cpp:771) 对 `IdentifierExpr` 的处理：
1. 检查 `knownVariantVars_` — 如果在集合中，返回 true
2. 查询符号表 `symTab_.lookup(name)` 和 `symTab_.lookupModule(name)`

问题：步骤 2 的 `lookupModule` 会搜索所有模块的公共符号。如果另一个模块有同名的 Variant 返回类型属性/函数，会误判本地 BSTR 变量为 Variant。即使 `Key` 已在 `knownBstrVars_` 中注册，`isDefinitelyVariantExpr` 也不检查该集合。

### 根因 3: 常量声明不注册类型信息

- 局部 `Const` 声明 (cgen_stmt.cpp:3311) 只注册到 `knownLocalVars_`
- 模块级 `Const` 声明 (cgen_decl.cpp:557) 使用 `#define`，不注册到任何 `known*Vars_` 集合
- 对比：`Dim` 声明 (cgen_decl.cpp:749-767) 正确注册到 `knownBstrVars_`/`knownLongVars_`/`knownDoubleVars_`/`knownVariantVars_`

## 修复方案

### 修复 1: 局部常量类型注册 (cgen_stmt.cpp ~line 3317)

在局部 `ConstDecl` 处理中，根据 `cType` 注册到类型特定集合：
- `BSTR` → `knownBstrVars_`
- `int32_t`/`int16_t`/`VBABOOL` → `knownLongVars_`
- `double`/`float` → `knownDoubleVars_`
- `vb6_VARIANT` → `knownVariantVars_`

### 修复 2: 模块级常量类型注册 (cgen_decl.cpp ~line 561)

在模块级 `visit(ConstDecl&)` 中，添加相同的类型特定注册逻辑。

### 修复 3: wrapToBSTR VB6_SA_AT(BSTR, 检测 (cgen_expr.cpp ~line 811)

在 `wrapToBSTR` 的 BSTR 检测链中添加：
```cpp
if (expr.find("VB6_SA_AT(BSTR,") != std::string::npos) return expr;
```

### 修复 4: wrapToBSTR Variant case knownBstrVars_ 检查 (cgen_expr.cpp ~line 878)

当 `inferExprType` 返回 Variant 时，检查 AST 节点是否为已知 BSTR 变量：
```cpp
case Vb6Type::Variant: {
    if (node.kind == ASTNodeKind::IdentifierExpr) {
        auto& id = static_cast<IdentifierExpr&>(node);
        std::string lower = id.name;
        std::transform(lower.begin(), lower.end(), lower.begin(), ::tolower);
        if (knownBstrVars_.count(lower)) return expr;
    }
    return "vb6_CStr(" + expr + ")";
}
```

### 修复 5: isDefinitelyVariantExpr knownBstrVars_ 检查 (cgen_util.cpp ~line 805)

在 `IdentifierExpr` 处理中，在符号表查询之前检查已知具体类型集合：
```cpp
if (knownBstrVars_.count(lower) || knownLongVars_.count(lower)
    || knownDoubleVars_.count(lower)) {
    return false;
}
```

### 修复 6: vb6_VariantToString 提取守卫 (cgen_expr.cpp ~line 3358, 3384)

在参数包装代码中，插入 `vb6_VariantToString` 之前检查 C 表达式是否已是 BSTR：
```cpp
if (argVal.find("VB6_SA_AT(BSTR,") == std::string::npos
    && argVal.find("vb6_BSTR") == std::string::npos) {
    argVal = "vb6_VariantToString(" + argVal + ")";
}
```

## 注意事项

- 修复 4 使用 `knownBstrVars_` 检查而非 `cExprIsVariant`，因为 `cExprIsVariant` 对普通 Variant 变量名返回 false，会导致这些变量在 `wrapToBSTR` 中不被转换，引发 VARIANT→BSTR 错误。
- 修复 5 仅影响 `IdentifierExpr`，不影响 `IndexOrCallExpr` 和 `MemberAccessExpr` 的 Variant 检测。
- 修复 6 是安全网，防止 `isDefinitelyVariantExpr` 的 `IndexOrCallExpr` 路径对 BSTR 数组元素误报。
