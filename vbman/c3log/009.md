# Fix 009: MSVC 检测失败 + 命令行过长

## 问题

### 009a: MSVC 检测失败
vbman 完整编译时，C3 成功完成所有内部阶段（解析、语义分析、代码生成、TypeLib 生成），
但在最后的链接阶段报错：

```
C3: error: MSVC not found (install Visual Studio 2017+ with C++ workload)
```

本机已安装 Visual Studio Build Tools 2022（路径：
`C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools`），
vcvarsall.bat 存在于：
`C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvarsall.bat`

### 根因

`MsvcDriver::findVsInstallPath()` 使用 `vswhere.exe` 查找 VS 安装路径，
但命令行缺少 `-products *` 参数：

```cpp
// 修复前
std::string cmd = "\"" + vswhere + "\" -all -latest -property installationPath";
```

vswhere.exe 默认只查找 Visual Studio Community/Professional/Enterprise，
**不包含 BuildTools**。需要加 `-products *` 才能检测到 BuildTools 安装。

验证：
```
vswhere -all -latest -property installationPath        → 空 (找不到)
vswhere -all -latest -products * -property installationPath → C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools
```

### 修复

**文件**: `src\backend\msvc_driver.cpp`

1. **Fix 009a-1**: 在 vswhere 命令中添加 `-products *`

```cpp
// 修复后
std::string cmd = "\"" + vswhere + "\" -all -latest -products * -property installationPath";
```

2. **Fix 009a-2**: 添加文件系统直接路径检查作为额外后备方案

在 `findVsInstallPath()` 的注册表后备方法之后，添加 Method 3：
直接检查常见安装路径（BuildTools、Community、Professional、Enterprise，
覆盖 2022 和 2019 版本，检查 Program Files (x86) 和 Program Files 两个目录）。
这确保即使 vswhere 缺失或不报告产品，也能找到 MSVC 安装。

---

### 009b: cl.exe 命令行过长

### 问题

Fix 009a 修复后，MSVC 被成功检测到，cl.exe 开始执行，但报错：

```
The command line is too long.
```

### 根因

C3 生成了 126 个 .c 源文件（125 个 VB6 模块 + dll_entry.c），
`compileAndLink()` 将所有源文件路径和编译选项放在一条 cl.exe 命令行上。
126 个文件路径 + 编译选项总计超过 Windows cmd.exe 的 8191 字符限制。

### 修复

**文件**: `src\backend\msvc_driver.cpp` — `compileAndLink()` 方法

修改为使用 **response file** (@file.rsp) 传递编译参数：

1. 将所有 cl.exe 参数（/I 路径、编译选项、源文件列表、/link 链接选项）写入
   临时 response file（`_c3_cl_args.rsp`）
2. 命令行改为 `cl.exe @"_c3_cl_args.rsp"`，大幅缩短实际命令行长度
3. 编译完成后无论成功失败均清理 response file

MSVC cl.exe 原生支持 `@filename` 语法从文件读取命令行参数，
这是处理大量源文件的标准做法。

---

## 结果

- MSVC 检测：✅ 成功找到 BuildTools 2022
- cl.exe 执行：✅ response file 使命令行长度不再受限
- C 代码编译：❌ 发现大量 C 代码生成错误（13000+ 行错误），
  属于 C3 代码生成器（cgen）的问题，将在后续 Fix 010+ 中修复

## 涉及文件

- `src\backend\msvc_driver.cpp`:
  - `findVsInstallPath()`: 添加 `-products *` 到 vswhere 命令 + 文件系统路径后备
  - `compileAndLink()`: 使用 response file 替代直接命令行参数
