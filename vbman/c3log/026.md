## 1. 现象 (Symptom)

MSVC 报 48 处 `C2231`：

```text
cHttpServerRouter.c(29): error C2231: ".Context": 左操作数指向 "vb6_cls_cClientCallback"
                                         指向类型，请使用 "->"
```

集中在 `cHttpServerRouter.c`, `cHttpServer.c`, `cTlsSocket.c`, `cAsyncSocket.c`, `cClientCallback.c` 等大量使用 ByRef class 参数的文件。

## 2. 根因 (Root Cause)

VB6 中 `ByRef Client As cClientCallback` 这类**类参数**在 C 后端的形式是
`vb6_cls_cClientCallback**` (指针的指针)。`cgen_expr.cpp` 的 `IdentifierExpr` 为
ByRef 参数 emit 出 `(*Client)` 形式 (即解引用一次得到 `cls*`)，再访问其方法/字段
时应使用 `->`，而不是 `.`。

但 `MemberAccessExpr` 主体的类变量回退路径 (line ~1642) **直接用 `obj` 字符串做
小写后到 `knownClassVars_` 查表**。对于普通 class 成员变量 (`me->m_xxx`，调用方是
`this`) 来说 `obj` 是裸标识符，能正常命中；可一旦 `obj == "(*Client)"`，小写后
变成 `"(*client)"`，永远不可能命中 `knownClassVars_` 中的 `"client"` 条目，于是
代码兜底走最后一支 **`obj + "." + cIdent(node.memberName)`**，emit 出错误的
`(*Client).Context` —— 指针用 `.` 操作符正是触发 C2231 的元凶。

UDT (用户定义结构体 `Type ... End Type`) 的 ByRef 参数在 C 中是 `struct_t*`，
`(*rec)` 得 `struct_t`，`(*rec).field` 用 `.` 是**正确**的，不应改变。

因此 Fix 026 只需在**类变量查询前剥去 `(*X)` 外层**；剥之后:
* 若 X 在 `knownClassVars_` 命中 → 是 Class，仍走 `obj + "->" + ...` (注意 obj
  保留原始 `(*X)` 串，`(*X)->member` 是合法的 C 解引用后箭头)
* 若 X 不在 `knownClassVars_` 命中 (UDT、未知 struct) → 兜底 `obj + "." + ...`，
  emit `(*X).member`，对 UDT 仍正确

## 4. 关键边界说明 (Edge Cases)

### 4.1 为什么 UDT 不受影响

UDT (例如 `Type Rect : Left As Long : End Type`) 的 ByRef 参数 `ByRef R As Rect`
在 C 中是 `vb6_udt_Rect*`，`(*R)` 得到 `vb6_udt_Rect` 值。访问 `R.Left` 在 C 中
正确写法是 `(*R).Left`，必须用 `.`。

UDT 类型**不会**注册到 `knownClassVars_` (它只装 VB6 Class 实例变量)。所以剥离
`(*R)` 得到 `"r"` 之后，`knownClassVars_.find("r")` 仍然 miss，落入最后的
兜底支 `obj + "." + cIdent(...)`，emit `(*R).Left`，对 UDT 依然正确。

### 4.2 为什么 emit 仍用原 `obj` 而不是 `objBase`

emit 时若换 `obj` 为 `objBase` 会得到 `R->Left` —— 对 UDT 是错的
(`R` 在 UDT 上下文里是 `struct_t*`, `R->Left` 才是对的，**但前提是 R 本身就
是指针**)。ByRef UDT 的 `R` 在 C 里是 `vb6_udt_Rect*`，本就是指针，`R->Left`
其实也对；只是 VB6 后端为了统一 emit，强制写成 `(*R).Left` 形式，便于上下文
区分 (me->X 也类似处理)。

保留原 `obj = "(*R)"` 故 emit 出 `(*R)->Left` (Class, 正确) 或
`(*R).Left` (UDT 兜底, 正确)，两条路径各自正确。

### 4.3 链式访问 `(*Client)->Parent->RouteBefore`

链式表达式的内层 MemberAccess 已识别为 class (因 `Parent` 在 `cClientCallback`
的字段集里)，emit `(*Client)->Parent`。外层 `.RouteBefore` 接收 `obj =
"(*Client)->Parent"`，剥离逻辑因不满足"(`*X`)"完整匹配而不动 obj，正常走原有
Fix 014 尾部标识符提取逻辑 (`trailingLower = "parent"`) 在
`knownClassVars_` 找类型，并 emit `obj + "->" + RouteBefore`。
最终输出 `(*Client)->Parent ->RouteBefore` (中间无空格)，C 编译正确。
