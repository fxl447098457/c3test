# Fix 022 — For 循环变量作用域: 类成员被误注册为本地变量 (C2065)

**修复编号**: 022
**提交**: pending
**日期**: 2026-07-19
**类型**: codegen 作用域 bug 修复

## 现象

| 标识符 | 错误数 | 主要分布 |

## 调查

### 源

`vbman/src/Csv/cCsv.cls:51`:
```vb
Dim x, y, z, i As Long, ii As Long
```

声明在 `.cls` 文件**模块级** (类字段), 不是函数内 Dim. C3 正确生成 cCsv.h 的 struct 字段:
```c
struct vb6_cls_cCsv {
    ...
    vb6_VARIANT x;
    vb6_VARIANT y;
    vb6_VARIANT z;
    int32_t i;
    int32_t ii;
    ...
};
```

但 cCsv.c 中函数内对 `ii` 的所有引用都是裸标识符, 例:
```c
// For 循环头
ii = 1;
for (; ii <= ii_end; ii += ii_step) { ... }

// 循环体内
vb6_CStrLong(ii)
vb6_ComCall(Row, L"Item", (void*[]){vb6_ComPackInt(ii)}, 1)
```

而同函数内对其他类成员 (`HeadTitleWidth`) 的引用则是正确的 `me->HeadTitleWidth`. 所以 `ii` 应该是 `me->ii`. 函数内无任何 C 局部 `ii`, 唯一声明是 struct 字段 `me->ii`, 故 MSVC 报 C2065.

### Fix 010o 的回归

定位到 `src/backend/cgen_stmt.cpp`, `visit(ForStmt&)` 中 Fix 010o 添加的逻辑 (问题点):

```cpp
std::string var = cIdent(node.varName);

// Fix 010o: 注册For循环变量到 knownLocalVars_ (避免被错误加 me-> 前缀)
{
    std::string lower = node.varName;
    std::transform(lower.begin(), lower.end(), lower.begin(), ::tolower);
    knownLocalVars_.insert(lower);
}
```

**Fix 010o 的本意**: 若 For 循环变量在函数内以 Dim 声明 (local shadow), 避免 IdentifierExpr 给它加 `me->` 前缀 (因为它是 C 局部, 不是类成员). 这对 `Dim i As Long / For i = 1 To 10` 模式正确.

**bug**: Fix 010o 无差别注册, 不区分 "变量实际是类成员" 还是 "变量是局部 Dim". 当 For 循环变量是类成员 (例 `For ii = 1 To N` 且 `ii` 是 class field) 时, 错误地阻止了 `me->` 前缀.

### 影响路径

1. `ForStmt` emit 自身的 `var = start`, `var <= var_end`, `var += var_step` 直接拼字符串, **不走 IdentifierExpr**, 所以即使 knownLocalVars_ 不阻止 prefix, 这里也不会自动加 me->. 这是双重 bug.
2. 函数体内对 `ii` 的引用走 `visit(IdentifierExpr)` (cgen_expr.cpp), 第 425-432 行有 `me->` 前缀逻辑:
   ```cpp
   if (isClassModule_ && currentProc_ && foundSym->kind == SymbolKind::Variable
       && !knownLocalVars_.count(lower)
       && !foundSym->isExternal) {
       ...
       lastExpr_ = "me->" + cName;
   }
   ```
   `!knownLocalVars_.count(lower)` 为 false (因 Fix 010o 已注册), 因此跳过 `me->` 前缀 → 裸标识符 `ii`.
3. `knownLocalVars_` 也在其他 codegen 处检查 (ReDim/Erase/array access `arr(i)`), 同样受影响 (但 `ii` 是 Long 不是数组, 未触发).

### 验证来源

`classMemberVars_` 由 `cgen_base.cpp:89-138` 在类模块开始 codegen 时填充 (在处理方法体之前). 对每个 `module.declarations` 中的 VariableDecl, 同时注册两个 lowercase 形式: `m_Xxx` (m_ 前缀变体) 和原始 `Xxx`. cCsv 的 `i`/`ii` 都会进入此集合.

cCsv.h 的 struct 字段实际用**裸名** `int32_t i;` `int32_t ii;` (无 m_ 前缀), 所以 `me->i` `me->ii` 是正确的 C 表达式.

## 修复方案

`visit(ForStmt&)` 与 `visit(ForEachStmt&)` (后者同 bug 同模式), 在 Fix 010o 之前先检查变量是否是类成员:

```cpp
std::string lower = node.varName;
std::transform(lower.begin(), lower.end(), lower.begin(), ::tolower);
bool forVarIsClassMember = isClassModule_
    && classMemberVars_.count(lower)
    && !knownLocalVars_.count(lower);   // 局部 Dim 优先遮蔽类成员
std::string varAcc = forVarIsClassMember ? ("me->" + var) : var;
if (!forVarIsClassMember) {
    knownLocalVars_.insert(lower);       // Fix 010o (保留, 仅对非类成员)
}
```

- 若 `forVarIsClassMember == true`: 用 `varAcc = "me->" + var` emit 循环自身的赋值/比较/累加 (`me->ii = 1`, `me->ii <= ii_end`, `me->ii += ii_step`), 且**不**注册到 `knownLocalVars_` — 循环体内的 `ii` 引用走 IdentifierExpr 时下游 `me->` 路径自然触发.
- 若 false (变量是局部 Dim 或非类成员): 保持原 Fix 010o 行为 (注册 + 裸 var).
- `varAcc` 用于循环自身的赋值/比较/累加.
- `var` 仍用于临时变量名 `var_end` `var_step` (这些是 block-scoped int32_t, 无需 me->).

### 三层优先级处理

- **C 局部 Dim** (优先级最高): 局部 Dim 在 `cgen_decl.cpp` 处理时已注册到 `knownLocalVars_`, 所以 `!knownLocalVars_.count(lower)` 检查在 ForStmt 中为 false → forVarIsClassMember = false → 走原 Fix 010o 路径 (裸 var + 注册), 符合 "局部遮蔽类成员" 的 VB6 语义.
- **类成员** (无局部遮蔽): `classMemberVars_.count(lower)` 为 true 且 local 集合无 → forVarIsClassMember = true → 走新路径 (me->var, 不注册).
- **跨模块/全局变量** (非类模块或不在 classMemberVars_): `classMemberVars_.count(lower)` 为 false → forVarIsClassMember = false → 走原路径.
