# Fix 013: 类型名称规范化 — 消除 C2037 (undefined struct/union)

## 问题根因

VB6 模块有两个"名称"来源：

1. **文件名 stem** (`baseName_`): 由源文件名决定，如 `cWinSock.cls` → `cWinSock` (大写 S)
2. **VB_Name 属性** (`module.moduleName`): VB6 源码内的 `Attribute VB_Name = "cWinsock"` (小写 s)

C3 编译器在这两个名称不一致时，会在不同位置使用不同的名称，导致 C 类型系统断裂：

- **结构体定义** 使用 `baseName_` (文件名): `typedef struct vb6_cls_cWinSock { ... } vb6_cls_cWinSock;`
- **类型引用** (`mapTypeRef()`) 使用 `clsSym->name` (= `module.moduleName` = VB_Name): `vb6_cls_cWinsock*`
- **结果**: `vb6_cls_cWinsock*` 和 `vb6_cls_cWinSock` 是两个不同的 C 类型。小写版本只有前向声明 (不完整类型)，导致所有 `obj->member` 访问失败，报 C2037。

典型案例：`cWinSock.cls` 文件名大写 S，但 `VB_Name = "cWinsock"` 小写 s。

## 影响范围分析

不一致不仅影响结构体命名，还影响：

| 用途 | 之前使用 | 修复后使用 |
|------|---------|-----------|
| 结构体定义 (`vb6_cls_<X>`) | `baseName_` (文件名) | `moduleName_` (VB_Name) |
| 事件接收器 (`vb6_events_<X>`) | `baseName_` | `moduleName_` |
| 事件回调 (`vb6_evt_<X>_<evt>`) | `baseName_` | `moduleName_` |
| `classMeParam()` me 指针类型 | `baseName_` | `moduleName_` |
| `knownClassVars_["me"]` 类名 | `moduleName_` (之前=`baseName_`) | `moduleName_` (=VB_Name) |
| `cProcName()` 函数名前缀 | `moduleName_` (之前=`baseName_`) | `moduleName_` (=VB_Name) |
| 跨模块函数调用 `sourceModule` | `moduleBaseNames` (文件名) | `module->moduleName` (VB_Name) |
| 同模块类匹配 `resolveClassMemberCall` | `baseName_` | `moduleName_` |
| 同模块类匹配 (AssignmentStmt) | `baseName_` | `moduleName_` |
| 输出文件名 (.h/.c) | `baseName` (文件名) | `module->moduleName` (VB_Name) |

如果不将 `sourceModule` 和函数名前缀一并改为 VB_Name，跨模块函数调用会产生链接器错误（定义用 VB_Name 前缀，调用用文件名前缀）。

### C2037 消除机制

C2037 "undefined struct/union" 发生在 MSVC 遇到不完整类型 (只有前向声明) 的成员访问时。之前 `vb6_cls_cWinsock*` (小写, VB_Name) 只有前向声明，而完整定义是 `vb6_cls_cWinSock` (大写, 文件名) — 两个不同类型。Fix 013 统一使用 VB_Name，使类型引用指向完整定义。

### 被揭示的错误 (+97)

C2037 消除后，MSVC 能对完整类型执行成员访问检查，揭示了之前被掩盖的深层错误：

**C2039 按父类型分布 (top 10)**:
| 父类型 | 数量 | 说明 |
|--------|------|------|
| `vb6_cls_cWinsock` | 50 | 方法/属性调用被生成为数据字段访问 |
| `vb6_VARIANT` | 30 | Variant.member 访问 (pre-existing) |
| `vb6_cls_cByteBuffer` | 23 | 方法调用 → 数据字段 |
| `vb6_cls_cHttpServerResponse` | 19 | 同上 |
| `vb6_cls_cTlsSocket` | 19 | 同上 |
| `vb6_cls_cDataBase` | 16 | 同上 |
| `vb6_cls_cTlsReMaster` | 14 | 同上 |
| `vb6_cls_cHttpServerSvr` | 13 | 同上 |
| `vb6_cls_cClientCallback` | 11 | 同上 |
| `vb6_cls_cToolsUtf8` | 10 | 同上 |

主要两类：
1. **方法调用 → 数据字段访问**: `obj.Create()` 生成 `obj->Create` 而非 `vb6_cTlsSocket_Create(obj)`。`resolveClassMemberCall()` 返回空串 (未找到方法)，fallback 到数据字段。
2. **VARIANT.member**: Variant 类型变量直接 `.member` 访问，需要运行时分发。

### 013b 修复 C1083

013a 首次编译产生 129 个 C1083 (无法打开 include 文件 `ToolsTlsThunks.h`)，因为 `#include` 使用 VB_Name 而输出文件用文件名 stem。013b 将输出文件名也改为 VB_Name 后 C1083 清零。
