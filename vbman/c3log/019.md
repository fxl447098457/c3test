# Fix 019: 事件包装函数 handler 实参误用参数声明 (me C2065 -35)

## 背景

Fix 018 (commit `dbaa33e`) 完成后, vbman 编译仍有 3622 个错误, 其中 C2065 共 450 个.
按标识符聚合, `me` 关键字以 43 处位居榜首:

| 标识符 | 次数 |
|--------|------|
| `me`   | 43   |
| `ii`   | 34   |
| `vb6_hwnd_Timer1` | 14 |
| `Tstr` | 14   |
| ...    | ...  |

之前调查卡点: 第一次查询用普通单引号 `'me'` 在 MSVC GBK 输出中匹配数为 0 —
原因是 MSVC 中文版输出**智能引号** `\u201C\u201D` ("…") 而非 ASCII 单引号.
本次改用 `[\u201C\u201D'']` 正则后成功提取全部 43 处错误位置.

## 问题

### 根因 (35 处直接问题)

cgen_base.cpp 有两处事件包装函数体代码生成 (`cgen_base.cpp:570` 与 `cgen_base.cpp:675`):

1. **VB6 WithEvents 事件包装** (`cgen_base.cpp:525-582`) 生成形如:
   ```c
   void vb6_evt_wrap_<var>_<evt>(void* handler, ...) {
       vb6_<Mod>_<Handler>(vb6_cls_<Mod>* me/* from handler */, ...);
   }
   ```

2. **COM WithEvents 事件包装** (`cgen_base.cpp:588-689`) 生成形如:
   ```c
   void vb6_com_evt_<var>_<evt>(VARIANT* args, int argc, VARIANT* result) {
       ...
       vb6_<Mod>_<Handler>(vb6_cls_<Mod>* me/* from com-evt */, ...);
   }
   ```

两处都调用了 `classMeParam()` (`cgen_decl.cpp:1095`):
```cpp
std::string CCodeGen::classMeParam() const {
    std::string clsStruct = "vb6_cls_" + cIdent(moduleName_);
    return clsStruct + "* me";      // 返回的是 "vb6_cls_X* me" 参数声明
}
```

**Bug**: `classMeParam()` 返回的是**参数声明** (`vb6_cls_X* me`), 它用于函数签名定义是合法的,
但被错放在**函数调用实参位置**. C 编译器会将 `vb6_cls_X*` 当作类型名 (非法的表达式上下文),
解析失败 → 导致:
- C2065 `me`: 把 `me` 当成裸标识符读取时报未声明
- 同时连带触发 C2275 (非法使用类型名)、C2198 (调用实参过少) 等下游错误

cHeartbeat.c:273 修复前的实际输出:
```c
void vb6_evt_wrap_m_otimer_Timer(void* handler) {
    vb6_cHeartbeat_m_oTimer_Timer(vb6_cls_cHeartbeat* me/* from handler */);    // C2065 'me'
}
```

### 根因 (8 处 cHttpServerSession.c 级联)

`cHttpServerSession.c:453-460` 的 8 处 `me` 错误**并非** 570/675 路径引起,
而是 Fix 015 chain (方法链 compound literal) 在 `SaveToDatabase` 函数中生成的复杂表达式
(第 377 行起) 触发的 C2059/C2143 语法错误的**级联**:
解析器丢失了 `_New()` 工厂函数的函数边界, 误以为还在前一函数内,
于是把 `vb6_cls_cHttpServerSession* me = ...` 也当成了"表达式上下文中的类型名" → C2275/C2059/C2371.

这部分将在 Fix 020 单独处理 (Fix 015 chain syntax cascade).

## 修复

### 文件 1: `src/backend/cgen.hpp`

新增辅助方法 `classHandlerCast()` 声明:

```cpp
// Fix 019: 在事件包装函数体内把 void* handler 转换为类指针类型
// 用于替代历史上误用的 classMeParam() (那是参数声明, 不能作为函数调用实参)
std::string classHandlerCast() const;
```

### 文件 2: `src/backend/cgen_decl.cpp`

在 `classMeParam()` 旁新增 `classHandlerCast()` 实现:

```cpp
// Fix 019: 在事件包装函数体内, handler (void*) 需要被强制转换为类指针类型
// 以正确调用 vb6_<Mod>_<Handler>(cls* me, ...) 形式的类方法。
// 历史上这里误用了 classMeParam() ("vb6_cls_X* me" — 参数声明) 作为函数调用实参,
// 导致生成伪 C: vb6_<Mod>_<Hand>(vb6_cls_X* me/* from handler */, ...) 报 C2065 'me' 未声明。
std::string CCodeGen::classHandlerCast() const {
    std::string clsStruct = "vb6_cls_" + cIdent(moduleName_);
    return "((" + clsStruct + "*)handler)";
}
```

### 文件 3: `src/backend/cgen_base.cpp`

两处调用点替换:

**第一处** (VB6 WithEvents 包装函数体, ~570 行):
```cpp
// Before
callArgs += classMeParam() + "/* from handler */";
// After
callArgs += classHandlerCast();
```

**第二处** (COM WithEvents 包装函数体, ~675 行):
```cpp
// Before
callArgs += classMeParam() + "/* from com-evt */";
// After
callArgs += classHandlerCast();
```

`classMeParam()` 的其余 6 处使用 (cgen_com.cpp:188 和 cgen_decl.cpp:330/345/1061 等) 都是
用于函数签名参数列表, 不受影响, 保持不变.
