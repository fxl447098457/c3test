# Fix 029: VB6 Variant 反向提取（reverse-extraction）+ RaiseEvent 参数包装 + 多态 builtin 排除

> 提交时间：2026-07-19
> 净错误变化：2991 → 2993（**+2**，MSVC 显露更深层错误，**非回归**）
> 主要受影响类别：
> - C1003: 12 → 11（-1 ✅）
> - C2063: 46 → 44（-2 ✅）
> - C2197: 203 → 198（-5 ✅）
> - IIf over-wrap 回归：18 处 → 0 处（-18 ✅）

## 现象

Fix 024 已解决「具体标量 → ByVal Variant 形参」的正向包装（C2440 主力减少 230 个）。但 Fix 028 后剩余的 2991 个错误中 C2440 仍有 1529 个（51%）。对 C2440 做 destination 类型子类别分析：

| 源类型 → 目标类型 | 数量 | 典型场景 |
|------|------|------|
| vb6_VARIANT → int32_t | 254 | 调用 ByVal Long 形参的函数，实参是 Variant 局部变量 |
| vb6_VARIANT → BSTR | 124 | 同上，目标 String 形参 |
| vb6_VARIANT → vb6_SafeArray1D * | 98 | RaiseEvent 把 Variant 数组实参传给 ByVal Buffer() As Byte 事件参数 |
| vb6_VARIANT → intptr_t | 34 | LongPtr 形参 |
| vb6_VARIANT → 类指针（Winsock/WebSocket…） | ~76 | 类实例形参 |
| vb6_VARIANT → double / uint8_t* / int16_t / wchar_t* | ~60 | 其他具体类型形参 |
| **小计（源 VARIANT → 具体目标）** | **~675** | Fix 029 直接目标 |
| 具体源 → vb6_VARIANT | 735 | Forward-wrap 未触发（多为内置函数 calleeParams 为空） |

**典型症状 1**（cAsyncSocket.c RaiseEvent）：

```c
// 修复前
vb6_Raise_cAsyncSocket_ClosePalConn(me, uMsg_Buffer);
// uMsg_Buffer 实际是 vb6_VARIANT，但事件参数 ByVal Buffer() As Byte 期望 vb6_SafeArray1D* → C2440
```

**典型症状 2**（Fix 024 P2 引入的 IIf over-wrap 回归）：

```c
// 修复前（Fix 024 P2 错误包装）
v = vb6_VariantFromValue(vb6_IIfBSTR(cond, a, b));
// vb6_IIfBSTR 在 C 层已返回 BSTR，被误包装为 VARIANT，后续赋值给 BSTR 变量时再触发 C2440
```

## 根因分析

### 原因 1：`inferExprType` 的 Variant 回退

`src/backend/cgen_util.cpp:670-766` 中 `inferExprType()` 在以下情况会回退为 `Vb6Type::Variant`（line 765）：
- 调用的内置函数不在符号表中（如 `vb6_UBound`、`vb6_CStr`、`vb6_Split`、`ws_inet_ntoa`）
- UDT 字段访问（如 `uAddr.sin_addr`，`lookupModule` 失败）
- `MemberAccessExpr` 中 `lookupModule` 失败的成员访问

Variant 回退本身是「最安全」的兜底，但引发两类问题：

1. **Fix 024 P2 错误包装**：当实参是多态 builtin 返回值（`inferExprType` 返回 Variant，但 codegen 实际分发到具体类型化版本），会被再用 `vb6_VariantFromValue` 包装。
2. **缺乏反向提取**：ByVal 具体类型形参 + Variant 实参时，Fix 024 P1/P2 只解决「具体 → Variant」方向，未解决「Variant → 具体」。

### 原因 2：多态 builtin 在 symTab 与 codegen 不一致

`IIf`/`Choose`/`Switch` 在 symTab 注册为 `Vb6Type::Variant`（`semantic_analyzer.cpp:2283, 2307, 2308`），但 codegen 实际按上下文分发到类型化版本：

- `IIf` → `vb6_IIfBSTR` / `vb6_IIfLong` / `vb6_IIfDouble`（`cgen_expr.cpp:2009-2013`，按第三个参数推断返回类型）
- `Choose` → 嵌套三元链（`cgen_expr.cpp:2037-2046`）
- `Switch` → 嵌套三元链（`cgen_expr.cpp:2048-2058`）

这些函数的 **C 返回类型是 BSTR/int32_t/double，并非 vb6_VARIANT**。Fix 024 P2 调用 `inferExprType` 看到返回 Variant 就对其结果包装，造成 18 处 over-wrap 回归（cAsyncSocket.c、cTlsSocket.c、cZipArchive.c、ToolsTlsThunks.c 等）。

### 原因 3：RaiseEvent 缺乏参数包装

`src/backend/cgen_com.cpp` 原 `visit(RaiseEventStmt&)` 在生成事件回调调用时，把表达式的原始值直接传给回调函数。但事件参数可能声明为 `ByVal Buffer() As Byte`（C 端 `vb6_SafeArray1D*`），实参若是 Variant 变量则类型不匹配；反之事件参数声明为 `As Variant` 时，标量实参也需 `vb6_VariantFromValue` 包装。

## 修复方案

五大组件：

1. **新增 RTL 提取函数**：`vb6_VariantToSafeArray1D`、`vb6_VariantToObjectVal` 填补 Variant→具体类型反向提取的 API 空缺
2. **新增严格 Variant 检测**：`isDefinitelyVariantExpr()` 不回退到 Variant
3. **反向提取 codegen**：ByVal 具体类型形参 + 确实是 Variant 的实参 → 自动调用提取函数
4. **RaiseEvent 参数包装**：查找 `EventDecl`，对 Variant 形参调用 `vb6_VariantFromValue`
5. **多态 builtin 排除**：`isDefinitelyVariantExpr` 对 `IIf`/`Choose`/`Switch` 返回 false，消除 over-wrap 回归

### 不采用方案对比

- **方案 A（采用）**：在 `IndexOrCallExpr` 反向提取 + 严格 Variant 检测 + 多态 builtin denylist。改动集中、风险可控。
- **方案 B（否决）**：在 `AssignmentStmt` 加入 Variant→具体自动转换，覆盖面更广但易引发回归。
- **方案 C（否决）**：修改 `inferExprType` 内部不回退 Variant，会破坏已有 Fix 024 P2 行为（许多合法路径依赖此回退）。

## 实施

### 1. 新增 RTL 提取函数（`src/rtl/core/vb6rtl.h` + `vb6rtl.c`）

**vb6rtl.h** 声明（约 line 314、318，紧邻 `vb6_VariantToLong/ToDouble/ToString`）：

```cpp
// 309: int32_t vb6_VariantToLong(vb6_VARIANT v);       // 原有
// 310: double  vb6_VariantToDouble(vb6_VARIANT v);     // 原有
// 311: BSTR    vb6_VariantToString(vb6_VARIANT v);     // 原有
struct vb6_SafeArray1D* vb6_VariantToSafeArray1D(vb6_VARIANT v);
// 与 vb6_VariantToObject(vb6_VARIANT*) 互补; 后者要求实参是左值 (取地址),
// 这里提供右值兼容版本, 用于对函数返回值取 Variant→Object 提取
void* vb6_VariantToObjectVal(vb6_VARIANT v);
```

**vb6rtl.c** 实现（约 line 1462、1473，紧邻 `vb6_VariantToString`）：

```cpp
// Fix 029: 从 Variant 中提取 SafeArray1D* (当 Variant 持有数组时).
struct vb6_SafeArray1D* vb6_VariantToSafeArray1D(vb6_VARIANT v) {
    if ((v.vt & vb6_vtArray) && v.parray) {
        return v.parray;
    }
    return NULL;  // 与 VB6 行为一致; 调用方需 NULL 检查
}

// Fix 029: vb6_VariantToObject 的右值兼容版本.
void* vb6_VariantToObjectVal(vb6_VARIANT v) {
    if (v.vt == vb6_vtDispatch) return v.pdispVal;
    return NULL;
}
```

**设计要点**：
- `vb6_VariantToSafeArray1D`：按 `vb6_vtArray` 位判断，避免对非数组 Variant 误取 `parray`
- `vb6_VariantToObjectVal`：按值传参（rvalue-compatible），与原 `vb6_VariantToObject(vb6_VARIANT*)`（取指针、要求左值）互补。调用点包装的实参经常是函数返回值（`vb6_VariantArrayGet(...)` 等）无法取址，必须用此版本。

### 2. 新增 `isDefinitelyVariantExpr`（`src/backend/cgen.hpp` + `cgen_util.cpp`）

**cgen.hpp** 声明（line 577，紧邻 `inferExprType`）：

```cpp
bool isDefinitelyVariantExpr(Expr& expr, bool* isArrOut = nullptr) const;
```

**cgen_util.cpp** 实现（line 768-840，紧邻 `inferExprType`）：

```cpp
// Fix 029: 严格 Variant 推断. 仅当表达式明确为 Variant 时返回 true.
// 与 inferExprType 的差异: 内置函数 (sym==null) 与 UDT 字段访问 (lookupModule 失败) 等
// 通过 fallback 返回 Variant 的情形, 此处视为非 Variant, 避免对 int/BSTR 等实参误包装.
bool CCodeGen::isDefinitelyVariantExpr(Expr& expr, bool* isArrOut) const {
    if (isArrOut) *isArrOut = false;
    uint16_t variantArrRaw = static_cast<uint16_t>(Vb6Type::Variant)
                           | static_cast<uint16_t>(Vb6Type::Array);

    // 多态内置函数 denylist: symTab 注册为 Variant, 但 codegen 按上下文
    // 发出类型化版本 (vb6_IIfBSTR/Long/Double, Choose 嵌套三元, Switch 嵌套三元),
    // 实际 C 返回类型不是 vb6_VARIANT. 视为非 Variant 以避免错误包装.
    auto isPolymorphicBuiltin = [](const std::string& name) -> bool {
        std::string lower = name;
        std::transform(lower.begin(), lower.end(), lower.begin(), ::tolower);
        return lower == "iif" || lower == "choose" || lower == "switch";
    };

    auto checkSym = [&](Symbol* sym) -> bool {
        if (!sym) return false;
        if (sym->type == Vb6Type::Variant) return true;
        if (static_cast<uint16_t>(sym->type) == variantArrRaw) {
            if (isArrOut) *isArrOut = true;
            return true;
        }
        return false;
    };

    switch (expr.kind) {
        case ASTNodeKind::IdentifierExpr: {
            // ...
            if (knownVariantVars_.count(lower)) return true;
            Symbol* sym = symTab_.lookup(id.name);
            if (!sym) sym = symTab_.lookupModule(id.name);
            return checkSym(sym);
        }
        case ASTNodeKind::IndexOrCallExpr: {
            // callee 是 IdentifierExpr: 排除多态 builtin 后查 symTab
            if (isPolymorphicBuiltin(cid.name)) return false;
            Symbol* sym = symTab_.lookup(cid.name);
            if (!sym) sym = symTab_.lookupModule(cid.name);
            return checkSym(sym);          // 关键差异: sym==null (内置函数) 视为非 Variant
        }
        // MemberAccessExpr: 递归, 排除 Err.* 等具体类型成员
        // ...
    }
    return false;
}
```

**与 `inferExprType` 的关键差异**：
- `sym == nullptr`（内置函数不在符号表）→ 视为非 Variant（`inferExprType` 回退为 Variant）
- `lookupModule` 失败（UDT 字段访问）→ 视为非 Variant
- 多态 builtin（IIf/Choose/Switch）→ 直接返回 false，**不**查 symTab
- Err.* 成员（如 `Err.Number`）→ 视为非 Variant（其实际返回 Long 等具体类型）

### 3. 修改 `visit(RaiseEventStmt&)`（`src/backend/cgen_com.cpp:238-285`）

```cpp
// Fix 029: 查找当前模块的 EventDecl 以获取事件参数类型.
// 必须按 Variant 参数声明对实参做包装: 否则当事件参数声明 "As Variant"
// (或无类型默认 Variant) 时, 直接回调 typedef 期望 vb6_VARIANT, 而实参
// 是 int32_t/BSTR 等标量, 触发 C2440 "scalar → vb6_VARIANT" 错误.
const EventDecl* evtDecl = nullptr;
if (currentModule_) {
    for (auto& decl : currentModule_->declarations) {
        if (!decl) continue;
        if (decl->kind != ASTNodeKind::EventDecl) continue;
        auto& evt = static_cast<EventDecl&>(*decl);
        if (evt.name == node.eventName) { evtDecl = &evt; break; }
    }
}
// ...生成回调调用...
for (size_t i = 0; i < node.args.size(); i++) {
    emitExpr(*node.args[i]);
    std::string argVal = lastExpr_;
    if (evtDecl && i < evtDecl->params.size()) {
        auto& param = evtDecl->params[i];
        Vb6Type paramType = (param->asType && ...) ? typeSys_.resolveTypeName(...) : Vb6Type::Variant;
        if (paramType == Vb6Type::Unknown || paramType == Vb6Type::Empty)
            paramType = Vb6Type::Variant;
        if (paramType == Vb6Type::Variant) {
            argVal = "vb6_VariantFromValue(" + argVal + ")";
        }
    }
    call += ", " + argVal;
}
```

**设计注意**：仅对 Variant 形参做包装，其它具体类型（Long/String/Array 等）形参期望已由 `emitExpr` 生成匹配类型，不做额外包装以避免破坏现有正确调用。

### 4. 修改 `visit(IndexOrCallExpr&)` 反向提取（`src/backend/cgen_expr.cpp:2630-2663`）

紧接 Fix 024 P2 正向包装块之后，新增反向提取块：

```cpp
// Fix 024 P2 正向包装 (已有): ByVal Variant 形参 + 标量实参 -> vb6_VariantFromValue(arg)
if (!isByRef && i < calleeParams.size() && calleeParams[i].isByVal
    && calleeParams[i].type == Vb6Type::Variant) {
    argVal = "vb6_VariantFromValue(" + argVal + ")";
}

// Fix 029: 反向提取 — ByVal 具体类型形参 + 实参确定为 Variant -> 调用提取函数.
// 与 Fix 024 P2 互补: P2 处理 V(callee)=Variant,V(arg)=scalar; 此处处理
// V(callee)=concrete,V(arg)=Variant. 覆盖 C2440 子类 to_int32/to_BSTR/to_SafeArray.
// 严格判断: 用 isDefinitelyVariantExpr 避免 inferExprType 默认回退到 Variant
// 造成对内置函数 (LenB 等) / UDT 字段访问 (uAddr.sin_addr) 的错误包装.
if (!isByRef && i < calleeParams.size() && calleeParams[i].isByVal
    && calleeParams[i].type != Vb6Type::Variant) {
    bool paramIsArray = (static_cast<uint16_t>(calleeParams[i].type)
                          & static_cast<uint16_t>(Vb6Type::Array)) != 0;
    Vb6Type paramBase = static_cast<Vb6Type>(
        static_cast<uint16_t>(calleeParams[i].type)
        & ~static_cast<uint16_t>(Vb6Type::Array));
    bool argIsVariantArr = false;
    bool argIsVariant = isDefinitelyVariantExpr(*node.positional[i], &argIsVariantArr);
    if (argIsVariant || argIsVariantArr) {
        if (paramIsArray && (paramBase == Vb6Type::Byte || paramBase == Vb6Type::String
            || paramBase == Vb6Type::Long || paramBase == Vb6Type::Variant)) {
            argVal = "vb6_VariantToSafeArray1D(" + argVal + ")";
        } else if (paramBase == Vb6Type::Long || paramBase == Vb6Type::Integer
                   || paramBase == Vb6Type::Byte || paramBase == Vb6Type::Boolean) {
            argVal = "vb6_VariantToLong(" + argVal + ")";
        } else if (paramBase == Vb6Type::Double || paramBase == Vb6Type::Single
                   || paramBase == Vb6Type::Currency) {
            argVal = "vb6_VariantToDouble(" + argVal + ")";
        } else if (paramBase == Vb6Type::String) {
            argVal = "vb6_VariantToString(" + argVal + ")";
        } else if (paramBase == Vb6Type::Object) {
            argVal = "vb6_VariantToObjectVal(" + argVal + ")";   // 右值兼容
        }
    }
}
```

参数 base 类型→提取函数映射表：

| 形参 base 类型 | 提取函数 | 对应 C2440 子类 |
|------|------|------|
| `Array & (Byte/String/Long/Variant)` | `vb6_VariantToSafeArray1D` | to_SafeArray1D * (98) |
| `Long` / `Integer` / `Byte` / `Boolean` | `vb6_VariantToLong` | to_int32 (253) |
| `Double` / `Single` / `Currency` | `vb6_VariantToDouble` | to_double (20) |
| `String` | `vb6_VariantToString` | to_BSTR (124) |
| `Object` | `vb6_VariantToObjectVal` | to_void * (22), 类指针 |

### Fix 030 候选方向

1. **内置函数签名注册**：在 symTab 注入 `vb6_UBound`/`vb6_Split`/`vb6_CStr`/`vb6_Trim`/`vb6_BSTR_Concat` 等内置函数的 ByVal 参数类型，让 Fix 024 P2（正向包装）和 Fix 029（反向提取）都能正确触发。预估收益最大（覆盖 ~675 + ~735 中的大头）。
