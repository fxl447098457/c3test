# Fix 038: C2440 类型转换错误修复

## 概述

C2440 是 MSVC 的 "无法从类型 X 转换为类型 Y" 错误, 是 vbman 编译中最大的错误类别。
Fix 038 分为两个阶段:

- **Fix 038 Groups 1-7**: 针对 VB6_SA_AT、With 块、UDT 初始化、vb6_Len 等特定模式的修复
- **Fix 038b**: 基于 `cExprIsVariant()` 和 `getRuntimeParamCType()` 的通用 Variant 类型转换框架

### 修复效果

| 指标 | 修复前 (Fix 037) | Fix 038 Groups 1-7 后 | Fix 038b 后 |
|------|-----------------|----------------------|-------------|
| C2440 错误数 | 1082 | 1011 | **939** |
| 总错误数 | 2174 | 1994 | **1931** |

净减少: C2440 -143, 总错误 -243

## Fix 038 Groups 1-7 (特定模式修复)

### Group 1: VB6_SA_AT Variant 数组元素赋值 (~29 errors)

**问题**: `VB6_SA_AT(vb6_VARIANT, arr, idx) = value` 中, value 不是 VARIANT 时产生 C2440。

**修复**: 在 `cgen_stmt.cpp` `visit(AssignmentStmt)` 中, 当目标包含 `VB6_SA_AT(vb6_VARIANT,` 时,
用 `vb6_VariantFromValue(value)` 包装 RHS。`vb6_VariantFromValue` 是 `_Generic` 宏,
对已存在的 VARIANT 是 identity (no-op), 安全。

```c
// 修复前: VB6_SA_AT(vb6_VARIANT, arr, idx) = value;  // C2440 if value is int
// 修复后: VB6_SA_AT(vb6_VARIANT, arr, idx) = vb6_VariantFromValue(value);
```

### Group 2: VariantArrayGet 赋值改写 (~10 errors)

**问题**: `vb6_VariantArrayGet(&arr, idx) = value` — VariantArrayGet 返回右值, 不能赋值。

**修复**: 改写为 `vb6_VariantArraySet(&arr, idx, vb6_VariantFromValue(value))`。
同时处理 AssignmentStmt 和 LetStmt 路径。

### Group 3: With 块 UDT 自转换 (~25 errors)

**问题**: With 块临时变量初始化时, UDT 类型的 `tempType` 被错误地加上强制转换:
`(vb6_type_X)lastExpr_` 其中 lastExpr_ 已经是该 UDT 类型, 自转换对某些 UDT 产生 C2440。

**修复**: 在 `cgen_stmt.cpp` `visit(WithStmt)` 中, 当 `tempType` 以 `vb6_type_` 开头时,
省略强制转换: `tempType tempVar = lastExpr_;` 而非 `(tempType)lastExpr_`。

### Group 3b: With 块 VARIANT→void* (~21 errors)

**问题**: With 块 `tempType == "void*"` 但表达式是 VARIANT 时, 直接赋值产生 C2440。

**修复**: 当表达式确定为 Variant 时, 用 `vb6_VariantToObjectVal(expr)` 提取 void*;
当表达式是 UDT 时, 用 `&(expr)` 取地址。

### Group 4: UDT 函数返回值初始化 (~15 errors)

**问题**: 返回类型为 UDT 的函数, 其返回变量初始化为 `vb6_type_X vb6_ret_Func = 0;` — 
int 初始化 UDT 结构体产生 C2440。

**修复**: 在 `cgen_decl.cpp` 中, 当返回类型以 `vb6_type_` 开头时, 用 `{0}` 替代 `0`:
```c
// 修复前: vb6_type_X vb6_ret_Func = 0;  // C2440
// 修复后: vb6_type_X vb6_ret_Func = {0};
```

### Group 5: UDT 字段构造函数初始化 (~8 errors)

**问题**: COM 类构造函数中, UDT 字段用 `me->field = 0` 初始化, int 赋值 UDT 产生 C2440。

**修复**: 在 `cgen_com.cpp` 中, 当字段类型是 UDT 时, 用 `memset(&me->field, 0, sizeof(me->field))`。

### Group 7: vb6_Len(udt) → sizeof (~10 errors)

**问题**: `Len(udt_expr)` 被映射到 `vb6_Len(expr)`, 但 `vb6_Len` 期望 BSTR 参数,
UDT 表达式传入产生 C2440。

**修复**: 在 `cgen_expr.cpp` `visit(IndexOrCallExpr)` 中, 拦截 `Len(udt_expr)` 调用,
用 `inferUdtTypeOfExpr()` 检测 UDT, 然后生成 `((int32_t)sizeof(expr))`。

## Fix 038b (通用 Variant 类型转换框架)

### 根因分析

Fix 038 Groups 1-7 后仍有 1011 个 C2440 错误, 分析发现 90 种不同模式。
核心问题:

1. **`isDefinitelyVariantExpr()` 仅检查 AST 级信息**: 无法识别 C 级 Variant 表达式
   (如 `vb6_VariantArrayGet(...)`, `vb6_VariantFromComResult(...)` 等)
2. **`calleeParams` 对运行时/内置函数为空**: Fix 029 的 Variant→concrete 转换无法触发
3. **`Array()` 字面量不做类型转换**: `vb6_ArraySetLong(arr, i, variantExpr)` 产生 C2440
4. **赋值语句不做 Variant→concrete 转换**: `intVar = variantExpr` 产生 C2440
5. **CInt/CLng/CDbl/CStr 的 Variant 检测不完整**: 遗漏 C 级 Variant 表达式

### 关键设计决策: cExprIsVariant vs isDefinitelyVariantExpr

初版 Fix 038b 在所有新代码中同时使用 `isDefinitelyVariantExpr` (AST 级) 和 `cExprIsVariant` (C 字符串级),
导致 C2440 从 1011 增加到 1307 (回归 +296)。

**根因**: `isDefinitelyVariantExpr` 通过符号表查找函数返回类型, 但符号表中的 Variant 返回类型
可能与实际 C 函数返回类型不一致。例如 `prop_get_LastError` 在符号表中注册为 Variant,
但生成的 C 函数返回 `void*` (Object 类型)。当 `isDefinitelyVariantExpr` 误判为 true 后,
代码生成 `vb6_VariantToLong(void*)` — `vb6_VariantToLong` 期望 `vb6_VARIANT` 参数,
`void*` 传入产生 C2440。

**修复**: 所有 Fix 038b 新代码仅使用:
1. `cExprIsVariant(value)` — C 字符串级检测, 只匹配确定返回 `vb6_VARIANT` 的函数前缀
2. `knownVariantVars_` — 直接查找已知 Variant 变量名
3. **不使用** `isDefinitelyVariantExpr` — 避免符号表类型与 C 类型不一致的误判

Fix 029 原有代码保留 `isDefinitelyVariantExpr` (已在基线中), 仅添加 `cExprIsVariant` 作为回退。

### Fix 038b-1: cExprIsVariant() — C 字符串级 Variant 检测

**文件**: `src/backend/cgen_util.cpp`

检测 C 表达式字符串是否为 `vb6_VARIANT` 类型。去除前导括号/空白后,
检查是否以已知 Variant 返回函数前缀开头:

```cpp
bool CCodeGen::cExprIsVariant(const std::string& cExpr) {
    // 去除前导 ( 和空白
    // 检查前缀: vb6_VariantArrayGet(, vb6_VariantFromComResult(,
    // vb6_VariantFromStackVARIANT(, vb6_VariantFromValue(,
    // vb6_VariantEmpty(, vb6_VariantLong(, vb6_VariantDouble(,
    // vb6_VariantString(, vb6_VariantBool(, vb6_VariantArray(,
    // vb6_VariantObject(, vb6_VariantNull(, ...
}
```

**关键设计**: 仅检测顶层表达式 (去除前导括号后), 不递归子表达式, 避免误判。
`vb6_VariantToObjectVal(` 不在列表中 (它返回 `void*` 而非 `vb6_VARIANT`)。

### Fix 038b-2: getRuntimeParamCType() — 运行时函数参数类型表

**文件**: `src/backend/cgen_util.cpp`

硬编码运行时函数的参数 C 类型查找表。当 `calleeParams` 为空 (运行时/内置函数) 时,
通过函数名和参数索引查找期望的 C 类型:

```cpp
static const std::unordered_map<std::string, std::vector<std::string>> table = {
    {"vb6_ArraySetLong",    {"vb6_SafeArray1D*", "int32_t", "int32_t"}},
    {"vb6_BSTR_Assign",     {"BSTR*", "BSTR"}},
    {"vb6_BSTR_Concat",     {"BSTR", "BSTR"}},
    {"vb6_StrCmp",          {"BSTR", "BSTR"}},
    {"vb6_ErrRaise",        {"int32_t", "BSTR", "BSTR"}},
    {"vb6_CLng",            {"double"}},
    {"vb6_UBound",          {"vb6_SafeArray1D*", "int32_t"}},
    // ... 共 60+ 个运行时函数
};
```

### Fix 038b-3: Array() 字面量 Variant 参数转换

**文件**: `src/backend/cgen_expr.cpp` (Array handler, ~line 2079)

当 `Array()` 的元素是 Variant 表达式时, 先提取具体值再调用 `vb6_ArraySetLong/SetBSTR/SetDouble`:

```c
// 修复前: vb6_ArraySetLong(arr, 0, vb6_VariantArrayGet(&vElem, 0));  // C2440
// 修复后: vb6_ArraySetLong(arr, 0, vb6_VariantToLong(vb6_VariantArrayGet(&vElem, 0)));
```

### Fix 038b-4: CInt/CLng/CDbl/CStr Variant 检测扩展

**文件**: `src/backend/cgen_expr.cpp`

在 CInt/CLng/CDbl 的 V 后缀检测和 CStr 的 `vb6_VariantFromValue` 跳过逻辑中,
添加 `cExprIsVariant(args[0])` 作为回退检测:
- `CLng(vb6_VariantArrayGet(...))` → `vb6_CLngV(vb6_VariantArrayGet(...))`
- `CStr(vb6_VariantArrayGet(...))` → 跳过 `vb6_VariantFromValue` 包装 (已是 VARIANT)

### Fix 038b-5: 函数调用参数类型转换 (calleeParams 为空时)

**文件**: `src/backend/cgen_expr.cpp` (argument loop, ~line 3142)

两处增强:
1. **Fix 029 原有代码**: 添加 `cExprIsVariant(argVal)` 作为 `isDefinitelyVariantExpr` 的回退
2. **新代码**: 当 `calleeParams` 为空时, 用 `getRuntimeParamCType(callee, i)` 获取期望类型,
   当实参为 Variant 时自动插入提取函数

```c
// 修复前: vb6_ErrRaise(Number, (*Source), (*Description));  // C2440: VARIANT→BSTR
// 修复后: vb6_ErrRaise(Number, vb6_VariantToString((*Source)), vb6_VariantToString((*Description)));
```

### Fix 038b-6: 赋值语句类型转换

**文件**: `src/backend/cgen_stmt.cpp`

四处增强:
1. **AssignmentStmt BSTR 目标**: BSTR 变量 + Variant 值 → `vb6_VariantToString(value)`
2. **AssignmentStmt else 块**: Long/Double 变量或 `VB6_SA_AT(BSTR/int32_t/double,...)` + Variant 值 → 自动提取
3. **LetStmt else 块**: 同 AssignmentStmt 路径
4. **SetStmt**: Variant 值 → `vb6_VariantToObjectVal(value)` (对象引用提取)
5. **Select Case 临时变量**: Variant 测试表达式 → 自动提取为 int32_t/BSTR/double

```c
// 修复前: TimeOut = vb6_cAsyncSocket_Znl(...);  // C2440: VARIANT→int32_t
// 修复后: TimeOut = vb6_VariantToLong(vb6_cAsyncSocket_Znl(...));
// (仅当 Znl 的 C 返回值确实是 vb6_VARIANT 时, 通过 cExprIsVariant 检测)

// 修复前: int32_t _vb6_select_0 = vb6_VariantArrayGet(&vElem, 0);  // C2440
// 修复后: int32_t _vb6_select_0 = vb6_VariantToLong(vb6_VariantArrayGet(&vElem, 0));
```
