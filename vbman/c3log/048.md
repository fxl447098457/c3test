# Fix 048: VB6 $ 类型后缀剥离 + 缺失运行时函数声明 (LenB/SA_Destroy/DebugAssert)

## 日期
2026-07-22

## 问题

199 个 C4013 警告（未定义函数假设返回 int）是当前最严重的根因之一。C4013 直接导致大量 C2440 类型转换错误——MSVC 假设函数返回 `int`，当结果传入期望 `vb6_VARIANT` 或 `BSTR` 的参数时产生类型不匹配。

## 根因分析

### `$` 类型后缀问题

VB6 字符串函数有 `$` 后缀变体（如 `Mid$`、`Left$`、`Hex$`），表示返回 String (BSTR) 而非 Variant。C3 词法分析器将 `$` 作为标识符的一部分消费，生成 `IdentifierExpr` 节点名为 `"Mid$"`。

在 `visit(IdentifierExpr&)` 中：
1. `cIdent("Mid$")` 将 `$` 转换为 `_`，生成 `"Mid_"`
2. `builtinFuncs.find("mid$")` 查找失败（表中有 `"mid"` 而非 `"mid$"`）
3. 回退路径生成 `Mid_()`（无 `vb6_` 前缀，带尾部下划线）
4. `Mid_` 未在任何头文件中声明 → C4013 警告 → MSVC 假设返回 `int`

### 缺失的运行时函数

`vb6_LenB`、`vb6_SA_Destroy`、`vb6_DebugAssert`、`vb6_LoadResData` 由 codegen 生成调用但未在运行时库中声明/实现。

## 修改内容

### 1. `src/backend/cgen_expr.cpp` — `$` 后缀剥离 + builtinFuncs 扩展

**`$` 后缀剥离**（~line 673）：
在 `builtinFuncs.find(lower)` 之前，剥离 `lower` 末尾的 `$`：
```cpp
std::string lookupName = lower;
if (!lookupName.empty() && lookupName.back() == '$') {
    lookupName.pop_back();
}
auto it = builtinFuncs.find(lookupName);
```
这样 `Mid$` → `mid$` → `mid` → 找到 `vb6_Mid`，生成正确的函数调用。

**新增 builtinFuncs 条目**：
- `{"lenb", "vb6_LenB"}` — LenB 内置函数
- `{"loadresdata", "vb6_LoadResData"}` — LoadResData 内置函数

### 2. `src/rtl/core/vb6rtl.h` — 缺失运行时函数声明

**vb6_LenB**：使用 `_Generic` 宏实现双重语义：
- BSTR 参数 → `vb6_LenB_BSTR(x)` 返回字节长度
- UDT 参数 → `((int32_t)sizeof(x))` 返回结构体大小
```c
int32_t vb6_LenB_BSTR(BSTR s);
#define vb6_LenB(x) _Generic((x), \
    BSTR: vb6_LenB_BSTR(x), \
    const BSTR: vb6_LenB_BSTR(x), \
    default: ((int32_t)sizeof(x)) \
)
```

**vb6_SA_Destroy**：内联函数，封装 `vb6_SafeArrayDestroy1D`：
```c
static inline void vb6_SA_Destroy(void* arr) {
    if (arr) vb6_SafeArrayDestroy1D((vb6_SafeArray1D*)arr);
}
```

**vb6_DebugAssert**：内联空操作（Debug.Assert 仅在 IDE 中生效）：
```c
static inline void vb6_DebugAssert(int32_t cond) { (void)cond; }
```

**vb6_DebugPrint**：内联函数，转发到 `vb6_DebugPrintStr`：
```c
static inline void vb6_DebugPrint(BSTR s) { vb6_DebugPrintStr(s); }
```

**vb6_LoadResData**：存根函数，返回空 Variant。

### 3. `src/rtl/core/vb6rtl.c` — 实现

- `vb6_LenB_BSTR(BSTR s)`：返回 `vb6_BSTR_Len(s) * sizeof(wchar_t)`
- `vb6_LoadResData(int32_t, int32_t)`：返回空 Variant

### 4. `src/backend/cgen_util.cpp` — getRuntimeParamCType 表更新

- 删除 `vb6_Mid_` 条目（重复，`vb6_Mid` 已存在）
- `vb6_Hex_` → `vb6_Hex`（匹配 `$` 后缀修复后的正确函数名）
- `vb6_Oct_` → `vb6_Oct`（同上）

### C2198 回归分析
+4 C2198 回归是之前被 C4013 掩盖的预存问题：函数未声明时 MSVC 不检查参数数量，声明后暴露参数不足问题（如 `Mid(s, start)` 2 参数调用 vs C 函数 3 参数要求）。这些是预存 bug，非新引入。

## 局限性

1. **剩余 58 个 C4013**：主要是跨模块调用（`vb6_VBA_*`、`vb6_c*_*`、`vb6_pv*`），需要跨模块前向声明生成修复。
2. **C2198 +4 回归**：被 C4013 掩盖的预存参数不足问题，需单独修复（如 `Mid` 2 参数变体）。
3. **`BSTR → vb6_VARIANT` 增加**：C4013 修复后，原本被假设为 `int` 的函数结果现在正确为 `BSTR`，但传递给期望 VARIANT 的函数时仍需包装。
