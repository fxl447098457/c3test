# Fix 028: VB6 标识符类型后缀（$ % & ! # @）剥离

> 提交时间：2026-07-19
> 净错误变化：3029 → 2991（**-38**）
> 主要受影响类别：C2065 349 → 317（-32）

## 现象

vbman 编译中观察到一批以 `_` 结尾的局部变量声明，但使用处却没有 `_` 后缀，导致 C2065 "未声明的标识符" 错误。

cDatabase.c 第 215-218 行典型示例（修复前）：

```c
vb6_VARIANT Address_ = vb6_VariantEmpty();   // 声明带 _ 后缀
Address = vb6_VariantArrayGet(&Svr, 0);       // 使用不带 _ → C2065
vb6_VARIANT Port_ = vb6_VariantEmpty();
Port = vb6_BSTR_FromStr(L"3306");             // 同上 C2065
```

对应 VB6 源代码 `vbman/src/Database/cDatabase.cls` 第 294-295 行：

```vb6
Dim Address$: Address = Svr(0)
Dim Port$: Port = "3306"
```

注意 `$` 后缀——这是 VB6 的**类型后缀字符**，用于声明变量的隐式类型。问题与"局部变量重命名"无关，而是词法器把类型后缀错误地并入了标识符文本。

## 根因分析

### 词法器行为（`src/lexer/lexer.cpp:449-468`）

`scanIdentifierOrKeyword()` 在扫描完字母数字部分后，会检查后续字符是否是 VB6 类型后缀：

```cpp
// 可能带有类型后缀: name$, name%, name&, name!, name#, name@
// 注意: 这些后缀是标识符的一部分, 不单独返回
if (offset_ < content_.size()) {
    char c = peek();
    if (c == '$' || c == '%' || c == '&' || c == '!' || c == '#' || c == '@') {
        char next = peekNext();
        if (!isAlpha(next) && next != '_' && !isDigit(next)) {
            text += advance(); // 消费类型后缀
        }
    }
}
```

因此 `Dim Address$:` 中，`$` 后跟 `:`（非字母数字），`$` 被并入标识符文本，得到 `Token("Address$")`。
而 `Address = Svr(0)` 中，`Address` 后跟空格，不会触发后缀并入，得到 `Token("Address")`。

### cIdent 行为（`src/backend/cgen_base.cpp:1280-1317`）

`CCodeGen::cIdent()` 把标识符中的非字母数字字符（包括 `$`）替换为下划线：

```cpp
for (auto& ch : name) {
    if (!std::isalnum(static_cast<unsigned char>(ch)) && ch != '_') {
        ch = '_';
    }
}
```

所以 `cIdent("Address$")` 返回 `"Address_"`，而 `cIdent("Address")` 返回 `"Address"`，二者不一致。

### 灾难性组合

| 位置 | 词法器输出 | cgen 输出 | 结果 |
|------|-----------|-----------|------|
| `Dim Address$:` | `Identifier "Address$"` | `cIdent("Address$") = "Address_"` | 声明 `Address_` |
| `Address = Svr(0)` | `Identifier "Address"` | `cIdent("Address") = "Address"` | 使用 `Address` → C2065 |

**关键发现**：这不是局部变量重命名 bug（之前误判），而是词法器把 VB6 类型后缀字符错误地并入标识符文本的问题。

## 修复方案

采用**最小化方案（Option 1）**：在 parser 层剥离类型后缀，**不**注入对应类型（保留默认 Variant 行为）。

### 不采用方案对比

- **Lexer 层修复（删除后缀并入逻辑）**：会改变所有使用 `Mid$`、`Left$` 等带后缀内置函数名的代码路径，影响范围过大。
- **类型注入方案（Option 2）**：将 `$` → String(BSTR)、`&` → Long(int32_t) 等。会引入 Variant→BSTR 的 C2440 错误（如 `Address = Svr(0)` 中 RHS 为 Variant，LHS 为 BSTR 无法直接赋值）。需要配套 AssignmentStmt 加入 Variant→BSTR 自动转换逻辑，超出 Fix 028 范围。
- **Option 1（采用）**：仅剥离名字，类型保留默认 Variant。Fix 024（vb6_VariantFromValue _Generic 宏）已经能正确处理 Variant 赋值时的标量→Variant 自动包装，所以新代码生成的 `Variant = BSTR/Long/RHS` 都能安全类型匹配。

## 实施

### 1. 新增辅助方法（`src/parser/parser.hpp` + `src/parser/parser.cpp`）

```cpp
// parser.hpp
struct TypeSuffixStrip { std::string name; std::string typeName; };
TypeSuffixStrip stripTypeSuffix(const std::string& text) const;

// parser.cpp
Parser::TypeSuffixStrip Parser::stripTypeSuffix(const std::string& text) const {
    TypeSuffixStrip result;
    result.name = text;
    if (text.size() < 2) return result;
    const char last = text.back();
    switch (last) {
        case '$': result.typeName = "String";   break;
        case '%': result.typeName = "Integer";  break;
        case '&': result.typeName = "Long";     break;
        case '!': result.typeName = "Single";   break;
        case '#': result.typeName = "Double";   break;
        case '@': result.typeName = "Currency"; break;
        default: return result;
    }
    result.name = text.substr(0, text.size() - 1);
    return result;
}
```

### 2. 修改 4 个 parser 入口

| 文件 | 修改点 | 影响 |
|------|--------|------|
| `parser_decl.cpp::parseVariableDecl` | `nameTok.text` → `stripTypeSuffix(nameTok.text).name` | 单变量 Dim/Static/Private/Public |
| `parser_decl.cpp::parseParameter` | 同上 | Sub/Function/Property 参数 |
| `parser_decl.cpp::parseConstDecl` & `parseConstDeclList` | 同上 | Const 声明 |
| `parser_stmt.cpp::parseDimStmt` 逗号列表分支 | 同上 | `Dim a, b, c` 多变量列表中第 2+ 个变量 |

注：vbman 不使用 Sub/Function/Property 名带类型后缀，所以未修改 `parseSubDecl/parseFunctionDecl/parsePropertyDecl`。Type/Enum/Declare/Event 名也不带后缀，未修改。

## 验证

### 用户代码覆盖范围

vbman 中只有 5 行 Dim 使用类型后缀，共 6 个变量：

```
cDatabase.cls  L294: Dim Address$: Address = Svr(0)
cDatabase.cls  L295: Dim Port$: Port = "3306"
cSSE.cls       L250: Dim ResponseLine$, Tstr$
cToolsStr.cls  L410: Dim POSF&, POSE&, hasLeft&
```

### 修复前后对比（cDatabase.c 第 215-220 行）

修复前：
```c
vb6_VARIANT Address_ = vb6_VariantEmpty();
Address = vb6_VariantArrayGet(&Svr, 0);       // C2065
vb6_VARIANT Port_ = vb6_VariantEmpty();
Port = vb6_BSTR_FromStr(L"3306");             // C2065
```

修复后：
```c
vb6_VARIANT Address = vb6_VariantEmpty();
vb6_VariantClear(&Address);
Address = vb6_VariantArrayGet(&Svr, 0);       // ✅ 名称匹配
vb6_VARIANT Port = vb6_VariantEmpty();
vb6_VariantClear(&Port);
Port = vb6_VariantString(vb6_BSTR_FromStr(L"3306"));  // ✅ 自动 Variant 包装（Fix 024）
```

### cToolsStr.c 的 Long 后缀变量（POSF/POSE/hasLeft）

修复后正确生成 Variant 算术代码：

```c
vb6_VARIANT POSF = vb6_VariantEmpty();
vb6_VARIANT POSE = vb6_VariantEmpty();
vb6_VARIANT hasLeft = vb6_VariantEmpty();
hasLeft = vb6_VariantLong(vb6_InStr(1, ...));          // ✅ Long → Variant 包装
if ((vb6_VarCmpLongEq(&hasLeft, 0))) { ... }           // ✅ Variant == Long 比较（Fix 024 P1）
POSF = vb6_VariantFromValue((hasLeft + vb6_Len(...)));  // ✅ Variant 算术 + 自动包装
if ((vb6_VarCmpGt(&POSE, &POSF))) { ... }              // ✅ Variant > Variant（Fix 024 P1c）
```

完美验证了 Fix 024 的 `_Generic` 宏基础设施能与 Fix 028 配合良好。

## 后续计划

### Fix 029 候选方向（按当前剩余错误类别排序）

总剩余错误 2991：

1. **C2440 (1529, 51%)**：仍是最大头。下一轮目标——`to_VARIANT` 子类（732 处）和 `to_int32`（254 处）。
2. **C2198+C2197 (557, 19%)**：参数数量不匹配，函数调用约定问题。
3. **C2065 (317, 11%)**：
   - `pvState` (12) — Private Property Let 调用未被识别（赋值 = `pvState = 8` 未分发到 Property Set 调用）

5. **C2039 (75)**：成员未找到。
6. **C2088 (66)**、**C2172 (49)**、**C2224 (42)**、**C2297 (47)**：类型推断 / void* 访问问题。
