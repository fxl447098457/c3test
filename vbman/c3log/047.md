# Fix 047: 跨模块 Enum/UDT 参数类型预注册

## 日期
2026-07-22

## 问题

C2440 类型转换错误中，`vb6_VARIANT → int32_t`（167个）是最大子类别。根因：跨模块引用的 Enum 类型在语义分析期间不可见，导致参数类型被解析为 Variant 而非 Long。

典型场景：`cTlsSocket.cls` 中 `pvFireOnError` 的参数声明为 `ByVal EventMask As UcsAsyncSocketEventMaskEnum`，但该 Enum 定义在 `cAsyncSocket.cls` 中。在分析 `cTlsSocket.cls` 时，该 Enum 类型在 Pass 1 和 Pass 2 期间均不可见（因为 `runCrossModuleResolution()` 在所有模块分析完成后才运行），导致参数类型被解析为 Variant，codegen 用 `vb6_VariantFromValue()` 包装参数，而 C 函数签名期望 `int32_t`。

## 根因分析

### 语义分析时序问题

- `Driver::runSemanticAnalysis()`（driver.cpp:815）：逐个模块调用 `analyzer->analyze(*module)`，运行 Pass 1（收集声明）和 Pass 2（分析过程体）。
- `Driver::runCrossModuleResolution()`（driver.cpp:1076）：在所有模块分析完成后运行，注入跨模块公共符号。
- **问题**：在 Pass 1 和 Pass 2 期间，其他模块的公共 Enum/UDT 类型不可见。

### `resolveTypeRef()` 的回退行为

`resolveTypeRef()`（semantic_analyzer.cpp:552）查找模块作用域中的类型名。对于 `UcsAsyncSocketEventMaskEnum`：
- 如果找到 `SymbolKind::EnumType` → 返回 `Vb6Type::Long`
- 如果找到 `UserDefinedType` → 返回 `Vb6Type::UserDefinedType`
- 如果未找到 → 返回 `Vb6Type::Variant`（第 600 行）

由于跨模块 Enum 在分析期间不可见，`resolveTypeRef()` 返回 Variant，导致参数类型错误。

## 修改内容

### 1. `src/driver/driver.cpp` — 预注册跨模块 Enum/UDT 类型
在 `runSemanticAnalysis()` 中，每个模块的 `analyze()` 调用之前，预注册来自所有其他模块的公共 Enum 和 UDT 类型：
- 遍历 `otherModule->declarations` 中的 `EnumDecl`（→ `SymbolKind::EnumType`, `Vb6Type::Long`）和 `TypeDecl`（→ `SymbolKind::UserDefinedType`, `Vb6Type::UserDefinedType`）
- 调用 `defineExternal()` 注册到当前模块的符号表
- 外部符号不会与后续本地声明冲突（由 `defineExternal()` 的跳过逻辑保证）

### 2. `src/semantics/symbol_table.cpp` — 允许本地声明覆盖外部符号
修改 `define()` 函数，当存在外部符号（`existing->isExternal`）且新符号为本地声明（`!sym->isExternal`）时，先擦除外部符号再定义本地符号。这防止了当模块自己的 Pass 1 注册相同的 Enum/UDT 时出现"重复声明"错误。

### 3. `src/semantics/semantic_analyzer.cpp` — Pass 2 参数类型重解析
在 `visit(SubDecl)`、`visit(FunctionDecl)`、`visit(PropertyDecl)` 的 Pass 2 中，从 AST 重新解析参数类型和返回类型：
- 遍历参数列表，调用 `resolveTypeOrDefault()` 重新解析每个参数类型
- 如果类型发生变化（如 Variant → Long），更新 `sym->params[i].type`
- 对于 Function/PropertyGet，同时重新解析返回类型并更新 `sym->type`
- 同时更新 `classSym->memberParams` 以保持一致性

这是双重保险措施——主要的修复是 driver.cpp 中的预注册。

## 局限性

1. **剩余 95 个 `vb6_VARIANT → int32_t`** — 可能来自：
   - 私有 Enum（Private 声明，不在公共符号中）
   - 模块级 Enum（.bas 模块中的 Enum）
   - 参数类型推导的其他路径

2. **Pass 2 重解析仅作为后备** — 如果预注册正常工作，Pass 2 重解析不应改变任何类型。它存在是为了捕获预注册遗漏的情况。
