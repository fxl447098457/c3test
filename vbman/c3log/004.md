## 修复内容

### 4a. Type 成员数组的多种维度语法

**问题**: VB6 的自定义类型（UDT）成员支持数组维度：
- `Data() As Byte` — 动态数组
- `sin_zero(1 To 8) As Byte` — 下界 To 上界
- `Data4(0 To 7) As Byte` — 同上

`parseTypeDecl()` 中的数组维度处理只支持 `memberName(size)` 单数字形式，无法处理空括号 `()` 和 `To` 范围语法。

**根因**: `parser_decl.cpp:173-177` 使用 `parseExpression()` 解析维度大小，但：
- `()` — `parseExpression()` 遇到 `)` 会返回 nullptr 但不报错，空括号被静默丢弃
- `(1 To 8)` — `parseExpression()` 解析 `1` 后遇到 `To` 停止，然后 `expect(RightParen)` 失败因为当前 token 是 `To`
- 多维 `(1, 2)` — `parseExpression()` 解析 `1` 后遇到 `,` 停止，`expect(RightParen)` 失败

**修复** (`parser_decl.cpp`):
- 空括号 `()` — 检查 `cur_` 是否为 `)`，如是则跳过 `parseExpression()`
- `To` 范围 — 解析下界后检查 `To`，如匹配则解析上界并仅保留上界
- 多维 — 添加 `while(match(Comma))` 循环消费后续维度

### 4b. With 块 `.Member` 不接受硬关键字

**问题**: VB6 中 `With New ADODB.Stream : .Type = adTypeText` 报 "expected member name after '.'"。`Type` 是 VB6 硬关键字。

**根因**: `parseWithMemberExpr()` (`parser_expr.cpp:370-376`) 使用 `expectName()`，只接受 Identifier 和软关键字。Fix 002c 只修复了 `parsePostfix()` Dot 分支（即 `obj.Type`），但 With 块的 `.Type` 走完全不同的代码路径：`parseStatement()` → `parseLabelOrAssignmentOrCall()` → `parseExpression()` → `parseNullDenotation()` → `parseWithMemberExpr()`。

**修复** (`parser_expr.cpp`): 在 `parseWithMemberExpr()` 中用与 `parsePostfix()` Dot 分支相同的逻辑替换 `expectName()`：先检查 `canBeName()`，否则接受任何具有非空文本且不是分隔符（EOF/NewLine/Colon/括号/逗号）的 token。

### 4c. 无括号调用中的 ByVal/ByRef 前缀

**问题**: VB6 允许在无括号调用中覆盖参数传递方式：`SendMessageW thunkID, 0&, 0&, ByVal 0&`。Fix 002d 只修复了有括号调用路径。

**根因**: `parseLabelOrAssignmentOrCall()` (`parser_stmt.cpp:1045-1095`) 的参数解析循环没有检查 `ByVal`/`ByRef` 前缀。

**修复** (`parser_stmt.cpp`): 在第一个参数和后续每个逗号后的参数解析前，添加 `if (cur_.kind == TokenKind::ByVal || cur_.kind == TokenKind::ByRef) { advance(); }`。

### 4d. Get/Put 语句中的空记录号

**问题**: VB6 文件 I/O 允许省略记录号：`Get #iFileNum, , baData` 和 `Put #hFile, , m_Buffer`。连续逗号表示空参数。

**根因**: `parseGetStmt()` 和 `parsePutStmt()` (`parser_stmt.cpp:1176-1206`) 在匹配第一个逗号后无条件调用 `parseExpression()`，但当前 token 可能是第二个逗号（空参数），`parseExpression()` 无法处理。

**修复** (`parser_stmt.cpp`): 在两个函数中，`match(Comma)` 后添加 `if (cur_.kind != TokenKind::Comma)` 检查，若当前 token 是逗号则跳过 `parseExpression()`，保持 `recordNumber` 为 nullptr。

### 4e. 无括号调用中的命名参数

**问题**: VB6 允许在无括号调用中使用命名参数：`m_oSocket.Create SocketType:=(m_eProtocol And 1)`。

**根因**: `parseLabelOrAssignmentOrCall()` 的参数解析只使用 `call->positional`，没有检查 `name := value` (TokenKind::Assign) 语法。

**修复** (`parser_stmt.cpp`): 在第一个参数和后续参数的 `canStartArg()` 检查后，添加命名参数检测：`if (canBeName(cur_.kind) && next_.kind == TokenKind::Assign)`，如是则解析参数名和 `:=`，将结果加入 `call->named`。
