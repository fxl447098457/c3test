# Fix 030: COM 参数通用打包宏 vb6_ComPackValue + UBound/LBound 参数签名注册

**提交**: 待提交
**前序**: Fix 029 (`d87566b`, 总错误 2993)
**结果**: 总错误 2993 → 2797 (**-196**), C2440 1537 → 1322 (**-215**)

## 目标

继续推进 C2440 子类修复，针对两个最大子类别：

1. **正向 (concrete → vb6_VARIANT)**: Fix 029 final 时约 740 个 C2440 错误
   - 根因: `comPackExpr()` 的 `case Vb6Type::Variant` 返回 `"vb6_ComPackVariant"` (期望 `vb6_VARIANT` 按值传递)，但 `inferExprType()` 回退到 Variant 时实际实参可能是标量 / BSTR / `vb6_SafeArray1D*` / 类指针等非 Variant C 类型，导致类型不匹配。

2. **反向 (vb6_VARIANT → vb6_SafeArray1D\*)**: Fix 029 final 时约 98 个 C2440 错误
   - 根因: `UBound`/`LBound` 通过 `addBuiltinFunc("UBound", Vb6Type::Long)` 注册时没有填充 `sym->params`，导致 `IndexOrCallExpr` 中 `calleeParams` 为空，Fix 029 的反向提取逻辑无法在 Variant 实参上触发 `vb6_VariantToSafeArray1D` 包装。

## Fix 030a — COM 参数通用打包宏 `vb6_ComPackValue`

### 思路

引入 `_Generic` 宏 `vb6_ComPackValue(x)` = `vb6_ComPackVariant(vb6_VariantFromValue((x)))`。
- `vb6_VariantFromValue` (Fix 024) 在编译期按实参 C 类型选择 Variant 构造函数:
  - 标量 → `VariantLong/Int/Double/Bool/Byte`
  - `wchar_t*` → `VariantString`
  - `vb6_SafeArray1D*` → `VariantArray`
  - `void*`/class ptr → `VariantObject`
  - `vb6_VARIANT` → `VariantIdentity` (no-op 拷贝，向后兼容)
- 然后 `vb6_ComPackVariant` 将 `vb6_VARIANT` 按值打包为 Windows VARIANT。

`comPackExpr` 在 `case Vb6Type::Variant` 改返回 `"vb6_ComPackValue"` 即可正确处理所有非 Variant 实参类型，且对真 Variant 实参保持等价 (经 `VariantIdentity` 路径)。

### COM 调用结果的特殊处理

`vb6_ComCall` / `vb6_ComGetProp` / `vb6_ComGetObjectProp` / `vb6_ComCallObject` 返回 `void*` (实际是 Windows `VARIANT*`)。`vb6_VariantFromValue` 对 `void*` 走 `VariantObject` 路径会错误地包装为 `VT_DISPATCH` 而非解封为 `vb6_VARIANT`。

解决方案: `resolveComMarkerForPack` 中两处 `if (packFnHint == "vb6_ComPackVariant")` 检查扩展为 `|| packFnHint == "vb6_ComPackValue"`，让 COM 调用结果先经 `vb6_VariantFromComResult(...)` 解封为 `vb6_VARIANT`，再被 `vb6_ComPackValue(vb6_VariantFromComResult(...))` 经 `VariantIdentity` 等价于 `vb6_ComPackVariant(vb6_VariantFromComResult(...))`。

### 修改

**`src/rtl/core/vb6rtl.h`** (line 891-895): 在 `vb6_ComPackVariant` 声明之后新增宏:
```c

```

**`src/backend/cgen_util.cpp` `comPackExpr()`** (line 1044-1045):

```cpp
    return "vb6_ComPackValue";  // Fix 030: 通用打包宏 (取代 "vb6_ComPackVariant")
```

## Fix 030b — `UBound`/`LBound` 参数签名注册

### 思路

新增 `addBuiltinFuncWithParams` lambda，注册 UBound/LBound 时填充 `sym->params`，让 `IndexOrCallExpr` 的 `calleeParams` 查找命中，从而触发:
- **Fix 024 P2** (ByVal Variant 正向包装): 第一参数 `Variant|Array` 非纯 Variant，不触发 P2 路径
- **Fix 029 反向提取**: 第一参数 `paramIsArray=true`, `paramBase=Variant` 命中 `vb6_VariantToSafeArray1D` 包装分支

参数签名:
- `array` (第一参数): `Variant|Array`, ByVal, 非可选
- `dimension` (第二参数): `Long`, ByVal, 可选 (VB6 `UBound(arr)` 等价 `UBound(arr, 1)`)

类型 `Variant|Array` 通过 `static_cast<Vb6Type>(static_cast<uint16_t>(Vb6Type::Variant) | static_cast<uint16_t>(Vb6Type::Array))` 构造，非纯 `Variant` 以让 Fix 029 的 `paramIsArray` 分支命中而非被视为 `Variant` 参数走 P2 路径。

### 关键副作用: 必须 gate padding/IsMissing 路径

注册参数签名后，`cgen_expr.cpp` 和 `cgen_stmt.cpp` 中的 Optional 参数填充 + `IsMissing _has_` 标志路径会触发，向调用点追加 `, 0, 0` 尾参，导致 `vb6_UBound(arr, 1, 0, 0)` 4 参数调用 — RTL C 签名只接受 2 参数，引发 C2197 "too many arguments"。

这些路径之前对 builtin 自动跳过的原因是: 注释 `calleeParams is empty for builtin RTL functions (registered without params), so they're auto-skipped`。Fix 030b 破坏了该假设。

修复: 新增 `bool calleeIsBuiltin = false;` 局部变量，在 `calleeParams = funcSym->params;` 处同步从 `funcSym->isBuiltin` 设置。然后 gate 以下四处 padding/IsMissing 路径:
- `cgen_expr.cpp` line 3209 (Optional padding): 加 `&& !calleeIsBuiltin`
- `cgen_expr.cpp` line 3239 (IsMissing _has_ flags): 加 `&& !calleeIsBuiltin`
- `cgen_stmt.cpp` line 2237 (bare-call Optional padding): 加 `&& !calleeIsBuiltin`
- `cgen_stmt.cpp` line 2262 (bare-call IsMissing): 隐式跳过 (在外层 `else if (calleeParams.size() > 0 && !calleeIsBuiltin)` 中)

注: Fix 024 P2 和 Fix 029 反向提取仍对 builtin 正常触发 (这是 Fix 030b 的核心目的)，仅 padding/IsMissing 路径被 gate。

### 修改

**`src/semantics/semantic_analyzer.cpp`**:
- 增加 `#include <tuple>` 和 `#include <initializer_list>`
- 新增 `addBuiltinFuncWithParams` lambda (line 2160-2174): 与 `addBuiltinFunc` 类似，但接收 `std::initializer_list<std::tuple<const char*, Vb6Type, bool, bool>>` 填充 `sym->params`
- 替换 `addBuiltinFunc("UBound", Vb6Type::Long)` / `addBuiltinFunc("LBound", Vb6Type::Long)` 为带参数版本 (line 2240-2243)

**`src/backend/cgen_expr.cpp`** `visit(IndexOrCallExpr&)`:
- 在 `calleeParams` 声明后新增 `bool calleeIsBuiltin = false;`
- 两处 `calleeParams = funcSym->params;` 后加 `calleeIsBuiltin = funcSym->isBuiltin;`
- Optional padding (line 3213) 和 IsMissing flags (line 3243) 的 `if` 条件加 `&& !calleeIsBuiltin`

**`src/backend/cgen_stmt.cpp`** `visit(CallStmt&)` bare-call 分支:
- 同样新增 `bool calleeIsBuiltin = false;` 并同步设置
- `else if (calleeParams.size() > 0)` 改为 `else if (calleeParams.size() > 0 && !calleeIsBuiltin)`
