# Fix 046: IIf Variant 参数提取 + 运行时函数参数类型表扩展 + 常量类型推导修复

## 日期
2026-07-22

## 问题

三个独立问题导致 C2440 类型转换错误：

1. **IIf 函数 Variant 参数未提取** — 当 IIf 的参数为 Variant 类型时，codegen 生成 `vb6_IIfLong(cond, vb6_VariantFromValue(arg1), vb6_VariantFromValue(arg2))`，但 `vb6_IIfLong` 期望 `int32_t` 参数，导致 `vb6_VARIANT → int32_t` 错误。需要从 Variant 中提取具体值。

2. **新增运行时函数缺少参数类型表** — `vb6_IIfBSTR`、`vb6_IIfLong`、`vb6_IIfDouble`、`vb6_IIfVariant`、`vb6_CLngV`、`vb6_CIntV`、`vb6_IntDiv` 等运行时函数不在 `getRuntimeParamCType()` 查找表中，导致参数包装决策缺失。

3. **VB6 常量类型推导失效** — 没有显式 `As Type` 的 VB6 常量（如 `Const HWND_TOPMOST = -1`）通过 `resolveTypeOrDefault()` 获得 `Vb6Type::Variant`。`registerConstant()` 中的值推导代码检查 `if (sym->type == Vb6Type::Unknown)` 来从字面量推断类型，但此检查为假（sym->type 已是 Variant 而非 Unknown），导致值推导从未触发。

## 根因分析

### IIf Variant 参数

IIf 特殊处理器（cgen_expr.cpp ~第 2057-2122 行）根据参数类型分派到 `vb6_IIfBSTR`/`vb6_IIfLong`/`vb6_IIfDouble`/`vb6_IIfVariant`。但当参数为 Variant 类型时，codegen 仍使用 `vb6_VariantFromValue()` 包装，而 `vb6_IIfLong` 期望 `int32_t`。需要从 Variant 中提取具体值（`vb6_VariantToLong`、`vb6_VariantToString`、`vb6_VariantToDouble`）。

### 常量类型推导

`resolveTypeOrDefault()`（semantic_analyzer.cpp:540）调用 `resolveTypeRef()`，对于未识别的类型名返回 `Vb6Type::Variant`（第 600 行）。当常量没有显式 `As Type` 时，`resolveTypeOrDefault()` 返回 Variant，而非 Unknown。`registerConstant()` 的值推导代码（第 431-525 行）检查 `sym->type == Vb6Type::Unknown`，但此时 sym->type 已是 Variant，推导被跳过。

## 修改内容

### 1. `src/backend/cgen_util.cpp` — 运行时函数参数类型表
在 `getRuntimeParamCType()` 中添加 7 个新条目：
- `vb6_IIfBSTR` → {"int32_t", "BSTR", "BSTR"}
- `vb6_IIfLong` → {"int32_t", "int32_t", "int32_t"}
- `vb6_IIfDouble` → {"int32_t", "double", "double"}
- `vb6_IIfVariant` → {"int32_t", "vb6_VARIANT", "vb6_VARIANT"}
- `vb6_CLngV` → {"vb6_VARIANT"}
- `vb6_CIntV` → {"vb6_VARIANT"}
- `vb6_IntDiv` → {"int32_t", "int32_t"}

### 2. `src/backend/cgen_expr.cpp` — IIf Variant 参数提取
在 IIf 特殊处理器（~第 2087-2122 行）中添加：
- `iifArgIsVariant()` lambda：检查参数是否为 Variant（`cExprIsVariant()` + `knownVariantVars_`）
- `extractVariantArg()` lambda：根据目标类型从 Variant 提取具体值
  - BSTR 目标 → `vb6_VariantToString()`
  - Double 目标 → `vb6_VariantToDouble()`
  - Long 目标 → `vb6_VariantToLong()`
- 当两个参数均为 Variant 时，使用 `vb6_IIfVariant` 回退

### 3. `src/semantics/semantic_analyzer.cpp` — 常量类型推导
在 `registerConstant()`（~第 436 行）中，当未指定显式 `As Type` 且 `sym->type == Vb6Type::Variant` 时，将 `sym->type` 重置为 `Vb6Type::Unknown`。这使得值推导代码能正确从字面量推断类型（如 `-2` → Long，`3.14` → Double，`"hello"` → String）。

## 局限性

1. **IIf 修复仅减少 1 个错误** — 大多数 IIf 调用的参数不是 Variant 类型，实际 Variant 参数的 IIf 调用很少。
2. **常量修复减少 23 个错误** — 主要影响常量参与的表达式和函数调用，减少了不必要的 Variant 包装。
3. **运行时函数参数类型表扩展** — 当前中性，但为 Fix 047 和后续运行时函数参数包装修复提供基础设施。
